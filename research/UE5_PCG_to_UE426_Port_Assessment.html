UE5 PCG 插件移植到 UE4.26 评估报告

目标是评估将 UE5.7.4 的 Procedural Content Generation Framework（PCG）及相关 Interop/示例插件移植到当前 UE4.26.2 工作区的改动范围、风险、兼容性问题和原生依赖缺口。本文档只做调研与评估，不修改引擎代码。

当前工程：UE 4.26.2
参考源码：UE 5.7.4
报告日期：2026-06-24
范围：PCG Runtime / Compute / Editor / Interops / PC + 移动端
结论摘要 源码证据 模块难度矩阵 PCG 核心专项 Interop 插件 移动端与 PC 依赖缺口 需剥离功能 实施路线

结论摘要

极高
整体风险。UE4.26 没有 PCG 插件本体，移植不是补小模块，而是回迁一套图执行框架、编辑器和大世界生成体系。
228k+
UE5 PCG 主插件源码规模：Runtime 约 190,521 行，Editor 约 37,060 行，Compute 约 336 行。
10+
PCG 相关插件/Interop：GeometryScript、ExternalData、Python、Niagara、Water、Nanite、InstancedActors、Biome 等。
总判断：如果目标是“UE5 PCG 完整能力”移植到 UE4.26，工作量接近一个中型引擎子系统回迁工程。PCG 本体深度依赖 UE5 的 World Partition/DataLayer、PropertyBag/StructUtils、ActorPartition、ComputeFramework、GeometryFramework/GeometryScripting、AssetDefinition、ContentBrowserData、TypedElement、EditorSubsystem 等。建议采用“核心运行时 + 最小编辑器 + 逐个 Interop”的分阶段回迁，而不是复制整个 UE5 PCG 插件目录。

优先级建议

  • 第一优先：PCG Graph、Node、Settings、Metadata、Point Data、基本 Spatial Data、Component 和 Subsystem。
  • 第二优先：最小 Editor 图编辑、资产创建、基础调试与手动生成。
  • 第三优先：Landscape/Foliage/StaticMesh 生成节点和必要运行时生成。
  • 暂缓/剥离：World Partition Builder、DataLayer、Nanite Assemblies、PCG Water、PCG Niagara、GPU Compute、Biome 工具链。

关键限制

  • UE4.26 不支持 UE5 World Partition；PCG 的 partition actor 与 builder 必须改造为 UE4 Level/Streaming 或直接裁剪。
  • UE5 PCG 广泛使用 TObjectPtr、FInstancedPropertyBag、UE_INLINE_GENERATED_CPP_BY_NAME，需要降级。
  • 移动端不能默认承诺 GPU PCG/Compute；应先限定 CPU 生成、离线 Bake、Cook 后运行。
  • Interop 插件很小但依赖很重，实际难度取决于目标系统是否存在。

PCG 核心专项分析

PCG 核心由哪些子系统组成
  • 图与节点：UPCGGraph、UPCGNode、UPCGSettings、Subgraph、GraphInstance。
  • 数据模型：PointData、ParamData、SpatialData、SurfaceData、VolumeData、LandscapeData、Metadata。
  • 执行系统：Graph Executor、Task、Context、Async Loading、Runtime Generation Scheduler。
  • 组件与子系统：UPCGComponent、UPCGSubsystem、Generated Resource 管理。
  • 分区与大世界：APCGPartitionActor、Grid、WorldPartitionBuilder、DataLayer 参数。
  • 编辑器：PCG 图编辑器、节点菜单、Pin 类型、可视化、AssetDefinition、Builder Settings。
为什么不能直接复制 UE5 PCG
  • UE5 PCG 代码广泛使用 TObjectPtr、TSoftObjectPtr、UE_INLINE_GENERATED_CPP_BY_NAME，UE4.26 需要批量降级。
  • UPCGGraph 依赖 ComputeFramework/ComputeGraphInstance.h 和 StructUtils/PropertyBag.h，UE4.26 没有等价基础设施。
  • APCGPartitionActor 继承 APartitionActor 并创建 FWorldPartitionActorDesc，UE4.26 没有 World Partition。
  • PCGEditor 依赖 UE5 AssetDefinition/ContentBrowserData/TypedElement/SubobjectDataInterface 等编辑器框架。
  • PCGCompute 依赖 ComputeFramework 和新版 Renderer/RHI 管线，移动端风险尤其高。
建议保留的最小功能集
  • PCG Graph 资产、基础节点执行、Metadata、PointData、ParamData、基础 SpatialData。
  • PCGComponent 手动生成、编辑器内生成、基础 Runtime 生成，不接 World Partition Builder。
  • StaticMesh/InstancedStaticMesh/Foliage 生成的最小闭环。
  • Landscape CPU 采样可作为第二阶段，GPU GrassMap/VirtualTexture 采样延后。
  • 移动端以 Cook 后资源和 CPU 运行时为主，不承诺编辑器构建和 GPU PCG。

移动端与 PC 适配评估

PC 端

  • 适合作为 PCG Editor 与完整 Runtime 的主要目标平台。
  • 可以逐步启用 PCGCompute、Landscape 缓存、Foliage/StaticMesh 批量生成。
  • World Partition Builder 在 UE4.26 不可用，PC 端也建议剥离或改为传统关卡批处理。
  • PCG Interop 可按业务需求逐个开：GeometryScript/Water/Niagara 都需要对应插件先稳定。

移动端

  • 建议目标是 Cook 后运行时生成或离线 Bake，不建议开放完整编辑器式动态生成。
  • 首轮仅支持 CPU PCG、Point/Metadata、基础 StaticMesh/ISM 生成。
  • PCGCompute/GPU Landscape Sampling/VirtualTexture 采样需要 Android Vulkan、Android ES3.1、iOS Metal 分别验证。
  • 运行时异步生成需要严格预算，避免大图、递归 Subgraph 和高密度点云导致卡顿。
移动端建议口径：“适配移动端”应定义为 PCG 结果可 Cook、可加载、可运行基本 CPU 生成。不要默认承诺 UE5 PCG 的 GPU Compute、复杂 Landscape/Water/Niagara Interop、Runtime Partition Generation。

World Partition / 地形与大世界功能剥离建议

PCG 比 Niagara 更强地绑定 UE5 大世界体系。源码中 WorldPartition 命中 383 次，DataLayer 命中 369 次，Landscape 命中 1445 次。UE4.26 没有 World Partition，因此必须在设计阶段决定哪些功能不移植。

建议保留：传统关卡中的 PCG Component、手动/运行时生成、基础 Landscape CPU 采样、StaticMesh/ISM/Foliage 输出、Cook 后资源加载。
建议剥离：WorldPartitionBuilder、DataLayer 过滤、Partition Actor ActorDesc、Cell Loading、One File Per Actor 绑定流程、Nanite/InstancedActors Interop。

替代设计

  • 将 APCGPartitionActor 替换为普通管理 Actor 或直接禁用分区生成。
  • 将 DataLayer 选择改为 Actor Tag、Level Streaming 名称、编辑器自定义过滤器。
  • 将 WorldPartitionBuilder 命令行构建改为 UE4 Commandlet 或 Editor Utility 的传统关卡遍历。
  • 对于开放世界项目，PCG 生成结果建议先 Bake 到关卡/子关卡，而不是运行时动态全量生成。

决策建议

推荐方案：PCG 子集回迁

以 UE4.26 为底座新增 PCG 插件，先回迁 Runtime 最小闭环，再补最小 Editor。World Partition、PCGCompute、Interop 全部后置。这样最可能在可控周期内拿到可用结果。

不推荐方案：全量复制 UE5 PCG

UE5 PCG 已经与 UE5 大世界、编辑器资产体系、几何脚本、计算框架深度绑定。全量复制会迅速扩散为“把 UE5 一批基础设施搬回 UE4.26”的工程。

验收口径建议
  • PC Editor 可创建 PCG Graph，并能通过 PCGComponent 执行基础点生成。
  • PC Runtime 可生成 StaticMesh/ISM/Foliage 类结果，并能清理生成资源。
  • 移动端可加载 Cook 后 PCG 资产，基础 CPU 生成无崩溃、无大量 shader 阻塞。
  • World Partition/DataLayer/Nanite/PCGCompute/Interop 被明确剥离或置灰。
  • 现有 UE4.26 工程模块无编译回归。
