一分钟看懂

切到 Standard ACES 之后，整体亮度其实没变：18% 中灰在两种模式下都显示为像素值 ≈ 118。变的是两头和颜色：暗部被抬亮、亮部被压低、颜色变淡。对比度一降，画面就“灰”了。

造成这种变化的是四件事，影响从大到小：

  • ①
    显示编码对不上（影响最大，一行配置就能修）。在后处理体积（PPV）里选 Standard ACES 后，UE 默认按 BT.1886（Gamma 2.4，暗室看电视的标准）输出；电脑和手机屏幕按 sRGB（约 Gamma 2.2）显示，结果暗部整体被抬亮。
  • ②
    ACES 2.0 的曲线本身更柔。中间调对比度比 Filmic 低约 27%，到 99% 白需要的亮度是 Filmic 的 3 倍多，相当于把空间留给了高光层次。所以同一盏灯、同一张贴图，亮部会更暗、更平。
  • ③
    颜色处理方式不同。Filmic 对 R、G、B 三个通道分别压缩，会顺带加饱和，并让亮色偏色（火焰发黄、蓝光发青）。ACES 2.0 保持色相，代价是正常亮度下颜色淡一些，色卡平均彩度低约 14%。
  • ④
    Filmic 专属参数全部失效：Film Slope / Toe / Shoulder / Black Clip / White Clip、Blue Correction、Tone Curve Amount、Color Grading LUT 贴图。工程正式内容里有 3 张地图改过 Film 参数，1 张用了 LUT 贴图。

短期：先把画面救回来

  • 不急着切：存量关卡继续用 Filmic，零成本。
  • 要切：DefaultEngine.ini 加一行 r.LUT.TonemappingSDRInvEOTF=0，把编码改回 sRGB。再按需补偿：曝光 +0.1 档、全局对比度 ×1.15、饱和度 ×0.95。
  • 这样与原 Filmic 画面的平均色差能从 4.8 降到 2.8（只改编码），再降到 1.8（加补偿）。

→ 具体做法

长期：以 ACES 2.0 为基准重打光

  • 正好配合 PBR 重打光：统一“ACES 2.0 + sRGB 编码”，建一张标定场景，用 18% 灰卡（BaseColor 0.18）把正确曝光定死。
  • 本工程曝光锁定 ×1，PPV 的曝光补偿不生效：亮度靠灯光，主光照到灰卡上约 π lux 就是正确曝光。
  • 自发光、特效、天空按档位重调：ACES 下亮部要多给约 1 档。
  • 项目的 Look 用 Color Grading 预设来做；LUT 贴图在 ACES 下不生效。
  • DCC 预览要对齐 UE 额外乘的 ×1.5（+0.58 档）。

①显示编码：给显示器的“翻译方式”变了（影响最大）

渲染算出来的是“光有多亮”。最后一步要把它翻译成 0–255 的像素值发给显示器，显示器再按自己的规则翻译回亮度。两边必须用同一本“字典”：

  • Filmic 按 sRGB 编码；电脑屏幕、手机屏幕按 sRGB 显示：配对。
  • Standard ACES 在 UE 里默认按 BT.1886（Gamma 2.4）编码。这是暗室里看电视、调色监视器的标准，而普通屏幕仍按约 2.2 解码：不配对。同样的暗部亮度被编成更大的像素值，显示出来就亮了，阴影发灰。

引擎源码的说明写得很直白：“The default for ACES is BT.1886 to prioritize compatibility between SDR and Rec. 2100 for HDR.” Epic 是为了让 SDR 和 HDR 电视的观感一致才选了 BT.1886；但我们的玩家绝大多数用的是 sRGB 屏幕。这个默认值只在 PPV 选了 Standard ACES 时启用（Filmic 一直是 sRGB）。可以用 r.LUT.TonemappingSDRInvEOTF 改：0 = sRGB，1 = BT.1886。

灰阶曲线：场景亮度 → 屏幕像素值

横轴是比 18% 中灰亮或暗几档（1 档 = 亮度 ×2），纵轴是最终发给屏幕的像素值（0–255）。把鼠标放到图上可以看每档的具体数值。

具体数字：比中灰暗 3 档 / 5 档的地方，Filmic 的屏幕亮度是 0.65% / 0.06%，ACES 默认是 1.62% / 0.33%（×2.5 / ×5.2）。改成 sRGB 编码后是 0.81% / 0.05%，与 Filmic 基本一致。

A/B 对比的坑 控制台的 r.LUT.TonemappingMethod 1 只会把曲线换成 ACES，编码仍然跟着 PPV 走（源码里编码默认值读的是 PPV 的设置，不是这个控制台变量）。所以在控制台里切，看到的是“ACES + sRGB”；在 PPV 里切，看到的是“ACES + BT.1886”，两种方法的结果不一样。反过来，PPV 选了 ACES、控制台强制 Filmic 时，Filmic 也会被按 BT.1886 编码，同样发灰。团队讨论“ACES 好不好看”之前，先统一切换方法（下面有命令）。

②曲线形状：ACES 2.0 更柔，把空间留给了高光

编码修好之后（上图青色线），暗部和 Filmic 基本重合，但从中灰往上 ACES 2.0 一直更低、更平：

  • 中间调对比度：中灰附近每亮 1 档，Filmic 增加 51.5 个像素值，ACES 2.0 只增加 37.5，低 27%。
  • 高光到白的距离：Filmic 在比中灰亮 +5.2 档（中灰的 37 倍）时就到了 99% 白；ACES 2.0 要到 +7.0 档（中灰的 128 倍）。比中灰亮 2 档的地方，Filmic 是 208.5，ACES 是 183.8。
  • 为什么中灰刚好一样？UE 在 ACES 前面额外乘了 1.5（r.HDR.Aces.SceneColorMultiplier，约 +0.58 档），配合 BT.1886 编码，正好让中灰与 Filmic 对齐（117.9 vs 117.6）。可见 Epic 有意保证“整体亮度不变”，只是两头对不齐。

换成美术的直觉：中间调不用动；想让亮部像以前一样亮，ACES 下要多给能量，越亮的地方要多给得越多：

这不是 ACES 的缺陷，而是取舍。Filmic 很快把亮部压到白，画面“实”、出片快，但强光、火焰、天空容易糊成一片。ACES 2.0 给高光留了 3 倍多的余量，层次更多，也是它能自然适配 HDR 屏幕的原因。代价是默认观感更平，需要在上面自己做 Look。

③颜色：Filmic 逐通道压缩，ACES 2.0 保色相

Filmic 把 R、G、B 三个通道各自套同一条 S 曲线。亮的通道先被压平，暗的通道后被压，所以一个颜色越亮，就越往黄、青、品红偏，同时中等亮度的颜色被“顺带”加了饱和。ACES 2.0 在色貌空间里只压亮度，彩度单独控制，所以色相基本不变，亮到头是“变白”而不是“变色”。下面每一行是同一个颜色从 −2 档逐渐提亮到 +8 档：

Filmic 下火焰橙最多偏 47°，魔法蓝偏 38°，血红偏 17°，奥术紫偏 15°；ACES 2.0 全部不超过 5°。

对特效 / 自发光的影响 以前火焰的“黄白芯”、魔法光的“青白芯”，很大一部分是 Filmic 偏色“送”的。ACES 下颜色不会自己变，火焰会更橙、更红（对比滑块里的选角场景）。想要黄白芯，就要在特效贴图或颜色渐变里明确做出来。好处是：特效颜色调成什么样，屏幕上就是什么样，不会因为亮度一变就跑色。

平均彩度随曝光的变化（色卡 18 个彩色块）

正确曝光附近 ACES 2.0 更淡；但比正确曝光亮 1.5 档以上时，ACES 反而比 Filmic 更保色。Filmic 的亮色会很快被压成白色或黄色。

短期方案：不重做美术，先把画面救回来

目标：在 PBR 重打光完成之前，既可以继续用 Filmic，也可以先切 ACES 而不让画面变灰。

  1. 先决定要不要现在切 存量关卡的灯光、材质、特效都是在 Filmic 下调的，继续用 Filmic 是零成本、零风险的选择。建议只在新做或重打光的关卡里用 ACES，旧关卡等重打光时再切。下面的 2–5 步是“必须现在切”时的做法。
  2. 必做：把输出编码改回 sRGB 解决“暗部发灰”这个最大的问题，只影响 Standard ACES，Filmic 不受影响： 
    ; Config/DefaultEngine.ini
[/Script/Engine.RendererSettings]
; Standard ACES 在 SDR 下按 sRGB 编码（默认 -1：PPV 选 ACES 时用 BT.1886 / Gamma 2.4，普通屏幕暗部发灰）
r.LUT.TonemappingSDRInvEOTF=0
    效果：与 Filmic 的平均色差 4.8 → 2.8（地牢场景 5.0 → 1.4）。这个变量每帧读取，编辑器里用控制台输入同名命令可以立即看到效果。
  3. 可选：把观感补偿到接近 Filmic 下面三个数是用两张工程截图加色卡拟合出来的，与 Filmic 最接近（平均色差 2.8 → 1.8）：
    参数在哪里改值作用
    曝光r.HDR.Aces.SceneColorMultiplier=1.6（默认 1.5，只影响 ACES）；或者 PPV → Color Grading → Global → Gain 填 ×1.07。PPV 的 Exposure Compensation 在本工程不生效，别用它+0.1 档中灰对齐 Filmic

    饱和度PPV → Color Grading → Global → Saturation（Y）×0.95对比度加上去后饱和度会略高，轻微回收

    “×”的意思是在原值上乘：UE 的 Contrast 是以 0.18 为支点的幂运算，Saturation 是围绕亮度的插值，两次叠加正好等于两个系数相乘。所以已经改过对比度、饱和度的地图（正式内容里分别有 4 个和 21 个）用“原值 × 系数”，没改过的直接填系数。补偿后的灰阶曲线是第一张图里的黄色线。

    备选：如果以后要做 HDR 输出，并且要求 SDR/HDR 观感严格一致，也可以保留 BT.1886 编码，改用曝光 −0.1 档（SceneColorMultiplier 1.4）、对比度 ×1.3、饱和度 ×0.95，色差为 1.4，数值上更接近，但对比度要加得更猛。对 PC / 手机项目，第 2 步的 sRGB 编码在原理上更正确，推荐用它。

  4. 检查清单：切换前逐项看一遍
    • 3 张改过 Film Slope 的正式地图（HD_MiLiuZhiHuan000、YongShuangBingPo ×2）：这个参数失效后要用 Contrast 重新找感觉。
    • SD_GeBuLinYingDi02 的 LUT 贴图会失效：要么用 Color Grading 重调，要么这张图先留在 Filmic。
    • 火焰、魔法、刀光等高饱和特效：颜色不再偏黄、偏青，亮度也偏暗，需要特效同学确认。
    • 天空、自发光、灯光高光：要达到原来的亮度大约要多 1 档（见原因 ② 的表）。
    • 用 SceneCapture 渲到 UI 的画面（角色展示、头像）同样走 Tonemapper，也会变。
    • 前面提到的 2 张已经存成 ACES 的地图。
  5. 统一的 A/B 对比方法（编辑器 / PIE 控制台） 
    r.LUT.TonemappingMethod 0         // 强制 Filmic
r.LUT.TonemappingMethod 1         // 强制 Standard ACES（ACES 2.0）
r.LUT.TonemappingSDRInvEOTF 0     // 编码 = sRGB
r.LUT.TonemappingSDRInvEOTF 1     // 编码 = BT.1886（= 在 PPV 里选 ACES 时的默认）
r.HDR.Aces.SceneColorMultiplier 1.6  // ACES 曝光补偿（默认 1.5）
r.LUT.TonemappingMethod -1        // 恢复：跟随 PPV
r.LUT.TonemappingSDRInvEOTF -1    // 恢复：跟随默认规则

    两个变量要一起设，才能确定看到的是哪种组合。“ACES 默认”是 1 / 1，“ACES + sRGB”是 1 / 0，Filmic 是 0 / 0。

  6. 不要用局部后处理体积来切换 Tonemapping Method 是“开关型”属性，不做混合：只要体积权重大于 0 就整个切过去（源码 SET_PP(TonemappingMethod)）。角色走进带 Blend Radius 的局部体积时，画面会瞬间跳变。请在每张图的全局（Unbound）PPV 上整图切换。

长期方案：以 ACES 2.0 为基准的 PBR 重打光

既然美术效果本来就要按 PBR 重新打光，这是切到 ACES 2.0 最合适的时机。目标是让“美术在屏幕上看到的”和“物理上应该是的”一致，再在上面叠项目自己的风格。和灯光、曝光有关的步骤（②③④⑤⑦⑨）都配了图解和逐步操作。

▶先动手：4 个小实验，从操作反推原理

不需要摄影基础，在一张空关卡里 10 分钟就能做完；后面所有规范都能和这几个读数对上。实验统一用 ACES 2.0 + sRGB 编码（控制台 r.LUT.TonemappingMethod 1、r.LUT.TonemappingSDRInvEOTF 0），并临时关掉工程默认的局部曝光（r.DefaultFeature.LocalExposure.HighlightContrastScale 1、r.DefaultFeature.LocalExposure.ShadowContrastScale 1，原因见第 ③ 步），读到的数才和下面一致。

118% 灰卡在 UE 里是哪个数

做
新建材质，BaseColor 接一个 Constant3Vector，双击打开取色器，在 Hex sRGB 框里输入 767676 回车。
看
R、G、B 三个数值框都变成 0.18。再输入 808080（PS 里正中间的 128），数值变成 0.216。
为什么
取色器的 R、G、B 数值框是线性值：表面把多少比例的光反射回去，0.18 就是 18%。Hex sRGB 和 PS 的 0–255 是给眼睛看的编码，暗部分得细、亮部分得粗，所以 118 才对应 18%。常见坑：把 PS 的 118 直接 ÷255，填成 0.463，等于反射 46% 的光，亮了约 +1.4 档。

2把灰卡放到灯下，读出“正确曝光”

做
空关卡里只放一盏平行光（不要天光、天空大气、雾），旋转成垂直向下，强度 3.14 lux；下面放一块水平的平面，用实验 1 的材质（Metallic 0、Specular 0、Roughness 1）。打开 Tools → Debug → Pixel Inspector，点 Start Pixel Inspector，鼠标移到平面上。
看
Scene Color Before Tonemap ≈ 0.18，PreExposure = 1；Final Color ≈ 0.157（这是线性值，换成屏幕像素值就是 110）。
为什么
漫反射表面的亮度 = BaseColor × 照度 ÷ π = 0.18 × 3.14 ÷ 3.14 = 0.18。本工程曝光锁定 ×1，这个值原封不动进入色调映射。所以在本工程，“主光照到灰卡上约 π lux”就是正确曝光：此时任何正对主光的表面，Scene Color 读数都约等于它自己的 BaseColor。

3灯光翻倍，还是 BaseColor 翻倍

做
把平行光改成 6.28 lux，读一次；改回 3.14，再把 BaseColor 改成 0.36，读一次。
看
两次 Scene Color 都是 0.36（亮了 1 档），屏幕都是 148，画面完全一样。
为什么
画面只认“BaseColor × 光”的乘积，同一个画面可以有无数种组合。材质组随手调 BaseColor、灯光组随手调强度，换一个场景就对不上。所以规范是：BaseColor 按真实反射率定死（第 ④ 步），亮暗只用灯光来调。

4同一个场景值，换两种 Tonemapper

做
在灰卡旁边放一块白卡（BaseColor 0.87，PS 240）。控制台切 r.LUT.TonemappingMethod 0（Filmic）和 1（ACES），分别读两块卡。
看
Scene Color 不变（0.18 / 0.87）。Final Color：灰卡 0.180 → 0.157，白卡 0.69 → 0.53；换成屏幕像素值是灰卡 118 → 110，白卡 216 → 192。
为什么
色调映射只改变“场景值 → 屏幕像素值”这一步翻译，不改变场景。ACES 给高光留的空间更多，所以同一块白卡显示得更暗。这不是材质错了，不要靠把 BaseColor 调到 255 来补（1.0 也只到 198）。

  2. 做一张“标定场景”（Look-dev 地图）

    它的作用就像摄影棚里的灰卡和色卡：用一组反射率已知的道具，把“灯光对不对、曝光对不对”变成可以读数的问题。所有灯光、材质、特效先在这里过一遍，再进关卡。

    怎么摆

    • 机位：用游戏镜头的角度和距离（工程按 30°–45° 俯角算阴影距离，见 r.CSM.CameraRotatorY），存成相机书签（Ctrl + 数字键保存，数字键调用），每次都用同一个机位截图。
    • 两组道具：一组在主光下，一组在一堵墙的阴影里。两张灰卡的读数差，就是这套灯光的光比（第 ③ 步）。
    • 四套灯光：白天户外、室内、地牢、夜晚各做成一个子关卡（或 Data Layer），PPV 共用一个，切换时其他设置不变。
    • 读数时：关掉高度雾、体积雾（雾会叠加进 Scene Color）；Lumen 保持打开，它就是游戏里的实际光照。Bloom 在色调映射时才叠加，不影响 Scene Color 读数。
  3. 建立曝光体系
    先纠正一个误会：本工程的曝光是锁死的 工程在所有画质档位都设了 r.EyeAdaptationQuality=0（DefaultScalability.ini，以及 PC / Android / IOS / Emulator 各自的 Scalability.ini）。它不只是关掉自动曝光：引擎会把 EyeAdaptation 显示标志一起关掉，曝光计算走“全部置 1”的分支，曝光锁定 ×1，PPV 里的 Exposure Compensation 不参与计算（源码见附录 A）。全工程有 83 个包（正式内容 27 个）设置过 Exposure Compensation，这些值在游戏和编辑器的主视口里都不起作用，UE4.26 的老工程也一样。所以在本工程：画面整体有多亮，完全由灯光强度 × 材质反射率决定。

    例外：SceneCapture（UI 里的 3D 角色展示、头像常用它）不走这个开关。源码里只有游戏视口和编辑器视口会套用 r.EyeAdaptationQuality，捕获画面的曝光仍按捕获组件和 PPV 的曝光设置计算，默认测光方式是自动曝光。这类画面建议在捕获组件的后处理设置里把测光方式改成 Manual、关掉 Apply Physical Camera Exposure，此时曝光 = 2Exposure Compensation，填 0 就和主视口的 ×1 一致（不填时默认值是 1，会亮 1 档）。

    正确曝光的标准（三种说法，说的是同一件事）

    • 读数：主光下 18% 灰卡的 Scene Color Before Tonemap = 0.18。0.16–0.20（−0.17 ~ +0.15 档）都算合格，对应屏幕像素值 104–116。
    • 灯光：主光加上天光等补光，照到灰卡上的总照度约 π ≈ 3.14 lux。
    • 现场检查：任何正对主光的漫反射表面，Scene Color 读数 ≈ 它自己的 BaseColor。草地 BaseColor 0.21 却读出 0.42，说明这里亮了 1 档。

    操作：用 Pixel Inspector 标定一盏主光

    1. 视口左上角的视图模式菜单（Lit）→ Exposure，确认勾着 Game Settings。拖过下面的 EV100 滑条会自动取消勾选，视口就改按固定 EV100 曝光（EV100 = 1 时比游戏暗 1 档），和游戏对不上。

    Substrate 下别看 GBuffer 分组。工程开了 Substrate（自适应 GBuffer），Pixel Inspector 里 BaseColor、Metallic 等 GBuffer 项可能不准；BaseColor 以材质里填的数为准。Scene Color 和 Final Color 不受影响。

    局部曝光会“压扁”大块明暗。工程默认开了 Local Exposure（高光、暗部对比都是 0.8，全工程 0 张图改过它）：大块区域相对中灰的档数会乘 0.8。主光下的灰卡正好在支点上，不受影响；大片阴影 −2.5 档在屏幕上像 −2 档（像素值 32 → 45），地牢 −5 档像 −4 档（2 → 7）。它只影响 Final Color，不影响 Scene Color；本文表格里的屏幕值都没算它。

    灯光强度怎么换算（本工程曝光 ×1）

    • 平行光（lux）：正对表面时，强度就是照度。斜着照时，平放表面收到的是“强度 × 光线与地面夹角的正弦”。UE 新建平行光默认 10 lux，正对表面时在本工程比正确曝光亮约 +1.7 档，拖进场景后先改成 3.14 左右再细调。
    • 点光源（工程默认单位是流明，r.DefaultFeature.LightUnits=2）：坎德拉 = 流明 ÷ 4π（约 ÷12.6）；距离 d 米处的照度 = 坎德拉 ÷ d²。距离翻倍，照度变成 ¼，暗 2 档。新建点光源默认约 100 流明（8 坎德拉），在 1.6 米处正好正确曝光。
    • 聚光灯：同样的流明，锥角越小中心越亮（UE 按锥角把光通量重新分配）。想让强度不随锥角变，改用坎德拉。
    • 天光、自发光：都按“比灰卡亮或暗几档”来定，见第 ④ 步。

    想让整张图整体亮一点或暗一点

    因为曝光补偿不生效，可用的办法按推荐顺序是：

    1. 按比例调所有灯（推荐）：选中主光、补光、天光，强度一起 ×2（+1 档）或 ×½（−1 档），灰卡读数跟着变，光比不变。自发光不会跟着变；想让它和环境的相对亮度不变，Emissive 也一起乘。
    2. PPV → Color Grading → Global → Gain：在色调映射之前给整个画面乘一个数，连自发光一起变，效果约等于曝光（Gain 2 = +1 档），Filmic 和 ACES 都生效。它本来是调色参数，团队要约定只在 Global 这一项用，并把档数记进表里。Gain 不影响 Scene Color 读数，所以标定照常以 0.18 为准，Gain 记作这张图“正常曝光”的偏移（Gain 0.5 = −1 档）。
    3. 全项目统一偏移：r.HDR.Aces.SceneColorMultiplier（默认 1.5，只影响 ACES）。会改动所有地图，只在定项目基准时用一次。
    4. 视口的 EV100 滑条只用来临时预览，不进包，用完记得勾回 Game Settings。
    可选路线：打开手动曝光，让 Exposure Compensation 生效（需要 TA 决定）

    如果团队想用真实世界的亮度（太阳约 10 万 lux、室内几百 lux），或希望每张图有一个独立的曝光旋钮，可以把曝光切成“手动”。每张图的 Exposure Compensation 就等于 −EV100：晴天约 −15，阴天约 −12，室内约 −7。要一次改齐这些地方：

    • 所有 Scalability.ini 的每个 PostProcessQuality 档位：r.EyeAdaptationQuality=2。UEChecker 会核对这个值，模板也要一起改。
    • DefaultEngine.ini：r.DefaultFeature.AutoExposure.Method=2（默认测光方式 = Manual），r.DefaultFeature.AutoExposure.Bias=0（UE 默认是 1，会让所有图突然亮 1 档）。
    • 每张图的全局 PPV 关掉 Apply Physical Camera Exposure。引擎默认开着，默认相机 f/4、1/60 秒、ISO 100 相当于 EV100 9.9，不关的话画面会暗约 10 档。
    • 打开前先检查已经存过曝光设置的图：正式内容里 27 个包存过 Exposure Compensation、11 个改过测光方式、6 个改过 Apply Physical Camera Exposure（全工程分别是 83 / 45 / 14 个）。这些值打开后会突然生效。
    • 自发光、特效、UI 3D 元素的强度要跟着曝光一起放大，或在材质里乘 EyeAdaptationInverse 节点。
    • Lumen 的缓存光照默认只覆盖曝光 −8 到 +12 档（r.EyeAdaptation.CachedLightingPreExposure=4），用真实太阳亮度时要改成 8。

    不打算用真实世界的绝对亮度，就保持现状，更省事。要切就在重打光开始前一次性切换并重新标定，不要中途切。

  4. 材质与自发光规范

    一句话：BaseColor 用 UE 的线性值思考，按真实材质定死；自发光按“比中灰亮几档”定强度。

    同一个颜色的两种写法：UE 的线性值 vs PS 的 sRGB 值

    BaseColor 对照尺

    上排是 PS / Substance 里的 sRGB 值（0–255），下排是同一个位置在 UE 里要填的线性值。斜线区是非金属不该用的范围；下方蓝色三角标的是 UE 官方文档给的真实材质实测值。

    • UE 的 0.18 = PS 的 118（18% 灰卡）；UE 的 0.5 = PS 的 188，不是 128；PS 的 128 在 UE 里是 0.216。
    • 线性值和光的能量成正比，所以 UE 里“0.36 正好比 0.18 亮 1 档”；sRGB 值是按眼睛的感觉排的，PS 里 118 → 236 并不是亮 1 档。
    在哪里看到 / 填的是怎么做
    PS、Substance 的拾色器、贴图像素sRGB 值（0–255 / Hex）按下面的安全范围画，存成普通 8 bit 贴图。
    UE 取色器的 R、G、B 数值框线性值（BaseColor 实际用的数）直接填线性值；或把 PS 的 Hex 粘贴到 Hex sRGB 框，UE 自动换算（源码用的就是 sRGB 公式）。
    材质里的 Constant3Vector、VectorParameter线性值不要把 PS 的 0–255 直接 ÷255 填进去：118 ÷ 255 = 0.463，亮了约 +1.4 档。
    BaseColor 贴图贴图里存 sRGB 值，采样时自动转成线性值贴图设置里的 sRGB 要勾上（颜色贴图默认就是勾上的）。
    粗糙度、金属度、AO、遮罩贴图贴图里存的就是数据本身sRGB 不勾，压缩设置选 Masks (no sRGB)。勾错了，0.5 的粗糙度会被当成 0.21。

    正确曝光下，Filmic 让中间调“画什么显示什么”（118 → 118），亮部压得较少；ACES 2.0 把整段都放低一点，白卡（240）只显示 192。原因是第 ③ 步的档位尺：漫反射白只有 +2.3 档，ACES 把 +2.3 到 +7.0 档留给了光源。

    想要更白的白：调项目 Look（Color Grading 的对比度，第 ⑥ 步），或者给那片区域更多光。不要把 BaseColor 推过 240：推到 255（1.0）也只显示 198，却会让这个材质在所有光照下都过亮。

  5. 特效重调

    火焰、魔法等高饱和特效的“白芯 / 黄芯”要在贴图或颜色曲线里明确做出来，不再依赖 Tonemapper 偏色。好处是颜色所见即所得：调成什么色，越亮也还是那个色。下面是同一条火焰渐变（外圈 → 核心，强度从 0 档升到 +6 档）：

    1. 颜色渐变按“外圈深红橙 → 橙 → 黄 → 淡黄 → 近白”做，越靠核心越降饱和。
    2. 强度按档位升：外圈 0 ~ +2 档，核心 +5 ~ +6 档。黄色放在 +3 档左右最鲜艳，再亮 ACES 会把它推向白色。
    3. 在标定场景里和灰卡一起看，确认核心不糊、外圈不发灰。
  6. 项目 Look 用 Color Grading 做，不用 LUT 贴图 ACES 2.0 默认是“中性原片”。项目风格（对比、饱和、暗部偏冷、高光偏暖等）用 Color Grading 的全局 / 暗部 / 中间调 / 高光分区来做，整理成几套 PPV 预设，按场景类型复用。LUT 贴图在 ACES 下不生效。实在需要 LUT 式调色，可以用 After Tonemapping 的后处理材质，但有额外开销，移动端要慎用。
  7. DCC 和 UE 对齐

    Substance Painter、Nuke、DaVinci Resolve、Maya / Houdini 等支持 OCIO 的软件，用 ACES 2.0 配置（sRGB 显示、SDR 100 nit）预览时，要额外 +0.58 档曝光，因为 UE 在 ACES 前乘了 1.5。用灰卡核对最直观：

    同一个 18% 灰（场景值 0.18）屏幕像素值
    UE：ACES 2.0 + sRGB 编码（内部 ×1.5）110
    DCC：OCIO ACES 2.0，sRGB 显示，视图曝光 089

    另一种做法是把 UE 的 r.HDR.Aces.SceneColorMultiplier 设回 1.0，与行业标准完全一致。但本工程曝光补偿不生效，补回这 0.58 档只能把所有灯光调亮 1.5 倍，灰卡读数也会变成 0.27，第 ③ 步的标定口径要跟着改。所以推荐保留 1.5、在 DCC 里加 +0.58 档。两种做法选一种，全项目统一。

  8. 为 HDR 输出留好路 ACES 2.0 的 SDR 和 HDR 是同一曲线家族，开 HDR 后自动按屏幕峰值亮度展开，观感一致。Filmic 在 HDR 下是“先算出 SDR 结果，再反推扩展”，一致性较差。以后要支持 HDR 屏幕，ACES 是更省事的基础。

Filmic vs ACES 2.0：优劣对比（美术版）

一句话：Filmic 像“自带滤镜的相机”，好看、省事，但亮部会偏色、层次少。ACES 2.0 像“原片”，干净、准确、高光层次多，但要自己调出风格。

维度Filmic（UE4 以来的默认）ACES 2.0（Standard ACES）
中间调对比高：中灰附近每档 51.5 个像素值，画面“实”，出片快低约 27%（每档 37.5）：默认偏平，需要自己加对比
暗部干净，压得住默认发灰：UE 默认的 BT.1886 编码在普通屏幕上把暗部抬亮；改成 sRGB 编码后与 Filmic 接近
高光容易糊白：+5.2 档（中灰的 37 倍）就到 99% 白，强光、火焰、天空亮部层次少层次多：+7.0 档（中灰的 128 倍）才到 99% 白，过渡到白更自然
色相越亮越偏：火焰橙→黄 47°、魔法蓝→青 38°、血红→橙 17°保色相（≤ 5°）：亮了是“变白”，不是“变色”
饱和度中等亮度更艳（色卡平均彩度 12.3）正确曝光下淡一些（10.6，−14%）；很亮的颜色反而比 Filmic 更保色
可调性曲线可调：Film Slope / Toe / Shoulder / Clip、LUT 贴图、Blue Correction曲线固定：只能在曲线前用曝光和 Color Grading 调，LUT 贴图不生效
SDR / HDR 一致性一般：HDR 是从 SDR 结果反推再扩展一致：同一曲线家族，按屏幕峰值自动适配
行业标准 / 工具链UE 私有曲线，DCC 里没法用同一标准预览行业标准：ACES 2.0 / OpenColorIO，DCC、影视、外包流程可以对齐（注意 UE 额外的 ×1.5）
迁移成本零：现有美术都是在它下面调的需要重新校准灯光、自发光、特效、调色，正好配合 PBR 重打光

适合继续用 Filmic 的情况

  • 存量关卡，没有重打光计划
  • 依赖 LUT 贴图或 Film 参数做出的强风格化画面
  • 上线时间紧，没有精力回归

适合切到 ACES 2.0 的情况

  • 按 PBR 重打光的关卡（你们现在的计划）
  • 强光、火焰、魔法特效多，Filmic 下经常糊白、跑色
  • 以后要支持 HDR 屏幕，或者要和 DCC、预渲染 CG 对齐

正确曝光 vs 正常曝光：一个测出来，一个选出来

正确曝光一个可以测量的技术基准：主光下 18% 灰卡的场景值正好是 0.18。此时被主光照亮的表面，场景值约等于它自己的 BaseColor；灰卡在屏幕上约 110（ACES 2.0 + sRGB）或 118（Filmic）。每张图只有一个正确曝光，和个人喜好无关。本文的“0 档”都指它。
正常曝光一个创作判断：这张图看起来“亮度合适”的曝光。多数场景就等于正确曝光；夜晚可以有意暗 1–2 档，雪地、沙漠可以亮一点。用“相对正确曝光 ±N 档”记录，写进验收表。

顺序是先正确、再正常：先用灰卡把正确曝光标定好，所有资源才有可比性；再决定这张图要偏离多少。有人说“这张图曝光不对”时，先分清是没标定（正确曝光错了），还是风格取舍（正常曝光的选择）。注意：摄影书里这两个词的用法并不统一，本文按上面的定义使用。

档（EV / Stop）亮度翻一倍 = 亮 1 档，减半 = 暗 1 档。+3 档 = ×8，−2 档 = ×¼。本文以“正确曝光下的 18% 灰卡”为 0 档。
18% 灰卡 / 中灰反射 18% 光线的中性灰，是曝光的基准。在 UE 里就是 BaseColor 常量 0.18（取色器 Hex sRGB 767676，PS 里 118）。
反射率 / Albedo / BaseColor物体把照到它的光漫反射回去多少（0–1）。UE 的 BaseColor（Substrate 里叫 Diffuse Albedo）填的就是它，而且是线性值：0.18 = 反射 18%。
线性值 / sRGB 值同一个颜色的两种写法。线性值和光的能量成正比，UE 材质常量和取色器的 R、G、B 框用它；sRGB 值按眼睛的感觉排，PS、Substance 的 0–255 和 Hex 用它。0.18 ↔ 118，0.5 ↔ 188，PS 的 128 ↔ 0.216。
场景值（Scene Color）进入色调映射之前的 HDR 线性值，可以远大于 1。本工程曝光 ×1，被照亮的漫反射表面场景值 = BaseColor × 照度 ÷ π。Pixel Inspector 里叫 Scene Color Before Tonemap。
曝光 / 曝光补偿曝光是进色调映射前给整个画面乘的系数（+1 档 = ×2）。PPV 的 Exposure Compensation 本来用来调它，但本工程 r.EyeAdaptationQuality=0，曝光锁定 ×1，这个参数不生效。
EV100相机的曝光值（按 ISO 100 算）：数字越大，表示场景越亮、相机给的曝光越少。真实世界晴天约 15、室内约 7。本工程的曝光相当于一台固定在 EV100 = 0 的相机。
照度 lux / 坎德拉 / 流明lux：落到表面上的光有多少（平行光的单位）。坎德拉 cd：灯朝某个方向有多亮。流明 lm：灯一共发出多少光（点光源 cd = lm ÷ 4π）。离点光源 d 米处的照度 = cd ÷ d²。
光比亮处和暗处差多少，常说“主光 + 补光 : 补光”。用档数说更直观：2:1 = 1 档，4:1 = 2 档，8:1 = 3 档。光比越大，画面越硬、暗部越沉。
自发光（Emissive）材质自己发出的亮度，单位和场景值相同，不受灯光影响。本工程曝光 ×1，Emissive = 0.18 × 2N 就是“比中灰亮 N 档”。
Pixel Inspector编辑器自带的取值工具（Tools → Debug → Pixel Inspector）：鼠标指到哪里，就显示那个像素的场景值、最终颜色等。注意 Final Color 显示的是线性值（0.157 = 屏幕 110）。
标定场景（Look-dev）专门用来校准灯光、材质、曝光的测试地图：放灰卡、色卡、标准球和几套典型灯光。所有资源先在这里过一遍再进关卡。
ColorChecker 色卡24 块标准颜色的实物色卡（X-Rite），每块都是真实颜料的反射率。常用来检查颜色还原、饱和度合不合理。
色调映射（Tonemapper）把可以无限亮的场景亮度压进屏幕能显示的 0–1 范围的那条曲线。Filmic 和 ACES 就是两种曲线。
显示编码（sRGB / BT.1886）把 0–1 的亮度翻译成像素值的规则，必须和屏幕的显示方式配对。sRGB ≈ Gamma 2.2（电脑、手机），BT.1886 = Gamma 2.4（暗室电视）。
逐通道 / 保色相逐通道：R、G、B 各压各的，简单但会偏色。保色相：只压亮度、单独控制彩度，色相不变。
彩度 / 色相彩度是“有多鲜艳”，色相是“是什么颜色”（红、橙、黄…）。本文都在 OKLab 感知色彩空间里度量。
ACES 2.0美国电影艺术与科学学院（AMPAS）维护的色彩管理标准，2.0 版重写了显示端的输出变换（也就是 Tonemapping）。UE 5.8 的 Standard ACES 默认用它。

B. 计算方法与可信度

  • Filmic：把上面的 Filmic 处理按源码逐行移植到 Python（numpy），参数为 UE 默认值。中灰 0.18 → 显示 0.18，与源码设计一致。
  • ACES 2.0：输出变换使用 OpenColorIO 2.6 内置的官方实现（ACES2065-1 → SDR 100 nit Rec.709），前后按 UE 源码补上 ×1.5、外层 LUT 的裁剪和编码。用 UE 源码里的 tonescale 公式逐点核对灰阶，与 OCIO 的结果相对误差小于 1×10⁻⁶。场景值超过 128 时 OCIO 会裁到峰值，UE 同样有 clamp_zero_to_peakLuminance。
  • 没有模拟的部分：3D LUT 的插值误差（UE 用 32³ LUT 加 PQ 编码，误差很小）、Bloom 等在 Tonemapper 之前的效果（截图反推时已包含在场景值里）、显示器个体差异。屏幕亮度按标准 sRGB 显示器计算。
  • 截图反推：用完整的 Filmic 正向模型做逐像素迭代求逆，地牢场景平均残差 0.002 个像素值，0.03% 的像素超过 2。选角场景的火焰区比 Filmic 能输出的颜色还要纯，约 8% 的像素有 2–6 个像素值的误差。
  • 补偿参数：以“与 Filmic 的平均 OKLab 色差”为目标，在两张截图（约 9 万个采样像素）和色卡（−1 / 0 / +1 档）上做坐标下降拟合，再取到 0.05 的整数档复算。
  • 长期方案的图解（make_exposure.py）：屏幕值都用同一套模型按“曝光 ×1、正确曝光 = 灰卡场景值 0.18”计算，没有算局部曝光。光比与曝光阶梯小图是 numpy 光线求交渲染的示意场景：Lambert 漫反射、一盏平行光加均匀天空半球，平放灰卡的主光 + 天光照度定为 π lux，再走 ACES 2.0 + sRGB；只用来说明光比和曝光，不代表引擎的实际光照。
