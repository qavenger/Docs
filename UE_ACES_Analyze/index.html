第一章

ACES 2.0：为什么切过去画面会变灰

色彩输出是整套流程的“尺子”，先把它换对。这一章对比 Filmic 和 Standard ACES（ACES 2.0），拆解变灰的四个原因，并给出重构完成前的过渡做法。

1.0 一分钟看懂

切到 Standard ACES 之后，整体亮度其实没变：18% 中灰在两种模式下都显示为像素值 ≈ 118。变的是两头和颜色：暗部被抬亮、亮部被压低、颜色变淡。对比度一降，画面就“灰”了。

造成这种变化的是四件事，影响从大到小：

  • ①
    显示编码对不上（影响最大，一行配置就能修）。在后处理体积（PPV）里选 Standard ACES 后，UE 默认按 BT.1886（Gamma 2.4，暗室看电视的标准）输出；电脑和手机屏幕按 sRGB（约 Gamma 2.2）显示，结果暗部整体被抬亮。
  • ②
    ACES 2.0 的曲线本身更柔。中间调对比度比 Filmic 低约 27%，到 99% 白需要的亮度是 Filmic 的 3 倍多，相当于把空间留给了高光层次。所以同一盏灯、同一张贴图，亮部会更暗、更平。
  • ③
    颜色处理方式不同。Filmic 对 R、G、B 三个通道分别压缩，会顺带加饱和，并让亮色偏色（火焰发黄、蓝光发青）。ACES 2.0 保持色相，代价是正常亮度下颜色淡一些，色卡平均彩度低约 14%。
  • ④
    Filmic 专属参数全部失效：Film Slope / Toe / Shoulder / Black Clip / White Clip、Blue Correction、Tone Curve Amount、Color Grading LUT 贴图。工程正式内容里有 3 张地图改过 Film 参数，1 张用了 LUT 贴图。

过渡期：重构完成前就要切

  • 不急着切：存量关卡继续用 Filmic，零成本。
  • 要切：DefaultEngine.ini 加一行 r.LUT.TonemappingSDRInvEOTF=0，把编码改回 sRGB。再按需补偿：曝光 +0.1 档、全局对比度 ×1.15、饱和度 ×0.95。
  • 这样与原 Filmic 画面的平均色差能从 4.8 降到 2.8（只改编码），再降到 1.8（加补偿）。

→ 1.4 具体做法

重构后：ACES 2.0 是整套流程的基准

  • 全项目统一“ACES 2.0 + sRGB 编码”；18% 灰卡（BaseColor 0.18）在正确曝光下显示 110。
  • 灯光用物理单位，相机手动对准每张图的 EV100，曝光补偿只做过渡和氛围。
  • 自发光、特效、天空按物理量级重做：ACES 下亮部要多给约 1 档，特效的黄芯要画进贴图。
  • 项目 Look 用 Color Grading 预设；DCC 预览对齐 UE 额外的 ×1.5（+0.58 档）。

①显示编码：给显示器的“翻译方式”变了（影响最大）

渲染算出来的是“光有多亮”。最后一步要把它翻译成 0–255 的像素值发给显示器，显示器再按自己的规则翻译回亮度。两边必须用同一本“字典”：

  • Filmic 按 sRGB 编码；电脑屏幕、手机屏幕按 sRGB 显示：配对。
  • Standard ACES 在 UE 里默认按 BT.1886（Gamma 2.4）编码。这是暗室里看电视、调色监视器的标准，而普通屏幕仍按约 2.2 解码：不配对。同样的暗部亮度被编成更大的像素值，显示出来就亮了，阴影发灰。

引擎源码的说明写得很直白：“The default for ACES is BT.1886 to prioritize compatibility between SDR and Rec. 2100 for HDR.” Epic 是为了让 SDR 和 HDR 电视的观感一致才选了 BT.1886；但我们的玩家绝大多数用的是 sRGB 屏幕。这个默认值只在 PPV 选了 Standard ACES 时启用（Filmic 一直是 sRGB）。可以用 r.LUT.TonemappingSDRInvEOTF 改：0 = sRGB，1 = BT.1886。

灰阶曲线：场景亮度 → 屏幕像素值

横轴是比 18% 中灰亮或暗几档（1 档 = 亮度 ×2），纵轴是最终发给屏幕的像素值（0–255）。把鼠标放到图上可以看每档的具体数值。

具体数字：比中灰暗 3 档 / 5 档的地方，Filmic 的屏幕亮度是 0.65% / 0.06%，ACES 默认是 1.62% / 0.33%（×2.5 / ×5.2）。改成 sRGB 编码后是 0.81% / 0.05%，与 Filmic 基本一致。

A/B 对比的坑 控制台的 r.LUT.TonemappingMethod 1 只会把曲线换成 ACES，编码仍然跟着 PPV 走（源码里编码默认值读的是 PPV 的设置，不是这个控制台变量）。所以在控制台里切，看到的是“ACES + sRGB”；在 PPV 里切，看到的是“ACES + BT.1886”，两种方法的结果不一样。反过来，PPV 选了 ACES、控制台强制 Filmic 时，Filmic 也会被按 BT.1886 编码，同样发灰。团队讨论“ACES 好不好看”之前，先统一切换方法（下面有命令）。

②曲线形状：ACES 2.0 更柔，把空间留给了高光

编码修好之后（上图青色线），暗部和 Filmic 基本重合，但从中灰往上 ACES 2.0 一直更低、更平：

  • 中间调对比度：中灰附近每亮 1 档，Filmic 增加 51.5 个像素值，ACES 2.0 只增加 37.5，低 27%。
  • 高光到白的距离：Filmic 在比中灰亮 +5.2 档（中灰的 37 倍）时就到了 99% 白；ACES 2.0 要到 +7.0 档（中灰的 128 倍）。比中灰亮 2 档的地方，Filmic 是 208.5，ACES 是 183.8。
  • 为什么中灰刚好一样？UE 在 ACES 前面额外乘了 1.5（r.HDR.Aces.SceneColorMultiplier，约 +0.58 档），配合 BT.1886 编码，正好让中灰与 Filmic 对齐（117.9 vs 117.6）。可见 Epic 有意保证“整体亮度不变”，只是两头对不齐。

③颜色：Filmic 逐通道压缩，ACES 2.0 保色相

Filmic 把 R、G、B 三个通道各自套同一条 S 曲线。亮的通道先被压平，暗的通道后被压，所以一个颜色越亮，就越往黄、青、品红偏，同时中等亮度的颜色被“顺带”加了饱和。ACES 2.0 在色貌空间里只压亮度，彩度单独控制，所以色相基本不变，亮到头是“变白”而不是“变色”。下面每一行是同一个颜色从 −2 档逐渐提亮到 +8 档：

对特效 / 自发光的影响 以前火焰的“黄白芯”、魔法光的“青白芯”，很大一部分是 Filmic 偏色“送”的。ACES 下颜色不会自己变，火焰会更橙、更红（对比滑块里的选角场景）。想要黄白芯，就要在特效贴图或颜色渐变里明确做出来。好处是：特效颜色调成什么样，屏幕上就是什么样，不会因为亮度一变就跑色。

1.3 Filmic vs ACES 2.0：优劣对比（美术版）

一句话：Filmic 像“自带滤镜的相机”，好看、省事，但亮部会偏色、层次少。ACES 2.0 像“原片”，干净、准确、高光层次多，但要自己调出风格。

中间调对比高：中灰附近每档 51.5 个像素值，画面“实”，出片快低约 27%（每档 37.5）：默认偏平，需要自己加对比
暗部干净，压得住默认发灰：UE 默认的 BT.1886 编码在普通屏幕上把暗部抬亮；改成 sRGB 编码后与 Filmic 接近
高光容易糊白：+5.2 档（中灰的 37 倍）就到 99% 白，强光、火焰、天空亮部层次少层次多：+7.0 档（中灰的 128 倍）才到 99% 白，过渡到白更自然
色相越亮越偏：火焰橙→黄 47°、魔法蓝→青 38°、血红→橙 17°保色相（≤ 5°）：亮了是“变白”，不是“变色”
饱和度中等亮度更艳（色卡平均彩度 12.3）正确曝光下淡一些（10.6，−14%）；很亮的颜色反而比 Filmic 更保色
可调性曲线可调：Film Slope / Toe / Shoulder / Clip、LUT 贴图、Blue Correction曲线固定：只能在曲线前用曝光和 Color Grading 调，LUT 贴图不生效
SDR / HDR 一致性一般：HDR 是从 SDR 结果反推再扩展一致：同一曲线家族，按屏幕峰值自动适配
行业标准 / 工具链UE 私有曲线，DCC 里没法用同一标准预览行业标准：ACES 2.0 / OpenColorIO，DCC、影视、外包流程可以对齐（注意 UE 额外的 ×1.5）
迁移成本零：现有美术都是在它下面调的需要重新校准灯光、自发光、特效、调色，正好和第二章的 PBR 重构一起做
运行时性能相同：两者都烘焙成 3D LUT，每帧只查表；LUT 只在参数变化时重算（ACES 2.0 重算稍贵，但不是每帧）

适合继续用 Filmic 的情况

  • 存量关卡，没有重打光计划
  • 依赖 LUT 贴图或 Film 参数做出的强风格化画面
  • 上线时间紧，没有精力回归

适合切到 ACES 2.0 的情况

  • 按 PBR 重构的关卡（本文第二章）
  • 强光、火焰、魔法特效多，Filmic 下经常糊白、跑色
  • 以后要支持 HDR 屏幕，或者要和 DCC、预渲染 CG 对齐

1.4 过渡期：重构完成前就要切 ACES 怎么办

目标：在第二章的 PBR 重构完成之前，既可以继续用 Filmic，也可以先切 ACES 而不让画面变灰。重构开始后，这一节的曝光补偿就不再需要，曝光改由物理相机决定。

  1. 先决定要不要现在切 存量关卡的灯光、材质、特效都是在 Filmic 下调的，继续用 Filmic 是零成本、零风险的选择。建议只在新做或按第二章重构的关卡里用 ACES，旧关卡等重构时再切。下面的 2–5 步是“必须现在切”时的做法。
  2. 必做：把输出编码改回 sRGB 解决“暗部发灰”这个最大的问题，只影响 Standard ACES，Filmic 不受影响：

第二章

全流程 PBR 重构：从灯光校准到后期调色

按下面的顺序做：先定标准、改工程设置，再用标定场景校准灯光和曝光，然后调 Lumen、自发光和特效，最后才是调色与氛围过渡，逐关卡迁移验收。每一节都写了“为什么、怎么做、怎么验收”。

2.1 目标与原则

让“美术在屏幕上看到的”和“物理上应该是的”一致，再在上面叠项目自己的风格。

四条原则

  1. 先标定，再创作。用灰卡把“正确曝光”定死，所有材质、灯光、特效在同一把尺子上比较；每张图想要的明暗（“正常曝光”）写成“相对正确曝光 ±几档”。
  2. 各管各的。BaseColor 按真实反射率定；灯光按物理量定；相机按测光定（正确曝光）；曝光补偿只做过渡和创作偏移（正常曝光）；调色只做风格。
  3. 相对物理。太阳、天空、月亮用天空大气的真实值；火盆、法阵等人工光可以比真实的亮，但同类灯全项目统一，光比保持真实。
  4. 能物理就别伪造。熔岩区要暖，先加熔岩自发光和暖光，让 Lumen 算出真实的反光，再用调色加强，而不是把整屏染橙。

画面从光到屏幕要经过的环节

灯光（lux / 流明）×BaseColor÷ π场景亮度（尼特）×曝光（物理相机 + 曝光补偿）→白平衡 · 调色→ACES 2.0→sRGB 编码 → 屏幕

每个环节只做自己的事：曝光之前的数都是物理量，可以用 Pixel Inspector 读出来核对；曝光之后才是“好不好看”的问题。

2.2 先动手：4 个小实验，从操作反推原理

不需要摄影基础，在一张空关卡里 10 分钟就能做完；后面所有规范都能和这几个读数对上。

实验 2–4 需要曝光系统已经打开（2.4 改完工程设置；临时验证可以在控制台输入 r.EyeAdaptationQuality 2）。统一用 ACES 2.0 + sRGB 编码（r.LUT.TonemappingMethod 1、r.LUT.TonemappingSDRInvEOTF 0），并临时关掉工程默认的局部曝光（r.DefaultFeature.LocalExposure.HighlightContrastScale 1、r.DefaultFeature.LocalExposure.ShadowContrastScale 1，原因见 2.6），读到的数才和下面一致。

118% 灰卡在 UE 里是哪个数

做
新建材质，BaseColor 接一个 Constant3Vector，双击打开取色器，在 Hex sRGB 框里输入 767676 回车。
看
R、G、B 三个数值框都变成 0.18。再输入 808080（PS 里正中间的 128），数值变成 0.216。
为什么
取色器的 R、G、B 数值框是线性值：表面把多少比例的光反射回去，0.18 就是 18%。Hex sRGB 和 PS 的 0–255 是给眼睛看的编码，暗部分得细、亮部分得粗，所以 118 才对应 18%。常见坑：把 PS 的 118 直接 ÷255 填成 0.463，等于反射 46% 的光，亮了约 +1.4 档。

2晴天 16 法则：用物理相机读出“正确曝光”

做
空关卡里放一盏平行光（不要天空大气、天光、雾），旋转成垂直向下，强度 100000 lux；下面放一块水平平面，用实验 1 的材质（Metallic 0、Specular 0、Roughness 1）。放一个 Unbound 的 PPV：Metering Mode = Manual、勾 Apply Physical Camera Exposure、Shutter Speed 125、ISO 100、Aperture 16、Exposure Compensation 0。用 Tools → Debug → Pixel Inspector 指向平面。
看
Scene Color Before Tonemap ≈ 5730（尼特，cd/m²）；PreExposure ≈ 3.1×10⁻⁵；两者相乘 ≈ 0.179。Final Color ≈ 0.156（线性值，换成屏幕像素值就是 110）。
为什么
灰卡亮度 = 0.18 × 100000 ÷ π ≈ 5730 尼特。相机 EV100 = log₂(16² × 125 × 100 ÷ 100) ≈ 14.97，曝光 = 1 ÷ 2EV100，正好把灰卡压回 0.18 附近。摄影里“晴天用 f/16、快门 1/ISO”的老规矩在 UE 里同样成立——这说明 UE 的物理相机和真实相机是同一套标定，真实世界的灯光数据可以直接拿来用。

3曝光的三个旋钮：灯光、相机、曝光补偿

做
在实验 2 的基础上分别试：快门改成 250；或者曝光补偿改成 +1；或者太阳改成 200000 lux。每次读完改回去。
看
快门 250：灰卡屏幕值 110 → 75（暗 1 档）。曝光补偿 +1 或太阳翻倍：→ 148（亮 1 档），两种做法画面完全一样。
为什么
画面只认“灯光 × BaseColor × 曝光”的乘积，同一个画面有无数种组合。所以要规定谁管什么：BaseColor 按真实反射率（2.5），灯光按物理量（2.7），相机按测光（正确曝光），曝光补偿只做过渡和氛围（正常曝光，2.8）。否则换一个场景，大家调出来的东西就对不上。

做

2.3 现状盘点与决策（开工前一次性）

先弄清楚现在的工程和目标差在哪里，再把需要拍板的事情一次定下来，写进项目的画面标准文档。

现状：工程的曝光现在是锁死的

源码核实 工程在所有画质档位都设了 r.EyeAdaptationQuality=0（DefaultScalability.ini，以及 PC / Android / IOS / Emulator 各自的 Scalability.ini）。它不只是关掉自动曝光：引擎会把 EyeAdaptation 显示标志一起关掉，曝光计算走“全部置 1”的分支，曝光锁定 ×1，PPV 里的 Exposure Compensation 和物理相机都不参与计算（源码见附录 A2）。全工程有 83 个包（正式内容 27 个）设置过 Exposure Compensation，这些值在游戏和编辑器的主视口里都不起作用，UE4.26 的老工程也一样。

换成物理相机的说法：现在相当于一台固定在 EV100 = 0 的相机，主光照到灰卡上约 π（3.14）lux 时才是正确曝光，比真实晴天暗了约 15 档。所以现有关卡的灯光数值不能直接搬进新流程，重打光时按 2.7 重新定。例外：SceneCapture（UI 里的 3D 角色展示、头像常用它）不走这个开关，它的曝光一直按捕获组件和 PPV 的设置计算。

2.5 材质规范：BaseColor 按真实反射率定死

一句话：BaseColor 用 UE 的线性值思考，按真实材质定死。标定场景里的灰卡、白卡、黑卡也按这里的规范做。

BaseColor 的规范和曝光、灯光都无关：物理相机打开前后不用改，材质组现在就可以按这一节开工。

③ 太阳、天空、月亮：天空大气 + 实时天光，按真实值

设置（照抄）

  • 平行光（太阳）：勾 Atmosphere Sun Light（索引 0）。Intensity 填大气层外的照度，起步 120000 lux（真实约 12.8 万）；地面实际收到的是它乘以大气透过率，太阳越低越暗、越红，天空大气会自动算。Light Color 保持白色。UE 新建平行光默认只有 10 lux，比晴天暗约 13 档，拖进来先改。
  • 天空大气（Sky Atmosphere）：默认参数就是地球大气，先保持默认。天空的亮度由太阳决定：不要单独提亮天空，也不要再用自发光的天空球。
  • 天光（Sky Light）：Source Type 选 SLS Captured Scene，勾 Real Time Capture，Intensity Scale 保持 1。阴影里的亮度主要靠它，它决定了光比。
  • 月亮：第二盏平行光，Atmosphere Sun Light 索引 1，Intensity 约 1 lux（真实满月 0.05–0.3 lux，相对物理地提亮 2–4 档）。颜色保持白色或微冷，“夜晚偏蓝”放到调色层做（2.11），夜晚的暗用曝光补偿 −2 做。
  • 高度雾：Fog Inscattering Color 实际是绝对亮度（源码属性名 FogInscatteringLuminance），物理相机下旧数值约等于 0。改成黑色，让天空大气给雾上色（天空大气的 Height Fog Contribution 默认 1，r.SupportSkyAtmosphereAffectsHeightFog 默认开）。
  • 体积云（可选）：需要云影、阴天层次时再加，天光会实时捕获它。

为什么这样做

天空大气按物理算出太阳的透过率和天空的亮度、颜色，所以白天、黄昏、阴天只需要转太阳角度、加云，不用为每种天气单独调灯光和雾的颜色；阴影里只有天光，晴天光比自然落在 2–3 档。

平放灰卡收到的照度 = 太阳直射 × sin（太阳高度角）+ 天光。太阳高度 50°–60°、晴天时直射约 7–9 万 lux，加上天光，基准 EV100 落在 14.5–15，和场景表一致。

2.8 曝光体系：物理相机 + PPV 曝光过渡

不用自动曝光。每张图一个全局 PPV 定相机（正确曝光），区域 PPV 只混合曝光补偿（正常曝光）来做场景过渡。

① 全局 PPV：相机定“正确曝光”

设置（每张图一个，勾 Unbound）

  • Lens → Exposure：Metering Mode = Manual，勾 Apply Physical Camera Exposure，Exposure Compensation = 0（夜晚这类创作偏移写在这里，如 −2）。
  • Lens → Camera：ISO 100，Aperture 4（全项目固定），Shutter Speed 按下面的对照表填。
  • 曝光 = 2曝光补偿 − EV100，EV100 = log₂(光圈² × 快门 × 100 ÷ ISO)；f/4、ISO 100 时就是 log₂(16 × 快门)。

为什么只用快门这一个旋钮

  • 光圈还管景深（过场的 Cine Camera 开了对焦就会写入自己的光圈），ISO 在游戏里没有噪点可言。固定这两个，“快门 ↔ 场景亮度”就是一一对应的。
  • UE 的快门只参与曝光计算，不影响运动模糊（源码里 Shutter Speed 只用在 EV100 公式里）。可填范围 0.01–8000，f/4 时覆盖 EV100 −2.6 ~ 17。
  • 正确曝光交给相机（测出来），正常曝光交给曝光补偿（选出来）：两件事分开记，出问题时一眼看出是哪一个。

2.9 Lumen 设置：先物理正确，再调性能

Lumen 只负责把直接光和自发光“弹”到别处去。只要灯光、材质、曝光都对，默认参数基本就是对的；要改的多半是覆盖范围和漏光。

① 工程层面已经具备

Lumen GI 与反射（r.DynamicGlobalIlluminationMethod=1、r.ReflectionMethod=1）、硬件光追（r.RayTracing=True）、距离场、虚拟阴影贴图、MegaLights 都已开启。Lumen 只做一件事：把直接光、天光和自发光“弹”到别处。它和灯光一样是线性的，灯光、材质、曝光对了，Lumen 的结果就对；不要用 Lumen 参数去补画面的亮度。

② 必改：缓存光照的曝光范围

Lumen 的缓存光照和天光的实时捕获用一个固定的预曝光来存储，r.EyeAdaptation.CachedLightingPreExposure 默认 4，只覆盖曝光 −8 ~ +12 档。晴天 EV100 14–15 超出这个范围，光照会被截断，屏幕上会出现 “Cached lighting in Lumen and real-time sky capture lighting is going to be clipped” 的警告。改成 8（覆盖 −4 ~ +16，源码注释的说法是 “fully covers physically based lighting range”）。它是固定值，不随画面曝光变化，也不改变画面亮度。

④ 自发光和 Lumen

  • Lumen 会让自发光照亮周围：大面积的熔岩、发光地面、窗户不用再配一圈点光源，反光自然正确。
  • 又小又亮的自发光（火星、小灯珠）会让 Lumen 出噪点；重要的光源仍然用真实的灯，自发光只负责“看起来亮”。
  • 自发光的强度要按物理量级定（2.10），否则 Lumen 弹出来的光会和画面上看到的亮度对不上。

⑤ 用路径追踪做“标准答案”

  1. 标定场景和每张图的关键机位，视口切到 Path Tracing（视图模式菜单；工程已开硬件光追），等它收敛。
  2. 用 Pixel Inspector 读阴影里、室内的灰卡；切回 Lit 再读一次。
  3. Lumen 和路径追踪相差 0.5 档以内就合格；差得多，先查材质（BaseColor 是否过亮）、再查 Lumen 场景覆盖（视图模式 → Lumen → Surface Cache，粉色的地方是没进 Lumen 场景的物体）。

2.10 自发光与特效

物理曝光下，同一个自发光在白天和地牢里看起来会差十几档。先把自发光分成两类，再重做特效的颜色渐变。

① 自发光分两类

发光体：按绝对亮度（尼特）

灯罩、窗户、熔岩、火盆、会照亮环境的法阵。Emissive 填的就是亮度（尼特，和 Scene Color 读数同一单位），白天看起来暗、地牢里看起来亮，这是物理正确的，Lumen 也按这个亮度把光弹出去。

定法：想比这类场景的灰卡亮 N 档，Emissive = 0.18 × 2EV100 + N（下表）。

玩法提示、技能特效、UI 3D：跟着曝光走

拾取物光圈、选中描边、伤害数字、技能特效，在任何场景下屏幕亮度都要一样。做法：母材质里把强度乘 EyeAdaptationInverse 节点（Alpha = 1 表示完全抵消曝光，0 表示不抵消，0.5 就是“一半跟着曝光走”）。

  • ④ 单独看会比 ② 更黄、中间调偏橄榄色，这是正常的：贴图里存的是“ACES 下要显示成这个颜色所需要的颜色”，乘上强度、经过 ACES 才是最终效果。不要按贴图本身的观感去“修”它。

怎么改一张特效贴图

  1. 灰度形状不用重画：同一张灰度贴图，只换上色方式。
  2. 上色改成渐变映射：PS 里用“渐变映射”调整图层，按上表的节点取色；Niagara / 材质里用 1D 渐变贴图或 Curve Atlas，按灰度采样。
  3. 强度系数按新贴图重新定（这张火焰 ×26 → ×11.3）；技能特效的母材质乘 EyeAdaptationInverse，这些数值在任何场景曝光下都直接适用。
  4. 在标定场景里，和 Filmic 版截图并排看：色差 ≤ 2 就算还原了，核心不糊白、外圈不发灰。

图中的强度是“曝光后”的数值（相当于正确曝光、曝光补偿 0），渲染只经过色调映射，没有 Bloom、没有叠加混合，用来说明颜色关系。

2.11 后期调色与氛围过渡

调色放在最后：灯光、曝光、Lumen、自发光都对了，再用 Color Grading 叠项目风格；同一张图里从正常环境走到熔岩环境，用“物理层 → 曝光层 → 调色层”三层一起过渡。

① 项目 Look：在全局 PPV 上用 Color Grading 做

  • ACES 2.0 默认是“中性原片”。项目风格（对比、饱和、暗部偏冷、高光偏暖等）用 Color Grading 的 Global / Shadows / Midtones / Highlights 来做。UE 的调色在色调映射之前、直接作用于场景线性值，这正是 ACES 推荐的工作方式。
  • 想先回到接近 Filmic 的观感，可以从第一章拟合的数开始：Global Contrast ×1.15、Saturation ×0.95（1.4）。如果还想让中灰和 Filmic 一样亮（118 而不是 110），全局曝光补偿再给 +0.2 档，作为全项目统一的偏移写进规范。
  • 做成共享预设：把 Look 存进一个带 Post Process 组件（勾 Unbound）的蓝图，参数写在类默认值里；每张图放一个实例，改一处全项目生效。它的 Priority 设得比每张图的全局 PPV 高，并且只勾调色相关的参数，相机仍然由全局 PPV 决定。
  • LUT 贴图在 ACES 下不生效。实在需要 LUT 式调色，可以用 After Tonemapping 的后处理材质，但有额外开销，移动端慎用。

② 例：从正常环境走到熔岩环境

氛围过渡分三层，先物理、再曝光、最后调色。只做第三层（整屏染橙），角色、怪物、地面的颜色会一起变橙，读不清；熔岩自己也没有照亮地面和角色，看起来是“贴了一层滤镜”。

1物理层：灯光与材质

  • 熔岩材质按发光体定自发光：比区域灰卡亮 3–5 档。例如熔岩区基准 EV100 12：灰卡 737 尼特，熔岩约 5900–23600 尼特。
  • 沿熔岩河放几盏 1500–2000 K 的矩形光、点光做主照明（工程开了 MegaLights，数量不是问题），Lumen 再把熔岩的光弹到岩壁和角色底面。
  • 热气、烟尘用 Local Fog Volume 放在熔岩区，它按自己的形状淡出，不需要额外混合。

靠近熔岩时自然变化，不用写过渡逻辑。

2曝光层：区域 PPV 的曝光补偿

  • 熔岩区多了大量自发光和暖光，相机不变的话亮处会过曝：曝光补偿 −0.5 ~ −1，保住熔岩和火光的层次。
  • 如果熔岩区是暗的洞穴，则按 2.8 的山洞做法给正的曝光补偿。

和调色在同一个区域 PPV 里，一起混合。

3调色层：区域 PPV 的 Color Grading

  • 白平衡 Temp 从 6500 调到 7000–7500：White Balance 模式下数值越大画面越暖。
  • Highlights 的 Gain 偏暖，Shadows 稍偏红褐，Global Saturation 略加；Bloom 稍加。
  • Blendables 里放热浪扭曲的后处理材质实例，参数随权重一起混合。

最后才加，幅度宁小勿大。

③ 过渡怎么做

A. 区域 PPV + Blend Radius

最简单，适合边界清楚的区域。注意权重按镜头位置算：体积要往上、往镜头一侧做大（2.8 的示意图）。Blend Radius 5–10 米。

B. 触发器 + Timeline 推 Blend Weight（推荐）

区域 PPV 勾 Unbound、Blend Weight 0；角色进入触发框时 1.5–3 秒推到 1，离开时推回 0。时机由角色决定，从哪个方向进都一样；同一个 Timeline 可以同步推不在 PPV 里的东西。

④ 不在 PPV 里、不会跟着混合的东西

  • 高度雾、天空大气、太阳：不是后处理参数。区域性的雾用 Local Fog Volume；非要改全局的雾或太阳，就用上面的 Timeline 同步推，并接受整张图一起变（俯视角能看到的天空很少，通常可以接受）。
  • 开关型参数（Tonemapping Method、测光方式、物理相机开关、GI 方法、Lumen 质量）：放进区域 PPV 会瞬间跳变，见 2.8 的表。

⑤ 护栏（验收时逐条看）

  • 氛围用的曝光补偿最多 ±1 档；更大的明暗差（户外 → 山洞）属于场景过渡，按 2.8 做。
  • 调色后在标定场景里重新看色卡：可以整体偏暖，但白卡要仍然看得出是白、肤色仍然是肤色。
  • 角色、怪物在两种氛围下都读得清：亮处灰卡的屏幕像素值都在 100–120 左右。
  • 不要用调色补灯光：缺光就加灯，颜色不对先查灯的色温。
  • 不要在区域 PPV 里改 Tonemapper、测光方式和物理相机开关。

DCC 里看到的和 UE 里看到的要是同一个灰卡。

Substance Painter、Nuke、DaVinci Resolve、Maya / Houdini 等支持 OCIO 的软件，用 ACES 2.0 配置（sRGB 显示、SDR 100 nit）预览渲染结果时，要额外 +0.58 档曝光，因为 UE 在 ACES 前乘了 1.5。用灰卡核对最直观：

2.13 逐关卡迁移与验收

先把单位换成物理量、保住画面，再按物理重打光；每张图按同一张清单验收。

① 一张图的迁移顺序

  1. 先等效换算，把单位换成物理量、画面不变 选定这张图的基准 EV100，把所有“绝对亮度”的数值乘以 2EV100（EV100 14 就是 ×16384），再把旧图兼容预设（2.4）换成物理相机、快门按这个 EV100 填。曝光正好除回去，画面应该和迁移前几乎一样，可以用截图对比确认。要乘的东西：
    • 所有灯光的强度（平行光、点光、聚光、矩形光，以及 Niagara 粒子的光源）；
    • 高度雾的 Fog Inscattering Color、Directional Inscattering Color，体积雾的 Emissive；
    • 天光：用指定 Cubemap 时乘它的 Intensity；捕获场景时乘被捕获的天空球自发光（天光会跟着变，不要两边都乘）；
    • 环境材质的自发光：可以批量乘，也可以先在母材质里乘 EyeAdaptationInverse（Alpha 1），旧数值原样保留；特效、UI 3D 元素同理。
    灯光、雾可以用编辑器 Python 脚本批量处理；材质靠母材质统一改，不要一个个调。
  2. 再按物理重打光 太阳、天空换成天空大气 + 实时天光（2.7 ③），人工光按 2.7 ④ 重定；读灰卡、定光比，登记进场景表。
  3. 特效、自发光 发光体改成尼特、去掉 EyeAdaptationInverse；技能特效保留它，按 2.10 重画渐变。
  4. 场景过渡与氛围 区域 PPV 只留曝光补偿和调色参数（2.8、2.11）。
  5. Lumen 检查、调色，按下表验收 截图归档，之后改灯光都和这一版对比。

按关卡整图切换（1.4 第 6 步），优先切新做或要重打光的关卡；同一张图不要一半物理一半旧值。

③ 为 HDR 输出留好路

名词小抄

正确曝光 vs 正常曝光：一个测出来，一个选出来

正确曝光一个可以测量的技术基准：主光下 18% 灰卡曝光后的场景值正好是 0.18。用物理相机时，就是“相机的 EV100 = 测光得到的 EV100”（EV100 = log₂(灰卡照度 ÷ π)）。此时被主光照亮的表面，曝光后约等于它自己的 BaseColor；灰卡在屏幕上约 110（ACES 2.0 + sRGB）或 118（Filmic）。每张图只有一个正确曝光，由相机（快门）对准，和个人喜好无关。本文的“0 档”都指它。
正常曝光一个创作判断：这张图看起来“亮度合适”的曝光。多数场景就等于正确曝光；夜晚可以有意暗 1–2 档，雪地、沙漠可以亮一点。在全局 PPV 里写成曝光补偿（−2 = 暗 2 档），并登记进验收表。

顺序是先正确、再正常：先用灰卡和相机把正确曝光标定好，所有资源才有可比性；再用曝光补偿决定这张图要偏离多少。有人说“这张图曝光不对”时，先分清是没标定（快门不对），还是风格取舍（曝光补偿的选择）。注意：摄影书里这两个词的用法并不统一，本文按上面的定义使用。

档（EV / Stop）亮度翻一倍 = 亮 1 档，减半 = 暗 1 档。+3 档 = ×8，−2 档 = ×¼。本文以“正确曝光下的 18% 灰卡”为 0 档。
18% 灰卡 / 中灰反射 18% 光线的中性灰，是曝光的基准，也是读灯光强度的“测光表”。在 UE 里就是 BaseColor 常量 0.18（取色器 Hex sRGB 767676，PS 里 118）。
反射率 / Albedo / BaseColor物体把照到它的光漫反射回去多少（0–1）。UE 的 BaseColor（Substrate 里叫 Diffuse Albedo）填的就是它，而且是线性值：0.18 = 反射 18%。
线性值 / sRGB 值同一个颜色的两种写法。线性值和光的能量成正比，UE 材质常量和取色器的 R、G、B 框用它；sRGB 值按眼睛的感觉排，PS、Substance 的 0–255 和 Hex 用它。0.18 ↔ 118，0.5 ↔ 188，PS 的 128 ↔ 0.216。
场景值（Scene Color）进入色调映射之前的 HDR 线性值，可以远大于 1。用物理单位时，被照亮的漫反射表面亮度 = BaseColor × 照度 ÷ π（尼特），再乘曝光进入色调映射。Pixel Inspector 的 Scene Color Before Tonemap 显示的是乘曝光之前的值（已除以 PreExposure）。
曝光 / 曝光补偿曝光是进色调映射前给整个画面乘的系数（+1 档 = ×2）。手动曝光 + 物理相机时，曝光 = 2曝光补偿 − EV100。曝光补偿（Exposure Compensation）是在相机之上再加减几档，本文只用它做正常曝光的偏移和场景过渡。改造前工程设了 r.EyeAdaptationQuality=0，曝光锁定 ×1，这个参数不生效。
EV100相机的曝光值（按 ISO 100 算）：EV100 = log₂(光圈² × 快门 × 100 ÷ ISO)。数字越大，表示场景越亮、相机给的曝光越少。正确曝光时 EV100 = log₂(灰卡照度 ÷ π)：晴天约 15、室内约 7、月夜约 −2。
物理相机PPV 里勾 Apply Physical Camera Exposure，用快门、ISO、光圈算曝光，和真实相机同一套标定（晴天 16 法则在 UE 里同样成立）。本项目固定 ISO 100、f/4，只用快门对准每张图的 EV100：快门 = 2EV100 ÷ 16。
照度 lux / 坎德拉 / 流明lux：落到表面上的光有多少（平行光的单位）。坎德拉 cd：灯朝某个方向有多亮。流明 lm：灯一共发出多少光（点光源 cd = lm ÷ 4π）。离点光源 d 米处的照度 = cd ÷ d²。
尼特（cd/m²）亮度的单位：表面或光源看起来有多亮。Scene Color 读数、Emissive 用的都是它。sRGB 显示器的白约 80 尼特，正午晴空约 1 万尼特，晴天下的灰卡约 5700 尼特。
光比亮处和暗处差多少，常说“主光 + 补光 : 补光”。用档数说更直观：2:1 = 1 档，4:1 = 2 档，8:1 = 3 档。光比越大，画面越硬、暗部越沉。
自发光（Emissive）材质自己发出的亮度，单位和场景值相同（尼特），不受灯光影响。发光体直接按尼特填；玩法类在材质里乘 EyeAdaptationInverse 后，Emissive = 0.18 × 2N 就是“比灰卡亮 N 档”。
EyeAdaptationInverse材质节点：把输入的数值除以当前曝光（Alpha 1 = 完全抵消，0 = 不变）。乘上它的自发光在任何场景曝光下屏幕亮度都一样，适合玩法提示、技能特效和 UI 3D 元素。
天空大气（Sky Atmosphere）UE 的物理天空：按太阳方向和大气参数实时算出天空的颜色亮度、太阳的透过率（越低越红越暗）和空气透视。勾了 Atmosphere Sun Light 的平行光，强度是大气层外的照度。
天光（Sky Light）把整个天空的光当成环境光照亮场景，阴影里的亮度主要靠它。勾 Real Time Capture 时会实时捕获天空大气和云，太阳一动它就跟着变。
PPV 混合（Blend Radius / Blend Weight）区域 PPV 的权重 0–1：镜头进入体积外 Blend Radius 的过渡带开始线性增加，进入体积内为 1；Blend Weight 再整体乘上去，可以用蓝图按时间推。数值参数按权重插值，开关型参数权重一大于 0 就整个切过去。
Pixel Inspector编辑器自带的取值工具（Tools → Debug → Pixel Inspector）：鼠标指到哪里，就显示那个像素的场景值、当前曝光（PreExposure）、最终颜色等。注意 Final Color 显示的是线性值（0.157 = 屏幕 110）。
标定场景（Look-dev）专门用来校准灯光、材质、曝光的测试地图：放灰卡、色卡、标准球和几套典型灯光。所有资源先在这里过一遍再进关卡。
ColorChecker 色卡24 块标准颜色的实物色卡（X-Rite），每块都是真实颜料的反射率。常用来检查颜色还原、饱和度合不合理。
色调映射（Tonemapper）把可以无限亮的场景亮度压进屏幕能显示的 0–1 范围的那条曲线。Filmic 和 ACES 就是两种曲线。
显示编码（sRGB / BT.1886）把 0–1 的亮度翻译成像素值的规则，必须和屏幕的显示方式配对。sRGB ≈ Gamma 2.2（电脑、手机），BT.1886 = Gamma 2.4（暗室电视）。
逐通道 / 保色相逐通道：R、G、B 各压各的，简单但会偏色。保色相：只压亮度、单独控制彩度，色相不变。
彩度 / 色相彩度是“有多鲜艳”，色相是“是什么颜色”（红、橙、黄…）。本文都在 OKLab 感知色彩空间里度量。
ACES 2.0美国电影艺术与科学学院（AMPAS）维护的色彩管理标准，2.0 版重写了显示端的输出变换（也就是 Tonemapping）。UE 5.8 的 Standard ACES 默认用它。
PPVPost Process Volume，后处理体积。勾 Unbound 的是全局 PPV，作用于整张图；不勾的只在体积内（加上 Blend Radius 的过渡带）生效，权重按镜头位置计算。Tonemapping Method 在 PPV → Film 分类里（显示名 Method）。

B. 计算方法与可信度

  • Filmic：把上面的 Filmic 处理按源码逐行移植到 Python（numpy），参数为 UE 默认值。中灰 0.18 → 显示 0.18，与源码设计一致。
  • ACES 2.0：输出变换使用 OpenColorIO 2.6 内置的官方实现（ACES2065-1 → SDR 100 nit Rec.709），前后按 UE 源码补上 ×1.5、外层 LUT 的裁剪和编码。用 UE 源码里的 tonescale 公式逐点核对灰阶，与 OCIO 的结果相对误差小于 1×10⁻⁶。场景值超过 128 时 OCIO 会裁到峰值，UE 同样有 clamp_zero_to_peakLuminance。
  • 没有模拟的部分：3D LUT 的插值误差（UE 用 32³ LUT 加 PQ 编码，误差很小）、Bloom 等在 Tonemapper 之前的效果（截图反推时已包含在场景值里）、显示器个体差异。屏幕亮度按标准 sRGB 显示器计算。
  • 截图反推：用完整的 Filmic 正向模型做逐像素迭代求逆，地牢场景平均残差 0.002 个像素值，0.03% 的像素超过 2。选角场景的火焰区比 Filmic 能输出的颜色还要纯，约 8% 的像素有 2–6 个像素值的误差。
  • 补偿参数：以“与 Filmic 的平均 OKLab 色差”为目标，在两张截图（约 9 万个采样像素）和色卡（−1 / 0 / +1 档）上做坐标下降拟合，再取到 0.05 的整数档复算。
  • 第二章的数值与图解（make_exposure.py）：屏幕值都按“曝光后的场景值”计算（正确曝光 = 灰卡曝光后 0.18），没有算局部曝光。物理量按 UE 的标定换算：灰卡亮度 = 0.18 × 照度 ÷ π，正确曝光的 EV100 = log₂(照度 ÷ π)，曝光 = 2补偿 − EV100；晴天 16 法则（f/16、1/125 秒、ISO 100、10 万 lux）用来交叉验证。PPV 过渡曲线按源码的线性插值，分别插值曝光补偿、快门（1/1024 → 1/8 秒）和 ISO（100 → 12800）。光比与曝光阶梯小图是 numpy 光线求交渲染的示意场景（Lambert 漫反射、一盏平行光加均匀天空半球），只用来说明光比和曝光，不代表引擎的实际光照。
  • 特效贴图反推：火焰形状是程序生成的灰度图；旧贴图 = 灰度 × 单一橙色，强度 ×26，先算出它在 Filmic 下的显示颜色，再沿 log 亮度取 1024 个样本，用 Levenberg–Marquardt 在 OKLab 里找出 ACES 下显示成同一颜色的输入，经中值去异常、高斯平滑后作为新渐变；强度按新渐变的最大值归一。渐变本身的平均色差 0.4，整张图 0.7（只改模式是 8.7）。渲染只经过色调映射，没有 Bloom 和半透明叠加。
