为什么切到 ACES 2.0，画面会变灰？

Filmic 与 Standard ACES（ACES 2.0）的差异、变灰的原因、短期与长期方案——写给美术的版本。

依据：工程引擎 UE 5.8.2 源码逐行复刻 + OpenColorIO 2.6 官方 ACES 2.0 实现，并用工程实际截图验证 · 2026-10-26

注：工程用的 UE 5.8.2 已经带了 Standard ACES 和 ACES 2.0（r.HDR.Aces.Version 默认就是 2），本文结论以 5.8.2 源码为准。以后升级到 5.8.4 等新版本时，附录列出了全部源码位置，可以逐条复核。

一分钟看懂

切到 Standard ACES 之后，整体亮度其实没变：18% 中灰在两种模式下都显示为像素值 ≈ 118。变的是两头和颜色：暗部被抬亮、亮部被压低、颜色变淡。对比度一降，画面就“灰”了。

造成这种变化的是四件事，影响从大到小：

  • ①
    显示编码对不上（影响最大，一行配置就能修）。在后处理体积（PPV）里选 Standard ACES 后，UE 默认按 BT.1886（Gamma 2.4，暗室看电视的标准）输出；电脑和手机屏幕按 sRGB（约 Gamma 2.2）显示，结果暗部整体被抬亮。
  • ②
    ACES 2.0 的曲线本身更柔。中间调对比度比 Filmic 低约 27%，到 99% 白需要的亮度是 Filmic 的 3 倍多，相当于把空间留给了高光层次。所以同一盏灯、同一张贴图，亮部会更暗、更平。
  • ③
    颜色处理方式不同。Filmic 对 R、G、B 三个通道分别压缩，会顺带加饱和，并让亮色偏色（火焰发黄、蓝光发青）。ACES 2.0 保持色相，代价是正常亮度下颜色淡一些，色卡平均彩度低约 14%。
  • ④
    Filmic 专属参数全部失效：Film Slope / Toe / Shoulder / Black Clip / White Clip、Blue Correction、Tone Curve Amount、Color Grading LUT 贴图。工程正式内容里有 3 张地图改过 Film 参数，1 张用了 LUT 贴图。

短期：先把画面救回来

  • 不急着切：存量关卡继续用 Filmic，零成本。
  • 要切：DefaultEngine.ini 加一行 r.LUT.TonemappingSDRInvEOTF=0，把编码改回 sRGB。再按需补偿：曝光 +0.1 档、全局对比度 ×1.15、饱和度 ×0.95。
  • 这样与原 Filmic 画面的平均色差能从 4.8 降到 2.8（只改编码），再降到 1.8（加补偿）。

→ 具体做法

长期：以 ACES 2.0 为基准重打光

  • 正好配合 PBR 重打光：统一“ACES 2.0 + sRGB 编码”，建一张标定场景，固定曝光体系。
  • 自发光、特效、天空按档位重调：ACES 下亮部要多给约 1 档。
  • 项目的 Look 用 Color Grading 预设来做；LUT 贴图在 ACES 下不生效。
  • DCC 预览要对齐 UE 额外乘的 ×1.5（+0.58 档）。

①显示编码：给显示器的“翻译方式”变了（影响最大）

渲染算出来的是“光有多亮”。最后一步要把它翻译成 0–255 的像素值发给显示器，显示器再按自己的规则翻译回亮度。两边必须用同一本“字典”：

  • Filmic 按 sRGB 编码；电脑屏幕、手机屏幕按 sRGB 显示：配对。
  • Standard ACES 在 UE 里默认按 BT.1886（Gamma 2.4）编码。这是暗室里看电视、调色监视器的标准，而普通屏幕仍按约 2.2 解码：不配对。同样的暗部亮度被编成更大的像素值，显示出来就亮了，阴影发灰。

引擎源码的说明写得很直白：“The default for ACES is BT.1886 to prioritize compatibility between SDR and Rec. 2100 for HDR.” Epic 是为了让 SDR 和 HDR 电视的观感一致才选了 BT.1886；但我们的玩家绝大多数用的是 sRGB 屏幕。这个默认值只在 PPV 选了 Standard ACES 时启用（Filmic 一直是 sRGB）。可以用 r.LUT.TonemappingSDRInvEOTF 改：0 = sRGB，1 = BT.1886。

灰阶曲线：场景亮度 → 屏幕像素值

横轴是比 18% 中灰亮或暗几档（1 档 = 亮度 ×2），纵轴是最终发给屏幕的像素值（0–255）。把鼠标放到图上可以看每档的具体数值。

具体数字：比中灰暗 3 档 / 5 档的地方，Filmic 的屏幕亮度是 0.65% / 0.06%，ACES 默认是 1.62% / 0.33%（×2.5 / ×5.2）。改成 sRGB 编码后是 0.81% / 0.05%，与 Filmic 基本一致。

A/B 对比的坑 控制台的 r.LUT.TonemappingMethod 1 只会把曲线换成 ACES，编码仍然跟着 PPV 走（源码里编码默认值读的是 PPV 的设置，不是这个控制台变量）。所以在控制台里切，看到的是“ACES + sRGB”；在 PPV 里切，看到的是“ACES + BT.1886”，两种方法的结果不一样。反过来，PPV 选了 ACES、控制台强制 Filmic 时，Filmic 也会被按 BT.1886 编码，同样发灰。团队讨论“ACES 好不好看”之前，先统一切换方法（下面有命令）。

②曲线形状：ACES 2.0 更柔，把空间留给了高光

编码修好之后（上图青色线），暗部和 Filmic 基本重合，但从中灰往上 ACES 2.0 一直更低、更平：

  • 中间调对比度：中灰附近每亮 1 档，Filmic 增加 51.5 个像素值，ACES 2.0 只增加 37.5，低 27%。
  • 高光到白的距离：Filmic 在比中灰亮 +5.2 档（中灰的 37 倍）时就到了 99% 白；ACES 2.0 要到 +7.0 档（中灰的 128 倍）。比中灰亮 2 档的地方，Filmic 是 208.5，ACES 是 183.8。
  • 为什么中灰刚好一样？UE 在 ACES 前面额外乘了 1.5（r.HDR.Aces.SceneColorMultiplier，约 +0.58 档），配合 BT.1886 编码，正好让中灰与 Filmic 对齐（117.9 vs 117.6）。可见 Epic 有意保证“整体亮度不变”，只是两头对不齐。

换成美术的直觉：中间调不用动；想让亮部像以前一样亮，ACES 下要多给能量，越亮的地方要多给得越多：

想在屏幕上达到的像素值Filmic 需要（档）ACES + sRGB 需要（档）差多少相当于强度 ×

“档”指相对 18% 中灰的曝光档位。表里的倍数是灰阶的结果；彩色自发光还会受原因 ③ 影响。

这不是 ACES 的缺陷，而是取舍。Filmic 很快把亮部压到白，画面“实”、出片快，但强光、火焰、天空容易糊成一片。ACES 2.0 给高光留了 3 倍多的余量，层次更多，也是它能自然适配 HDR 屏幕的原因。代价是默认观感更平，需要在上面自己做 Look。

③颜色：Filmic 逐通道压缩，ACES 2.0 保色相

Filmic 把 R、G、B 三个通道各自套同一条 S 曲线。亮的通道先被压平，暗的通道后被压，所以一个颜色越亮，就越往黄、青、品红偏，同时中等亮度的颜色被“顺带”加了饱和。ACES 2.0 在色貌空间里只压亮度，彩度单独控制，所以色相基本不变，亮到头是“变白”而不是“变色”。下面每一行是同一个颜色从 −2 档逐渐提亮到 +8 档：

数值越大，表示越亮时颜色变得越多（OKLCH 色相角）。

Filmic 下火焰橙最多偏 47°，魔法蓝偏 38°，血红偏 17°，奥术紫偏 15°；ACES 2.0 全部不超过 5°。

对特效 / 自发光的影响 以前火焰的“黄白芯”、魔法光的“青白芯”，很大一部分是 Filmic 偏色“送”的。ACES 下颜色不会自己变，火焰会更橙、更红（对比滑块里的选角场景）。想要黄白芯，就要在特效贴图或颜色渐变里明确做出来。好处是：特效颜色调成什么样，屏幕上就是什么样，不会因为亮度一变就跑色。

平均彩度随曝光的变化（色卡 18 个彩色块）

正常曝光附近 ACES 2.0 更淡；但比正常亮 1.5 档以上时，ACES 反而比 Filmic 更保色。Filmic 的亮色会很快被压成白色或黄色。

在暗场景（地牢）里，编码一项就占了约 72% 的差异（5.0 → 1.4）。在强光特效场景（选角）里，编码只占约 37%（5.2 → 3.2），剩下的主要来自曲线和颜色。色卡几乎全是中间调和亮色，所以改编码帮助很小（4.4 → 4.1），要靠补偿（→ 2.3）。剩下的差异是 ACES 2.0 本来的样子：更多高光层次、颜色不跑偏。这部分不需要、也不应该完全“修”回去。

短期方案：不重做美术，先把画面救回来

目标：在 PBR 重打光完成之前，既可以继续用 Filmic，也可以先切 ACES 而不让画面变灰。

  1. 先决定要不要现在切 存量关卡的灯光、材质、特效都是在 Filmic 下调的，继续用 Filmic 是零成本、零风险的选择。建议只在新做或重打光的关卡里用 ACES，旧关卡等重打光时再切。下面的 2–5 步是“必须现在切”时的做法。
  2. 必做：把输出编码改回 sRGB 解决“暗部发灰”这个最大的问题，只影响 Standard ACES，Filmic 不受影响： 
    ; Config/DefaultEngine.ini
[/Script/Engine.RendererSettings]
; Standard ACES 在 SDR 下按 sRGB 编码（默认 -1：PPV 选 ACES 时用 BT.1886 / Gamma 2.4，普通屏幕暗部发灰）
r.LUT.TonemappingSDRInvEOTF=0
    效果：与 Filmic 的平均色差 4.8 → 2.8（地牢场景 5.0 → 1.4）。这个变量每帧读取，编辑器里用控制台输入同名命令可以立即看到效果。
  3. 可选：把观感补偿到接近 Filmic 下面三个数是用两张工程截图加色卡拟合出来的，与 Filmic 最接近（平均色差 2.8 → 1.8）：
    参数在哪里改值作用
    曝光r.HDR.Aces.SceneColorMultiplier=1.6（默认 1.5，只影响 ACES）；或者 PPV → Exposure Compensation+0.1 档中灰对齐 Filmic
    对比度PPV → Color Grading → Global → Contrast（亮度 Y 那一项）×1.15补回中间调对比度和亮部
    饱和度PPV → Color Grading → Global → Saturation（Y）×0.95对比度加上去后饱和度会略高，轻微回收

    “×”的意思是在原值上乘：UE 的 Contrast 是以 0.18 为支点的幂运算，Saturation 是围绕亮度的插值，两次叠加正好等于两个系数相乘。所以已经改过对比度、饱和度的地图（正式内容里分别有 4 个和 21 个）用“原值 × 系数”，没改过的直接填系数。补偿后的灰阶曲线是第一张图里的黄色线。

    备选：如果以后要做 HDR 输出，并且要求 SDR/HDR 观感严格一致，也可以保留 BT.1886 编码，改用曝光 −0.1 档（SceneColorMultiplier 1.4）、对比度 ×1.3、饱和度 ×0.95，色差为 1.4，数值上更接近，但对比度要加得更猛。对 PC / 手机项目，第 2 步的 sRGB 编码在原理上更正确，推荐用它。

  4. 检查清单：切换前逐项看一遍
    • 3 张改过 Film Slope 的正式地图（HD_MiLiuZhiHuan000、YongShuangBingPo ×2）：这个参数失效后要用 Contrast 重新找感觉。
    • SD_GeBuLinYingDi02 的 LUT 贴图会失效：要么用 Color Grading 重调，要么这张图先留在 Filmic。
    • 火焰、魔法、刀光等高饱和特效：颜色不再偏黄、偏青，亮度也偏暗，需要特效同学确认。
    • 天空、自发光、灯光高光：要达到原来的亮度大约要多 1 档（见原因 ② 的表）。
    • 用 SceneCapture 渲到 UI 的画面（角色展示、头像）同样走 Tonemapper，也会变。
    • 前面提到的 2 张已经存成 ACES 的地图。
  5. 统一的 A/B 对比方法（编辑器 / PIE 控制台） 
    r.LUT.TonemappingMethod 0         // 强制 Filmic
r.LUT.TonemappingMethod 1         // 强制 Standard ACES（ACES 2.0）
r.LUT.TonemappingSDRInvEOTF 0     // 编码 = sRGB
r.LUT.TonemappingSDRInvEOTF 1     // 编码 = BT.1886（= 在 PPV 里选 ACES 时的默认）
r.HDR.Aces.SceneColorMultiplier 1.6  // ACES 曝光补偿（默认 1.5）
r.LUT.TonemappingMethod -1        // 恢复：跟随 PPV
r.LUT.TonemappingSDRInvEOTF -1    // 恢复：跟随默认规则

    两个变量要一起设，才能确定看到的是哪种组合。“ACES 默认”是 1 / 1，“ACES + sRGB”是 1 / 0，Filmic 是 0 / 0。

  6. 不要用局部后处理体积来切换 Tonemapping Method 是“开关型”属性，不做混合：只要体积权重大于 0 就整个切过去（源码 SET_PP(TonemappingMethod)）。角色走进带 Blend Radius 的局部体积时，画面会瞬间跳变。请在每张图的全局（Unbound）PPV 上整图切换。

长期方案：以 ACES 2.0 为基准的 PBR 重打光

既然美术效果本来就要按 PBR 重新打光，这是切到 ACES 2.0 最合适的时机。目标是让“美术在屏幕上看到的”和“物理上应该是的”一致，再在上面叠项目自己的风格。

  1. 定死输出标准 全项目统一用 Standard ACES（r.HDR.Aces.Version=2）加 sRGB 编码（r.LUT.TonemappingSDRInvEOTF=0），编辑器视口、PIE、打包包体保持一致。移动端走的是同一套 LUT 生成代码，结论通用。美术的显示器统一校准到 sRGB（Gamma 2.2、D65 白点）。
  2. 做一张“标定场景”（Look-dev 地图） 放 18% 灰卡、ColorChecker 色卡、白 / 灰 / 镜面三颗球、常用材质样本，以及白天、室内、地牢、夜晚几套典型灯光。所有灯光、材质、特效先在这里过一遍再进关卡。本文的灰阶条和色卡图可以直接当参照。
  3. 建立曝光体系 工程关了自动曝光（r.EyeAdaptationQuality=0），曝光由 PPV 的 Exposure Compensation 决定。约定每类场景主光下 18% 灰显示为像素值约 110–118，用物理单位（lux / 坎德拉 / EV100）记录主光强度。ACES 2.0 的灯光直觉：比中灰亮 +3.9 档约到 90% 白（像素值 230），+7.0 档才到 99% 白；Filmic 分别是 +2.9 档和 +5.2 档。
  4. 材质与自发光规范 Albedo 控制在 sRGB 约 50–240（线性约 0.03–0.87），不要纯黑、纯白、纯饱和。自发光、天空、灯罩、UI 3D 元素按“比中灰亮几档”来定强度：ACES 下要达到原来的亮度大约多 1 档（亮部）到 1.5 档（接近白）。
  5. 特效重调 火焰、魔法等高饱和特效的“白芯 / 黄芯”在贴图或颜色曲线里明确做出来，不再依赖 Tonemapper 偏色。好处是颜色所见即所得：调成什么色，越亮也还是那个色。
  6. 项目 Look 用 Color Grading 做，不用 LUT 贴图 ACES 2.0 默认是“中性原片”。项目风格（对比、饱和、暗部偏冷、高光偏暖等）用 Color Grading 的全局 / 暗部 / 中间调 / 高光分区来做，整理成几套 PPV 预设，按场景类型复用。LUT 贴图在 ACES 下不生效。实在需要 LUT 式调色，可以用 After Tonemapping 的后处理材质，但有额外开销，移动端要慎用。
  7. DCC 和 UE 对齐 Substance Painter、Nuke、DaVinci Resolve、Maya / Houdini 等支持 OCIO 的软件，用 ACES 2.0 配置（sRGB 显示、SDR 100 nit）预览时，要额外 +0.58 档曝光，因为 UE 在 ACES 前乘了 1.5。另一种做法是把 UE 的 r.HDR.Aces.SceneColorMultiplier 设回 1.0，与行业标准完全一致，再用场景曝光补回这 0.58 档。两种做法选一种，全项目统一。
  8. 为 HDR 输出留好路 ACES 2.0 的 SDR 和 HDR 是同一曲线家族，开 HDR 后自动按屏幕峰值亮度展开，观感一致。Filmic 在 HDR 下是“先算出 SDR 结果，再反推扩展”，一致性较差。以后要支持 HDR 屏幕，ACES 是更省事的基础。
  9. 逐关卡迁移、逐关卡验收 按关卡整图切换（见短期第 5 步），优先切新做或重打光的关卡。每张图切换前后在固定机位截图对比，并在标定场景里检查中灰和白点。验收时用统一的 A/B 命令，避免前面那个“控制台切与 PPV 切结果不同”的误会。

Filmic vs ACES 2.0：优劣对比（美术版）

一句话：Filmic 像“自带滤镜的相机”，好看、省事，但亮部会偏色、层次少。ACES 2.0 像“原片”，干净、准确、高光层次多，但要自己调出风格。

维度Filmic（UE4 以来的默认）ACES 2.0（Standard ACES）
中间调对比高：中灰附近每档 51.5 个像素值，画面“实”，出片快低约 27%（每档 37.5）：默认偏平，需要自己加对比
暗部干净，压得住默认发灰：UE 默认的 BT.1886 编码在普通屏幕上把暗部抬亮；改成 sRGB 编码后与 Filmic 接近
高光容易糊白：+5.2 档（中灰的 37 倍）就到 99% 白，强光、火焰、天空亮部层次少层次多：+7.0 档（中灰的 128 倍）才到 99% 白，过渡到白更自然
色相越亮越偏：火焰橙→黄 47°、魔法蓝→青 38°、血红→橙 17°保色相（≤ 5°）：亮了是“变白”，不是“变色”
饱和度中等亮度更艳（色卡平均彩度 12.3）正常曝光下淡一些（10.6，−14%）；很亮的颜色反而比 Filmic 更保色
可调性曲线可调：Film Slope / Toe / Shoulder / Clip、LUT 贴图、Blue Correction曲线固定：只能在曲线前用曝光和 Color Grading 调，LUT 贴图不生效
SDR / HDR 一致性一般：HDR 是从 SDR 结果反推再扩展一致：同一曲线家族，按屏幕峰值自动适配
行业标准 / 工具链UE 私有曲线，DCC 里没法用同一标准预览行业标准：ACES 2.0 / OpenColorIO，DCC、影视、外包流程可以对齐（注意 UE 额外的 ×1.5）
迁移成本零：现有美术都是在它下面调的需要重新校准灯光、自发光、特效、调色，正好配合 PBR 重打光
运行时性能相同：两者都烘焙成 3D LUT，每帧只查表；LUT 只在参数变化时重算（ACES 2.0 重算稍贵，但不是每帧）

适合继续用 Filmic 的情况

  • 存量关卡，没有重打光计划
  • 依赖 LUT 贴图或 Film 参数做出的强风格化画面
  • 上线时间紧，没有精力回归

适合切到 ACES 2.0 的情况

  • 按 PBR 重打光的关卡（你们现在的计划）
  • 强光、火焰、魔法特效多，Filmic 下经常糊白、跑色
  • 以后要支持 HDR 屏幕，或者要和 DCC、预渲染 CG 对齐

名词小抄

档（EV / Stop）亮度翻一倍 = 亮 1 档。本文横轴都以 18% 中灰为 0 档。
18% 中灰反射率 18% 的灰卡，是曝光的基准。正常曝光下显示为像素值约 110–118。
色调映射（Tonemapper）把可以无限亮的场景亮度压进屏幕能显示的 0–1 范围的那条曲线。Filmic 和 ACES 就是两种曲线。
显示编码（sRGB / BT.1886）把 0–1 的亮度翻译成像素值的规则，必须和屏幕的显示方式配对。sRGB ≈ Gamma 2.2（电脑、手机），BT.1886 = Gamma 2.4（暗室电视）。
逐通道 / 保色相逐通道：R、G、B 各压各的，简单但会偏色。保色相：只压亮度、单独控制彩度，色相不变。
彩度 / 色相彩度是“有多鲜艳”，色相是“是什么颜色”（红、橙、黄…）。本文都在 OKLab 感知色彩空间里度量。
ACES 2.0美国电影艺术与科学学院（AMPAS）维护的色彩管理标准，2.0 版重写了显示端的输出变换（也就是 Tonemapping）。UE 5.8 的 Standard ACES 默认用它。
PPVPost Process Volume，后处理体积。Tonemapping Method 在 PPV → Film 分类里（显示名 Method）。

B. 计算方法与可信度

  • Filmic：把上面的 Filmic 处理按源码逐行移植到 Python（numpy），参数为 UE 默认值。中灰 0.18 → 显示 0.18，与源码设计一致。
  • ACES 2.0：输出变换使用 OpenColorIO 2.6 内置的官方实现（ACES2065-1 → SDR 100 nit Rec.709），前后按 UE 源码补上 ×1.5、外层 LUT 的裁剪和编码。用 UE 源码里的 tonescale 公式逐点核对灰阶，与 OCIO 的结果相对误差小于 1×10⁻⁶。场景值超过 128 时 OCIO 会裁到峰值，UE 同样有 clamp_zero_to_peakLuminance。
  • 没有模拟的部分：3D LUT 的插值误差（UE 用 32³ LUT 加 PQ 编码，误差很小）、Bloom 等在 Tonemapper 之前的效果（截图反推时已包含在场景值里）、显示器个体差异。屏幕亮度按标准 sRGB 显示器计算。
  • 截图反推：用完整的 Filmic 正向模型做逐像素迭代求逆，地牢场景平均残差 0.002 个像素值，0.03% 的像素超过 2。选角场景的火焰区比 Filmic 能输出的颜色还要纯，约 8% 的像素有 2–6 个像素值的误差。
  • 补偿参数：以“与 Filmic 的平均 OKLab 色差”为目标，在两张截图（约 9 万个采样像素）和色卡（−1 / 0 / +1 档）上做坐标下降拟合，再取到 0.05 的整数档复算。
