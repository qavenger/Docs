效果系统

效果系统页解释 Verse 如何用 effect specifier 描述表达式能力：是否纯计算、读写状态、分配、事务、失败、挂起或发散。

源文件：13_effects.md小节数：17生成：2026-06-25

核心提炼

  • effects 是函数类型的一部分，也是调用方能否调用该函数的能力契约。
  • cardinality/计算相关效果包括 <computes>、<converges>、<decides> 等。
  • heap 相关效果包括 <reads>、<writes>、<allocates>、<transacts>，表示读取、写入、分配和可回滚事务。
  • suspension 相关效果用 <suspends> 表示异步挂起能力。
  • 内部/特殊效果包括 native、no_rollback、diverges 等，与实现和终止性相关。
  • 多个 effects 会组合，调用链的总效果通常是所需能力的并集。
  • 函数类型兼容允许更“少能力需求/更纯”的函数赋给允许更多效果的类型。
  • class/interface/struct 的 specifier 与字段初始化、block、构造器效果有约束。

规则与坑点

  • 可失败 <decides> 函数必须在失败上下文用 [] 或等价方式处理。
  • 不能把会写状态的 <transacts> 函数赋给只允许 <computes> 的函数类型。
  • field initializer 和 class block 的效果不能超过类型声明允许范围。
  • 数据类型本身通常不能声明 async/failable effects；构造函数可以表达可失败或事务能力。
  • 发布 API 的 effects 是兼容契约，未来只能朝更少副作用方向演化。

典型语法

  • Validate(X:int)<decides>:int = ...
  • ReadState()<reads>:int
  • Update()<transacts>:void
  • Wait()<suspends>:void
  • type{_(:int)<computes><decides>:int}
