代码演化

代码演化页阐述 Verse 发布代码后的长期兼容契约：公开 API、持久化 schema、effects 和类型 specifier 都会成为未来版本要尊重的承诺。

源文件：18_evolution.md小节数：16生成：2026-06-25

核心提炼

  • 发布 <public> 定义意味着用户可长期依赖其名称、种类和类型契约。
  • Verse 在发布时进行兼容检查，阻止破坏已有依赖的更新。
  • 一般原则是新增能力安全，删除能力危险；返回可更具体，参数可更宽泛，effects 可更少。
  • 弃用机制先给警告，再配合版本迁移。
  • closed enum、persistable 类型和可覆写实例成员最难演化。
  • final 或模块级 API 往往比可继承/可覆写 API 更容易兼容演化。

规则与坑点

  • 不能删除、重命名或改变公开定义 kind。
  • closed enum 不能添加/删除/重排枚举项；需要扩展时应一开始用 open。
  • class 可加有默认值字段，但不能加无默认值字段或删字段。
  • 不能把 <computes> 扩成 <reads> 或 <transacts>。
  • 不能降低访问性；持久化类型规则最严格。

典型语法

  • Thing<public>:int = 777
  • enum<open>
  • class<final>
  • @deprecated
  • @experimental
  • @available
