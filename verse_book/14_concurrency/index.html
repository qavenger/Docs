并发

并发页介绍 Verse 的时间流控制：即时表达式与异步表达式、<suspends>、结构化并发、spawn/task、取消、清理、计时函数和事件同步。

源文件：14_concurrency.md小节数：37生成：2026-06-25

核心提炼

  • 表达式分 immediate 与 async；使用 async 能力的函数需要 <suspends>。
  • sync 同时启动多个分支并等待全部完成，结果可组合。
  • race 取最先完成分支并取消其他分支；rush 允许最先完成后继续，其他分支仍运行。
  • branch 启动结构化后台工作，仍受父作用域生命周期约束。
  • spawn 是非结构化并发，返回 task(t) 句柄，可 cancel 或 await。
  • task 的 Await() 可等待结果，已完成任务再次 await 通常立即返回缓存结果。
  • 取消只在 suspension point 生效，长循环可通过 Sleep(0.0) 或 tick 让出执行。
  • defer 用于清理，但不能包含 suspending 操作。
  • Sleep、NextTick、GetSecondsSinceEpoch 支持时间控制和日志/分析。
  • 事件、sticky events、subscribable events 与 awaitable/signalable 接口构成同步机制。

规则与坑点

  • sync/race/rush/branch 等结构化并发通常只能在 <suspends> 函数中使用。
  • spawn 需要 suspends 函数，不能直接 spawn decides 函数。
  • 取消不是立即中断 CPU 循环，必须到达挂起点。
  • race 分支返回类型会合并为共同超类型；需要识别赢家时可返回带 tag 的值。
  • defer 不应直接 suspend，资源清理要保持即时。

典型语法

  • sync: A(); B()
  • race: Slow(); Fast()
  • rush: Work(); Timeout()
  • spawn{AsyncWork()}
  • Task.Cancel()
  • Result := Task.Await()
  • Sleep(0.0)
  • NextTick()
