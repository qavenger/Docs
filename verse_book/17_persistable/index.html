可持久化类型

持久化页讲哪些类型能跨会话保存，以及如何通过模块级 weak_map(player,t) 自动加载玩家数据。重点是类型限制、schema 演化和序列化边界。

源文件：17_persistable.md小节数：11生成：2026-06-25

核心提炼

  • 持久化数据通常存放在模块作用域 weak_map(player,t)。
  • 内建可持久化类型包括 logic、int、float、string、char、char32。
  • array、map、option、tuple 只有元素/键/值也可持久化时才可持久化。
  • 自定义 class、struct、enum 可用 <persistable> 标记。
  • 可持久化 class 必须 <final>，不能 <unique>，字段必须都是持久化类型。
  • JSON serialization 小节标注为未发布功能，可用于调试和迁移设想。

规则与坑点

  • any、comparable、type、rational、函数、weak_map、接口不能作为持久化字段。
  • 可持久化 class 不能有 var 字段。
  • 可持久化 struct 发布后 schema 很难修改。
  • 反序列化不会执行 class block 初始化逻辑。

典型语法

  • Data : weak_map(player, int) = map{}
  • profile := class<final><persistable>:
  • coords := struct<persistable>:
  • day := enum<persistable>:
  • set PlayerData[Player] = NewStats
