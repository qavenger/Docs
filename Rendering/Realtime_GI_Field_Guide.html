A required distinction

Irradiance Probe 与 PRT Probe 存的不是同一种东西

“都叫 Probe、都可能存 SH”只是外形相似。判断它们的可靠方法是追问：缓存的是某次求解后的光照答案，还是固定场景对任意输入光照的传输响应？

Answer cache versus operator cache

同一个空间点，两种完全不同的更新契约

Irradiance Probe 保存当前或烘焙光照下的 irradiance / radiance 结果；灯光改变后，要重新追踪、重烘或预算化刷新。PRT / Transfer Probe 保存 visibility、余弦、BRDF 与多次传输在某组基底下的系数或矩阵；固定几何下，只需把新光照投影系数与传输做点积即可 relight，但几何或遮挡关系改变会让预计算算子失效。

典型内容：irradiance atlas、distance moments、validity。DDGI 用新射线更新答案，并常借助 hysteresis 跨帧收敛。

Module 07 · PRT / Transfer Probe

缓存“固定场景的响应算子”

典型内容：transfer vector / matrix、SH transport。运行时换低维光照很快；动态几何、未包含在基底里的局部光和高频遮挡是主要边界。

打开 PRT 专题 →
不要用更新时间区分：一个静态 Irradiance Probe 可以是烘焙的，一个 PRT Probe 也可以每帧 relight。真正分歧是数据语义：前者是结果场，后者是线性传输近似。SH 只是二者都可能采用的方向基底。
Executive answer

先给结论：高速运动光源怎么选

“全动态”不等于“当前帧就收敛”。快速光源最怕的不是平均误差，而是历史帧拖影、能量滞后与 disocclusion 闪烁。

首选候选 · 3D / 自研管线

无时序 Voxel GI / VCT
＋ Clustered 光照注入

每帧用当前光照重建体素辐射度，再做锥体追踪；GI 核心不读取上一帧辐照度。将大量光源先按空间簇剔除，体素只遍历影响自己的局部光源列表，避免成本直接等于“全场灯数 × 全部体素”。

GI 历史依赖：无 高速光响应：当前帧 离屏覆盖：世界空间 代价：体素分辨率 / 漏光
边界条件：推荐先做“一次反弹、全帧更新”。二次反弹若用跨帧反馈，就重新引入时序延迟；若在同一帧固定迭代，则增加 GPU 成本。静态几何的占据体素可以缓存——这属于空间缓存，不是光照历史。

Reference architecture

大量高速运动光源：建议的数据流

核心思路是让 GI 消费“当前帧已经合并好的局部直接辐射度”，并把光源总数问题转化为局部空间密度问题。

构建光源簇Forward+ / Clustered culling；快速更新光源包围体与 cluster 索引。
准备体素几何静态 occupancy 缓存；动态物体写入独立低分辨率层并与静态层合并。
当前帧注入每个体素只评估其 cluster 的光。写入方向性辐射度与不透明度。
空间预滤波生成各向异性 mip / octree 层级，让一次 cone sample 代表一束方向。
单帧 gather每像素 4–6 个漫反射锥；必要时仅做空间双边上采样，不采历史帧。

不要让每个体素遍历全场所有灯。先用 Clustered Culling 给体素一张“附近灯名单”，再只处理名单；Cone Gather 的另一半成本来自屏幕像素、锥数量和每锥步数。

近似成本 ≈ O(受影响体素数 × 每簇平均灯数)
＋ O(着色像素数 × 锥数量 × 步数)

这是容量估算，不是可执行着色公式；必须同时限制局部灯密度、体素分辨率、cone 数与最大距离。

for 每个 dirty voxel:
  cluster = 查找 voxel 所在的光源簇
  radiance = 0
  for cluster 中真正影响该 voxel 的灯:
    radiance += 评估当前灯的可见性与直接光

逐 Pass 可执行案例见 VoxelGI 页面；真实 D3D12/Vulkan 资源链、Texture3D 与 barrier 见 RenderGraph Workbench。原生样例目前用一个高速移动点光验证 history=0；大量灯版本仍需接入框架尚未提供的 clustered light-list buffer。

工程优势

  • 灯光变化同帧进入 GI，不产生历史拖尾
  • 间接光成本对全局灯数弱敏感，更关心局部重叠
  • 世界空间覆盖，不会因光源离开屏幕立刻消失
  • 不强制 RT 硬件，可用计算 / 光栅体素化实现

必须接受的代价

  • 低分辨率体素会漏光、吞薄墙、模糊小光源
  • 全动态几何体素化和 mip 构建可能成为瓶颈
  • 无时序时只能靠更多空间样本换稳定细节
  • 在 Unreal 中更像自研 RDG / 插件路线，不是 Lumen 开关

Shared DNA & fault lines

共同点与分歧点

看懂这些共性后，新方案通常只是换了一种“采样、压缩、复用与可见性”的组合。

01

都在近似渲染方程

实时预算无法穷举所有路径，方案差别在于丢掉哪些维度、如何复用有限样本。

02

都先分离直接与间接光

直接光通常由 shadow map / RT shadow / clustered shading 完成，GI 再传播已着色表面的能量。

03

都在压缩辐射场

光照贴图压到纹理；探针压到 SH；VCT 压到体素 mip；Lumen 压到 Surface Cache；ReSTIR 压到 reservoir。

04

可见性始终最难

屏幕空间缺失离屏信息；探针与体素会穿墙；低样本射线有噪声。多数伪影都能追溯到可见性近似。

05

漫反射比高光更容易

低频 irradiance 很适合探针与 SH；镜面、高光、焦散需要更高方向频率，常被拆给反射或路径追踪。

06

混合方案才是常态

SSGI 补近场细节、探针给离屏底色、RT 解决关键可见性、烘焙承担静态远场——工程上很少只用单一算法。

场景表示屏幕深度 / 光照贴图 / 探针网格 / 体素或 SDF / 三角形 BVH / Surface Cache。
更新时机离线烘焙、事件触发、级联滚动、预算化探针更新、每帧全量、跨帧 reservoir。
时序策略完全不读历史、历史仅降噪、历史承担收敛、跨帧摊销真实工作量。它们的运动表现完全不同。
覆盖范围仅屏幕、相机周围级联、局部 volume、全世界流送。覆盖越完整，内存与更新越贵。
动态性边界动态灯、动态遮挡物、蒙皮几何、动态 emissive 是四件不同的事；文档里的“dynamic”必须逐项核对。
能表达的频率SH / probes 偏低频；体素锥中频；射线 + 路径样本可保留高频，但需要采样和降噪。
缓存的数据语义Irradiance Probe 缓存光照结果；PRT / Transfer Probe 缓存固定传输算子；同样使用 SH 并不代表更新方式相同。
模块耦合Cone Tracing 不是独立 GI：它必须消费可靠的 occupancy / radiance volume 与 mip；可用的 VoxelGI 系统还需要当前帧注光、合成和可见性策略。
成本主导项灯数、像素数、体素数、probe×ray、BVH 更新、缓存内存或时序收敛速度，各方案瓶颈不同。
失败方式漏光、遮挡缺失、能量滞后、ghosting、噪点、disocclusion、距离裁切、内存爆炸。
Learning route

建议学习顺序

按“信息存储位置”递进，比从某个大型引擎的开关反推原理更容易形成稳定认知。

STEP 01 · 必经

基线与一束光

沿直接光与间接反弹理解 radiance、irradiance、BRDF、坐标、GBuffer 与抽样权重。

STEP 02 · 屏幕 / 光源空间

RSM ＋ SSAO / SSGI

从 MRT 和 GBuffer 调试视图出发，能解释 VPL、离屏缺失与 depth thickness 问题。

STEP 03 · 世界空间 · 严格依赖

Voxelization → Cone Tracing → VoxelGI

先确认 occupancy / radiance / mip 的语义，再让 Cone 消费这些输出，最后组装当前帧注光与合成。不要从 Cone 页面跳过 Voxel 前置。

STEP 04 · 方向与缓存

SH → Irradiance Probe → PRT

先学 SH 投影、卷积与旋转，再明确 Probe 是“结果缓存”、PRT 是“传输算子缓存”。

STEP 05 · 算法组装

RCGI ＋ DDGI

在 RCGI 中观察 single-shot interval merge 核心；在 DDGI teaching-lite 中观察 rays、atlas、hysteresis、visibility、relocation 与 scrolling。

STEP 06 · 原生组装

RenderGraph GI Workbench

把基础 Pass 放入 D3D12 / Vulkan RenderGraph，核对资源依赖、barrier、dispatch 和中间纹理预览。

最有价值的对照实验

  1. 同一封闭房间放置 64 / 256 / 1024 个移动点光，速度覆盖 1–30 m/s。
  2. 每 0.5 秒随机切换 20% 灯光颜色和强度；同时做一次硬切镜头。
  3. 逐帧抓取 indirect-only、history weight、voxel/probe debug view 与 GPU profile。
  4. 记录“光源变化到间接光达到 90% 新稳态”的帧数；它比静止截图更能揭示时序问题。
