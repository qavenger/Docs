不要先背 Cascade。

STAGE 01 · PENUMBRA HYPOTHESIS

为什么“近处看位置，远处看方向”

离遮挡物近时，轻微移动位置就可能从“看见灯”变成“看不见灯”，所以空间采样要密。离得远时，位置变化影响较小，但很窄的方向变化仍可能擦过小光源，所以方向采样要密。

STAGE 02 · INTERVAL

一根完整射线，先切成四个互不重叠的区间

Cascade 0 只负责最近一段；Cascade 1 从上一段终点继续。每一层只回答“我的区间里先撞到什么”，不重复计算更近的路程。

02

选择 Probe、方向和 Cascade

画面中的圆环就是区间起点/终点；粗紫线是当前被 ray march 的一段。

独立 Demo B
—

把射线想成四节透明水管。每节只报告三件事：有没有撞到、撞到后是什么颜色、如果没撞到还剩多少透明度。近节撞到墙后，远节即使看见灯也不能穿回来。

tend,l = b·4l

—

从 tStart 开始
while t 小于 tEnd:
  查询当前位置到最近表面的距离
  如果距离足够小:
    返回 命中颜色 与 不透明
  t += 安全步长
返回 黑色 与 透明
function marchInterval(origin, angle, start, end) {
  let distance = start;
  for (let step = 0; step < 56 && distance < end; step += 1) {
    const point = {
      x: origin.x + Math.cos(angle) * distance,
      y: origin.y + Math.sin(angle) * distance,
    };
    const sample = sampleScene(point.x, point.y);
    if (sample.distance < 0.32) {
      return {
        rgb: sample.emissive ? state.lightColor : [0, 0, 0],
        alpha: 1,
        distance,
        material: sample.material,
      };
    }
    distance += clamp(sample.distance * 0.78, 0.28, 2.4);
  }
  return { rgb: [0, 0, 0], alpha: 0, distance: end, material: 'none' };
}

function buildCascade(level) {
  const spacing = state.baseSpacing * (2 ** level);
  const directions = BASE_DIRECTIONS * (2 ** level);
  const start = level === 0 ? 0 : BASE_INTERVAL * (4 ** (level - 1));
  const end = BASE_INTERVAL * (4 ** level);
  const columns = Math.ceil(SCENE_WIDTH / spacing);
  const rows = Math.ceil(SCENE_HEIGHT / spacing);
  const values = new Float32Array(columns * rows * directions * 4);

  for (let y = 0; y < rows; y += 1) {
    for (let x = 0; x < columns; x += 1) {
      const origin = { x: (x + 0.5) * spacing, y: (y + 0.5) * spacing };
      for (let ray = 0; ray < directions; ray += 1) {
        const angle = (ray + 0.5) / directions * TAU;
        writeInterval(values, x, y, ray, marchInterval(origin, angle, start, end));
      }
    }
  }
  return { level, spacing, directions, start, end, columns, rows, values };
}
STAGE 04 · MERGE

远处答案不能直接相加，要先问近处是否已经挡住

Merge 从近到远读取区间，但语义是“远结果补到近结果的透明缺口”。近区间 opacity=1 时，远处贡献乘到 0；这就是遮挡顺序。

04

单个查询点、单个方向的合并账本

拖动方向后，表格和条带由四层缓存重新采样。

独立 Demo G

先看最近水管。如果它撞墙，透明度归零，后面三节全部作废；如果它没撞，才允许下一节把颜色补进来。

L ← L + T · Ll
T ← T · (1 − αl)

—

颜色 = 0
剩余透明度 = 1
for cascade 从近到远:
  样本 = 在该层插值 Probe 与方向
  颜色 += 剩余透明度 * 样本颜色
  剩余透明度 *= 1 - 样本不透明度
  如果几乎不透明: 提前结束
function mergeDirection(x, y, angle) {
  const radiance = [0, 0, 0];
  let transmittance = 1;
  for (const cascade of cascadeData) {
    const sample = sampleCascade(cascade, x, y, angle);
    for (let channel = 0; channel < 3; channel += 1) {
      radiance[channel] += transmittance * sample.rgb[channel];
    }
    transmittance *= 1 - sample.alpha;
    if (transmittance < 0.001) break;
  }
  return { rgb: radiance, transmittance };
}

STAGE 06 · WHAT THE DEMO IS

这是真算法实验，但不是通用 3D 产品实现

诚实区分成熟范围，避免把二维成功直接外推到任意三维游戏场景。

本页真实做了什么

  • 解析 SDF 场景上的区间 ray march。
  • 逐层不同 Probe spacing / direction count。
  • 双线性 Probe 与最近方向采样。
  • 近到远 opacity merge。
  • 逐像素参考解和误差度量。

教学版省略了什么

  • 普通表面的二次再发射 / 多跳：当前 interval 只在命中 emissive 时返回 radiance，命中普通墙返回 0；因此它验证的是 emissive→query 的 single-transport 核心，而不是完整多跳材质 GI。
  • 若要完整 GI，还需先生成 secondary surface radiance，再做迭代传播或等价的多跳更新。
  • 生产级方向插值与双线性修正。
  • 优化的 radiance interval packing。
  • 屏幕边界、动态几何和复杂材质。
  • 3D 球方向、内存压缩和调度优化。

进入 3D 要新增什么

  • 体素/SDF/DXR 可见性表示。
  • 三维 Probe lattice 和球方向参数化。
  • 更高的方向与内存预算。
  • volume slice / raymarch debug views。
与 RenderGraph Workbench 的连接：原生教学版将沿用“Build Intervals → Merge → Resolve → Debug”资源链，但 ray source 会明确标成 voxel/SDF teaching-lite；框架目前没有硬件 Ray Query，文档不会伪造该能力。
STAGE 07 · COST & FAILURE

优势、代价和最常见误读

“single-shot”只说明核心不需要历史，并不等于无限分辨率、无限场景或免费三维。

问题正确理解本页如何观察
为什么移动光没有拖尾？每次交互都重建当前 interval field；核心 0 history reads。播放光源，观察历史检查始终为 0。
为什么仍有误差？Probe、方向和区间离散；single-shot 不等于解析真值。看 error heatmap 与 base spacing。
能否直接称为成熟 3D GI？不能。三维方向/内存/可见性成本显著增加，公开实践仍在快速演进。第 06 阶段明确列出缺口。
和 Radiance Cache 一样吗？不一样。Cascades 组织的是多尺度射线区间；cache 通常保存稀疏查询结果并更新/淘汰。看页首缩写边界。
