Stage 01 · frame inputs

先锁定坐标、域与当前光源

若 gizmo 与计算使用的 position/direction 不一致，之后每一张 radiance 图都会误导。

Demo 01 · Scene + domain + light gizmoINDEPENDENT CANVAS
黄色球表示点光位置；黄色箭头表示方向光的传播方向。红/绿/蓝箭头分别是 +X/+Y/+Z。

方向光没有有限位置，只需要方向；点光有位置，且每个 voxel 指向它的方向都不同。页面不会画一个位置球却暗中按方向光计算。

directional: toLight = constant
point: toLight = normalize(lightPosition − surfacePosition)
attenuation = 1 / max(distance², minimumDistance²)
directional toLight=(0.45,0.82,-0.35)
如果是方向光：所有表面使用同一个 toLight
如果是点光：从表面位置指向 lightPosition
用同一份 light 对象绘制 gizmo 与计算 injection

function makeLight(type, degrees) {
  const angle = degrees * Math.PI / 180;

  if (type === "point") {
    return {
      type,
      position: [
        Math.cos(angle) * 0.62,
        0.58,
        Math.sin(angle) * 0.62
      ],
      strength: 1.5
    };
  }

  return {
    type,
    toLight: normalize([
      Math.cos(angle) * 0.58,
      0.82,
      Math.sin(angle) * 0.58
    ]),
    strength: 2.2
  };
}

Demo 06 · Actual cone sample tracksSTAGE 06
顶部黄色 gizmo 与 Stage 01 相同；trace 读取 Stage 05 的 MIPS，而不是 mesh。

每个 cone 返回一束方向范围内的近似 radiance。多个 cone 只是在半球上换方向重复同一查询，再按 cosine 权重平均。

diameter=2t·tan(aperture/2)
lod=log₂(max(diameter/voxelSize,1))
color += (1−opacity) × sample.rgb
t=0.50, aperture=42°, voxelSize=0.125
diameter≈0.384，lod≈1.62
对 receiver 半球上的每个 cone：
  沿方向前进
  用 footprint 选小数 LOD
  trilinear + 层间插值读取 mip
  front-to-back 累计
按 normal·coneDirection 加权合并各 cone

function gatherReceiver(receiver, coneCount, aperture, forceLevel0) {
  const directions = diffuseDirections(coneCount);
  const traces = directions.map((direction) =>
    traceCone(
      receiver.position,
      direction,
      aperture,
      forceLevel0
    )
  );
  const weight = 1 / traces.length;
  const indirect = [0, 1, 2].map((channel) =>
    traces.reduce(
      (sum, trace) => sum + trace.color[channel] * weight,
      0
    )
  );

  return { indirect, traces };
}

Direct 是灯直接照到 receiver 的结果；Indirect 是其他表面先被灯照亮，再经 voxel field 被 cone 收集回来的结果。Final 只是两者在同一线性 HDR 空间相加。

display = 1 − exp(−exposure × finalLinear)
direct=(0.30,0.28,0.25), indirect=(0.08,0.10,0.14), gain=1.35

不要分别 tone map 后再相加

function compositeReceiver(receiver, indirect, gain) {
  const finalLinear = receiver.direct.map(
    (value, channel) => value + indirect[channel] * gain
  );

  return finalLinear.map(
    (value) => 1 - Math.exp(-value * 1.45)
  );
}
Completion gate · what this proves

能跑通不等于没有误差

下面明确区分“本页已经真实执行的部分”和“生产 RenderGraph 仍需补齐的部分”。

项目本页证据生产实现边界
当前帧动态灯播放高速移动光时，Inject/Mip/Gather/Composite 每 tick 更新；history=0。真实 GPU 仍受 3D volume 写入和 mip 带宽限制，需灯光裁剪。
VoxelizationCPU 解析 surface proxy，输出可检查 occupancy/attributes。不是硬件 conservative raster；mesh triangle、alpha test、skinning 需独立 pass。
Cone 查询实际 Float32 mip chain、三线性、层间插值、front-to-back。各向同性 mip 会跨墙混色；尖锐 specular 不可靠。
RenderGraph资源/Pass DAG 与独立中间产物。HTML 未接入 F:\RenderGraph，没有真实 UAV barrier、descriptor 或 compute dispatch。
画质Direct-only / Final A/B，能定位间接光来自何处。低分辨率 receiver 与 1–5 cones 仅教学；生产需更密集 shading pixels、抗漏与性能预算。
最重要的限制：“无 history”意味着光源响应没有 temporal lag，但不会自动消除空间离散误差。体素锯齿、mip 漏光、cone 欠采样仍要靠空间分辨率、方向相关存储、更多 cones 或其他可见性方案处理。
