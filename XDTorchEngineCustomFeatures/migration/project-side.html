怎么用这份清单：这些功能与引擎核心不强绑定，可以放到项目工程、插件或配置层实现，从而让引擎 fork 变薄。落地顺序：先做「yes（完全工程化）」，再做「partial（引擎留接入点）」。每迁走一项，就在引擎里删掉对应代码，并在 Feature Registry 登记新位置。

判定口径

取值含义典型落点
yes完全工程化，不需要动引擎项目 Module、Editor 插件、CVar/ini/DeviceProfile、命令行、资产侧规则、Game Feature
partial主体可工程化，需要引擎留少量接入点引擎加 Delegate/Interface/ModularFeature，逻辑在插件
no必须改引擎RHI/渲染管线内部、反射 schema、Cook 核心流程（这类见 接入点方案）

可工程化放项目/插件/配置即可，不动引擎

引擎内实现必须改引擎核心

引擎改动方式

L0 无需改引擎纯工程/插件/配置即可（对应「可工程化」）
L0 引擎内补丁需改引擎源码，但不必新增扩展点（对应「引擎内实现」）
L1 仅加接入点引擎只需暴露 Delegate / Interface / CVar 等扩展点
L2 结构性改动枚举 slot / 新 Pass / schema 字段
L3 深度侵入核心结构/生命周期/序列化，慎入
