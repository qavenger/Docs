结论先行：81 个宏属于「可以主动舍弃」——它们服务于 UE5 已经**架构性替换掉**的子系统，迁移到 UE5 后不需要把它们带过去。其中 39 个可以直接舍弃（连等价实现都不用做），11 个需要在新体系里重做等价能力，31 个需要先确认前提是否仍然成立。共涉及 6 个替代类别。

和「可丢弃清单」的区别：可丢弃清单（drop）是「UE5 自己已经修好了，所以宏可以删」；本页是可主动舍弃（reclaim）是「UE5 换了另一套子系统，这个宏服务的老对象已经不在迁移范围内，所以我们可以选择不做」。两者判断依据不同，但都落在迁移路线图的第 0 阶段（直接不处理）。

判定前提与替代关系

类别UE5 的替代舍弃的前提
Cascade 粒子 → NiagaraNiagara System / NiagaraComponent / NiagaraDataInterface迁移后在 UE5 用 Niagara 重做特效，不再走 Cascade 运行时（Cascade 在 UE5 只保留兼容维护）
PhysX / Apex → ChaosChaos Physics / ChaosCloth / GeometryCollection无条件：UE5 已移除 PhysX/Apex，没有回退路径
旧音频 / Wwise 版本适配新版 Wwise UE5 插件 / MetaSounds需确认：新插件是否已修掉旧版 GC / AssetRegistry 问题
平台工具链 / SDK 版本适配UE5 新工具链下限（Xcode 15+ / 新 NDK / 新 MSVC）需确认：同一问题在新工具链 + 新 SDK 下是否重现
旧 RHI / 平台图形路径UE5 保留的 RHI（D3D12 / Vulkan / Metal）需确认：目标平台是否还走这条路径（如 OpenGL ES、D3D11）
旧编辑器 / 工具链UE5 新编辑器框架（Niagara Editor / Sequencer / 新 Blueprint UI）需确认：编辑器扩展点是否由新框架原生提供

Cascade 粒子 → Niagara49 个宏

宏的作用对象是 Cascade 粒子运行时/编辑器。UE5 的特效体系已全面转向 Niagara（Cascade 只保留兼容维护），项目在 UE5 做特效时会用 Niagara 重做，针对 Cascade 的定制可以不带过去。

仍在排查的同类线索

同样的判断方式可以套用到其它「UE5 换了子系统」的地方，正在用独立 Agent 逐宏复核，确认后会补进本页：

  • 自研 GI / 光照：UE5 的 Lumen + 虚拟阴影图（VSM）替代了 UE4 时代大量自研 GI 与阴影方案，相关宏需评估。
  • 资源导入器：UE5 主推 Interchange 框架，旧的 FBX 导入器定制（默认设置、坐标轴转换等）可能被替代。
  • 移动端渲染路径：UE5 移动端管线（Mobile Deferred / 移动端阴影与后处理）与 UE4 差异较大，部分移动端专属优化可能失效或被原生能力覆盖。
  • 材质与着色模型：Substrate 材质体系与新的 Shading Model 接入方式会改变自研着色模型（如 ToonLit）的落地方式。
  • DDC / Shader 缓存：UE5 的 Zen / DDC / PSO 预编译机制变化，旧的缓存与编译优化项需重新评估。

舍弃要留退路：以上判定都写在「前提成立」的条件下。一旦前提变化（例如低端机仍需 Cascade、或某个平台仍走 OpenGL ES），对应宏就要从「舍弃」重新回到「移植」清单——本页每行都给出了类别与前提，方便逐条勾选确认。
