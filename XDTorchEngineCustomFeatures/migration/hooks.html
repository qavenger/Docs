核心思路：引擎里只保留稳定、低语义、可复用的接入点；功能主体（算法、策略、UI、工具、Shader）放到插件/项目模块；开关与数值用 CVar/ini/DeviceProfile 表达；资产格式变化用 CustomVersion 做兼容。
判定顺序：能配置就不写代码 → 能插件就不改引擎 → 必须改引擎就只加 Hook → 万不得已才动核心结构。

4. Hook 设计模式（按能力类型选）

  1. 事件式 Hook（Delegate）：引擎在关键节点广播，插件订阅。
    适用：资产保存前后、Pak 挂载失败、低内存、Cook 起止、PSO 预编译结束。
    XD 对应：XD_MISC_ADD_PAK_MOUNT_FAIL_DELEGATE、XD_EXT_ADD_ON_LOW_MEMORY_DELEGATE、XD_TOOL_ADD_SAVE_DELEGATES_FOR_EDITOR——这类已接近正确形态，直接沿用到 UE5。
  2. 接口式 Hook（Interface / Extension）：引擎定义接口与注册表，插件实现。
    适用：渲染阶段（ISceneViewExtension）、自定义 Cook 输出、平台策略。
    原则：接口小、稳定、无业务字段。
  3. Slot 式 Hook（枚举槽位）：在稳定的枚举里预留 slot（如 EMeshPass、ShadingModel、FeatureMask 位）。
    适用：必须进入引擎数据结构的能力。
    风险：改动 EMeshPass::Num/shading model 数量会影响序列化与 Shader；必须做版本兼容（CustomVersion）。
  4. Shader Include Hook：引擎 Shader 主文件只留 #include "/Plugin/Xxx/..." 或注入 define，实现放插件。
    适用：ToonLit、CustomGI、自定义光照分支。
    配套：AddShaderSourceDirectoryMapping + DDC/ShaderVersion 管理。
  5. 配置式 Hook（CVar / ini / DeviceProfile）：只改数值与开关，不改代码结构。
    适用：移动端画质档、Bloom/畸变强度、串流参数、平台策略。
    注意：UE5 的 CVar 数量庞大，新增 xd.* 前先确认 UE5 是否已有同类开关（本页清单会标出 covered）。
  6. Schema 兼容式（CustomVersion）：字段永久保留 + 版本迁移，关闭功能时隐藏 UI/返回默认值。
    适用：UPROPERTY/UFUNCTION/材质属性/资产格式。
    禁止：用编译宏控制反射字段是否存在。

8. 落地优先级

  1. 工具/前端先插件化：Dump/Report/AssetAudit/P4/PreCheckIn——收益高、风险低。
  2. 项目配置外迁：赛季号、材质 selector 数量、场景/UI 规则——消灭「项目数值进引擎全局宏」。
  3. FixBug 生命周期治理：稳定的转常开补丁；临时/测试宏限期删除；平台 workaround 进 PlatformCompatibility。
  4. 渲染扩展抽象：先做 RendererExtension 边界（shading model slot、材质扩展属性、后处理 hook、Shader include），再迁具体功能。
  5. 资产/反射/Cook 最后动：风险最高，先设计兼容策略与 CI 校验。
