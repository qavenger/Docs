怎么读这份文档

  1. 先看主题脉络：每个主题页讲清“为什么做、怎么做、涉及哪些宏、有什么坑”。
  2. 再看全量参考：按 UBT 源文件分册，逐宏给出作用、当前值、源码引用位置。
  3. 用搜索定位：不确定在哪个主题时，直接搜关键字。

宏取值含义：= 1 功能开启/存在；= 0 关闭或预留；其它数字为参数值（如 SEASON=16）。

修改任何宏之后：
① 重新编译；② 删除 Engine/DerivedDataCache 与 项目/DerivedDataCache 重编 Shader；③ 部分宏（PSO/DDC 相关）需要清理缓存并在下次 Cook 后才完全生效。

本目录只包含一个入口 index.html，其余内容按模块放在 topics/、ref/ 子目录中。

数据说明

本文档基于对引擎源码的静态分析生成：检索范围为 Engine/Source、Engine/Shaders、Engine/Plugins（已排除 Intermediate 等生成目录）；“源码引用 N”表示该宏在上述范围内的出现次数，仅供参考，不代表全部生效路径。宏的默认值与依赖关系以 UBT 源码为准；若代码有更新，请以实际源码为准重新核对。

标签说明

颜色规则：覆盖度=红绿灯 · 工程化=蓝色系 · 侵入=紫色系 · 处置=中性灰；色越深表示程度越高 / 可行性越低。

UE5 覆盖度

UE5 已覆盖UE5.8 原生等价，可直接删除
部分覆盖UE5 有同类能力，只迁差异部分
未覆盖UE5 没有该能力，需迁移或补丁
待确认证据不足，迁移前需人工确认

工程化可行性

可工程化放项目/插件/配置即可，不动引擎
需接入点引擎留少量 Hook，逻辑在工程侧
引擎内实现必须改引擎核心

引擎侵入等级

L0 无需侵入不改引擎源码
L1 仅加接入点Delegate / Interface / CVar 等扩展点
L2 结构性改动枚举 slot / 新 Pass / schema 字段
L3 深度侵入核心结构/生命周期/序列化，慎入

迁移处置

删除UE5 已覆盖，直接删
常开补丁确认的 bugfix，作为 fork 常开补丁
配置化改为 CVar / ini / DeviceProfile / 命令行
插件化迁到项目模块 / 编辑器插件
接入点引擎只留 Hook，逻辑在插件
移植代码保留，适配后移植
保留引擎深度绑定，暂留并登记 Feature Card
