2. 修改步骤（移植）

  1. 定位 UE5 对应文件
    见下方「UE5 对应文件」；重点比对同文件在 UE4/UE5 的差异。
  2. 移植实现
    原实现位置：Shaders/Private/LightmapCommon.ush、Shaders/Private/MobileBasePassPixelShader.usf、Source/Runtime/Engine/Private/LightMap.cpp、Source/Runtime/Renderer/Private/MobileBasePassRendering.h。如涉及 Shader，需同步改 shader define 或共享 include。
  3. 适配 UE5 接口与规范
    注意 C++20、UHT（反射）规则、bValidateCircularDependencies 默认开启等差异；必要时回归 DDC/Cook。
  4. Shader 侧配套
    删除 DerivedDataCache 重编 Shader；同步更新受影响的 shader permutation / ShaderVersion。

3. 代码级实现（开发用）

独立 Agent 审核并修正修正 4 处　提出问题 4 条

审核意见：LightMap.cpp 两处算法与 UE5 同构、api-adapt 判断成立，且 78/80/940/942/389/237-242 等关键锚点都真实；最大问题是 shader 侧改了机制（LightmapCommon.ush 提前返回 vs UE4 的整屏覆盖）导致观感不等价，以及 Red 覆盖插入点选错会被 texel 调试色覆盖。

改接口/改名 改动方式：LightMap.cpp 两处算法在 UE5 完全同构可照搬，但 UE5 的 GetLightMapColorLQ 改成 out 参数形式（LightmapCommon.ush:78），shader 侧必须改写。

代码脉络：宏=1 时 GenerateLightmapMipsAndDilateColor（LightMap.cpp:1099）在 mip 循环里按 MipIndex 覆盖纯色（XD 块 1162-1181）并在 1186 提前 return 跳过 dilate；EncodeCoefficientTexture（LightMap.cpp:1788/1790）在 1976 把 Mip0 写成 Red；MobileBasePassRendering.h:540 下发宏，LightmapCommon.ush:64-66 让 GetLightMapColorLQ 直接返回采样，MobileBasePassPixelShader.usf:701-716 用整像素覆盖+提前输出。

风险评估

原代码风险：调试用：纯色覆盖会污染 lightmap mip 数据并提前 return 跳过 dilate，只允许在离线调试构建打开。

移植风险：只影响移动端 LQ lightmap 着色与光照贴图 CPU 生成，改宏后需重跑光照并全量重编 shader。

开发自检

  • 宏=1 时低 mip 呈 Green/Blue/Cyan/Yellow/White，移动端收到的就是原始采样
  • 宏=0 时 lightmap 压缩、dilate 与 UE5 原生逐位一致
  • 宏=0 打包后 shader 组合数与 UE5 原生相同

结论置信度：medium — UE5 侧 shader 提前返回点是直改 GetLightMapColorLQ 还是另在 MobileBasePassPixelShader.usf:242 覆盖输出，观感等价性需人工确认。
