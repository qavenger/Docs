1. UE5 现状与证据

结论依据：UE5 ParticleSystemComponent.cpp:2207-2212 TickComponent 仅判 Template==nullptr||Emitters.Num()==0，无 !GetWorld() 早退；:2275 check(World) 会直接断言

2. 修改步骤（常开补丁）

  1. 在 UE5 上复核问题
    UE5 证据：UE5 ParticleSystemComponent.cpp:2207-2212 TickComponent 仅判 Template==nullptr||Emitters.Num()==0，无 !GetWorld() 早退；:2275 check(World) 会直接断言。先在 UE5 复现原问题；若已不存在，则按「删除」处理。
  2. 在 UE5 fork 重新应用补丁
    原实现位置：Source/Runtime/Engine/Private/Particles/ParticleComponents.cpp。引擎侧改动点：UParticleSystemComponent::TickComponent。补丁应保持最小范围，避免改公共接口。
  3. 登记为常开补丁
    在 Feature Registry 记录：问题、修法、验证方式、回滚方式；不再挂编译开关。

UE5 已覆盖UE5.8 原生等价，可直接删除

落地位置（工程化可行性）

可工程化放项目/插件/配置即可，不动引擎
需接入点引擎留少量 Hook，逻辑在工程侧
引擎内实现必须改引擎核心
—处置=删除的行不适用（已删除/不迁移）

引擎改动方式

L0 无需改引擎纯工程/插件/配置即可（对应「可工程化」）
L0 引擎内补丁需改引擎源码，但不必新增扩展点（对应「引擎内实现」）
L1 仅加接入点引擎只需暴露 Delegate / Interface / CVar 等扩展点
L2 结构性改动枚举 slot / 新 Pass / schema 字段
L3 深度侵入核心结构/生命周期/序列化，慎入

迁移处置

删除UE5 已覆盖，直接删

配置化改为 CVar / ini / DeviceProfile / 命令行
插件化迁到项目模块 / 编辑器插件
接入点引擎只留 Hook，逻辑在插件
移植代码保留，适配后移植
保留引擎深度绑定，暂留并登记 Feature Card
