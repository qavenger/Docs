修改草案 · XD_FIX_BUG_FReferencerFinder_GetAllReferencers_Crash

修复 FReferencerFinder::GetAllReferencers 崩溃（TORCHLIGHT-86072）

UE5 已覆盖 删除 引擎内实现 引擎内补丁 工作量 S风险 低开发者 Ran Qing Sen主要模块 CoreUObject

一句话结论：UE5 已修复。

0. 根因溯源（这个宏为什么存在）

上游缺陷（需上游修复或长期携带补丁）

结论：FReferencerFinder::GetAllReferencers(TSet) 的并行 lambda 里对 GUObjectArray 枚举对象时只判 ObjectItem.Object，未跳过已不可达/半析构对象，GC 期访问其引用即崩。XD 在 4.26 fork 参考上游补 !IsUnreachable() 并把 CollectReferences 包 FGCScopeGuard(TORCHLIGHT-86072)。

上游引入：上游缺陷，引入即 4.26 的 `if (ObjectItem.Object)`（4.26.0-release ReferencerFinder.cpp:104）。修复 5a1f877188e9（2021-09-22，francis hurteau，CL 17595028，JIRA UE-127091，'Skip unreachable objects when gathering references some might have been partially destroyed already'）。

上游历史（是否修过）：4.26/4.27 tag 仍为 `if (ObjectItem.Object)`；5.0.0-release 起为 `ObjectItem.Object && !ObjectItem.IsUnreachable()`（5.8.2:284，blame 该行末次为私有化重命名 ea180e097654，语义行始自 5a1f877188e9）。FGCScopeGuard 由 UE5 引用收集器重写 50944fd71202(2021-04-29) 带入，5.0.0:123、5.8.2:305 均在。ue5-main 未回退。

为什么可以断定不是「故意为之」4 条依据
  • XD 两处改动与上游 5a1f877188e9 语义逐字一致，属回填上游补丁而非 XD 需求。
  • UE5 同一文件两条枚举路径都加了该判定(5.8.2:203 与 :284)，说明 Epic 认为不可达对象必须跳过。
  • IsUnreachable 表示对象已进入 GC 待销毁队列，其成员/引用可能已析构，读取即悬垂，不可能是设计意图。
  • 上游提交信息明言 'partially destroyed already'。

调用方契约：编辑器事务/删除/重实例化调用：KismetReinstanceUtilities.cpp:193、ObjectTools.cpp:228/267/2760（UE5 同）。调用方期望返回真实引用目标集的对象列表。

内层真实语义：失败路径：不可达对象被塞入 ObjectsToSerialize，CollectReferences 遍历其 token 流崩溃；正常路径：可达对象照常返回。UE5 不可达直接 continue(5.8.2:284、:203)。

代码库惯例：同文件通用写法是先判 `!GetObject()||IsUnreachable()` 再取 Object(5.8.2:203)；自动生成 token 流的收集器必须在 FGCScopeGuard 内调用(5.8.2:305)。

为何长期未被发现：只在 GC/资源回收与 GetAllReferencers 并发时触发，需特定包重载路径；崩溃栈指向 GC 而非调用方。

XD 侧的做法与意图：4.26 fork Runtime/CoreUObject/Private/UObject/ReferencerFinder.cpp:104-135 用宏包住两处，默认 =1；配置 XDBuildFixBugConfiguration.cs:109。

只加 !IsUnreachable 漏 FGCScopeGuard（或反之）会留另一半崩溃；UE5 再包一层 #if 与 :203 的 continue 重复且无意义；不要用 GetObject()!=nullptr 替代 IsUnreachable。

迁移方案（按根因定）

删除宏与两处 #if，直接采用 5.8.2:283-307 原逻辑（含 :203 的 AsyncLoadingPhase1 过滤），无需移植。

根因级自检用例

  • 构造 GC 待销毁对象仍被引用时调用不崩且结果不含不可达对象
  • 正常可达引用仍正确返回(Kismet 重实例化)
  • 无引用/无对象时返回空而非崩溃
  • 并发收集路径(GAllowParallelReferenceCollection)无 FGCScopeGuard 缺失告警
