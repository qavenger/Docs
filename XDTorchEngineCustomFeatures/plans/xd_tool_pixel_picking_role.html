修改草案 · XD_TOOL_PIXEL_PICKING_ROLE

像素拾取角色功能（鼠标点选屏幕像素反查角色/物体）

未覆盖 插件化 需接入点 结构性改动 工作量 L风险 中开发者 Ran Qing Sen主要模块 Engine

一句话结论：渲染读回需少量引擎 hook，主体放项目插件。

⚠ 原宏备注：默认 0。用于编辑器/工具自动截取角色信息。

0. 根因溯源（这个宏为什么存在）

XD 定制需求（非上游缺陷）

结论：全链路自建：PlayerController.cpp:2065-2143 AddHitProxyQueryRequest → World.cpp:8065-8125 → SceneRendering.cpp:4022 → DeferredShadingRenderer.cpp:2357 ReadbackHitProxyIds；id 写入自建 GBufferD MRT（SceneRenderTargets.cpp:812，仅 XD_PC_RENDERING_CUSTOM_UNLIT 分支），经 FReadbackHitProxyManager 三缓冲回读。

上游引入：XD 定制（非 git）；XDBuildToolsConfiguration.cs:34 值=0；另给 FRHIGPUTextureReadback 加 Lock(uint32,int32&,int32&)（RHIGPUReadback.h:106，.cpp:169-188）。

上游历史（是否修过）：上游无此能力；UE5 5.8.2 只有编辑期 hit proxy，无运行期 GPU id 回读（rg HitProxyQuery/ReadbackHitProxy 在 Renderer/Engine 无命中）；RHIGPUReadback.h:160 已有 Lock(OutRowPitchInPixels, OutBufferHeight*) 等价语义，未修（也无需修）。

为什么可以断定不是「故意为之」4 条依据
  • 宏默认 0 未启用，是待验证功能
  • 自建 GBufferD MRT 与自定义 unlit 管线强耦合（SceneRenderTargets.cpp:812 在 XD_PC_RENDERING_CUSTOM_UNLIT 内），非上游设计
  • UE5 已提供等价 Lock(rowpitch,height)，重载多余
  • XD 未改 UE5 的 Render 签名接入点（DeferredShadingRenderer.cpp:1822 已变），本就依赖私有插入点

调用方契约：上层拾取依赖 QueriedHitProxyIds 映射（World.cpp:8065-8125）；PlayerController 提供请求入口。

内层真实语义：回读有三缓冲两帧延迟；宏=0 时全部路径不参与渲染，零影响。

代码库惯例：UE5 惯例是项目插件 FSceneViewExtension + AddReadbackTexturePass 自建 ID 通道，不改 base pass/GBuffer 布局。

为何长期未被发现：默认关，只有开启自定义管线的项目才触发；延迟两帧表现为拾取慢半拍，易误判为网络。

XD 侧的做法与意图：移动端运行期点击/触摸选物体（角色像素拾取）。

照搬 UE4 的 DeferredShadingRenderer 插入点会因 UE5 签名变化编译失败；继续改 base pass 输出布局会污染所有平台渲染。

迁移方案（按根因定）

推荐改项目插件 FSceneViewExtension::PrePostProcessPass_RenderThread + AddReadbackTexturePass 读自建 ID RT，不动 GBuffer/base pass；删原 Lock 重载，直接用 UE5 原生 Lock(RowPitch,Height)。

根因级自检用例

  • 拾取命中 id 正确
  • 两帧延迟量可接受
  • 宏=0 零渲染开销
  • 多平台不崩
  • 插件卸载无残留 RT

覆盖说明：UE5 有读回原语但无角色像素拾取

风险评估

原代码风险：自建 GBufferD MRT 与自定义 unlit 管线耦合（SceneRenderTargets.cpp:812 在 XD_PC_RENDERING_CUSTOM_UNLIT 内），base pass 输出布局被改，且三缓冲读回有两帧延迟。

移植风险：涉及 RHI/Renderer/Engine/UMG/shader 五处；宏默认 0（未启用），改 base pass 会波及所有平台渲染，回归面大。

开发自检

  • 宏=0 时编译与运行与 UE5 原生一致
  • 同屏 100 个角色点击拾取命中正确 primitive
  • PC DX12 与 Android Vulkan 各验证读回延迟与结果

结论置信度：low — UE5.8 GBuffer 布局（FGBufferBinding/FSceneTextures）与移动端 stencil 位分配需人工确认；建议按 disposition=plugin 只保留读回原语，ID 通道走项目自建 RT。
