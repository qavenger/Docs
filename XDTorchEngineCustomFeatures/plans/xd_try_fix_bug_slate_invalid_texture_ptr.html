尝试修复 Slate 纹理指针失效导致的崩溃（UE4-4846）

部分覆盖 常开补丁 引擎内实现 仅加接入点 工作量 M风险 中开发者 Ran Qing Sen主要模块 Slate

一句话结论：崩溃多与 GC 竞态相关，先在 UE5 复现再决定补丁（UE4-4846）。

2. 修改步骤（常开补丁）

  1. 在 UE5 上复核问题
    UE5 证据：Runtime/SlateRHIRenderer/Private/SlateMaterialResource.cpp:15-48 CheckInvalidUMaterial/CheckInvalidMaterialProxy、:263 checkf("Material %s has become invalid" with DebugName)；SlateRHIResourceManager.cpp:68 ReleaseTextureAtlases(..., bWaitForRelease)，:774-846 资源有效性检查。先在 UE5 复现原问题；若已不存在，则按「删除」处理。
  2. 在 UE5 fork 重新应用补丁
    原实现位置：Source/Runtime/SlateRHIRenderer/Private/SlateRHIResourceManager.cpp。引擎侧改动点：FSlateRHIResourceManager 资源释放时机、FSlateMaterialResource 有效性检查。补丁应保持最小范围，避免改公共接口。
  3. 登记为常开补丁
    在 Feature Registry 记录：问题、修法、验证方式、回滚方式；不再挂编译开关。

风险评估

原代码风险：未判空直接解引用回收资源，GC/资源释放竞态下可能空指针崩溃(UE4-4846)；该分支本身无锁保护。

移植风险：若 UE5 已保证 free list 只含有效指针，则该补丁为冗余防御；若因引用计数问题放入空指针仍会崩，需在 UE5 先复现 UE4-4846。

开发自检

  • UE5 下反复刷 UI 贴图不崩
  • 确认 UTextureFreeList 未被放入空 shared_ptr

结论置信度：medium — UE5 是否仍存在空纹理指针路径需复现 UE4-4846；无法复现则可改为 abandon
