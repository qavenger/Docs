修改草案 · XD_TOOL_MEMORY_DEBUG_FORCE_ANSIC_MALLOC

强制使用 ANSI C malloc（配合 Perfetto 排查内存泄漏，当前关闭）

UE5 已覆盖 删除 可工程化 无需改引擎 工作量 S风险 低开发者 Ran Qing Sen主要模块 Core

一句话结论：改用 UE5 原生 -ansimalloc

0. 根因溯源（这个宏为什么存在）

平台/工具链绕行

结论：在 5 个平台 BaseAllocator 里加宏，在 UE_BUILD_DEBUG 下无条件改用 FMallocAnsi，省去命令行参数，供 Perfetto 采样 malloc。值=0（默认关）。

上游引入：XD 定制（非 git）；XDBuildToolsConfiguration.cs:64 值=0；改点 WindowsPlatformMemory.cpp:168、Unix:257、Mac:131、Apple:500、Android:505（直接 return new FMallocAnsi）。

上游历史（是否修过）：上游无此宏；UE4 已有原生 -ansimalloc（WindowsPlatformMemory.cpp:130）与 FORCE_ANSI_ALLOCATOR（:99）；UE5 5.8.2 保留 -ansimalloc（:181）与 FORCE_ANSI_ALLOCATOR（Windows:145 / Android:467），未移除。

为什么可以断定不是「故意为之」4 条依据
  • 若平台必须应写 constexpr，而非默认 0 的可关宏
  • 原生 -ansimalloc 已覆盖同需求，宏属冗余
  • 用 #if ... && UE_BUILD_DEBUG 限死调试，是一次性排障便利
  • 无任何运行时/资产依赖该分配器类型

调用方契约：仅影响 FPlatformMemory::BaseAllocator 返回值；Perfetto 抓栈脚本隐性依赖。

内层真实语义：Ansi 分配无池化/对齐优化，内存与性能明显劣化；非 DEBUG 或宏=0 时完全走原生分支。

代码库惯例：UE5 惯例用 FORCE_ANSI_ALLOCATOR 编译宏或 -ansimalloc 命令行（WindowsPlatformMemory.cpp:145/181）。

为何长期未被发现：只在 UE_BUILD_DEBUG 生效，不影响出货包，长期无人关注。

XD 侧的做法与意图：调试构建免加命令行即得 Perfetto malloc 栈。

误删后忘用 -ansimalloc，Perfetto 堆栈变成 Binned/Mimalloc 内部帧，误以为内存 bug 消失。

迁移方案（按根因定）

删除 5 处宏，改用 -ansimalloc；Android 无命令行则用 FORCE_ANSI_ALLOCATOR=1；或保留宏作为 DEBUG 别名但桥接到 FORCE_ANSI_ALLOCATOR。

根因级自检用例

  • DEBUG 下 -ansimalloc 生效
  • FORCE_ANSI_ALLOCATOR 在 Android 生效
  • 非 DEBUG 不强制
  • Perfetto 栈含 malloc
  • 关宏后回到 Mimalloc/Binned

3. 代码级实现（开发用）

独立 Agent 审核通过

审核意见：核实: 5 个平台行号精确（WindowsPlatformMemory.cpp:168、Unix:257、Mac:131、Apple:500、Android:505 且 Android 为 return new FMallocAnsi()），宏 .cs:64 值=0；UE5 Windows :145 FORCE_ANSI_ALLOCATOR、:181-184 -ansimalloc，Android :467-469 FORCE_ANSI_ALLOCATOR 均在。abandon 成立。改进: draft note ':166-184' 实际 #if !UE_BUILD_SHIPPING 在 :

建议舍弃 改动方式：UE5 已有原生命令行/构建开关等价物（-ansimalloc、FORCE_ANSI_ALLOCATOR），宏无必要。

代码脉络：值=0，且需 UE_BUILD_DEBUG。5 个平台内存模块在 BaseAllocator 里把 AllocatorToUse 强制成 Ansi：Runtime/Core/Private/Windows/WindowsPlatformMemory.cpp:168、Unix/UnixPlatformMemory.cpp:257、Mac/MacPlatformMemory.cpp:131、Apple/ApplePlatformMemory.cpp:500（均为 `= EMemoryAllocatorToUse::Ansi`），Android/AndroidPlatformMemory.cpp:505 直接 `return new FMallocAnsi()`。

步骤 1Source/Runtime/Core/Private/Windows/WindowsPlatformMemory.cppUE4:168-170 → UE5:181-184（同文件 FWindowsPlatformMemory::BaseAllocator）

删除 XD 宏块，改用 UE5 内置命令行开关

#if XD_TOOL_MEMORY_DEBUG_FORCE_ANSIC_MALLOC && UE_BUILD_DEBUG
    AllocatorToUse = EMemoryAllocatorToUse::Ansi;
#endif
else if (FCString::Stristr(CommandLine, TEXT("-ansimalloc")))
{
	// see FPlatformMisc::GetProcessDiagnostics()
	AllocatorToUse = EMemoryAllocatorToUse::Ansi;
}

⚠ UE5 WindowsPlatformMemory.cpp:145 还有 FORCE_ANSI_ALLOCATOR 编译分支；-ansimalloc 解析在 !UE_BUILD_SHIPPING 内(:166-184)，调试包可用

步骤 2Source/Runtime/Core/Private/Android/AndroidPlatformMemory.cppUE4:505-507（FAndroidPlatformMemory::BaseAllocator）→ UE5:467-469

Android 无命令行，改用 FORCE_ANSI_ALLOCATOR 编译宏

#if XD_TOOL_MEMORY_DEBUG_FORCE_ANSIC_MALLOC && UE_BUILD_DEBUG
    return new FMallocAnsi();
#endif
#if FORCE_ANSI_ALLOCATOR
	return (Instance = new FMallocAnsi());
#endif

⚠ UE5 Android 另有 configrule malloctype=ansi/mimalloc 路径(AndroidPlatformMemory.cpp:472)；Unix/Mac/Apple 三个文件的 XD 块同法删除，对应 UE5 已有 FORCE_ANSI_ALLOCATOR 与 UE4_FORCE_MALLOC_ANSI 环境变量

风险评估

原代码风险：把 Ansi 分配器作为默认会让内存占用/性能显著劣化（无 pool/无对齐优化），所以只能 UE_BUILD_DEBUG 生效；Perfetto 抓 malloc 时需要它。

移植风险：无需移植；若误删后忘了用 -ansimalloc，Perfetto 的 malloc 堆栈会变成 Binned/Mimalloc 内部帧，需要重新确认抓取流程。

开发自检

  • Windows 上 -ansimalloc 启动后 log 显示 Ansi 分配器
  • Android 以 FORCE_ANSI_ALLOCATOR 构建后 malloc 栈含 libc malloc

结论置信度：high — Android/主机平台仍需要『无命令行强制 Ansi』时需在 Target.cs 里显式加 FORCE_ANSI_ALLOCATOR 定义，需人工确认是否有该构建项。
