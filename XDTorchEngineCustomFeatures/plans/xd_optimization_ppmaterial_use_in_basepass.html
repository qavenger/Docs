修改草案 · XD_OPTIMIZATION_PPMATERIAL_USE_IN_BASEPASS

暴露接口控制是否为 Mobile BasePass 编译 PostProcess 材质变体

部分覆盖 移植 引擎内实现 结构性改动 工作量 M风险 高开发者 Liu Xing Kui主要模块 Engine

一句话结论：新增材料枚举会影响材质序列化与 Cook 结果一致性；若项目已无 PP 材质进移动 BasePass 的需求可评估直接丢弃

背景：减少移动端着色器变体数量，缩短编译与包体大小。

1. UE5 现状与证据

结论依据：UE5 MATUSAGE 枚举无 PPMaterialBasePassPermutation（Engine/Public/Materials/MaterialInterface.h:79-113）；Runtime/Engine/Private/Materials/HLSLMaterialTranslator.cpp:8326-8332（移动端着色下 PP 材质不可访问 GBuffer 场景纹理，引擎侧已有约束）；Runtime/Renderer/Private/PostProcess/PostProcessMaterial.cpp:250-257（MD_PostProcess 材质单独编译）

覆盖说明：UE5 通过移动端着色路径约束与 MD_PostProcess 分支部分达到目的，但无 XD 的材质级开关

  1. 定位 UE5 对应文件

  2. 移植实现

3. 代码级实现（开发用）

完全重构 改动方式：UE5 移动 BasePass 策略仍在但枚举/位域/映射位置全变，须按新结构重建。

static bool ShouldCompilePostProcessBasePassPermutation(const FMeshMaterialShaderPermutationParameters& Parameters)
{
	if (Parameters.MaterialParameters.MaterialDomain == MD_PostProcess && !Parameters.MaterialParameters.bIsUsedWithPPMaterialBasePassPermutation)
		return false;
	return true;
}
// UE5 MobileBasePassRendering.h：TMobileBasePassVS/PS::ShouldCompilePermutation 首行
if (P.MaterialParameters.MaterialDomain == EMaterialDomain::MD_PostProcess
	&& !P.MaterialParameters.bIsUsedWithPPMaterialBasePassPermutation) return false;

⚠ 只裁 MobileBasePass，勿动 PostProcessMaterial.cpp:244 与延迟路径

风险评估

原代码风险：属性默认 true 才编译；材质域误设 MD_PostProcess 会静默少编译变体，运行时回退默认材质。

移植风险：新增枚举位改变材质序列化/DDC，Cook 与非 Cook 一致性风险高。

开发自检

  • 移动 BasePass PS/VS 变体数下降
  • PP 材质移动后处理仍正常(PostProcessMaterial.cpp:416)

结论置信度：medium — UE5 是否仍为 MD_PostProcess 编译 MobileBasePass 变体未实测，建议先 stat shaders 采样再决定是否值得移植。
