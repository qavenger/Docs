修改草案 · XD_TOOL_GET_RESOLUTIONS_FROM_SPECIFIED_MONITOR_ID

获取指定显示器支持的全屏分辨率列表

UE5 已覆盖 删除 可工程化 仅加接入点 工作量 S风险 低开发者 Han Shu Bin主要模块 RHI-PC

一句话结论：UE5 已覆盖，直接删除

0. 根因溯源（这个宏为什么存在）

上游缺失能力（UE5 可能已补）

结论：上游 RHIGetAvailableResolutions 只按当前输出取分辨率，XD 增加 3 参重载以便按指定 output 取某台显示器全屏分辨率（逐 output 调 GetDisplayModeList 慢）。UE5 改为 RHIGetAvailableResolutionsForDisplay(Resolutions,bIgnore,void* NativeMonitorHandle)，以句柄而非索引定位监视器，XD 需求被原生覆盖。

上游引入：XD 定制。UE4 fork：DynamicRHI.h:1238 虚接口、:1806 inline，D3D11 实现 WindowsD3D11Device.cpp:2246、D3D12 实现 WindowsD3D12Device.cpp:1089，调用点 WindowsD3D11Device.cpp:2689；配置 XDBuildToolsConfiguration.cs:142=1。

上游历史（是否修过）：上游以新接口解决同类问题：UE5 DynamicRHI.h:733 声明 RHIGetAvailableResolutionsForDisplay(...,void* NativeMonitorHandle)，:1306/:1308 转发，D3D11 实现 WindowsD3D11Device.cpp:1724、D3D12 实现 WindowsD3D12Device.cpp:2215，调用点 SceneViewport.cpp:1636 传 Monitor.NativeHandle。

为什么可以断定不是「故意为之」3 条依据
  • UE5 有等价且更稳的句柄版本，说明按索引旧做法已被上游取代
  • XD 重载仅 D3D11/D3D12 两分支实现，是绕行而非通用设计
  • 以 output 索引定位显示器在 adapter reset 后不稳定，属缺陷性设计

调用方契约：XD 的 UI/分辨率枚举路径按 SpecifiedOutputIndex 取某显示器分辨率（UE4 fork WindowsD3D11Device.cpp:2689 调用）；UE5 内无该重载调用方。

内层真实语义：索引越界或 GetDisplayModeList 失败时返回 false/空表（慢调用，源码自述可达约 1 秒），不抛异常。

代码库惯例：UE5 统一以 void* NativeHandle 标识监视器，见 SceneViewport.cpp:1636 与 DynamicRHI.h:733。

为何长期未被发现：慢调用只在启动枚举分辨率时出现，偶发卡顿难归因；返回空表时上层静默降级。

XD 侧的做法与意图：UE4 fork WindowsD3D11Device.cpp:2246 按 output 索引取分辨率，意图让每台显示器显示各自可用分辨率。

在 UE5 上保留/重造 index 重载是看似省事的错法：output 索引在换显卡、重置 adapter 后会错位。删除时须同时清掉 D3D11RHIPrivate.h:300、D3D12RHIPrivate.h:420 的 override 及全部调用点，否则虚表不匹配/链接失败。

迁移方案（按根因定）

直接删宏。调用点改用 RHIGetAvailableResolutionsForDisplay(..., MonitorInfo.NativeHandle)（参照 SceneViewport.cpp:1636）。不要在 UE5 重造索引版。

根因级自检用例

  • 删宏后全仓无 RHIGetAvailableResolutions(*,*,int32) 引用且编译链接通过
  • 多显示器分别取到正确分辨率（用 NativeHandle 验证）
  • NativeHandle 失效时安全返回 false/空表
  • 切换/重置显卡后结果不串屏

3. 代码级实现（开发用）

独立 Agent 审核通过

审核意见：abandon 与全部锚点核实通过：UE4 DynamicRHI.h:1238-1240 三参重载 / :1806-1808 inline、WindowsD3D11Device.cpp:2246 实现 / :2689 调用、WindowsD3D12Device.cpp:1089；UE5 DynamicRHI.h:733 RHIGetAvailableResolutionsForDisplay + :1306 全局包装、D3D11 实现 :1724、D3D12 实现 :2215、FMonitorInfo::NativeHandle(GenericApplication.h:357) 均在，替换语

建议舍弃 改动方式：UE5 已原生提供按显示器句柄取分辨率的 RHIGetAvailableResolutionsForDisplay(NativeMonitorHandle)，并带 D3D11/D3D12 实现，XD 的按 output 序号版本冗余。

代码脉络：宏=1 给 IRHI 增加 3 参重载 RHIGetAvailableResolutions(Resolutions,bIgnore,SpecifiedOutputIndex)（Runtime/RHI/Public/DynamicRHI.h:1238，inline :1806），D3D11 按 output 索引实现于 WindowsD3D11Device.cpp:2246，D3D12 见 WindowsD3D12Device.cpp:1089；显示器枚举处调用点 WindowsD3D11Device.cpp:2689。

步骤 1Runtime/RHI/Public/DynamicRHI.hUE5 DynamicRHI.h:733

不移植 XD 3 参重载，调用方改用 UE5 新接口

#if XD_TOOL_GET_RESOLUTIONS_FROM_SPECIFIED_MONITOR_ID
virtual bool RHIGetAvailableResolutions(FScreenResolutionArray& Resolutions, bool bIgnoreRefreshRate, int32 SpecifiedOutputIndex){ return RHIGetAvailableResolutions(Resolutions,bIgnoreRefreshRate); }
#endif
// 直接用 UE5 现有声明（无需新增）
virtual bool RHIGetAvailableResolutionsForDisplay(FScreenResolutionArray& Resolutions, bool bIgnoreRefreshRate, void* NativeMonitorHandle) { return RHIGetAvailableResolutions(Resolutions, bIgnoreRefreshRate); }

⚠ UE5 实现见 WindowsD3D11Device.cpp:1724、WindowsD3D12Device.cpp:2215

步骤 2Runtime/Windows/D3D11RHI/Private/Windows/WindowsD3D11Device.cppUE4:2245-2428 实现 / :2689 调用

删除 XD 的按索引用 GetDisplayModeList 的实现，调用点改传显示器 NativeHandle

#if XD_TOOL_GET_RESOLUTIONS_FROM_SPECIFIED_MONITOR_ID
RHIGetAvailableResolutions(MonitorInfo.FullScreenResolutions, true, CurrentOutput);
#endif
// 不再需要 XD 重载，NativeHandle 来自 UE5 FMonitorInfo
RHIGetAvailableResolutionsForDisplay(MonitorInfo.FullScreenResolutions, true, MonitorInfo.NativeHandle);

⚠ FMonitorInfo::NativeHandle 见 ApplicationCore/Public/GenericPlatform/GenericApplication.h:357；WindowsD3D12Device.cpp 同步删除

风险评估

原代码风险：每 output 调用 GetDisplayModeList 是慢调用（源码自述可达 1 秒），可能造成启动卡顿。

移植风险：删除的是 RHI 公开虚函数，需清理 D3D11RHIPrivate.h:526/D3D12RHIPrivate.h:368 的 override 及所有调用点，否则链接失败。

开发自检

  • 多显示器下按指定显示器返回其支持分辨率列表
  • 删除后 IRHI 无残留 3 参重载引用，全平台编译通过

结论置信度：high
