iOS 使用 _Exit(0) 直接结束进程

部分覆盖 移植 引擎内实现 仅加接入点 工作量 S风险 低开发者 Ran Qing Sen主要模块 Core

一句话结论：若仍有退出卡死则保留 _Exit(0) 补丁

1. UE5 现状与证据

结论依据：Runtime/Core/Private/IOS/IOSPlatformMisc.cpp:2255 Force 路径委托 FApplePlatformMisc::RequestExit，不再直接 _Exit(0)

覆盖说明：退出路径重构，行为是否等价待实测

2. 修改步骤（移植）

  1. 定位 UE5 对应文件
    见下方「UE5 对应文件」；重点比对同文件在 UE4/UE5 的差异。
  2. 移植实现

3. 代码级实现（开发用）

待独立 Agent 审核该草案尚未进入审核轮次：审核会打开 UE5 源码逐条核对行号、函数与 after 代码 引用的 API 是否存在。

完全重构 改动方式：UE5 退出 API 改为 (Force,CallSite) 并委托基类，需在新结构中重新插入 _Exit(0) 分支。

代码脉络：UE4 IOSPlatformMisc.cpp:1737-1745 在 RequestExit(bool Force) 的 Force 分支用 #if 宏切到 _Exit(0)（跳过崩溃上报，直接结束进程）。UE5 IOSPlatformMisc.cpp:2255 已重构为 RequestExit(bool Force, const TCHAR* CallSite)，Force 时 :2268 委托 FApplePlatformMisc::RequestExit(进而 abort)，一参重载已删除。

步骤 1D:/Torchlight/frontend/trunk/Editor/Engine/Source/Programs/UnrealBuildTool/Configuration/XDBuildConfiguration/XDBuildMiscConfiguration.csXDBuildMiscConfiguration.cs:158

保留宏定义(值 1)并注入全局宏。

public static int XD_MISC_IOS_REQUEST_EXIT_BY_FORCE = 1;
// Target.cs: GlobalDefinitions.Add("XD_MISC_IOS_REQUEST_EXIT_BY_FORCE=1");

⚠ 仅 iOS 生效，建议在 iOS 平台规则里注入。

步骤 2E:/TorchLight_UE5/Engine/Engine/Source/Runtime/Core/Private/IOS/IOSPlatformMisc.cppIOSPlatformMisc.cpp:2266-2269

在 Force 分支按宏改调 _Exit(0)，保留 else 的 ForceExit 行为。

if (Force)
{
	FApplePlatformMisc::RequestExit(Force, CallSite);
}
else
{
	[[IOSAppDelegate GetDelegate] ForceExit];
}
if (Force)
{
#if XD_MISC_IOS_REQUEST_EXIT_BY_FORCE
	_Exit(0); // 直接结束进程，不走 CrashReporter
#else
	FApplePlatformMisc::RequestExit(Force, CallSite);
#endif
}
else
{
	[[IOSAppDelegate GetDelegate] ForceExit];
}

⚠ _Exit 已在 UE5 IOSPlatformMisc.cpp:134/:2031 使用（<unistd.h> 可用）；注意与 XD_MISC_IOS_EXIT_WITH_ABORT_METHOD 语义相反，勿同时作用于同一退出点。

风险评估

原代码风险：_Exit(0) 跳过 flush/析构，可能丢日志；仅用于卡死兜底。

移植风险：会让 iOS 主动退出不产生崩溃记录，与 abort 宏冲突，需明确优先级。

开发自检

  • iOS 主动退出无崩溃上报且进程立即结束
  • 卡死场景退出成功

结论置信度：medium — UE5 是否仍需该补丁取决于 UE5 原生退出是否卡死，建议真机实测后再决定保留。
