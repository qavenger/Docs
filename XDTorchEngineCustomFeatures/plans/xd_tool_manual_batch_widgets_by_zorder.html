修改草案 · XD_TOOL_MANUAL_BATCH_WIDGETS_BY_ZORDER

按 ZOrder 手动合批 Slate/UMG 控件（可配置分组规则）

UE5 已覆盖 删除 可工程化 仅加接入点 工作量 M风险 中开发者 Ran Qing Sen主要模块 Slate

一句话结论：UE5 已原生覆盖，删除宏；项目在 DefaultEngine.ini 启用 bExplicitCanvasChildZOrder 即可

背景：为绘制批次提供手动合批策略，减少 UI DrawCall，是 UI 性能优化工具。

0. 根因溯源（这个宏为什么存在）

XD 定制需求（非上游缺陷）

结论：在 UE4 给 SConstraintCanvas 加运行时 CVar r.Mobile.EnableManualBatchWidgetsByZOrders + UCanvasPanel 的 bIsBatchChildren/BatchChildredZOrders 白名单，让指定 ZOrder 子项进入同层以便 Slate 合批，避免全局开 bExplicitChildZOrder 波及所有画布。

上游引入：XD 定制（UE4 fork 非 git 仓库，无提交号）；XDBuildToolsConfiguration.cs:25 值=1；CVar 定义 XDConsoleVariables.inc:12-19。

上游历史（是否修过）：上游无此宏；UE5 5.8.2 SConstraintCanvas.cpp:218/220/294 只读 USlateSettings::bExplicitCanvasChildZOrder（SlateSettings.cpp:13 默认 false），无 CVar/白名单，未修也无需修。

为什么可以断定不是「故意为之」4 条依据
  • UE5 注释明确该行为应由 Project setting 决定，XD 的 CVar 是额外私有分支
  • XD 自设 CVar 默认 0（XDConsoleVariables.inc:14），是实验灰度而非既定语义
  • UCanvasPanel 新字段默认 false（CanvasPanel.cpp:16），不改存量资产
  • UE5 用 const static 缓存设置，XD 每次 Arrange 查 CVar，属临时旁路写法

调用方契约：CanvasPanel.cpp:122-123 SynchronizeProperties 把 bIsBatchChildren/BatchChildredZOrders 灌给 SConstraintCanvas（SConstraintCanvas.h:151-152）；无第三方依赖。

内层真实语义：仅 bExplicitChildZOrder && bIsBatchChildren && 白名单含 ZOrder 时走同层分支（SConstraintCanvas.cpp:180-183）；否则回退全局 bExplicitChildZOrder，不改层序。

代码库惯例：UE5 惯例用 UDeveloperSettings（USlateSettings，SlateSettings.h:25）暴露此类全局开关，而非散落 TAutoConsoleVariable。

为何长期未被发现：CVar 默认 0 且仅移动端手动开；合批错误表现为 UI 遮挡/闪烁，难归因到 Slate。

XD 侧的做法与意图：移动端 DrawCall 优化，逐画布灰度以降低回归风险。

直接删宏却忘记在项目 Config 打开 bExplicitCanvasChildZOrder，会静默丢失合批收益（性能回退）而非报错；反之全局打开会改变所有 ConstraintCanvas 层序。

迁移方案（按根因定）

删除宏块，改用 [/Script/Slate.SlateSettings] bExplicitCanvasChildZOrder=True（DefaultEngine.ini）；若需逐画布控制保留 CVar 但桥接到 USlateSettings。优先原生设置。

根因级自检用例

  • 白名单命中项同层
  • 未命中项保持独立层
  • CVar=0/设置关等于上游
  • 开启后遮挡回归
  • 打包后设置生效

风险评估

原代码风险：CVar 每次 Arrange 查询、静态成员在新实例可能未初始化；白名单与全局 ZOrder 混用易出现绘制顺序错乱。

移植风险：UE5 只有全局开关，白名单粒度丢失；开启后所有 ConstraintCanvas 子项按 ZOrder 可能改变层序，需回归 UI 遮挡关系。

开发自检

  • UI 遮挡顺序与 UE4 一致
  • DrawCall/合批数与预期相符

结论置信度：medium — 项目是否需要“仅部分面板合批”的白名单行为，全局开关是否可接受
