采集 Lua 内存统计（供 MemReport 展示）

未覆盖 插件化 可工程化 仅加接入点 工作量 M风险 低开发者 Zhao Shuai Nan主要模块 仅定义（无引用）

一句话结论：Lua 内存统计迁到项目 Lua 插件

1. UE5 现状与证据

结论依据：UE5 无内置 Lua，无对应实现

覆盖说明：依赖项目 Lua 方案

覆盖度：未覆盖  处置：插件化

2. 修改步骤（插件化）

  1. 确定插件/模块归属
    项目 UnLua/Lua 插件向 MemReport 注册自定义段落
  2. 实现主体逻辑
    把原引擎内实现迁到插件：（无源码引用记录）。引擎侧只保留必要接口/事件。
  3. 模块与构建规则
    Editor 工具放 Editor 模块（Shipping 自动剔除）；运行时逻辑放 Runtime 模块；如需引擎接口，见「引擎改动」列。

3. 代码级实现（开发用）

待独立 Agent 审核该草案尚未进入审核轮次：审核会打开 UE5 源码逐条核对行号、函数与 after 代码 引用的 API 是否存在。

简单移植 改动方式：引擎侧本来无实现，UE5 仍是『注册 Exec 命令 + MemReport ini 段落』同一机制，只需重注册开关并在项目插件侧重建命令。

代码脉络：仅配置开关，无源码引用：UE4 全树只有 XDBuildMiscConfiguration.cs:352 的定义（另 :534 与 XD_MISC_COLLECT_PARTICLE_MEM_FROM_STAT 做依赖校验），引擎无任何 #if；实际由项目 Lua/UnLua 侧读该宏在 MemReport 里挂自定义段落。

步骤 2Runtime/Engine/Private/UnrealEngine.cppUE4:6942 GConfig->GetSectionPrivate(TEXT("MemReportCommands")) → UE5:8191/8233

项目 ini 与命令注册改成 UE5 的 Cmd= 数组形式

FConfigSection* CommandsToRun = GConfig->GetSectionPrivate(TEXT("MemReportCommands"), 0, 1, GEngineIni);  // UE4:6942
// UE5: const FString SectionToRead = FString::Format(TEXT("MemReport{0}Commands"), { InTypeName });  // :8191
GConfig->GetArray(*SectionToRead, TEXT("Cmd"), CommandsToRun, GEngineIni);  // :8233
// DefaultEngine.ini: [MemReportCommands] +Cmd=UnLua.MemReport

⚠ 段落由 Key=Value 改为 Cmd=/File= 数组；Lua 内存统计命令本体在 UnLua 插件里实现（引擎不 제공）。

风险评估

原代码风险：无源码，仅配置文件级风险；宏与 XD_MISC_MEMREPORT_TIMER 有隐式依赖约束。

移植风险：若 ini 未按 UE5 新格式迁移，段落静默不执行、MemReport 中看不到 Lua 内存项。

开发自检

  • 执行 MemReportDeferred 后报告里出现 Lua 内存段落
  • 确认 [MemReportCommands] 的 Cmd= 数组被读取（UE5 日志 MemReport: Begin command）

结论置信度：medium — 项目 UnLua 插件里该段落的具体实现不在本引擎树内，需与项目侧确认是否已迁到 UE5 的 Lua 方案。
