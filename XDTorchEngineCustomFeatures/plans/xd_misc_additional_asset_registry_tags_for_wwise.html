3. 代码级实现（开发用）

独立 Agent 审核并修正修正 2 处　提出问题 3 条

审核意见：核心结论『引擎侧零引用、UE5 改名 bUseAssetRegistryTagsAllowListInsteadOfDenyList 而 ini key 不变、读取点 :1240/:1244/:1248、ParseFilterTags :1299 语法 (Class=..,Tag=..)』全部核实无误；问题集中在 step1 的伪造 before 与文件错位。

建议舍弃 改动方式：引擎侧零引用，需求可由 ini 标签白/黑名单 + Wwise 集成插件打标签覆盖，且该选项在 UE5 已改名。

代码脉络：仅配置开关，无源码引用（全 Source grep 只有定义 XDBuildMiscConfiguration.cs:270；UE4 侧唯一相关机制是 AssetRegistryState.h:36 的 bUseAssetRegistryTagsWhitelistInsteadOfBlacklist 与 AssetRegistry.cpp:381-394 从 Engine ini 读 CookedTagsWhitelist/CookedTagsBlacklist）。

步骤 1Runtime/AssetRegistry/Private/AssetRegistry.cppUE4 :381 → UE5 :1240

不迁移宏；改用 UE5 ini 配置（字段改名，ini key 未变）

// UE4 AssetRegistry.cpp:381
EngineIni->GetBool(TEXT("AssetRegistry"), TEXT("bUseAssetRegistryTagsWhitelistInsteadOfBlacklist"), Options.bUseAssetRegistryTagsWhitelistInsteadOfBlacklist);
// UE5 AssetRegistry.cpp:1240 —— 字段已改名 bUseAssetRegistryTagsAllowListInsteadOfDenyList，ini key 不变
// DefaultEngine.ini：
[AssetRegistry]
bUseAssetRegistryTagsWhitelistInsteadOfBlacklist=True
+CookedTagsWhitelist=(Class=AkAudioEvent,Tag=SomeTag)
// 语法见 UE5 AssetRegistry.cpp:1299 ParseFilterTags（"(Class=SomeClass,Tag=SomeTag)"）

⚠ UE5 的 CookedTagsWhitelist/Blacklist 读取点仍在 :1244/:1248；白名单只能保留已存在的 Tag，不能凭空造 Tag。

步骤 2Runtime/AssetRegistry/Private/AssetRegistry.cpp（仅作为『过滤规则由此处消费』的参照）；实际改动落点在 Wwise 集成插件的 Ak* 类 GetAssetRegistryTags，应改标为项目插件文件。UE4 AssetRegistryState.cpp:228 / UE5 AssetRegistryState 过滤实现

确认 Wwise 类（Ak*）的 Tag 由 Wwise 插件在 GetAssetRegistryTags 中补齐，不要在引擎里加特判

// UE4 无对应引擎源码（该宏在引擎 Source 中零引用，仅 UBT 开关 XDBuildMiscConfiguration.cs:270）；本 step 无 before 可引用，应删除 before 字段或留空。
// 项目插件（Wwise 集成）：
void UAkAssetBase::GetAssetRegistryTags(FAssetRegistryTagsContext Context) const
{
    Super::GetAssetRegistryTags(Context);
    Context.AddTag(FAssetRegistryTag(TEXT("AkAssetType"), GetAkAssetTypeName(), FAssetRegistryTag::TT_Alphabetical));
}

⚠ Tag 必须由类自己上报；引擎侧白名单只负责不裁掉它。

风险评估

⚠ 与早期迁移处置结论存在分歧：早期结论=要移植，代码级分析=建议舍弃。早期结论=插件化，代码级分析=建议舍弃；建议以代码级分析为准并回写评估矩阵。

原代码风险：宏开启时若与 XD_MISC_WWISE_ASSET_REGISTRY_FREE（XDBuildMiscConfiguration.cs:266）同时生效，两个相反意图（加 Tag / 让资产脱离 AR）可能互相抵消，仅靠 ini 时不易排查。

移植风险：改为纯 ini 后，如果忘了配 CookedTagsWhitelist，Wwise Tag 会在 cook 的 AR 中被裁掉，导致的只是资产搜索/分包失效，不致命但回归成本高。

开发自检

  • 打包后打开 cooked AssetRegistry，确认 Ak* 资产的 Tag 仍可被搜索/命中同一分包
  • 确认 XD_MISC_WWISE_ASSET_REGISTRY_FREE 与新 ini 配置不冲突

结论置信度：medium — 原宏真正的生效点在 Wwise 项目插件（不在引擎源码内），需项目侧确认插件里是否已有对应的 GetAssetRegistryTags 实现。
