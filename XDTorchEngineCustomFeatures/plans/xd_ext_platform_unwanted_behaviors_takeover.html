修改草案 · XD_EXT_PLATFORM_UNWANTED_BEHAVIORS_TAKEOVER

平台级不希望的行为接管（弹窗、退出请求等，Android 优先）

未覆盖 接入点 需接入点 仅加接入点 工作量 M风险 中开发者 Gong Bai Liang主要模块 RHI-Mobile

一句话结论：平台级行为接管，PC 组影响小，优先移动端

1. UE5 现状与证据

结论依据：UE5 无对应接管机制（AndroidPlatformMisc::MessageBoxExt/RequestExit 无 shipping 接管）

覆盖说明：Android/iOS 为主

覆盖度：未覆盖  处置：接入点

2. 修改步骤（接入点）

  1. 引擎侧只加接入点
    需要的接入点：FAndroidMisc/GenericPlatformMisc::MessageBoxExt、FPlatformMisc::RequestExit（机制：Interface）。引擎改动应最小、稳定、无业务语义。
  2. 插件侧实现完整逻辑
    项目模块包装/重写平台弹窗与 RequestExit 等行为
  3. 无插件时的行为
    未绑定接入点时应回退到官方默认行为（引擎侧不能假设插件存在）。

3. 代码级实现（开发用）

风险评估

原代码风险：shipping 下所有平台弹窗被吞，仅留日志，会隐藏关键错误（如存档损坏）。

移植风险：宏还门控 VulkanRHI/OpenGL 30+ 处，需连同 XD_EXT_ANDROID_VULKAN_ENHENCED_SELF_CHECK 等一起迁移，否则自检路径丢失；PC 组影响小。

开发自检

  • Android shipping 触发 MessageBoxExt 只出日志不弹框
  • Vulkan 自检/RestartApplication 路径仍生效

结论置信度：medium — VulkanRHI 侧 30+ 引用由移动组负责，需确认组合宏是否同步迁移

UE5 已覆盖UE5.8 原生等价，可直接删除
部分覆盖UE5 有同类能力，只迁差异部分
未覆盖UE5 没有该能力，需迁移或补丁
待确认证据不足，迁移前需人工确认

落地位置（工程化可行性）

可工程化放项目/插件/配置即可，不动引擎
需接入点引擎留少量 Hook，逻辑在工程侧
引擎内实现必须改引擎核心
—处置=删除的行不适用（已删除/不迁移）

引擎改动方式

L0 无需改引擎纯工程/插件/配置即可（对应「可工程化」）
L0 引擎内补丁需改引擎源码，但不必新增扩展点（对应「引擎内实现」）
L1 仅加接入点引擎只需暴露 Delegate / Interface / CVar 等扩展点
L2 结构性改动枚举 slot / 新 Pass / schema 字段
L3 深度侵入核心结构/生命周期/序列化，慎入

迁移处置

删除UE5 已覆盖，直接删
常开补丁确认的 bugfix，作为 fork 常开补丁
配置化改为 CVar / ini / DeviceProfile / 命令行
插件化迁到项目模块 / 编辑器插件
接入点引擎只留 Hook，逻辑在插件
移植代码保留，适配后移植
保留引擎深度绑定，暂留并登记 Feature Card
