新增 SetDeviceOrientation 接口，供游戏控制设备方向

部分覆盖 移植 可工程化 仅加接入点 工作量 S风险 低开发者 Ran Qing Sen主要模块 Core

1. UE5 现状与证据

结论依据：Runtime/Engine/Classes/Kismet/BlueprintPlatformLibrary.h:270 SetAllowedDeviceOrientation

覆盖说明：UE5 有允许方向设置，无直接 SetDeviceOrientation

证据路径（UE5.8.2）行号核对结果

2. 修改步骤（移植）

  1. 定位 UE5 对应文件
    见下方「UE5 对应文件」；重点比对同文件在 UE4/UE5 的差异。
  2. 移植实现
    原实现位置：Source/Runtime/ApplicationCore/Private/IOS/IOSView.cpp、Source/Runtime/ApplicationCore/Public/IOS/IOSView.h、Source/Runtime/Core/Private/Android/AndroidPlatformMisc.cpp、Source/Runtime/Core/Private/GenericPlatform/GenericPlatformMisc.cpp、Source/Runtime/Core/Private/IOS/IOSPlatformMisc.cpp、Source/Runtime/Core/Public/Android/AndroidPlatformMisc.h、Source/Runtime/Core/Public/GenericPlatform/GenericPlatformMisc.h、Source/Runtime/Core/Public/IOS/IOSPlatformMisc.h。如涉及 Shader，需同步改 shader define 或共享 include。
  3. 适配 UE5 接口与规范
    注意 C++20、UHT（反射）规则、bValidateCircularDependencies 默认开启等差异；必要时回归 DDC/Cook。

3. 代码级实现（开发用）

独立 Agent 审核通过

审核意见：抽查通过：UE4 组合宏 GenericPlatformMisc.h:1366/223、BlueprintPlatformLibrary.h:254-260/259 均实测存在；UE5 原生 EDeviceScreenOrientation 已含 PortraitSensor/LandscapeSensor/FullSensor(GenericPlatformMisc.h:221-227)、CORE_API SetAllowedDeviceOrientation(GenericPlatformMisc.h:1775)、FAndroidMisc::SetAllowedDeviceOrientat

建议舍弃 改动方式：UE5 引擎已原生实现同一套方向枚举与 SetAllowedDeviceOrientation 链路，再打补丁会与原生枚举成员重复定义。

代码脉络：宏新增 FPlatformMisc::SetDeviceOrientation/SetAllowedDeviceOrientation(GenericPlatformMisc.h:1366)、UBlueprintPlatformLibrary::SetDeviceOrientation(BlueprintPlatformLibrary.cpp:180)，Android 转 AndroidThunkCpp_SetOrientation(AndroidJNI.cpp:1347)、iOS 设 SupportedInterfaceOrientations(IOSPlatformMisc.cpp:377)，并给 EDeviceScreenOrientation/EScreenOrientation 加 Sensor 枚举(GenericPlatformMisc.h:223)。UE5 已原生全覆盖：GenericPlatformMisc.h:1775 SetAllowedDeviceOrientation、BlueprintPlatformLibrary.h:270、AndroidPlatformMisc.cpp:3467、IOSPlatformMisc.cpp:471，且 FullSensor 已在 BlueprintPlatformLibrary.h:51。

步骤 1Source/Runtime/Engine/Classes/Kismet/BlueprintPlatformLibrary.hBlueprintPlatformLibrary.h:270

不迁移引擎补丁；项目蓝图节点由 SetDeviceOrientation 改为 UE5 原生 SetAllowedDeviceOrientation

// UE4 BlueprintPlatformLibrary.h:254-260
UFUNCTION(BlueprintCallable, Category = "Platform|LocalNotification")
static void SetDeviceOrientation(EScreenOrientation::Type NewAllowedDeviceOrientation);
// UE5 原生已存在，直接使用:
UFUNCTION(BlueprintCallable, Category="Platform|LocalNotification")
static ENGINE_API void SetAllowedDeviceOrientation(EScreenOrientation::Type NewAllowedDeviceOrientation);

⚠ UE5 EScreenOrientation 已含 PortraitSensor/LandscapeSensor/FullSensor，勿再添加

步骤 2Source/Runtime/Core/Public/GenericPlatform/GenericPlatformMisc.hGenericPlatformMisc.h:1775

删除 GenericPlatformMisc/Android/JNI 的 XD 补丁，改调原生 API

#if XD_MISC_ADD_SetDeviceOrientation_Method
    static void SetDeviceOrientation(EDeviceScreenOrientation NewDeviceOrientation);
    static void SetAllowedDeviceOrientation(EDeviceScreenOrientation NewAllowedDeviceOrientation) { SetDeviceOrientation(NewAllowedDeviceOrientation); }
#endif
// 直接用 UE5 原生:
static CORE_API void SetAllowedDeviceOrientation(EDeviceScreenOrientation NewAllowedDeviceOrientation);
// 项目代码等价调用:
UBlueprintPlatformLibrary::SetAllowedDeviceOrientation(EScreenOrientation::LandscapeLeft);

⚠ UE5 Android 实现已调用 AndroidThunkCpp_SetOrientation(AndroidPlatformMisc.cpp:3472)

风险评估

⚠ 与早期迁移处置结论存在分歧：早期结论=要移植，代码级分析=建议舍弃。早期结论=移植，代码级分析=建议舍弃；建议以代码级分析为准并回写评估矩阵。

原代码风险：iOS 在 IOSView 未创建时调用仅打 Warning，方向设置静默失败(IOSPlatformMisc.cpp:377)；Android 枚举值须与 Java 侧 SCREEN_ORIENTATION 一致。

移植风险：不迁引擎补丁；若照 UE4 添加 Sensor 枚举会与 UE5 原生成员冲突导致编译失败，蓝图旧节点需批量改名。

开发自检

  • Android SetAllowedDeviceOrientation 触发实际旋转
  • iOS SupportedInterfaceOrientations 更新
  • 蓝图无 SetDeviceOrientation 断链

结论置信度：high — 项目蓝图/脚本对旧节点名的引用数量需项目侧统计。
