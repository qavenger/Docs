修改草案 · XD_TOOL_GET_MONITOR_INFO_FROM_ADAPTER

按 GPU 适配器获取所连接的显示器信息

部分覆盖 删除 可工程化 仅加接入点 工作量 S风险 低开发者 Han Shu Bin主要模块 RHI

一句话结论：改用 UE5 FDisplayMetrics/FMonitorInfo

背景：多屏/混合显卡环境下把显示器与 GPU 正确对应，用于分辨率与全屏设置。

1. UE5 现状与证据

结论依据：Runtime/ApplicationCore/Public/GenericPlatform/GenericApplication.h:339 FMonitorInfo(NativeHandle/Name/DPI)+FDisplayMetrics；Runtime/RHI/Public/DynamicRHI.h:733 RHIGetAvailableResolutionsForDisplay

覆盖说明：UE5 有显示器信息与按句柄分辨率查询，无 XD 的适配器聚合结构

证据路径（UE5.8.2）行号核对结果
Runtime/ApplicationCore/Public/GenericPlatform/GenericApplication.h339✅ 已命中：Source/Runtime/ApplicationCore/Public/GenericPlatform/GenericApplication.h
Runtime/RHI/Public/DynamicRHI.h733✅ 已命中：Source/Runtime/RHI/Public/DynamicRHI.h

覆盖度：部分覆盖  处置：删除

2. 修改步骤（删除）

  1. 确认删除原因
    覆盖度为「部分覆盖」，删除原因不是 UE5 覆盖，而是：UE5 有显示器信息与按句柄分辨率查询，无 XD 的适配器聚合结构。请先确认该功能当前确实不再需要（默认关闭 / 无引用 / 已被其它方案替代）。
  2. 删除 UE4 侧的宏与代码
    涉及位置：Source/Runtime/D3D12RHI/Private/D3D12RHIPrivate.h、Source/Runtime/D3D12RHI/Private/Windows/WindowsD3D12Device.cpp、Source/Runtime/Engine/Classes/Kismet/KismetSystemLibrary.h、Source/Runtime/Engine/Private/KismetSystemLibrary.cpp、Source/Runtime/RHI/Public/DynamicRHI.h、Source/Runtime/RHI/Public/RHI.h、Source/Runtime/Windows/D3D11RHI/Private/D3D11RHIPrivate.h、Source/Runtime/Windows/D3D11RHI/Private/Windows/WindowsD3D11Device.cpp。删除后全仓搜索宏名应为 0 命中（含 Shaders、Plugins）。
  3. 回归验证
    改用 UE5 FDisplayMetrics/FMonitorInfo

3. 代码级实现（开发用）

待独立 Agent 审核该草案尚未进入审核轮次：审核会打开 UE5 源码逐条核对行号、函数与 after 代码 引用的 API 是否存在。

完全重构 改动方式：UE5 RHI/D3D11 设备类已重构（FD3D11Adapter/DXGIAdapter 成员，FD3D11Adapter Adapter 见 D3D11RHIPrivate.h:694），UE4 的 ChosenAdapter/DXGIFactory1 写法失效，须按新结构重写。

代码脉络：宏=1 新增 RHI 虚接口 RHIGetAttachedMonitorInfos（Runtime/RHI/Public/DynamicRHI.h:1242，inline 包装 :1813）、XD 结构 FAttachedMonitorInfoRHI/Array（RHI.h:1279/1368），D3D11 实现于 WindowsD3D11Device.cpp:2614（用 DXGIFactory1 + ChosenAdapter 枚举 IDXGIOutput），并暴露为 UKismetSystemLibrary::GetAttachedMonitorInfos（KismetSystemLibrary.cpp:2322）。

步骤 1Runtime/RHI/Public/RHI.hUE5 RHIDefinitions.h:1758 struct FScreenResolutionRHI 之后

UE5 无 FAttachedMonitorInfoRHI/FAttachedMonitorInfoArray，照搬 XD 结构

风险评估

⚠ 与早期迁移处置结论存在分歧：早期结论=UE5 已覆盖，代码级分析=需完全重构。早期结论=删除，代码级分析=完全重构；建议以代码级分析为准并回写评估矩阵。

原代码风险：依赖 DXGIFactory1 缓存，运行期切换桌面/显卡时枚举可能返回过期 output（DXGI 已知问题）。

移植风险：仅 D3D11 分支重写，D3D12 分支若不迁移会缺功能；蓝图 GetAttachedMonitorInfos 签名需保持一致。

开发自检

  • D3D11/D3D12 下双屏+混合显卡能列出各自适配器对应显示器
  • 全屏分辨率列表非空且与系统显示设置一致

结论置信度：medium — 是否需要保留“显示器↔GPU 适配器绑定”语义；UE5 FDisplayMetrics::MonitorInfo 只有 Name/DisplayRect/NativeHandle，无适配器关联，若项目不需要绑定可直接用 FDisplayMetrics 替换整个 XD 路径
