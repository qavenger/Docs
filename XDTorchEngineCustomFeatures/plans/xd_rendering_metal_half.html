修改草案 · XD_RENDERING_METAL_HALF

Metal 平台相关精度（half）开关，当前关闭

部分覆盖 配置化 需接入点 仅加接入点 工作量 M风险 中开发者 DU Peng主要模块 Shaders

一句话结论：默认关闭；着色器 permutation 变化，迁移时需重估精度与性能

⚠ 原宏备注：默认 0，涉及 ShaderCompilerCommon 与多个移动端 USF 的精度宏。

1. UE5 现状与证据

结论依据：Runtime/Renderer/Private/MobileBasePassRendering.h / Runtime/RenderCore/Private/ShaderParameterMetadata.cpp（XD 侧定义点）；UE5 有 half / PRECISION_MEDIUMP 精度体系

证据路径（UE5.8.2）行号核对结果

2. 修改步骤（配置化）

  1. 确定配置承载
    材质/ShaderPermutation 侧精度开关，建议用 ShaderInclude 或 CVar 替代宏
  2. 设定默认值与灰度
    默认值应与当前线上行为一致；通过 ini/DeviceProfile 按平台/机型灰度，可随时回滚。
  3. 清理宏
    删除 UE4 宏与 Shaders/Private/ComputeGenerateMips.usf、Shaders/Private/MobileBasePassCommon.ush、Shaders/Private/MobileBasePassVertexShader.usf、Shaders/Private/PostProcessCombineLUTs.usf、Shaders/Private/PostProcessMobile.usf、Source/Developer/ShaderCompilerCommon/Private/ShaderCompilerCommon.cpp、Source/Runtime/RenderCore/Private/GenerateMips.cpp、Source/Runtime/RenderCore/Private/ShaderParameterMetadata.cpp 中的编译期分支，改为读取配置。

3. 代码级实现（开发用）

建议舍弃 改动方式：默认 0，UE5 精度由 EShaderPrecisionModifier/PRECISION_MEDIUMP 体系管理，16bit 由 FShaderConductorOptions.bEnable16bitTypes 控制。

代码脉络：宏=0；开启时在 Apple 把 UBO 元数据 half 降级为 float（ShaderParameterMetadata.cpp:66、ShaderParameters.cpp:182），强制 ShaderConductor 16bit Types + SM6.2（ShaderCompilerCommon.cpp:2773/2782），并向 USF 环境注入 XD_RENDERING_METAL_HALF（MobileBasePassRendering.h:254/534、GenerateMips.cpp:36、PostProcessCombineLUTs.cpp:506）。

步骤 1Source/Runtime/RenderCore/Private/ShaderParameterMetadata.cppUE4:66 / UE5:103

删 half→float 的 XD 分支，保留 UE5 原生 half 行为

else if (GetPrecision() == EShaderPrecisionModifier::Half)
{
#if XD_RENDERING_METAL_HALF && PLATFORM_APPLE
    Result = TEXT("float");
#else
    Result = TEXT("half");
#endif
}
else if (PrecisionModifier == EShaderPrecisionModifier::Half)
{
    Result = TEXT("half");
}

⚠ UE5 ShaderParameterMetadata.cpp:103 已是 after；宏=0 时二者一致。

步骤 2Source/Developer/ShaderCompilerCommon/Private/ShaderCompilerCommon.cppUE4:2773 / UE5 ShaderConductorContext.cpp:494

不迁移；若确需 16bit 改走 UE5 的 FShaderConductorOptions

#if XD_RENDERING_METAL_HALF && PLATFORM_APPLE
    OutOptions.enable16bitTypes = true;
    OutOptions.shaderModel = ShaderConductor::Compiler::ShaderModel{6, 2};
#else
    OutOptions.enable16bitTypes = InOptions.bEnable16bitTypes;
#endif
OutOptions.enable16bitTypes = InOptions.bEnable16bitTypes;
OutOptions.shaderModel = ShaderConductor::Compiler::ShaderModel{ (uint8)InOptions.ShaderModel.Major, (uint8)InOptions.ShaderModel.Minor };

⚠ UE5 ConvertScOptions 已重构并 check 16bit 与 SM6.2 搭配（ShaderConductorContext.cpp:487）。

风险评估

原代码风险：强制 SM6.2+16bit 会改变所有 Apple 着色器 permutation，编译时间与精度风险大。

移植风险：照搬宏若 UE5 缺 bEnable16bitTypes 语义会编译失败或精度回归；需重跑 Metal shader 编译。

开发自检

  • Metal UBO half 精度与 UE5 默认一致
  • 无 XD_RENDERING_METAL_HALF 未定义符号

结论置信度：medium — 是否需在 UE5 Apple 重新启用 16bit types 需按画质/性能实测决定。

颜色规则：覆盖度=红绿灯 · 工程化=蓝色系 · 侵入=紫色系 · 处置=中性灰。
分级方式：工程化/侵入用「实心 → 底色 → 描边 → 虚线」四级形态表示程度递进（实心最强）。

UE5 覆盖度

UE5 已覆盖UE5.8 原生等价，可直接删除
部分覆盖UE5 有同类能力，只迁差异部分
未覆盖UE5 没有该能力，需迁移或补丁
待确认证据不足，迁移前需人工确认

落地位置（工程化可行性）

可工程化放项目/插件/配置即可，不动引擎
需接入点引擎留少量 Hook，逻辑在工程侧
引擎内实现必须改引擎核心
—处置=删除的行不适用（已删除/不迁移）

引擎改动方式

L0 无需改引擎纯工程/插件/配置即可（对应「可工程化」）
L0 引擎内补丁需改引擎源码，但不必新增扩展点（对应「引擎内实现」）
L1 仅加接入点引擎只需暴露 Delegate / Interface / CVar 等扩展点
L2 结构性改动枚举 slot / 新 Pass / schema 字段
L3 深度侵入核心结构/生命周期/序列化，慎入

迁移处置

删除UE5 已覆盖，直接删
常开补丁确认的 bugfix，作为 fork 常开补丁
配置化改为 CVar / ini / DeviceProfile / 命令行
插件化迁到项目模块 / 编辑器插件
接入点引擎只留 Hook，逻辑在插件
移植代码保留，适配后移植
保留引擎深度绑定，暂留并登记 Feature Card
