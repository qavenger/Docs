修改草案 · XD_OPT_FOLIAGE_BAKE_LIGHTMAP_AND_SHADOWMAP_INTO_INSTANCE_BUFFER

植被 ISM 按实例采样 LightMap/ShadowMap（把结果烘焙进实例缓冲）

未覆盖 保留引擎 需接入点 深度侵入 工作量 L风险 高开发者 Lu Xun主要模块 Engine

一句话结论：ES3.1 仍需；改 Shader 与光照数据，须清 DDC 重烘焙

背景：原版每股实例都要逐像素采样光照图；此优化把光照图/阴影图采样结果按实例写入 Instance Buffer，Shader 直接读取，显著降低大片植被的光照开销。

1. UE5 现状与证据

结论依据：UE5 FStaticMeshInstanceData 仅含实例 LM UV bias（Runtime/Engine/Public/StaticMeshResources.h:1030,1063）；Nanite/VSM 不构成等价替代：r.Nanite.Foliage 只是实验开关（Runtime/Engine/Classes/Engine/RendererSettings.h:1549-1553 'Nanite Foliage (Experimental)'，NaniteResources.cpp:118 仅其定义），且 Nanite/VSM 在 ES3.1 移动端不可用，而本项优化面向移动端

覆盖说明：无逐实例烘焙 LM/SM

2. 修改步骤（暂留引擎）

  1. 登记 Feature Card
    记录 owner、影响面、依赖、关闭条件、验证方式与回滚方式；这是当前最高风险的一类（引擎内深度改动）。
  2. 评估替代路径
    优先考虑改用 UE5 原生机制（如 Niagara / Substrate / PSOPrecache / WorldPartition）替代自研实现；替代前保留最小可用补丁。
  3. 设定复查条件
    每个版本复查一次：是否可以降级为插件/配置，或直接删除。
  4. Shader 侧配套
    删除 DerivedDataCache 重编 Shader；同步更新受影响的 shader permutation / ShaderVersion。
