修改草案 · XD_RENDERING_MOBILE_ANDROID_FORCE_DEPTH_FETCH

Android 强制从深度 RT 采样深度（不使用深度解析 Pass）

部分覆盖 配置化 可工程化 无需改引擎 工作量 S风险 中开发者 Gong Bai Liang主要模块 Renderer

一句话结论：先确认 Android GL/Vulkan 下 r.Mobile.AllowFramebufferFetch 是否已满足深度读取需求；GLES 路径变化较大需真机验证

1. UE5 现状与证据

结论依据：UE5 无 FORCE_DEPTH_FETCH shader define（grep 无结果）；对应机制为 Runtime/RenderCore/Private/RenderUtils.cpp:501-504（MobileAllowFramebufferFetch）、Runtime/RenderCore/Private/ReadOnlyCVARCache.cpp:83-89（r.Mobile.AllowFramebufferFetch，覆盖 AndroidOpenGLESPlatform）、同文件 1075-1081（不支持时关闭 GSupportsShaderDepthStencilFetch 等）

覆盖说明：UE5 用平台驱动的 framebuffer fetch / depth-stencil fetch 能力位替代 XD 的 Android 强制深度 fetch define

证据路径（UE5.8.2）行号核对结果
Runtime/RenderCore/Private/RenderUtils.cpp501✅ 已命中：Source/Runtime/RenderCore/Private/RenderUtils.cpp
Runtime/RenderCore/Private/ReadOnlyCVARCache.cpp83✅ 已命中：Source/Runtime/RenderCore/Private/ReadOnlyCVARCache.cpp

覆盖度：部分覆盖  处置：配置化

2. 修改步骤（配置化）

  1. 确定配置承载
    通过 DeviceProfile 的 r.Mobile.AllowFramebufferFetch 控制（注意有平台白名单限制）
  2. 设定默认值与灰度
    默认值应与当前线上行为一致；通过 ini/DeviceProfile 按平台/机型灰度，可随时回滚。
  3. 清理宏
    删除 UE4 宏与 Shaders/Private/SceneTexturesCommon.ush、Source/Runtime/Renderer/Private/MobileBasePassRendering.h 中的编译期分支，改为读取配置。

3. 代码级实现（开发用）

待独立 Agent 审核该草案尚未进入审核轮次：审核会打开 UE5 源码逐条核对行号、函数与 after 代码 引用的 API 是否存在。

建议舍弃 改动方式：UE5 已删除 FORCE_DEPTH_FETCH，改由平台能力位与 r.Mobile.AllowFramebufferFetch 驱动 MOBILE_DEPTHFECTH(SceneTexturesCommon.ush:198/219)，等价目标已覆盖。

代码脉络：MobileBasePassRendering.h:510-512 与 634-636 注入 FORCE_DEPTH_FETCH define；SceneTexturesCommon.ush:159-166 的 GLES3.1 分支据此选 DepthbufferFetchES2 而非读 SceneColor.a。

不再注入 FORCE_DEPTH_FETCH define

⚠ 删除后 GLES3.1 走 UE5 原生 depth-stencil fetch

步骤 2Config/DefaultDeviceProfiles.iniAndroid DeviceProfile 的 CVar 区

需要时用 CVar 覆盖，而非改 define

+CVars=r.Mobile.AllowFramebufferFetch=1

⚠ uE5 读该 ini：ReadOnlyCVARCache.cpp:83-91(AndroidOpenGLESPlatform 分支)、不支持时 1075-1080 关掉 GSupportsShaderDepthStencilFetch

风险评估

原代码风险：强制 depth fetch 在缺 framebuffer_fetch_depth_stencil 的 GL 驱动上可能黑屏/精度丢失。

移植风险：不迁移后 Android GL 深度来源改由平台能力决定，个别机型行为变化，需真机回归。

开发自检

  • Android GLES3.1 真机 MobileHDR 场景深度正确
  • 部分深度读取的材质无花屏

结论置信度：medium — abandon_hint 标为 toolchain，但实为渲染路径；建议按平台能力位而非宏处理
