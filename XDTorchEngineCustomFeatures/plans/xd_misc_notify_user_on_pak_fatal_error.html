修改草案 · XD_MISC_NOTIFY_USER_ON_PAK_FATAL_ERROR

Pak 致命错误时给玩家输出引导性日志/提示

部分覆盖 插件化 可工程化 仅加接入点 工作量 S风险 低开发者 Yu Hang主要模块 PakFile

一句话结论：玩家引导属运营/启动器逻辑，全部搬项目侧，引擎不再改 WindowsErrorOutputDevice

1. UE5 现状与证据

结论依据：UE5 有 FCoreDelegates::PakFileMountFailedDelegate（CoreDelegates.h:152）与 FPakPlatformFile::bMountFailOnMissingUtoc（Runtime/PakFile/Public/IPlatformFilePak.h:2089），但无 pakchunk 损坏的玩家引导文案/崩溃处理

覆盖说明：机制在，文案不在

证据路径（UE5.8.2）行号核对结果
CoreDelegates.h152✅ 已命中：Source/Runtime/Core/Public/Misc/CoreDelegates.h
Runtime/PakFile/Public/IPlatformFilePak.h2089✅ 已命中：Source/Runtime/PakFile/Public/IPlatformFilePak.h

覆盖度：部分覆盖  处置：插件化

2. 修改步骤（插件化）

  1. 确定插件/模块归属
    项目热更/启动器模块 bind PakFileMountFailedDelegate，自行决定弹窗、文案与退出策略
  2. 实现主体逻辑
    把原引擎内实现迁到插件：Source/Developer/PakFileUtilities/Private/PakFileUtilities.cpp、Source/Developer/PakFileUtilities/Private/SignedArchiveWriter.cpp、Source/Runtime/PakFile/Private/IPlatformFilePak.cpp、Source/Runtime/PakFile/Public/IPlatformFilePak.h。引擎侧只保留必要接口/事件。
  3. 模块与构建规则
    Editor 工具放 Editor 模块（Shipping 自动剔除）；运行时逻辑放 Runtime 模块；如需引擎接口，见「引擎改动」列。

3. 代码级实现（开发用）

建议舍弃 改动方式：UE5 已有 FCoreDelegates::PakFileMountFailedDelegate（CoreDelegates.h:152）与 bMountFailOnMissingUtoc（IPlatformFilePak.h:2089），玩家引导属项目侧策略，无需引擎补丁。

代码脉络：把若干 log Fatal 点改成先 Error 输出玩家可读文案再 Fatal：IPlatformFilePak.h:244（FrozenIndex）/525（未知压缩类型）、IPlatformFilePak.cpp:378（加密 Key 无效）/8003（pakchunk 挂载失败）、SignedArchiveWriter.cpp:98、PakFileUtilities.cpp:2194/3668/5471。

步骤 1项目热更插件 StartupModuleFCoreDelegates::PakFileMountFailedDelegate

项目侧绑定委托做提示与上报

#if XD_MISC_NOTIFY_USER_ON_PAK_FATAL_ERROR && PLATFORM_WINDOWS
  if (FPaths::GetCleanFilename(InPakFilename).StartsWith(TEXT("pakchunk"), ESearchCase::IgnoreCase))
  { UE_LOG(LogPakFile, Fatal, TEXT("%s is not valid! Please do a file integrity check or reinstall the game!"), InPakFilename); }
#endif
FCoreDelegates::PakFileMountFailedDelegate.AddLambda([](const FString& Failed)
{
    UE_LOG(LogXDHotfix, Error, TEXT("XD: pak mount failed %s，请校验完整性或重装"), *Failed);
});

⚠ 须早于 FPakPlatformFile 初始化绑定；UE5 在 IPlatformFilePak.cpp:6165/6181/6190 广播

步骤 2Runtime/PakFile/Private/IPlatformFilePak.cppUE5:6096 / :4925

放弃引擎 Fatal 文案补丁，保留 UE5 原文案

UE_LOG(LogPakFile, Error, TEXT("Failed to find requested encryption key %s"), *InEncryptionKeyGuid.ToString());
UE_LOG(LogPakFile, Fatal, TEXT("Encryption Key is not valid! ..."));
// UE5 现状，保持不动：
UE_LOGF(LogPakFile, Fatal, "Failed to find requested encryption key %ls", *InEncryptionKeyGuid.ToString());

⚠ UE4 的 8 处改动只是在 Fatal 前多打一条 Error，等价信息可经委托拿到

风险评估

原代码风险：同一错误打两条日志造成噪声；玩家文案硬编码在引擎内无法本地化。

移植风险：若项目未绑委托，Pak 损坏时仍只有 Fatal 崩溃、无引导（体验回退）。

开发自检

  • 损坏一个 pakchunk 后能看到委托回调与提示
  • 加密 key 错误仍可凭日志定位

结论置信度：high — PakFileUtilities/SignedArchiveWriter 的工具侧 Fatal 是否也要玩家文案
