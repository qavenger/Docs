3. 代码级实现（开发用）

独立 Agent 审核并修正修正 1 处　提出问题 1 条

审核意见：thread 对 UE5 的判定准确（LogMacros.h:25-27 默认 1、:341 __builtin_FILE()、:135 TStaticBasicLogRecord::File、:114 UE_LOG_SOURCE_FILE），abandon 成立（UE5 默认不再裁剪 File/Line）；仅 before 需按真实源码改写。

建议舍弃 改动方式：UE5 日志宏重构后 fatal 路径已恒定携带调用点文件名，该宏要修的问题在 UE5 不存在。

代码脉络：该宏在 UE4 全树无 #if 引用（只有定义 XDBuildMiscConfiguration.cs:53 与生成的 Definitions.*.h）；真实改动是把主 UE_LOG 宏 fatal 分支里 UE_LOG_SOURCE_FILE(__FILE__) 注释掉（LogMacros.h:319），因为 DO_CHECK=0 时 UE_LOG_SOURCE_FILE 退化成 "Unknown"（:107-110）。UE5 已重写日志宏：UE_PRIVATE_LOG 把 __builtin_FILE() 编译期固化进 TStaticBasicLogRecord（LogMacros.h:341），fatal 走 BasicFatalLog→BasicFatalLogV→StaticFailDebugV(Log.File,...)（StructuredLog.cpp:1708-1714），不再受 DO_CHECK 裁剪。

步骤 1Runtime/Core/Public/Logging/LogMacros.hUE5:341 TStaticBasicLogRecord / UE4:107-110、:319

不迁移：核实 UE5 已等价，丢弃 UE4 的注释式补丁

FMsg::Logf_Internal(/*UE_LOG_SOURCE_FILE*/(__FILE__), __LINE__, LCategoryName.GetCategoryName(), ELogVerbosity::Verbosity, LFormat, UE_LOG_Args...);
// UE5 无需补丁：
constexpr TStaticBasicLogRecord LOG_Static(Format, __builtin_FILE(), __builtin_LINE(), ...);  // LogMacros.h:341
BasicFatalLogV(...) { StaticFailDebugV(TEXT("Fatal error:"), Log.File, Log.Line, ...); }  // StructuredLog.cpp:1708-1710

⚠ UE5 里 UE_LOG_SOURCE_FILE 仅剩 4 处调用（ShaderParameterMacros.h:1341、ExtensibleUniformBuffer.h:174、MaterialUniformExpressions.cpp:463/983），与 fatal 无关。

步骤 2Source/Programs/UnrealBuildTool/Configuration/XDBuildConfiguration/XDBuildMiscConfiguration.cs宏定义 :53

不注册该宏；改为在 Target.cs/CI 保证 Shipping 不定义 NO_LOGGING

public static int XD_MISC_FATAL_ERROR_PRINT_FILE_NAME_IN_SHIPPING_MODE = 1;
// 丢弃。仅在需要 NO_LOGGING 的平台上才补一个带 __FILE__ 的 LowLevelFatalError 变体。

⚠ NO_LOGGING=1 时 UE_LOG 走 LogMacros.h:186-206 的 LowLevelFatalError(Format) 不带文件名，此情况下才需小补丁。

风险评估

原代码风险：补丁使 Shipping 崩溃日志暴露源码文件名/路径（日志体积与信息外泄）。

移植风险：影响面仅在日志；若误判漏改 NO_LOGGING 平台，Shipping 仍无文件名，定位变慢。

开发自检

  • Shipping 包触发一次 Fatal，确认日志/崩溃转储含源文件行号
  • 确认包体与日志体积无异常（DO_CHECK 相关代码未被意外放开）

结论置信度：medium — 是否仍有平台在 Shipping 下定义 NO_LOGGING=1 需按 Target.cs 实际配置确认。
