修改草案 · XD_BUG_FIX_EDITOR_PREVIEW_FEATURE_LEVEL_NOT_MATCH_UI

修复编辑器预览实际特性等级与 UI 显示不一致（显示 ES3.1 实际 SM5）

部分覆盖 常开补丁 引擎内实现 仅加接入点 工作量 M风险 中开发者 Ran Qing Sen主要模块 Editor/UnrealEd

一句话结论：先确认 UE5 是否仍有该不一致，再决定是否保留补丁。

0. 根因溯源（这个宏为什么存在）

XD 定制需求（非上游缺陷）

结论：预览模式只更新 UI/GEditor 活动等级，而 LoadMap 用 FEATURELEVEL= 或 GMaxRHIFeatureLevel 初始化世界，出现 UI 显示 ES3.1、世界实为 SM5。XD 在 World->InitWorld 后强制 World->ChangeFeatureLevel(GetActiveFeatureLevelPreviewType())。

上游引入：XD fork 无 git 元数据；XDBuildFixBugConfiguration.cs:35 注释 https://xindong.atlassian.net/browse/UE4-529；EditorServer.cpp:2745 注释 ENGINE-727。上游预览选择由 1d5834996ec4(2019-01-10 josh jensen) 引入，4.26 已在 SLevelViewport::OnMapChanged:1200 调 ChangeFeatureLevel。

上游历史（是否修过）：上游 4.26 已在 SLevelViewport OnMapChanged 处理。5.8 提交 42dfe52f0df8(2026-03-23 florin pascu, UE-370235) 弃用 ChangeFeatureLevel(World.h:1546)；SLevelViewport.cpp:1441 改用 World->ShaderPlatformChanged(GEditor->GetActiveShaderPlatform())；同提交把 EditorServer.cpp:2683 改为 ShaderPlatformChanged(GShaderPlatformForFeatureLevel[FeatureLevel])。

为什么可以断定不是「故意为之」3 条依据
  • 上游不是在 LoadMap 里修，而靠 SLevelViewport::OnMapChanged(4.26:1200) 事后同步，说明上游认可该行为存在但选了不同注入点。
  • UE4-529/ENGINE-727 描述的是 UI 与实际等级不一致的用户可见 bug，不是有意设计。
  • 宏只在编辑器 Target 生效，且 XD 裸强转 (UEditorEngine*)GEngine 未判空，属临时绕行。

调用方契约：GEditor->GetActiveFeatureLevelPreviewType()(UE5 EditorEngine.h:3306)；World->FeatureLevel 被渲染/物理/FX 子系统读取(UE4 EditorServer.cpp:2716/2733 之后)。

内层真实语义：UE4 ChangeFeatureLevel 直接重设等级并重建场景；UE5 World.cpp:10079 起它只是 ShaderPlatformChanged(GShaderPlatformForFeatureLevel[...]) 的弃用包装。

代码库惯例：UE5 统一走 ShaderPlatformChanged：EditorServer.cpp:2683、SLevelViewport.cpp:1441；预览变化由 OnPreviewShaderPlatformChanged 委托广播(SLevelViewport.cpp:5024)。

为何长期未被发现：只在 r.FeatureLevelPreview=1 且换图/新建地图时可见；SLevelViewport 事后往往补救，肉眼难辨。

XD 侧的做法与意图：EditorServer.cpp:2745 在 InitWorld 后同步，保证加载期子系统用正确等级；宏定义见 XDBuildFixBugConfiguration.cs:35。

照搬 UE4 写法调 ChangeFeatureLevel 会触发 UE_DEPRECATED(5.8)(World.h:1546)，在 -Werror 构建直接失败；它内部就是 ShaderPlatformChanged，等于白绕一层。

迁移方案（按根因定）

首选删宏，依赖 UE5 既有 SLevelViewport::OnMapChanged(:1441)/OnPreviewShaderPlatformChanged(:5024)。若确需加载期同步，用 World->ShaderPlatformChanged(GEditor->GetActiveShaderPlatform())，勿再经 GetActiveFeatureLevelPreviewType 二次映射；注意 ShaderPlatformChanged 会重建渲染资源(World.cpp:10079 起)，仅在需要时调。

根因级自检用例

  • Preview=ES3.1，新建地图，LoadMap 后 World 的 ShaderPlatform 对应 ES3.1。
  • Preview=Default(SM5) 时行为与未打补丁一致。
  • commandlet/非编辑器不触发裸强转 GEngine。
  • 切图后 SLevelViewport OnMapChanged 不重复重建场景两次。

可反馈上游：最小复现：编辑器 Preview Rendering Level 设 ES3.1 → File>New Level → 世界实际 FeatureLevel 仍为 SM5（UE4 4.26，UE4-529/ENGINE-727）。

风险评估

原代码风险：强转 GEngine 为 UEditorEngine 且未判空，尽管 EditorServer 仅编辑器编译。

移植风险：ShaderPlatformChanged 会重建渲染资源（World.cpp:10079），换图时可能卡一次；仅 r.FeatureLevelPreview=1 场景需要。

开发自检

  • 新建/切换地图后 UI 显示等级与实际 GPU 等级一致
  • SM5↔ES3.1 来回切换无残留

结论置信度：medium — UE5 换图是否仍错配未实测；若已修复可直接删宏。
