修改草案 · XD_RENDEING_ADJUST_PARTICLE_LUMINANCE_AND_ALPHA

统一调整粒子的整体亮度与 Alpha（材质/组件级开关）

未覆盖 插件化 可工程化 仅加接入点 工作量 M风险 中开发者 Ran Qing Sen主要模块 Engine

一句话结论：建议改用材质参数化实现，避免在粒子渲染路径加 uniform；注意与实例化方案的兼容

背景：给粒子材质与组件增加全局亮度/透明度乘数，并由 View.AdditiveColorMultiplier 等参数注入 Shader；用于控制特效在 HDR 下的过曝。

可主动舍弃性（UE5 架构更替）

直接舍弃 Cascade 粒子 → Niagara

判定依据：UE5 特效体系已全面转向 Niagara，Cascade 仅保留兼容维护；项目迁移到 UE5 后特效会重做，针对 Cascade 运行时的定制可在迁移时直接不带过去。

舍弃前提：前提：迁移后在 UE5 用 Niagara 重做特效（不再走 Cascade 运行时）

UE5 替代能力：Niagara（NiagaraSystem / NiagaraComponent / NiagaraDataInterface）

相关文件：Source/Runtime/Engine/Classes/Particles/FastParticleSystemComponent.h Source/Runtime/Engine/Classes/Particles/ParticleSystemComponent.h Source/Runtime/Engine/Private/Particles/FastParticleSystem/FastParticleSystemComponent.cpp

1. UE5 现状与证据

结论依据：UE5 ParticleSystemRender 无 XD 的亮度/Alpha 额外 uniform 与 AdditionalPrimitiveUniformBuffer（grep 无 Luminance/AdditionalPrimitiveUniformBuffer）

覆盖说明：24 处引用，UE5 无等价能力

覆盖度：未覆盖  处置：插件化

2. 修改步骤（插件化）

  1. 确定插件/模块归属
    材质侧用 Material Parameter Collection/动态材质实例提供亮度+Alpha 全局/单实例缩放，组件侧只在项目组件设置 MID 参数
  2. 实现主体逻辑
    把原引擎内实现迁到插件：Shaders/Private/BasePassPixelShader.usf、Shaders/Private/ColorSpace.ush、Shaders/Private/MaterialTemplate.ush、Shaders/Private/MobileBasePassPixelShader.usf、Shaders/Private/SceneData.ush、Source/Runtime/Core/Private/HAL/ConsoleManager.cpp、Source/Runtime/Engine/Classes/Particles/FastParticleSystemComponent.h、Source/Runtime/Engine/Classes/Particles/ParticleSystemComponent.h。引擎侧只保留必要接口/事件。
  3. 模块与构建规则
    Editor 工具放 Editor 模块（Shipping 自动剔除）；运行时逻辑放 Runtime 模块；如需引擎接口，见「引擎改动」列。

3. 代码级实现（开发用）

完全重构 改动方式：UE5 primitive uniform buffer 与批次绑定模型已变（无 AdditionalPrimitive 通道），必须改用 CustomPrimitiveData/MaterialParameterCollection 重写。

代码脉络：宏开启后新增全局 shader 参数结构 FAdditionalPrimitiveUniformShaderParameters（PrimitiveUniformShaderParameters.h:49-63），SceneView.cpp:40 IMPLEMENT_GLOBAL_SHADER_PARAMETER_STRUCT 并托管 GIdentityAdditionalPrimitiveUniformBuffer(:343)，FMeshMaterialShader 在 ShaderBaseClasses.cpp:668 按 FMeshBatch::AdditionalPrimitiveUniformBuffer(MeshBatch.h:56) 绑定。FParticleSystemSceneProxy 增 LuminanceScaleFactor/AlphaScaleFactor(ParticleHelper.h:3060-3076) 与 UpdateAdditionalPrimitiveUniformBuffer(ParticleSystemRender.cpp:10390)，组件侧 UParticleSystemComponent::SetLuminanceScale/SetAlphaScale(ParticleComponents.cpp:7608/7655) 经 ENQUEUE_RENDER_COMMAND 下发。

步骤 1Runtime/Engine/Public/PrimitiveUniformShaderParameters.hPrimitiveUniformShaderParameters.h:49-63

不再新增 FAdditionalPrimitiveUniformShaderParameters 全局结构，改用 UE5 既有的 CustomPrimitiveData

BEGIN_GLOBAL_SHADER_PARAMETER_STRUCT(FAdditionalPrimitiveUniformShaderParameters, ENGINE_API)
  SHADER_PARAMETER(float, RemapLuminanceScaleFactor)
  SHADER_PARAMETER(float, LuminanceScaleFactor)
  SHADER_PARAMETER(float, AlphaScaleFactor)
END_GLOBAL_SHADER_PARAMETER_STRUCT()
// UE5 PrimitiveUniformShaderParameters.h:72 已有：
// SHADER_PARAMETER_ARRAY(FVector4f, CustomPrimitiveData, [FCustomPrimitiveData::NumCustomPrimitiveDataFloat4s])
// 把 Luminance/Alpha 缩放写入 CustomPrimitiveData[x]，材质端用 Custom Primitive Data 节点取用。

⚠ UE5 无 SlotName/AdditionalPrimitive 绑定（ShaderBaseClasses 已无该分支），改法必须同时改材质

步骤 2Runtime/Engine/Private/Particles/ParticleComponents.cppParticleComponents.cpp:7608 SetLuminanceScale / :7655 SetAlphaScale

组件侧接口保留，下发目标从 SceneProxy->SetLuminance 换成 CustomPrimitiveData/MPC

ENQUEUE_RENDER_COMMAND(FPSC_UpdateParticleLuminanceScaleFactor)(
 [Proxy = SceneProxy, InLuminanceScale](FRHICommandList&){ static_cast<FParticleSystemSceneProxy*>(Proxy)->SetLuminance(InLuminanceScale); });
// 推荐零引擎改动：用 MaterialParameterCollection(全局/分类) + 动态材质实例
UParticleSystemComponent* PSC = ...;
PSC->SetScalarParameterValueOnMaterials(TEXT("LuminanceScale"), InLuminanceScale);
// 分类默认值由 FXDStaticParticleOptimizationCommonInfo 的映射表提供

⚠ 154 文件引用，改材质方案需同步改特效资源；注意与实例化方案兼容

风险评估

原代码风险：每帧比对 LuminanceScaleFactor!=Previous 才更新 UBO，跨 RT 用 mutable 缓存，存在数据竞争；RemapLuminanceScale 用 (x-0.5)*2 外插，HDR 下可能过曝/负值。

移植风险：走 CustomPrimitiveData 会占用项目已用的 custom data slot；材质必须重编，特效表现回归面极大。

开发自检

  • 粒子亮度/Alpha 分类缩放在 UE5 与 UE4 逐档一致
  • 材质重编后无 slot 冲突、HDR 不过曝
  • 移动端(ES3.1/Vulkan) CustomPrimitiveData 路径生效

结论置信度：medium — 项目是否已有 CustomPrimitiveData/MPC 占用需确认；UE5 是否有隐藏的额外 primitive buffer 通道未核实。
