0. 根因溯源（这个宏为什么存在）

XD 定制需求（非上游缺陷）

结论：UE4 fork 在 SSourceControlSubmit 里加 checkbox：读 GEditorIni [SourceControlSettings]/TargetContentFolder，把 FSubmitItem 分成 Filtered/UnFiltered 两份列表，勾选时切换 ListViewItems 并写回 bFileFilterCheckBoxChecked。纯编辑器便利，不涉运行时。

上游引入：XD fork 新增：SSourceControlSubmit.cpp:107-133/261-285/548/640-693、SSourceControlSubmit.h:175-188/238-243；作者 Lu Xun；注释引用 confluence pageId=567643804（XDBuildMiscConfiguration.cs:364-366）。UE4 目录非 git 仓库（无 .git），无法给出 XD 提交号。

上游历史（是否修过）：上游无此功能：UE5 5.8.2/ue5-main SSourceControlSubmit.h:203 ListViewItems=TArray<FChangelistTreeItemPtr>，cpp:179 MakeShared<FFileTreeItem>(Item)，rf 无 TargetContentFolder 过滤（Filter/SearchBox 无命中）。即上游从未实现，不存在修没修。

为什么可以断定不是「故意为之」4 条依据
  • 上游无对应代码路径，无所谓'Epic 故意不修'；这是 XD 产品需求（有 confluence 文档页）。
  • 上游提交窗口在本版本仍无过滤/搜索能力，说明 UE5 未视其为必要。
  • XD 用私有 ini 键 bFileFilterCheckBoxChecked/TargetContentFolder，上游 GEditorIni 无此键。
  • 按上游惯例会做成 SSearchBox/TFilterCollection 而不是两份列表互换，说明这是 XD 自定实现。

调用方契约：UE4：ListViewItems 是 ListView 的 ItemsSource，IsOKEnabled 也依赖其非空；OnCheckStateChanged_FilterFilesInTargetFoler(:641) 改指针后 RequestListRefresh。UE5 的 ListViewItems 会在提交/撤销时被动态增删（cpp:726 RemoveAll、:824/:922 判定），不再是静态列表。

内层真实语义：GEditorIni 无 TargetContentFolder → CanFilterFilesInTargetFoler()=false（checkbox 灰显 :670），只建一份列表；有 → 建两份并写盘(:642)，读回失败打 Warning 回落 Unchecked(:656)。失败/空路径均不崩溃。

代码库惯例：上游列表过滤用 SSearchBox+TFilterCollection；UE5 用 FFileTreeItem(继承 FChangelistTreeItem) 表达行（cpp:179、:1034 GetFileItem）。

为何长期未被发现：仅编辑器、仅提交时；无 TargetContentFolder 的工程自动禁用；GEditorIni 全局导致跨工程残留（risk_original 已指出）。

XD 侧的做法与意图：Torchlight 大量临时文件放在 Content 之外，需一键只显示目标目录、避免误提交。

⚠ 在 UE5 照抄'两个 TArray 成员+切换 ListViewItems'会坏：UE5 的 ListViewItems 在提交/撤销时 RemoveAll 动态变化(cpp:726/824)，两份副本会与勾选状态脱同步，导致漏提交或提交已撤下的文件；若只在 UI 层切列表而不重建 TreeItem，SortTree/全选/IsOKEnabled 仍基于未同步数据。

迁移方案（按根因定）

首选不移植（编辑器便利、收益低）。若保留：以 FChangelistTreeItem 派生 XD 过滤包装，或 SetItems 后统一走 RefreshFromFilter() 重建 ListViewItems（单一数据源）；勾选状态改存项目级 ini 而非全局 GEditorIni；用 ToolMenus/扩展槽挂载 UI，减少大段 #if 插桩。

根因级自检用例

  • 无 TargetContentFolder：checkbox 灰显、显示全部文件。
  • 有该键且勾选：只显示该目录文件，且提交文件集也只含这些（校数据而非仅视图）。
  • 切换工程：勾选状态不污染另一工程（per-project 存储）。
  • 全部文件都在目标目录外：ListViewItems 为空时 IsOKEnabled=false 与 UE4 一致。
  • 提交/撤销后再切换勾选：列表与勾选状态一致，无已移除文件残留。
