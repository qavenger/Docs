3. 代码级实现（开发用）

风险评估

原代码风险：字符串 Contains 在每文件路径上执行，仅 Debug/Dev 编译；Shipping 被 !UE_BUILD_SHIPPING 挡掉，风险低。

移植风险：不迁移则零影响；若迁 CVar 注意别留在 Shipping 热路径。

开发自检

  • xd.LogLoadTarget 1 后 Loading 日志出现 ACT_Drop_1HAxe 行
  • Shipping 构建无相关 Verbose 代码与 CVar

结论置信度：medium — UE5 AsyncLoading 的等价插入点需人工选（事件泵已重构）。

引擎内实现必须改引擎核心
—处置=删除的行不适用（已删除/不迁移）

引擎改动方式

L0 无需改引擎纯工程/插件/配置即可（对应「可工程化」）
L0 引擎内补丁需改引擎源码，但不必新增扩展点（对应「引擎内实现」）
L1 仅加接入点引擎只需暴露 Delegate / Interface / CVar 等扩展点
L2 结构性改动枚举 slot / 新 Pass / schema 字段
L3 深度侵入核心结构/生命周期/序列化，慎入
