避免 PSO LRU 重复淘汰（double eviction）导致的问题

部分覆盖 删除 引擎内实现 结构性改动 工作量 S风险 中开发者 （未署名）主要模块 RHI-Mobile

2. 修改步骤（删除）

  1. 确认删除原因
    覆盖度为「部分覆盖」，删除原因不是 UE5 覆盖，而是：double eviction 相关逻辑不复用。请先确认该功能当前确实不再需要（默认关闭 / 无引用 / 已被其它方案替代）。
  2. 删除 UE4 侧的宏与代码
    涉及位置：Source/Runtime/OpenGLDrv/Private/OpenGLShaders.cpp。删除后全仓搜索宏名应为 0 命中（含 Shaders、Plugins）。
  3. 回归验证
    删除宏，复核新 LRU 无重复淘汰

3. 代码级实现（开发用）

待独立 Agent 审核该草案尚未进入审核轮次：审核会打开 UE5 源码逐条核对行号、函数与 after 代码 引用的 API 是否存在。

完全重构 改动方式：UE5 LRU 已重写，FEvictedGLProgram 持 TUniqueObj<FOpenGLProgramBinary> 独占二进制，XD 的覆盖式重建无法照搬。

代码脉络：FGLProgramCacheLRU::EvictFromLRU(OpenGLShaders.cpp:1864) 入 EvictedPrograms 前有 checkf 非重入；宏在 :1881 先判 IsEvicted，若已淘汰则用 LRU 侧二进制重建 FEvictedGLProgram 并提前返回，避开重复淘汰。

步骤 1Runtime/OpenGLDrv/Private/OpenGLShaders.cppFGLProgramCacheLRU::EvictFromLRU l.1864

在 checkf 前加已淘汰守卫

#if XD_MISC_PSO_LRU_AVOID_REPEATED_EVICTION
if (IsEvicted(LinkedProgram->Config.ProgramKey))
{ UE_LOG(LogRHI,Warning,TEXT("already in the evicted program list, ignored"));
  EvictedPrograms.Emplace(LinkedProgram->Config.ProgramKey, FEvictedGLProgram(LinkedProgram));
  return; }
#endif
checkf(!EvictedPrograms.Contains(LinkedProgram->Config.ProgramKey), ...);
// UE5 :1616 EvictFromLRU，字段改 ProgramKey
if (EvictedPrograms.Contains(LinkedProgram->ProgramKey))
{
  UE_LOGF(LogRHI, Warning, "LRU: %ls already evicted, skip", *LinkedProgram->ProgramKey.ToString());
  return; // 不再 Emplace：UE5 二进制已 MoveTemp 移出，无法重建
}

⚠ UE5 仍保留 checkf(:1627)，重复淘汰仍会崩，故守卫必要

步骤 2Runtime/OpenGLDrv/Private/OpenGLShaders.cppIsEvicted(UE5 :1633)

确认可直接调用

bool IsEvicted(const FOpenGLProgramKey& ProgramKey)
// UE5 IsEvicted 已 public，内部可改为 EvictedPrograms.Contains

⚠ UE5 :1596 用 RemoveAndCopyValue 先移除，正常路径不会重入

风险评估

原代码风险：同一程序被重复淘汰触发 checkf 崩溃。

移植风险：守卫改为直接丢弃，需回归 GL 缓存回收与内存统计。

开发自检

  • LRU 压力测试无 checkf 崩溃
  • EvictedPrograms 计数正确

结论置信度：low — UE5 中 RepeatedEviction 是否仍可复现需实测；UE5 二进制独占使 XD 原重建逻辑不可用
