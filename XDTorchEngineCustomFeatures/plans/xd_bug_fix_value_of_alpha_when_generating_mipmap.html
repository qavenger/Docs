修复生成 Mipmap 时 Alpha 均值大于上一级（Alpha Scale 导致）

未覆盖 移植 需接入点 结构性改动 工作量 M风险 高开发者 Han Shu Bin主要模块 Engine

一句话结论：贴图 build settings + DDC key 变更，务必同步调整 DDC key 触发重烘焙

0. 根因溯源（这个宏为什么存在）

上游缺陷（需上游修复或长期携带补丁）

结论：mip 生成时 GenerateSharpenedMipB8G8R8A8Templ 以 AlphaThresholds!=0 判断是否调 ComputeAlphaScale；对默认 AlphaCoverageThresholds={0,0,0,1}，第 3 通道阈值=1 会被当成要保留覆盖，ComputeAlphaScale 仅缩放 alpha 通道，导致 alpha 均值逐级变大。XD 加 per-asset bForceUnitAlphaScale(Texture.h:717-720，EditorFactories.cpp:4554/4590 回写) 并在比值判定加 `&& !bForceUnitAlphaScale`(TextureCompressorModule.cpp:454)，同时写 DDC key(TextureDerivedData.cpp:106/369)。

上游引入：上游缺陷自 AlphaCoverageThresholds 引入 e581ead57267(2016-07-11 Gil Gribb) 起。XD 修复 XDBuildFixBugConfiguration.cs:290(默认1)。

上游历史（是否修过）：上游 52b23c8d20d8(2022-02-11 charles bloom，CL 18952713，首发布 5.3.0-preview-1) 自述 AlphaCoverageThresholds was accidentally enabled for all textures with thresholds={0,0,0,1}，新增 bool bDoScaleMipsForAlphaCoverage 与配置 EnableLegacyAlphaCoverageThresholdScaling 取代该启发式；UE5 TextureCompressorModule.cpp:977-980 改为 if(bDoScaleMipsForAlphaCoverage)，:1901-1903 加 check(thresholds!=0)。5.8.2/ue5-main 已修。

为什么可以断定不是「故意为之」4 条依据
  • 上游修复提交自述该行为是 accidental，直接否定故意
  • 默认阈值 {0,0,0,1} 让所有纹理都进 alpha 缩放，是宽泛误触发
  • 上游新增开关与 legacy 配置，说明旧启发式无法表达真实意图
  • 上游现在对 scaling+零阈值直接 check 失败，等于承认两者矛盾

调用方契约：UTexture::AlphaCoverageThresholds 与生成的 build settings.bDoScaleMipsForAlphaCoverage 决定 mip 生成；TextureDerivedDataBuildUtils.cpp:120 把该 bool 写入 DDC key，DDC 命中依赖其一致。

内层真实语义：正常(阈值非零且要缩放)：ComputeAlphaScale 保留覆盖。XD 意图：bForceUnitAlphaScale=true 时 AlphaScale=(1,1,1,1) 跳过缩放。空操作：阈值全 0 也跳过原有 path。

代码库惯例：UE5 以显式 bool 开关控制是否缩放(TextureCompressorModule.h:109)，并在派生数据序列化写 DDC 字段(TextureDerivedDataBuildUtils.cpp:120)。

为何长期未被发现：只影响 alpha 通道覆盖/裁剪(植被/UI 半透)，表现为逐级 mip alpha 偏大、边缘过厚，非崩溃，易归因美术。

XD 侧的做法与意图：给美术 per-Texture 开关，跳过 AlphaScale 使 mip alpha 均值不高于上一级，修正 alpha 覆盖/裁剪错误。

把 bForceUnitAlphaScale 直接映射为全局 bDoScaleMipsForAlphaCoverage=false：所有纹理都不做 alpha 覆盖缩放、画质回退并触发全量 DDC 重烘。移植字段却不改 DDC key：改开关不重烘→用错误旧数据。以为 UE5 的 check(thresholds!=0) 能替代：{0,0,0,1}+缩放仍会错误缩放，check 只在全 0 触发。

迁移方案（按根因定）

abandon XD 字段：UE5 用 bDoScaleMipsForAlphaCoverage 精确表达是否缩放。把原 bForceUnitAlphaScale=true 的纹理映射为 bDoScaleMipsForAlphaCoverage=false(或 AlphaCoverageThresholds 全 0)，并确保写入 DDC key。若仍要保留美术开关，则在 UTexture 加 bool 并在 TextureDerivedDataBuildUtils.cpp:120 附近补 DDC 字段，否则触发不当缓存；UE5 重烘语义变化大，需整批验证。

根因级自检用例

  • 阈值 {0,0,0,1} 且缩放关闭：生成 mip alpha 均值不高于上一级
  • 阈值有效且缩放开启：ComputeAlphaScale 生效、覆盖保留
  • 阈值全 0+缩放开启：UE5 check 触发(调用方错误)，编辑器侧需阻止或走 legacy 配置
  • DDC：切换开关后 key 变化、纹理重烘
  • 重烘后 mip 链 alpha 单调性正确

可反馈上游：最小复现：建纹理设 AlphaCoverageThresholds={0,0,0,1} 生成 mip，观察逐级 alpha 均值大于上一级；最小修复：仅当 bDoScaleMipsForAlphaCoverage 时才调 ComputeAlphaScale。UE4(≤4.27/5.2) 可复现，UE5 5.3+ 已修。

风险评估

原代码风险：AlphaScale 使生成 mip 的 alpha 均值大于上一级，导致 alpha 覆盖/裁剪错误。

移植风险：改 build settings + DDC key 会触发贴图全量重烘焙，耗时长；UE5 已用 bool 开关覆盖部分场景，语义映射需谨慎。

开发自检

  • 开启后各级 mip alpha 均值单调
  • 全量 DDC 重烘焙后无残留旧 key

结论置信度：high — UE5 的 bDoScaleMipsForAlphaCoverage 是否已覆盖原场景，是否仍需独立开关需与 TA 确认。
