修改草案 · XD_BUG_FIX_IOS_TEXT_INPUT_CRASH

修复 iOS 中文输入法导致文本框崩溃

部分覆盖 移植 引擎内实现 结构性改动 工作量 M风险 中开发者 Ran Qing Sen主要模块 Slate

一句话结论：iOS 中文输入法崩溃需在 UE5 新实现上复测，必要时补丁。

0. 根因溯源（这个宏为什么存在）

上游缺陷（需上游修复或长期携带补丁）

结论：IOSPlatformTextField::show: 旧实现无条件 release CachedTextContents 再 alloc，若入参 TextContents 正是缓存对象则 release 后立即读该已释放指针，中文输入法组字时随机崩溃。

上游引入：缺陷块在 4.26 fork 的 #else 分支（IOSPlatformTextField.cpp:226-236）：release 后无指针比较直接 initWithString:TextContents；-S 只命中 3b81cf820158(2020-09-24) 的合并，未能确认更早独立引入提交。XD 在 Zhao/Han 名下加宏修复（XDBuildFixBugConfiguration.cs）。

上游历史（是否修过）：已修：50944fd71202（2021-04-29，aurel cordonnier，Merge UE5/RES，代表 UE4/Main@16130047）加入 CachedTextContents != nil && CachedTextContents != TextContents 与 alloc 前 != 守卫，首发布 5.0.0-preview-1；UE5 5.8.2 IOSPlatformTextField.cpp:278-289、ue5-main:278-289 同语义。

为什么可以断定不是「故意为之」4 条依据
  • 若有意复用同一串，应跳过 release 而不是先释放再读——release 后立即 initWithString:TextContents 是典型 use-after-free。
  • 上游后来自己加了 CachedTextContents != TextContents 守卫，证明原写法是缺陷。
  • release 后未置 nil，正常路径本可只在指针不同时重建；三处不对称说明是漏判而非设计。
  • placeholder 也做同样比较，说明规则应为指针变化才重建。

调用方契约：show: 每次弹软键盘调用（UE4:208 / UE5:274），中文 IME 组字会把同一 NSString 回传给该入口。

内层真实语义：UE4 旧路径：release 传入对象后立即 initWithString:TextContents 读同一已释放指针→野指针；指针不同（正常）路径无异常。

代码库惯例：同文件 278-294 上游用指针比较，release 后 alloc 只在内容变化时执行。

为何长期未被发现：仅中文/第三方 IME 组字且文本回传同一 NSString 时触发，英文键盘不复现，崩溃点在 OC runtime随机。

XD 侧的做法与意图：fork IOSPlatformTextField.cpp:209-236 加指针比较，仅在不同指针时 release/alloc。

只 release 不 alloc 会丢文本；只 alloc 不 release 会泄漏；改成 autorelease 在手动 MRR 下会双重释放。

迁移方案（按根因定）

直接删除宏与 XDBuildFixBugConfiguration.cs:44 定义，采用 UE5 原生实现；回归中文 IME 连续开/关键盘（含 placeholder 相同字符串）。

根因级自检用例

  • 中文 IME 组字中反复开/关输入框（同一字符串）不崩溃
  • 传入不同 NSString 时旧缓存被释放且无泄漏（Instruments 验证）
  • TextContents 为 nil 时不触发 release/alloc 异常
  • placeholder 与 text 同指针/不同指针两种边界均正确
  • 英文键盘回归无行为变化
