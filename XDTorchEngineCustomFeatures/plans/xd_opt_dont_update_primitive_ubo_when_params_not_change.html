修改草案 · XD_OPT_DONT_UPDATE_PRIMITIVE_UBO_WHEN_PARAMS_NOT_CHANGE

图元 Shader 参数未变化时跳过 UBO 更新

部分覆盖 移植 引擎内实现 结构性改动 工作量 M风险 中开发者 Ran Qing Sen主要模块 Engine

一句话结论：UE5 GPUScene 已大幅降低该开销，建议先做 profiler 采样；确有热点再以 CVar 形式移植相等性缓存

背景：对比 PrimitiveShaderParameters（Primitive uniform buffer）内容，相同则不上传，降低移动端驱动开销。

0. 根因溯源（这个宏为什么存在）

XD 定制需求（非上游缺陷）

结论：XD 为省 UBO 上传，在 proxy 上缓存 FPrimitiveUniformShaderParameters 并手写字段比较；UE5 改为脏标记驱动 UpdateUniformBuffer，且多数 VF 根本不需要 PrimitiveUB。

上游引入：XD 自建：XDBuildOptConfiguration.cs:52-53=1；UE4 PrimitiveSceneProxy.h:1086-1088（CachedPrimitiveShaderParameters）、PrimitiveSceneProxy.cpp:393-433（operator==）、:478-501（分支）；D: 盘无 git 工作区。

上游历史（是否修过）：非上游 bug：UE5 5.8.2 PrimitiveSceneProxy.cpp:759-779 仍无条件 Build 并上传，但调用侧已变脏标记驱动——FPrimitiveSceneInfo::RequestUniformBufferUpdate（PrimitiveSceneInfo.cpp:2210-2218）写 Scene->PrimitivesNeedingUniformBufferUpdate（ScenePrivate.h:1758），在 RendererScene.cpp:6758-6777 消费；:765 加 DoesVFRequirePrimitiveUniformBuffer 门控（PrimitiveSceneProxy.h:837）。ue5-main 同。

为什么可以断定不是「故意为之」4 条依据
  • UE5 用位图脏标记（RendererScene.cpp:6659 CustomPrimitiveData 变更、:5226 反射捕获变更、PrimitiveSceneInfo.cpp:2213）表达同一意图，说明设 UBO 应由变更驱动而非逐帧比较
  • XD 的 IsMovable() 短路使缓存只对静态 proxy 生效（PrimitiveSceneProxy.cpp:479-490），而 UE5 静态 proxy 多数已不需要 PrimitiveUB（:765 门控），收益≈0
  • 手写 operator== 只比 25 字段+CustomPrimitiveData（:394-433），UE5 结构体已含 InstanceSceneDataOffset/NumInstanceSceneDataEntries/InstancePayload*/PersistentPrimitiveIndex/Nanite* 等 60 余字段（PrimitiveUniformShaderParameters.h:18-73），漏比即渲染错误
  • XD 未给字段覆盖任何测试/断言保护，若属有意设计应做结构体级比较而非手写列表

调用方契约：UniformBuffer 的消费者是所有需要 PrimitiveUB 的 mesh batch（RendererScene.cpp:6768-6776 批量调 Proxy->UpdateUniformBuffer）；缓存误判不更新时材质会拿到旧 LocalToWorld/Bounds/InstanceSceneDataOffset。

内层真实语义：正常：参数变化→UpdateUniformBufferImmediate 并回写缓存（UE4 :487-490）；不变→跳过上传（仅静态 proxy）；首次创建 UBO 时也写缓存（:498-500）；异常：operator== 误报不等只是多传一次（无害），漏字段则永久不更新。

代码库惯例：上游惯例是走 FPrimitiveSceneInfo 的 Request*Update + 位图（PrimitiveSceneInfo.cpp:2210-2218 RequestUniformBufferUpdate/RequestStaticMeshUpdate），不在 proxy 内保存副本比较。

为何长期未被发现：漏比较字段只在对应特性开启时出错（Nanite/实例化/MeshPaint/自定义数据），表现为视觉异常而非崩溃；IsMovable() 短路还掩盖了大部分静态 proxy 问题。

XD 侧的做法与意图：值=1；XD 目标 When PrimitiveShaderParameters don't change, skip ubo update（XDBuildOptConfiguration.cs:52），减少每帧 UBO 上传。

⚠ 把 UE4 的 operator== 原样搬到 UE5：漏比 InstanceSceneDataOffset(:20)/NumInstanceSceneDataEntries(:21)/InstancePayloadDataOffset(:53)/InstancePayloadDataStride(:55)/PersistentPrimitiveIndex(:59)/NaniteResourceID(:43) 会拿到过期实例数据与 Nanite 索引，出现错位/闪烁。⚠ 依赖 builder 产物比较也危险——BuildUniformShaderParametersInternal 与 Scene->BuildPrimitiveUniformShaderParameters_RenderThread（PrimitiveSceneProxy.cpp:784-797）会写入随帧变化的渲染器内部字段。

迁移方案（按根因定）

删宏（含 Cache 成员与 operator==）：UE5 已由脏标记 + VF 门控替代。若要进一步省，评估能否让更多 VF 声明不需要 PrimitiveUB（bVFRequiresPrimitiveUniformBuffer，PrimitiveSceneProxy.h:837），而不是加参数比较；若坚持保留比较，必须覆盖结构体全部字段并补新字段回归测试。

根因级自检用例

  • 静态 mesh 静止多帧：UpdateUniformBuffer 仅在脏标记置位时调用（RendererScene.cpp:6758）且视觉正确
  • 反射捕获变化（RendererScene.cpp:5226）后 PrimitiveUB 仍更新
  • CustomPrimitiveData 修改（RendererScene.cpp:6659）后材质读到新值
  • 实例化 ISMC+Nanite+MeshPaint 场景与关宏版本逐帧渲染一致（防漏字段）
  • 移动 proxy（IsMovable）每帧更新，速度/精度无回归

审核意见：锚点全部核实一致（UE4 PrimitiveSceneProxy.cpp:393-435 operator==（含 CustomPrimitiveData 循环）、:479-501 更新分支、PrimitiveSceneProxy.h:1086-1088 缓存成员；UE5 PrimitiveSceneProxy.cpp:759 UpdateUniformBuffer(FRHICommandList&)、:768-771 Builder、:773-777 守卫、Public/PrimitiveSceneProxy.h:1797 UniformBuffer 成员；UE5 确无 FPrimitive

代码脉络：XDBuildOptConfiguration.cs:53 定义；PrimitiveSceneProxy.h:1086 加 CachedPrimitiveShaderParameters，PrimitiveSceneProxy.cpp:393-435 定义 operator==，479-501 在 !IsMovable() 且参数不等时才 UpdateUniformBufferImmediate。

check(UniformBuffer);
if (UniformBuffer.IsValid())
{
#if XD_OPT_DONT_UPDATE_PRIMITIVE_UBO_WHEN_PARAMS_NOT_CHANGE
	if (IsMovable() || !(CachedPrimitiveShaderParameters == PrimitiveParams))
	{
		UniformBuffer.UpdateUniformBufferImmediate(RHICmdList, PrimitiveParams);
	}
	CachedPrimitiveShaderParameters = PrimitiveParams;

	UniformBuffer.UpdateUniformBufferImmediate(RHICmdList, PrimitiveParams);
#endif
}
步骤 2Engine/Private/PrimitiveSceneProxy.cppUpdateUniformBuffer (UE4:479-501)

改到 UE5 759-778 的 Builder 流程

#if XD_OPT_DONT_UPDATE_PRIMITIVE_UBO_WHEN_PARAMS_NOT_CHANGE
if (IsMovable()) { UniformBuffer.UpdateUniformBufferImmediate(PrimitiveUniformShaderParameters); }
else { if (!(CachedPrimitiveShaderParameters == PrimitiveUniformShaderParameters)) { Update(); } Cached = Params; }
#else /* 直接上传 */
#endif
FPrimitiveUniformShaderParameters PrimitiveParams = Builder.Build();
if (!UniformBuffer.IsValid()) { return; }
const bool bChanged = IsMovable() || !bHasCachedPrimitiveShaderParameters || !ArePrimParamsEqual(CachedPrimitiveShaderParameters, PrimitiveParams);
if (bChanged) { UniformBuffer.UpdateUniformBufferImmediate(RHICmdList, PrimitiveParams); CachedPrimitiveShaderParameters = PrimitiveParams; bHasCachedPrimitiveShaderParameters = true; }

⚠ UE5 无 FPrimitiveUniformShaderParameters 的 operator==，须按 PrimitiveUniformShaderParameters.h:18-60 逐字段比较；禁用 memcmp（含 padding）

风险评估

原代码风险：手写字段相等易漏字段→UBO 不更新，出现变换/剔除错误，且每 proxy 常驻数百字节。

移植风险：UE5 GPUScene 下多数 VF 已不需 PrimitiveUB(PrimitiveSceneProxy.cpp:753/765)，收益可能为 0；PositionHigh/Low 拆分再增漏比风险。

开发自检

  • 5000+ 静态物件滚屏无偏移跳动
  • RenderDoc 中 UBO 上传次数下降

结论置信度：medium — 建议先用 profiler 采样确认 RHIUpdateUniformBuffer 仍为热点，再决定是否移植。
