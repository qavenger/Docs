修改草案 · XD_OPT_COOK_ENABLE_CHERRY_PICK

Cook 支持 Cherry Pick 指定文件单独打进 Pak（热更用，依赖 XDLivePatch）

部分覆盖 插件化 可工程化 仅加接入点 工作量 M风险 中开发者 Yu Hang主要模块 Editor/UnrealEd

一句话结论：seed 注入用 ModifyCook 委托即可；XD 的 bShouldClearCookedContent/清单校验语义需在插件侧补齐

3. 代码级实现（开发用）

独立 Agent 审核通过

审核意见：引用点全部属实：CookOnTheFlyServer.cpp:30/9038/9236/9625/9975、CookOnTheFlyServer.h:146/434、CookCommandlet.cpp:745/919/1149，before 与 9038-9056 实际代码一致（bCookByCherryPick/GetBool/XDCherryPickManifest=/bShouldClearCookedContent=false）。UE5 落点亦核实：ICookInfo.h:339 UE::Cook::FDelegates::ModifyCook、GameDelegates.h:24

完全重构 改动方式：UE5 把「往 cook 注入额外包」正式化为扩展点（ModifyCook 委托 + GetExtraPackagesToCook），XD 直接改 cooker 内部的写法必须按新结构重写为插件。

代码脉络：CookOnTheFlyServer.cpp:9038-9054 在 sandbox 初始化时读 /Script/XDLivePatch.ProjectPackagingSettings 的 bCookByCherryPick 或 -XDCherryPickManifest=，命中即令 bShouldClearCookedContent=false，:9236/:9625/:9975 配合注入清单包并把失败传到 bCookByTheBookStartupError；CookOnTheFlyServer.h:146/434 与 CookCommandlet.cpp:745/919/1149 提供参数与开关。

用 ModifyCook 委托把 cherry-pick 清单包加进 cook seed

/* UE4: 直接改 UCookOnTheFlyServer 内部 FilesInPath / SeedPackages */
FGameDelegates::Get().GetModifyCookDelegate().AddLambda([](TConstArrayView<const ITargetPlatform*>, TArray<FName>& InOutPackagesToCook, TArray<FName>&){ for (const FString& P : CherryPickList){ InOutPackagesToCook.Add(FName(*P)); } });
// 或 UE::Cook::FDelegates::ModifyCook.AddLambda(... 写 FPackageCookRule)

⚠ UE5 亦支持 ITargetPlatform::GetExtraPackagesToCook

风险评估

原代码风险：cherry-pick 用「不清理 cooked 内容 + 只打清单包」组合，一旦清单与上次 pak 不一致会产生 pak 与运行时包集合不匹配（缺包/错包），且原逻辑无清单校验失败的原子回退。

移植风险：删掉引擎补丁后必须由插件等价实现 seed 注入与不清理语义，否则热更差包会缺内容；需回归热更包能正常 mount 与运行。

开发自检

  • 只改少量资产生成的 cherry-pick 包能正常挂载并生效
  • 清单为空/不存在时 cook 不产生半成品 pak

结论置信度：high — XD 原清单文件的格式与校验规则（本包只给了命令行/ini 名称）
