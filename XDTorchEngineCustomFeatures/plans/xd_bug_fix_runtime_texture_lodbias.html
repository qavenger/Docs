修改草案 · XD_BUG_FIX_RUNTIME_TEXTURE_LODBIAS

恢复运行时按设备档位（IOS_Mid/Android_Low）设置纹理 LODBias 的能力

部分覆盖 移植 可工程化 仅加接入点 工作量 S风险 中开发者 DU Peng主要模块 Engine

一句话结论：优先改用 DeviceProfile 的 mip bias CVar 达到分档效果；确需按 TextureGroup 分档再移植该分支（注意与 Cook 期裁剪重复叠加）

0. 根因溯源（这个宏为什么存在）

XD 定制需求（非上游缺陷）

结论：UTextureLODSettings::CalculateLODBias 中 Epic 于 2016-05-19(f180dff1073b, Matthew Griffin, 4.12) 把 UsedLODBias += LODBias + LODGroupInfo.LODBias 包进 if(!RequiresCookedData())，理由是 cook/DDC 已按 LODBias 剥离顶层 mip，运行期再叠加会 double-apply。XD 移动端需 IOS_Mid/Android_Low 细分档在运行期生效，故在 else 只补 LODGroupInfo.LODBias（UE4 TextureLODSettings.cpp:171-184，注释列明 TextureDerivedData/CalculateLODBias 调用链）。

上游引入：上游条件：f180dff1073b 2016-05-19 Matthew Griffin（4.12 起）；XD 4.26 fork 补 else：TextureLODSettings.cpp:171-184

上游历史（是否修过）：UE5 5.8.2 TextureLODSettings.cpp:268-278 仍只有 if(!RequiresCookedData()){LODBias; LODGroupInfo.LODBias(_VT); GlobalTextureLODBias;}，无 else。blame：f180dff1073b(条件+注释)、80c0ecb2666af 2020-12-02 Ben Ingram、9ccc373176403 2025-03-19 jeremy moore(加 LODBias_VT)、46fa60c91f3f1 2025-04-18 charles bloom。4.12→5.8.2 从未加运行期叠加。

为什么可以断定不是「故意为之」2 条依据
  • 这不是上游漏写：行内注释明写 Considering them again here would apply them twice，是刻意取舍
  • XD 动机是设备档覆盖——平台级档 cook 期生效，细分档需运行期生效，属 XD 运营需求而非引擎缺陷

调用方契约：CalculateLODBias 结果在 :329-333 转 WantedMaxLOD 用于流送/DDC；运行期由活动 UDeviceProfile 的 LODSettings 调用

内层真实语义：XD else 只加 LODGroupInfo.LODBias（TextureLODSettings.cpp:182），故意不含 LODBias/GlobalTextureLODBias；未命中细分档会回落平台档，同一档被应用两次（XD 注释已警告）

代码库惯例：同文件 :284-289 TEXTUREGROUP_UI 的 GUITextureLODBias 也在 if 外叠加，运行期额外叠加有先例

为何长期未被发现：差异只在 cooked 且命中细分档时少/多一层 mip，肉眼不可见，仅影响内存与带宽

XD 侧的做法与意图：让 IOS_Mid/Android_Low 细分档在真机运行期生效（TextureLODSettings.cpp:178-183 注释）

把 if 块三条整体复制进 else（或去掉 if）→ LODBias/GlobalTextureLODBias 与 cook 期剥离重复，纹理二次降 mip，正是上游注释警告的 double-apply

迁移方案（按根因定）

UE5 只新增 else{ UsedLODBias += bVirtualTexture ? LODGroupInfo.LODBias_VT : LODGroupInfo.LODBias; }，保留原 if 三条；删宏 XDBuildFixBugConfiguration.cs:602。先确认 DeviceProfiles 细分档确有覆盖，否则回落会双计

根因级自检用例

  • cooked 运行+细分级设备档：细分档 LODBias 生效且只生效一次
  • cooked 运行+仅平台档：不叠加，与 UE5 原生一致
  • 非 cooked(编辑器/DDC)：原 if 三条都叠加
  • VT 纹理用 LODBias_VT 而非 LODBias
  • GlobalTextureLODBias 运行期不被二次应用

风险评估

原代码风险：运行时与 cook 期重复叠加会二次降 mip，依赖细分设备档存在。

移植风险：影响所有运行时纹理 mip 选择(内存/带宽/画质)。

开发自检

  • Android_Low/IOS_Mid 与平台档不重复叠加
  • 纹理 mip/内存符合预期
  • VT 纹理 LODBias_VT 行为正确

结论置信度：medium — 项目是否真维护细分 DeviceProfile 的 LODBias 未知；UE5 是否有其它运行时 mip 偏置路径已替代需确认。
