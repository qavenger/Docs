修改草案 · XD_EXT_APPLYPARAMS_FOR_SPECIFIC_MAT_INDEX

支持只对指定材质索引应用参数覆盖

未覆盖 插件化 可工程化 无需改引擎 工作量 S风险 低开发者 Peng TianCheng主要模块 Engine

一句话结论：纯项目侧工具函数即可替代引擎 API 扩展

1. UE5 现状与证据

结论依据：Runtime/Engine/Classes/Components/MeshComponent.h:210 SetScalarParameterValueOnMaterials(FName,float) 无 MatIndex 参数（XD 版为 const int MatIndex=-1）

覆盖说明：UE5 未提供按材质索引覆盖参数

证据路径（UE5.8.2）行号核对结果
Runtime/Engine/Classes/Components/MeshComponent.h210✅ 已命中：Source/Runtime/Engine/Classes/Components/MeshComponent.h

覆盖度：未覆盖  处置：插件化

2. 修改步骤（插件化）

  1. 确定插件/模块归属
    项目模块封装 helper：GetMaterial(Index) + MID SetScalarParameterValue/SetVectorParameterValue，无需改引擎 API
  2. 实现主体逻辑
    把原引擎内实现迁到插件：Source/Runtime/Engine/Classes/Components/MeshComponent.h、Source/Runtime/Engine/Private/Components/MeshComponent.cpp。引擎侧只保留必要接口/事件。
  3. 模块与构建规则
    Editor 工具放 Editor 模块（Shipping 自动剔除）；运行时逻辑放 Runtime 模块；如需引擎接口，见「引擎改动」列。

3. 代码级实现（开发用）

独立 Agent 审核通过

审核意见：核实：UE4 MeshComponent.h:117/124 与 .cpp:264/273/317/355/364/410 的 XD_ 条件均为 //#if（宏无活引用），带 MatIndex 的签名在 :265/:356 无条件生效，越界点在 .cpp:276/320/367/413；UE5 MeshComponent.h:210/:214 无 MatIndex。abandon+项目 helper 合理。可把 change_type 视作 refactor（语义靠项目侧保留），但结论一致。

建议舍弃 改动方式：UE5 未提供该扩展且工程可纯项目侧替代，不必改引擎 API（宏本身也无真实引用）。

代码脉络：def XDBuildMiscConfiguration.cs:435。注意：UE4 里所有 #if 均被注释掉（MeshComponent.cpp:264/273/317/355/364/410，MeshComponent.h:117/124 均为 //#if），因此带 MatIndex 的签名是无条件生效的，宏本身没有活的源码引用。实际的 API 改动是 UMeshComponent::SetScalarParameterValueOnMaterials(FName,float,int MatIndex=-1)（MeshComponent.cpp:265）与 SetVectorParameterValueOnMaterials(...,int MatIndex=-1)（:356），在 MatIndex!=-1 时只改指定索引材质。UE5 MeshComponent.h:210/214 无 MatIndex 参数。

步骤 1Runtime/Engine/Classes/Components/MeshComponent.hMeshComponent.h:117-128

不移植引擎签名的 MatIndex 改动

//#if XD_EXT_APPLYPARAMS_FOR_SPECIFIC_MAT_INDEX
void SetScalarParameterValueOnMaterials(const FName ParameterName, const float ParameterValue, const int MatIndex = -1);
//#else
//void SetScalarParameterValueOnMaterials(const FName ParameterName, const float ParameterValue);
//#endif
// UE5 MeshComponent.h:210 保持 (FName,float)；项目侧自行封装 helper

用项目 helper 实现按索引覆盖参数

UMaterialInstanceDynamic* MID = Comp->CreateAndSetMaterialInstanceDynamic(Index); MID->SetScalarParameterValue(Name, Value);
static void SetScalarOnMatIndex(UMeshComponent* C, int32 Index, FName Name, float V){ if (UMaterialInstanceDynamic* MID = C->CreateDynamicMaterialInstance(Index, C->GetMaterial(Index))) MID->SetScalarParameterValue(Name, V); }

⚠ 如需引擎内 QoL 可另行加带默认参数的覆写，但非必需。

风险评估

⚠ 与早期迁移处置结论存在分歧：早期结论=要移植，代码级分析=建议舍弃。早期结论=插件化，代码级分析=建议舍弃；建议以代码级分析为准并回写评估矩阵。

原代码风险：MatIndex 未做越界校验即 MaterialInterfaces[MatIndex]（MeshComponent.cpp:276/320/367/413），非法索引会越界崩溃。

移植风险：改为项目侧后不存在引擎越界风险；但工程若已调用带 MatIndex 的引擎 API，需替换为 helper，遗漏则编译失败。

开发自检

  • 项目侧按索引覆盖参数生效
  • 无遗留对 Set*ParameterValueOnMaterials(...,MatIndex) 的调用

结论置信度：medium — 需全仓库确认是否有工程代码依赖带 MatIndex 的引擎重载。
