修改草案 · XD_MISC_MESH_PARTICLES_USE_STATIC_MESH_MIN_LOD

用 StaticMesh 的 MinLOD 控制网格粒子 LOD（即使 fx.FXAllowParticleMeshLODs=0，UE4-7141）

部分覆盖 配置化 可工程化 无需改引擎 工作量 S风险 低开发者 Lu Xun主要模块 仅定义（无引用）

一句话结论：直接配置开启 UE5 原生路径，无需移植 XD 代码

可主动舍弃性（UE5 架构更替）

直接舍弃 Cascade 粒子 → Niagara

判定依据：UE5 特效体系已全面转向 Niagara，Cascade 仅保留兼容维护；项目迁移到 UE5 后特效会重做，针对 Cascade 运行时的定制可在迁移时直接不带过去。

舍弃前提：前提：迁移后在 UE5 用 Niagara 重做特效（不再走 Cascade 运行时）

UE5 替代能力：Niagara（NiagaraSystem / NiagaraComponent / NiagaraDataInterface）

1. UE5 现状与证据

结论依据：UE5 ParticleSystemRender.cpp:1157-1165 GetMeshLOD 已有 StaticMesh->GetMinLODIdx() 钳制逻辑，但被 if(!InOwnerProxy || !GFXAllowParticleMeshLODs) 提前返回（cvar fx.FXAllowParticleMeshLODs 默认 0，:82）

覆盖说明：能力有，被开关挡住

证据路径（UE5.8.2）行号核对结果
ParticleSystemRender.cpp1157✅ 已命中：Source/Runtime/Engine/Private/Particles/ParticleSystemRender.cpp

覆盖度：部分覆盖  处置：配置化

2. 修改步骤（配置化）

  1. 确定配置承载
    打开 fx.FXAllowParticleMeshLODs（DefaultEngine.ini/DeviceProfile）+ 资产 StaticMesh MinLOD 设置
  2. 设定默认值与灰度
    默认值应与当前线上行为一致；通过 ini/DeviceProfile 按平台/机型灰度，可随时回滚。
  3. 清理宏
    删除 UE4 宏与 （无源码引用记录） 中的编译期分支，改为读取配置。

3. 代码级实现（开发用）

待独立 Agent 审核该草案尚未进入审核轮次：审核会打开 UE5 源码逐条核对行号、函数与 after 代码 引用的 API 是否存在。

简单移植 改动方式：UE5 ParticleSystemRender.cpp:1157-1165 已内置用 StaticMesh->GetMinLODIdx() 钳制 Mesh LOD 的逻辑，无需移植代码，只需打开 CVar。

代码脉络：仅配置开关，无源码引用（仅 XDBuildMiscConfiguration.cs:418 定义，UE4 引擎源码无任何 XD_MISC_MESH_PARTICLES_USE_STATIC_MESH_MIN_LOD 引用）。其意图由 UE5 原生 GetMeshLOD 实现。

步骤 1Config/DefaultEngine.ini 或 DeviceProfileUE5 ParticleSystemRender.cpp:82 CVarFXAllowParticleMeshLODs

把 fx.FXAllowParticleMeshLODs 设为 1（UE4 用宏绕过的判断）

static int32 GFXAllowParticleMeshLODs = 0;
static FAutoConsoleVariableRef CVarFXAllowParticleMeshLODs(
	TEXT("fx.FXAllowParticleMeshLODs"), GFXAllowParticleMeshLODs, ...);
[SystemSettings]
fx.FXAllowParticleMeshLODs=1   ; 或 DeviceProfile ConsoleVariables

⚠ UE5 :1149-1157 `if (!InOwnerProxy || !GFXAllowParticleMeshLODs) return FirstAvailableLOD;`，打开后才会执行 :1157 起的 MinLOD 钳制。

步骤 2Source/Runtime/Engine/Private/Particles/ParticleSystemRender.cppGetMeshLOD (ParticleSystemRender.cpp:1157-1165)

无需改代码，仅确认 MinLOD 钳制路径（ClampedMinLOD = Clamp(GetMinLODIdx(), FirstAvailableLOD, MaxLOD)）符合预期

const int32 EffectiveMinLOD = StaticMesh->GetMinLODIdx();
const int32 MaxLOD = StaticMesh->GetRenderData()->LODResources.Num() - 1;
const int32 ClampedMinLOD = FMath::Clamp(EffectiveMinLOD, FirstAvailableLOD, MaxLOD);
// 保持 UE5 原生实现；如需强制即使 CVar=0 也生效，可改成忽略 GFXAllowParticleMeshLODs 的早退

⚠ 若要完全等价 UE4（无视 fx.FXAllowParticleMeshLODs=0），需删/改 :1149 早退条件——建议先只走 CVar。

风险评估

原代码风险：该宏在 UE4 无源码引用，历史上可能通过其它手段（FXAllowParticleMeshLODs=0）规避，风险低。

移植风险：打开 mesh particle LOD 会改变网格粒子外观与开销，需美术确认；且 StaticMesh 的 MinLOD 设置不当会导致低模穿帮。

开发自检

  • 开启后网格粒子按 StaticMesh MinLOD 降级显示
  • 关 CVar 恢复原行为；不同 DeviceProfile 生效正确

结论置信度：high — 是否需要无视 CVar 强制生效（UE4 语义）需与美术/性能确认。
