修改草案 · XD_BUG_FIX_CRASH_ON_CREATE_GL_PROGRAM_FROM_BINARY

从二进制创建 GL Program 崩溃时跳过并回退到运行时编译

未覆盖 移植 引擎内实现 结构性改动 工作量 S风险 中开发者 Han Shu Bin主要模块 RHI-Mobile

一句话结论：在 UE5 GL 程序缓存上重打 Fatal→回退补丁（常开保留）

可主动舍弃性（UE5 架构更替）

需评估 旧 RHI / 平台图形路径

判定依据：UE5 的 RHI 层有增删（部分旧路径废弃、移动端默认管线变化），需按目标平台复核。

舍弃前提：需确认：新工具链/新插件/新 RHI 下该问题是否仍存在

UE5 替代能力：UE5 保留的 RHI（D3D12/Vulkan/Metal），部分旧路径已淘汰

相关文件：Source/Runtime/OpenGLDrv/Private/OpenGLShaders.cpp Source/Runtime/OpenGLDrv/Public/OpenGLShaderResources.h

1. UE5 现状与证据

结论依据：Runtime/OpenGLDrv/Private/OpenGLShaders.cpp:3455-3461 二进制建 program 失败即 Fatal（仅 PanicDelegate 上报）；XD 的『Unset+移出映射、回退编译』无等价实现（FOpenGLProgramBinaryCache 已改为 bIsOwned，见 OpenGLProgramBinaryFileCache.cpp:1098-1119）

覆盖说明：GL PBC 已重写，但失败路径仍为 Fatal（仅可挂 RHIGetPanicDelegate 上报），无 XD 式显式跳过/回退

3. 代码级实现（开发用）

独立 Agent 审核并修正修正 3 处　提出问题 4 条　其中高风险 1 条

审核意见：step0（Fatal→回退、不注册坏 program）方向正确且证据扎实；但 step1 的 before 伪造为 UE4、且混入另一宏，step1.after 未真正修状态，需按上面修正。

完全重构 改动方式：UE5 PBC 反序列化链已重写（CompleteLoadedGLProgramRequest_internal→OnGLProgramLoadedFromBinaryCache，返回 void 且失败仍 Fatal，OpenGLShaders.cpp:3455-3460），须按新结构重加回退；LRU 恢复路径的降级属另一宏。

代码脉络：从 PBC 反序列化程序时不再直接 Fatal：FOpenGLProgramBinaryCache::ScanProgramCacheFile 读出二进制后调 CompleteLoadedGLProgramRequest_internal（OpenGLShaders.cpp:5574）改为返回 bool，失败时把 entry 的 GLProgramState 置 Unset 并丢弃 ProgramBinaryData，AddProgramFileEntryToMap 被跳过（:4695-4717 / :4889-4911）；UseCachedProgram(:5405) 遇 Unset 直接 return false 回退到运行期编译；CheckSinglePendingGLProgramCreateRequest_internal(:5640-5706) 同样把失败 entry 移出。

风险评估

原代码风险：旧实现失败即 Fatal，模拟器/驱动返回坏二进制会直接崩；且 entry 会带 Unset 状态进入 ProgramToBinaryMap 引发后续 check。

移植风险：回退到运行期编译可能掩盖驱动问题并引入首帧卡顿；须确认失败 program 不会残留在 ProgramToBinaryMap / LRU。

开发自检

  • 注入坏程序二进制，验证不再崩而走运行期编译
  • LRU/非 LRU 两条路径均验证
  • 确认无残留 entry（NumPrograms 与 map 一致）

结论置信度：medium — UE5 mmap 存储（TUniqueObj<FOpenGLProgramBinary>）下丢弃后是否需显式 unmap，需看具体分配器实现
