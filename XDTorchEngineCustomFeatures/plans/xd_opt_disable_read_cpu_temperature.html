关闭读取 CPU 温度文件（Oppo 机型读取时会掉帧）

0. 根因溯源（这个宏为什么存在）

平台/工具链绕行

结论：XD 注释称 Oppo 机型读温度文件掉帧，故在 FAndroidMisc::GetCPUTemperature 首行恒返回 0。真实触发路径是 FAndroidStats::UpdateAndroidStats 在 GT 上按 0.1s 间隔 fopen（UE4 AndroidStats.cpp:124-130），并非每帧。

上游引入：XD 自建：XDBuildOptConfiguration.cs:55-56=1（注释 Oppo device may lost fps when read cpu temperature from file）；UE4 AndroidPlatformMisc.cpp:3696-3700；D: 盘无 git 工作区，无提交号。

上游历史（是否修过）：非上游 bug：UE5 5.8.2 AndroidPlatformMisc.cpp:3310 函数结构与 UE4 相同（:3313 判空缓冲、:3318 fopen），上游未加开关；但 UE5 已把采集整体移入后台任务（AndroidStats.cpp:368 UE::Tasks::Launch，注释 Run everything in a background task thread so that long system calls won't lock up game thread，:436 才调 GetCPUTemperature），频率也做成 CVar（:109-116 Android.CPUStatsUpdateRate，默认 0.1s，帮助文本写明 0 to disable）。

为什么可以断定不是「故意为之」4 条依据
  • 上游在 UE5 明确用后台任务消除 GT 停顿（AndroidStats.cpp:364 注释），说明作者知道 fopen 会卡 GT，选择异步而非禁用
  • 温度与 GetThermalStress/GThermalStatus 一起构成真机过热遥测，上游不会主动删
  • 可配置点已存在（Android.CPUStatsUpdateRate=0、android.CPUThermalSensorFilePath，AndroidPlatformMisc.cpp:117-122/252-274），无需改码
  • XD 注释只提 Oppo 机型，属设备特异现象而非普适引擎缺陷

调用方契约：唯一调用方是 FAndroidStats::UpdateAndroidStats（AndroidStats.cpp:436；UE4 侧 :130），结果写入 CSVStatValues.CPUTemp 供 CSV/STATS 输出；恒返回 0 会让该遥测列永久为 0。

内层真实语义：正常：fopen 成功→按位数折算 XX.X 返回；无传感器→缓冲为空直接 return 0（AndroidPlatformMisc.cpp:3313-3316）；打不开文件→Temp 保持 0 返回；XD 版：任何情况都 0，且 #if 后原逻辑仍保留未清理。

代码库惯例：上游惯例是能力开关用 CVar/ini 而非编译期宏：AndroidPlatformMisc.cpp:117-122 android.CPUThermalSensorFilePath、AndroidStats.cpp:109-123 CPUStatsUpdateRate/HWCPipeStatsEnabled，路径可用 GEngineIni 的 ThermalSensors.SensorLocations 覆盖（:252-274）。

为何长期未被发现：fopen 每 0.1s 一次、耗时依机型，UE4 中位于 GT；表现为个别机型掉帧且无日志；温度不参与任何逻辑，只有遥测，禁用的副作用长期无人察觉。

XD 侧的做法与意图：值=1；XD 在函数首行直接 return 0.0f（AndroidPlatformMisc.cpp:3698-3700），完全不读文件。

⚠ 原样搬 UE4 的 #if return 0：UE5 会连带丢掉 ThermalStats 与真机过热回归数据（CSV 全 0）。⚠ 用 android.CPUThermalSensorFilePath 指向不存在路径来关闭并不可靠——回调只校验长度不校验存在（:196-211），结果仍是每 0.1s 一次失败 fopen。⚠ 误以为必须改码：Android.CPUStatsUpdateRate=0 是官方开关，但会连 CPU 频率/占用统计一起关。

迁移方案（按根因定）

首选删宏：UE5 已在后台线程读温度，GT 抖动根因消失；若仍要完全关闭，用 Android.CPUStatsUpdateRate=0（代价是全部 CPU 统计关闭）。不要保留 return 0 的引擎改动，否则真机温度遥测永久失效。

根因级自检用例

  • Android 真机开 STATS/CSV：CPUTemp 有非 0 值且 GT 无抖动（对照 CPUStatsUpdateRate=0/0.1）
  • 无温度传感器设备：返回 0 且不崩（缓冲为空分支）
  • CPUStatsUpdateRate 热改为 0 后不再有 fopen（日志/strace 验证）
  • 后台任务与 CSVStatsLock 并发下 FCPUStatValues 读写无竞争
  • 关宏后 GThermalStatus/ThermalStress 等 CSV 列仍正常

风险评估

原代码风险：每帧读 /sys 温度文件在部分 Oppo 机型掉帧（宏注释即此意）；读取失败仅返回 0。

移植风险：仅改 Android Core 一处；宏关闭时行为与 UE5 完全一致。

开发自检

  • 宏=0 时温度值同改动前
  • Oppo 机型宏=1 时掉帧消失

结论置信度：high
