允许访问 UParticleModuleRequired 的 BoundingGeometryBuffer 属性

部分覆盖 移植 引擎内实现 仅加接入点 工作量 S风险 低开发者 Han Shu Bin主要模块 Engine

一句话结论：小改头文件即可，注意 WITH_EDITOR 条件与打包影响

可主动舍弃性（UE5 架构更替）

直接舍弃 Cascade 粒子 → Niagara

判定依据：宏只是把 Cascade 的 UParticleModuleRequired::BoundingGeometryBuffer（FSubUVBoundingGeometryBuffer*）在编辑器下开放为 public/private（UE4 ParticleModuleRequired.h:494-503），完全绑定 Cascade 模块资产结构。

舍弃前提：项目在 UE5 用 Niagara 重做特效，不再维护 Cascade 模块

UE5 替代能力：Niagara SubUV/材质与渲染器绑定（无等价 Cascade 资产字段）

3. 代码级实现（开发用）

独立 Agent 审核通过提出问题 1 条

审核意见：before/after 与 UE4 真实代码一致（D:/.../ParticleModuleRequired.h:494-503），宏注入点 XDBuildToolsConfiguration.cs:121、GlobalDefinitions（TargetRules.cs:2778）、CppCompileEnvironment.cs:691 均核实无误，仅 UE5 行号略偏。

简单移植 改动方式：UE5 同头文件 ParticleModuleRequired.h:504-518 的成员顺序与 UE4 完全一致，只需把同一段 #if 访问级切换贴回

代码脉络：宏只在 ParticleModuleRequired.h:493-503 做访问级切换：把默认 private 的 FSubUVBoundingGeometryBuffer* BoundingGeometryBuffer 在 WITH_EDITOR 下暴露为 public，供 XD 编辑器工具读 GPU 端 bounding geometry。引擎自身只通过 ParticleModuleRequired.h:449 GetBoundingGeometrySRV() 和 ParticleModules.cpp:1422 InitBoundingGeometryBuffer() 使用它，宏开启不改变逻辑，只改可见性。

//Allow access 'BoundingGeometryBuffer' property in UParticleModuleRequired.
public static int XD_TOOL_ALLOW_ACCESS_BOUNDING_GEOMETRY_BUFFER = 1;
// Engine/Source/UnrealEditor.Target.cs 构造函数内（或项目 Target.cs）
GlobalDefinitions.Add("XD_TOOL_ALLOW_ACCESS_BOUNDING_GEOMETRY_BUFFER=1");
// 若沿用 UBT 反射式注入：UE5 UBT 的 CppCompileEnvironment.Definitions 见
// Source/Programs/UnrealBuildTool/System/CppCompileEnvironment.cs:691

⚠ GlobalDefinitions 只加到当前 Target；Runtime 与 Editor 目标要都加，否则头文件两个分支编译出不同布局

风险评估

原代码风险：把 GPU 缓冲区指针暴露为 public，外部代码可能绕过 ReleaseFence/渲染线程规则直接访问，打包(非 WITH_EDITOR)下行为不同

移植风险：纯访问级改动，但 UHT/头文件可见性变化会触发大量重编；若忘记在 Shipping 目标定义该宏，会出现编辑器/运行时头文件布局不一致

开发自检

  • WITH_EDITOR 下 XD 工具能编译并读到 BoundingGeometryBuffer
  • 打包目标编译通过且 #if 为 0 分支无引用残留

结论置信度：high — UE4 引擎树内未见读取该成员的消费者（应在上层项目/编辑器插件），其 UE5 版本是否仍在用需人工确认
