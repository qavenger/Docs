提交前事件发送（CI/检查流程挂钩）

未覆盖 接入点 需接入点 仅加接入点 工作量 S风险 低开发者 Huang Chen主要模块 Plugins/ContentBrowser

一句话结论：最小侵入：引擎只留一个广播委托，业务逻辑全在项目插件

1. UE5 现状与证据

结论依据：E:/TorchLight_UE5/Engine/Engine/Source/Editor 无 FSourceControlWindows::OnCheckinPackages（grep OnCheckinPackages 无命中）

覆盖说明：UE5 无 checkin 前广播委托

覆盖度：未覆盖  处置：接入点

2. 修改步骤（接入点）

  1. 引擎侧只加接入点
    需要的接入点：FSourceControlWindows::OnCheckinPackages（bool& 是否继续, const TArray<FString>& 包列表）（机制：Delegate）。引擎改动应最小、稳定、无业务语义。
  2. 插件侧实现完整逻辑
    引擎在 FSourceControlWindows 暴露一个 multicast 委托，项目插件订阅后接 CI/检查流程
  3. 无插件时的行为
    未绑定接入点时应回退到官方默认行为（引擎侧不能假设插件存在）。

3. 代码级实现（开发用）

独立 Agent 审核通过

审核意见：全部锚点核实：UE4 SourceControlWindows.h:38-41 委托+静态实例、cpp:40-42 定义、:269-276 广播；UE5 class FSourceControlWindows(SourceControlWindows.h:89)、成员用 UE_API(:135/:147，类无 SOURCECONTROLWINDOWS_API)、cpp PromptForCheckin:314、CombinedFileList.Append(FilesForSubmit):476、Num()==0 早退 :480-491，故广播必须放在 :491 之后，草案描述正确。

简单移植 改动方式：UE5 的 FSourceControlWindows/PromptForCheckin 结构未变，只需加委托声明+广播两段代码（宏去掉常开）。

代码脉络：SourceControlWindows.h:38 声明 FOnCheckinPackages 多播委托（bool& 是否继续 + 文件列表），SourceControlWindows.cpp:40 定义静态实例，:269 在 FSourceControlWindows::PromptForCheckin 内、MarkForAdd/Checkin 之前广播并可用 return false 中断提交。UE5 同文件同函数仍在（Public/SourceControlWindows.h:89、Private/SourceControlWindows.cpp:314 PromptForCheckin）。

风险评估

原代码风险：多播委托无数量/异常保护，任一订阅者 return false 会静默取消整个提交；引擎内静态实例在模块卸载时可能悬垂。

移植风险：只影响编辑器提交流程；若项目插件订阅后抛异常/长时间阻塞，会卡住 Checkin 对话框。

开发自检

  • 无订阅者时提交流程与原生 UE5 完全一致
  • 订阅者置 false 时点击 OK 后不提交且提示取消
  • 插件热重载/关闭编辑器无崩溃

结论置信度：high — UE5 是否另有更合适的 checkin 前 hook（如 UEditorValidatorSubsystem）可替代，需与工具组确认。
