修改草案 · XD_MATERIAL_SELECTOR_SWITCH_NUM

材质 Selector Switch 的最大节点数（当前 7）

未覆盖 配置化 需接入点 仅加接入点 工作量 S风险 中开发者 Yu Hang主要模块 Engine

一句话结论：硬编码 7 改为配置项，注意数值变化会影响 shader hash/permutation 数量

背景：整数宏，决定材质中可用的选择器数量上限。

1. UE5 现状与证据

结论依据：none（UE5 无 Selector Switch，无对应常量）

覆盖说明：UE5 无该能力，仅作为 XD selector 实现的上限常量

覆盖度：未覆盖  处置：配置化

2. 修改步骤（配置化）

  1. 确定配置承载
    数值本身应改为 ini/CVar（如 r.Material.SelectorSwitchMaxNum），但仍需引擎读取该配置
  2. 设定默认值与灰度
    默认值应与当前线上行为一致；通过 ini/DeviceProfile 按平台/机型灰度，可随时回滚。
  3. 清理宏
    删除 UE4 宏与 Source/Runtime/Engine/Classes/Materials/MaterialExpressionStaticSwitchParameter.h、Source/Runtime/Engine/Private/Materials/HLSLMaterialTranslator.cpp、Source/Runtime/Engine/Private/Materials/MaterialExpressions.cpp、Source/Runtime/Engine/Private/Materials/MaterialInstance.cpp 中的编译期分支，改为读取配置。

3. 代码级实现（开发用）

待独立 Agent 审核该草案尚未进入审核轮次：审核会打开 UE5 源码逐条核对行号、函数与 after 代码 引用的 API 是否存在。

完全重构 改动方式：该常量只服务于 selector 子系统，而 UE5 需整体重建该子系统，顺带把 7 改成配置项。

代码脉络：数值 7 被硬编码在 selector 子系统的两处：MaterialInstance.cpp:72/102 的 FStaticSwitchParameter 手工序列化校验，以及 MaterialExpressions.cpp:8138/8148/8182 的 selector 越界与 UE_ARRAY_COUNT(Inputs) 断言。UE5 无该能力、无对应常量。

步骤 1Runtime/Engine/Private/Materials/MaterialInstance.cppUE4 :72 与 :102 FStaticSwitchParameter operator<<

改读 CVar/ini，不再编译期硬编码

if (C <= XD_MATERIAL_SELECTOR_SWITCH_NUM && D >= 1) { B = 7; } else { check(C == 0); check(D == 0); }
static int32 GSelectorSwitchMaxNum = 7;
static FAutoConsoleVariableRef CVarSelectorSwitchMaxNum(TEXT("r.Material.SelectorSwitchMaxNum"), GSelectorSwitchMaxNum, TEXT("max selector switch node count"));
if (C <= GSelectorSwitchMaxNum && D >= 1) { B = 7; } else { check(C == 0); check(D == 0); }

⚠ B=7 是格式标记，别跟着改；序列化路径读 CVar 会让 cook 产物依赖运行配置，建议只读启动时固定的 ini 值。

步骤 2Runtime/Engine/Private/Materials/MaterialExpressions.cppUE4 :8138 越界检查、:8148/:8182 UE_ARRAY_COUNT(Inputs)

用运行时上限 + 数组长度双保险

if (Value < 0 || Value > XD_MATERIAL_SELECTOR_SWITCH_NUM) { return Compiler->Errorf(...); }
check(XD_MATERIAL_SELECTOR_SWITCH_NUM == UE_ARRAY_COUNT(Inputs));
const int32 MaxSelectorNum = IConsoleManager::Get().FindConsoleVariable(TEXT("r.Material.SelectorSwitchMaxNum"))->GetInt();
if (Value < 0 || Value > FMath::Min(MaxSelectorNum, (int32)UE_ARRAY_COUNT(Inputs))) { return Compiler->Errorf(TEXT("Static selector switch index %d out of range"), Value); }

⚠ UPROPERTY Inputs 数组长度由类声明固定（编辑器 7），CVar 只能放宽/收紧运行时校验，不能改属性个数；数值变化会改 shader hash。

风险评估

原代码风险：硬编码 7 使 shader permutation 数与属性数量强耦合，改一个数字要同时改 3 处否则断言/越界。

移植风险：改成配置后若与 UPROPERTY 输入数量不一致会运行时才报错；hash 随数值变化，需全量重编 shader。

开发自检

  • 默认 7 时与旧行为一致（序列化/编译结果不变）
  • 把 CVar 调到 8 或 6，确认不越界且报错清晰
  • 材质编辑器里 selector 节点连线数校验正常

结论置信度：medium — UE5 侧该子系统的最终节点数上限是否仍为 7，需与材质组确认。
