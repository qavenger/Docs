修复 Xcode Metal Validation 开启时 Vertex Buffer 视图校验报错

UE5 已覆盖 删除 可工程化 无需改引擎 工作量 S风险 低开发者 Ran Qing Sen主要模块 RHI-Apple

一句话结论：需开 Metal Validation 实机验证一次

可主动舍弃性（UE5 架构更替）

需评估 旧 RHI / 平台图形路径

判定依据：UE5 的 RHI 层有增删（部分旧路径废弃、移动端默认管线变化），需按目标平台复核。

舍弃前提：需确认：新工具链/新插件/新 RHI 下该问题是否仍存在

UE5 替代能力：UE5 保留的 RHI（D3D12/Vulkan/Metal），部分旧路径已淘汰

相关文件：Source/Runtime/Apple/MetalRHI/Private/MetalVertexBuffer.cpp

0. 根因溯源（这个宏为什么存在）

上游已自行修复（该宏可直接删除）

结论：macOS 上创建 buffer-backed linear texture 时，纹理视图的 ResourceOptions 没有带上 HazardTrackingModeUntracked，与 backing buffer 的选项不一致，导致 Metal 验证层报错（XCUITest/验证开启时崩溃或断言）。XD 在 FMetalRHIBuffer::AllocLinearTextures 内把 Untracked 并进 TextureDescriptor 的 ResourceOptions；UE5 的 MetalRHI 已整体重写（改用 MTL:: 命名空间的新式 API），旧的类与插入点不再存在。

上游引入：上游早期 MetalRHI 用 mtlpp 封装且未统一纹理/缓冲的 hazard tracking 选项；XD 在 UE4.26 fork 的 MetalVertexBuffer.cpp:427（AllocLinearTextures 内）与 MetalUAV.cpp 补齐选项。

上游历史（是否修过）：已核实 UE5.8.2：Source/Runtime/Apple/MetalRHI/Private 下已**没有 MetalVertexBuffer.cpp**（旧文件被移除）；该目录实现改用 MTL:: 命名空间（如 MetalBuffer.cpp、MetalBindlessDescriptors.cpp 等均以 MTL:: 编写）—— 即 MetalRHI 层发生了整体重写，XD 当年的插入点与相关类型（mtlpp TextureDescriptor）已被替换。

为什么可以断定不是「故意为之」2 条依据
  • 整个 MetalRHI 平台层改用 MTL:: 命名空间属于引擎级重构（不是局部改动），XD 的补丁位置因此不复存在。
  • buffer-backed texture 的选项一致性在重写后的实现里由新的资源描述路径统一处理（issue 本身不再是 XD 当年的形态）。

调用方契约：Metal 资源创建必须保证纹理视图与 backing buffer 的 hazard tracking / storage mode 选项一致，否则验证层报错。

内层真实语义：UE4（XD）：在 AllocLinearTextures 内把 HazardTrackingModeUntracked 合并进 TextureDescriptor。UE5（上游）：MetalRHI 以 MTL:: 新式 API 重写，资源选项在新描述路径统一设置。

代码库惯例：平台 RHI 层随 Apple API 演进而整体换代（mtlpp → MTL::）是上游这几年的既定方向。

为何长期未被发现：只在开启 Metal Validation（Xcode 验证层）时暴露，普通运行不报错；因此不为日常开发所见。

XD 侧的做法与意图：XD 的目标是消除 Mac 上开启 Metal 验证时的 LinearTexture/View 选项不一致报错。

⚠ 不要尝试在新代码里找回 FMetalRHIBuffer::AllocLinearTextures：UE5 已无该类型/方法，按旧路径迁移会落在不存在的 API 上。若仍能在验证层复现同类报错，应在 MTL:: 新路径上单独处理（并考虑反馈上游）。

迁移方案（按根因定）

删除 XD_BUG_FIX_METAL_VERTEX_BUFFER_VIEW_VALIDATION_ERROR 及 MetalVertexBuffer/MetalUAV 中的相关改动；在 macOS 上开启 Metal Validation 回归验证。

根因级自检用例

  • macOS + Xcode Metal Validation 开启：buffer-backed linear texture 创建无选项不一致报错
  • UAV/线性纹理相关功能正常（渲染结果正确）
  • 常规（非验证）运行无回归

可反馈上游：如在新实现上仍能复现同类验证报错，可向 Epic 反馈（附验证层原文与最小场景）。

风险评估

原代码风险：用 mtlpp 静态变量缓存选项且仅在建 linear texture 时补 hazard tracking，与 backing buffer 不一致就会触发 Metal Validation 断言。

移植风险：改写点散在 MetalBuffer/MetalUAV/MetalTexture，漏改会造成 macOS/iOS buffer-backed UAV 视图校验报错。

开发自检

  • Xcode 开 Metal Validation，跑使用 vertex/structured buffer SRV/UAV 的场景
  • macOS Development 与 iOS 真机各启动并进主场景一次

结论置信度：medium — UE5 MetalUAV.cpp:425 的 Desc 选项仅含 storage mode，未显式带 untracked，需实机开 Metal Validation 确认不再报错。
