3. 代码级实现（开发用）

待独立 Agent 审核该草案尚未进入审核轮次：审核会打开 UE5 源码逐条核对行号、函数与 after 代码 引用的 API 是否存在。

完全重构 改动方式：类还在但成员类型、导出宏、PreSave 签名与 EnsureValidData 的清空语义都变了，方法实现必须按 UE5 结构改写。

代码脉络：SlateVectorArtData.cpp:199 CreateRectangleData 与 :233 ChangeRectangleSize 直接写私有 VertexData/IndexData 并建 MID，头文件 :110-116 暴露方法、:154-156 存 CachedRectangleHalfSize。UE5 的 USlateVectorArtData（Runtime/UMG/Public/Slate/SlateVectorArtData.h:84）类还在，但改成 UCLASS(MinimalAPI)、顶点改用 FVector2f、且 :150 EnsureValidData 在 MeshAsset==null 时会 Reset 掉 VertexData。

⚠ UE5 :169 PreSave 签名已改成 PreSave(FObjectPreSaveContext)，PreSave->EnsureValidData 会把自建数据清掉，所以必须加 bRuntimeCreated 标记；UE5 已自带 MeshAsset==null 判空（:153），UE4 的额外判空可不搬。

风险评估

原代码风险：直接改 UObject 的 VertexData 数组并替换 Material，若被 EnsureValidData/PreSave 重跑会丢数据；ChangeRectangleSize 只在 VertexData.Num()==4 时生效。

移植风险：只影响使用该资产的 UMG 控件；若忘记加 bRuntimeCreated 保护，打包/保存后矢量图会变空（静默白屏），需重点回归。

开发自检

  • 运行时 CreateRectangleData 后立即 ChangeRectangleSize，UI 显示正确比例
  • 保存/打包再加载该资产，自建矩形数据未被清空
  • 非编辑器模块能链接到 UMG_API 方法

结论置信度：medium — UE5 是否有更合适的替代（UImage+材质/MaterialSprite 动态构建），可彻底免除引擎改动，需 UI 组评估。
