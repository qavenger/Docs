0. 根因溯源（这个宏为什么存在）

上游缺失能力（UE5 可能已补）

结论：为让 SourceMovement 模块的偏移计算更准确（需在所有 spawn 模块执行完毕后做一次补偿），XD 在粒子模块基类加了虚接口 `RegisterCustomParticlePostSpawnBehaviour(FParticleEmitterInstance*)`，由发射器实例在 spawn 阶段结束后回调（`ParticleEmitterInstances.cpp:561`），SourceMovement 模块 override 它并做偏移修正。UE5 中没有该接口（全仓无命中），且粒子模块接口已重构为"上下文结构"（`FSpawnContext`/`FUpdateContext`），因此该机制需要在 UE5 的新接口上重新实现。

上游引入：XD 的粒子模块修正（宏定义 XDBuildFixBugConfiguration.cs:485（值=1））；生效链：`UParticleModule` 加虚接口 `RegisterCustomParticlePostSpawnBehaviour`（XD 侧 ParticleModule.h:492），`ParticleModuleSourceMovement.h:43` override，`ParticleEmitterInstances.cpp:561` 在 spawn 阶段调用 `CurrentModule->RegisterCustomParticlePostSpawnBehaviour(this);`，实现位于 `ParticleModules.cpp:1072`。

上游历史（是否修过）：已核实（rg 精确检索）：①UE5 全仓**无** `RegisterCustomParticlePostSpawnBehaviour`/`OnCollectParticlePostSpawn`/`PostSpawnBehaviour`；②UE5 的模块接口已是上下文形式：`Source/Runtime/Engine/Classes/Particles/ParticleModule.h:253` `struct FSpawnContext : FContext`（:258 构造 `FSpawnContext(FParticleEmitterInstance& Ow, int32 Of, float St, FBaseParticle* Pb)`、:260 `virtual void Spawn(const FSpawnContext& Context);`）、:269 `struct FUpdateContext : FContext`（:273 构造 `(Ow, Of, Dt)`、:275 `virtual void Update(const FUpdateContext&);`、:284 `virtual void FinalUpdate(const FUpdateContext&);`）；③XD 侧接口与调用点确认存在（ParticleModule.h:492、ParticleModuleSourceMovement.h:43、ParticleEmitterInstances.cpp:561、ParticleModules.cpp:1072）。

为什么可以断定不是「故意为之」2 条依据
  • 上游把模块接口改成上下文结构（FSpawnContext/FUpdateContext）以承载更多参数与状态，属架构演进；未提供"post-spawn 注册钩子"这一具体机制。
  • XD 的钩子是为修正 SourceMovement 的偏移精度所做的项目侧增强，不是上游缺陷修复。

调用方契约：SourceMovement 的偏移必须与实际发射器位移一致（且在所有 spawn 模块完成后计算），否则粒子源位置漂移（表现：粒子整体偏移/抖动）。

内层真实语义：UE4（XD）：模块基类虚接口 + 发射器实例在 spawn 后统一回调，SourceMovement 在回调里修正偏移。UE5（上游）：模块经 `Spawn(const FSpawnContext&)` 与 `Update/FinalUpdate(const FUpdateContext&)` 执行，无 post-spawn 注册机制。

代码库惯例：上游把模块行为收敛到上下文参数（Spawn/Update/FinalUpdate 三段），项目侧扩展应利用这些阶段而不是新增"回调注册"机制。

为何长期未被发现：属"粒子表现精度"修正：不迁移不会崩，只在发射器快速移动/旋转时表现为粒子源偏移不准（观感细节）；而接口形态已变（上下文结构），按旧实现迁移不可行。

XD 侧的做法与意图：XD 的目标是让 SourceMovement 模块在发射器移动时给出更准确的粒子源偏移（减少漂移感）。

⚠ 四点注意：①**不要照搬旧签名**——UE5 的 `Spawn` 已改为 `Spawn(const FSpawnContext&)`（ParticleModule.h:260），旧的三参数形式不存在；②重做前先确认 UE5 是否存在**等价的完成点**（例如 `FinalUpdate(const FUpdateContext&)`，:284）——若能在其中完成同样的偏移修正，就无需新增接口；③在模块基类加虚接口会影响**所有粒子模块**（接口污染、重编译面大），优先在 SourceMovement 模块内部解决；④与 GPU 粒子/Sprite 渲染路径的兼容性需验证（偏移修正若只作用于 CPU 侧数据，GPU 路径可能不一致）。

迁移方案（按根因定）

按 upstream-missing 处理：①先在 UE5 上复现"粒子源偏移不准"的问题，确认其影响是否仍值得迁移；②若需要，优先利用 UE5 的 `FinalUpdate(const FUpdateContext&)`（ParticleModule.h:284）在模块内部完成偏移修正；③若确实需要跨模块的统一回调点，则在项目层（粒子相关模块/插件）实现，避免改基类接口。

根因级自检用例

  • 发射器快速移动/旋转时粒子源偏移准确（无漂移/抖动）
  • 其它粒子模块行为不受影响（未因基类改动引入副作用）
  • 大量粒子与高速运动场景下表现稳定
  • 与 GPU 粒子/其它渲染路径一致（若项目启用）

可反馈上游：可向上游提议：为粒子模块提供"所有 spawn 完成后"的统一回调阶段（便于 SourceMovement 一类模块修正状态）。

风险评估

原代码风险：原粗估在 bUseLegacySpawningBehavior 下不准确，且忽略 PostSpawn 的位置插值，导致 SourceMovement 偏移错误。

移植风险：属结构性改动（新增模块虚接口+EmitterInstance 委托+数组），影响 Cascade 全部使用 SourceMovement 的粒子；需与粒子轨道一起回归。

开发自检

  • 使用 SourceMovement 的拖尾/残影粒子偏移正确
  • bUseLegacySpawningBehavior 开/关表现符合预期
  • 并行 tick 下委托/数组线程安全

结论置信度：medium — UE5 FinalUpdate 的逐粒子循环变量名（BEGIN_UPDATE_LOOP 内索引）与数组对齐方式需落位确认；Context.Owner 是否可用于写回需核对。
