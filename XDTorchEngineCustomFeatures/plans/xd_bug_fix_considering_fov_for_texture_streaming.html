修改草案 · XD_BUG_FIX_CONSIDERING_FOV_FOR_TEXTURE_STREAMING

计算纹理流送 ScreenSize 时考虑 FOV，并修正半径误差（UE4-3640）

部分覆盖 配置化 需接入点 仅加接入点 工作量 M风险 中开发者 Lu Xun主要模块 Editor/UnrealEd

一句话结论：以 CVar 形式移植 ConsiderFOV 开关

1. UE5 现状与证据

结论依据：FStreamingViewInfo 已含 FOVScreenSize（Engine/Source/Runtime/Engine/Public/ContentStreaming.h:78,94；ContentStreaming.cpp:444 计算），但 AsyncTextureStreaming.cpp:90 仍只用 ScreenSize+BoostFactor，无 r.Streaming.ConsiderFOV

2. 修改步骤（配置化）

  1. 确定配置承载
    在 AsyncTextureStreaming 内以 CVar 选择 FOVScreenSize
  2. 设定默认值与灰度
    默认值应与当前线上行为一致；通过 ini/DeviceProfile 按平台/机型灰度，可随时回滚。
  3. 清理宏
    删除 UE4 宏与 Source/Editor/UnrealEd/Private/EditorEngine.cpp、Source/Editor/UnrealEd/Private/ThumbnailHelpers.cpp、Source/Editor/UnrealEd/Private/ThumbnailRendering/WorldThumbnailRenderer.cpp、Source/Runtime/Engine/Private/Streaming/AsyncTextureStreaming.cpp 中的编译期分支，改为读取配置。

3. 代码级实现（开发用）

待独立 Agent 审核该草案尚未进入审核轮次：审核会打开 UE5 源码逐条核对行号、函数与 after 代码 引用的 API 是否存在。

改接口/改名 改动方式：结构仍在（FStreamingViewInfo::FOVScreenSize 存在），只需在 UE5 新集中点 ComputeViewInfoExtras 内加 CVar 选择并修两处 Tan 调用。

代码脉络：UE4 AsyncTextureStreaming.cpp:12-19 新增 r.Streaming.ConsiderFOV(默认0)，:123-127 按 CVar 在 ScreenSize/FOVScreenSize 间选择后算 EffectiveScreenSize；编辑器侧 ThumbnailHelpers.cpp:137-141、WorldThumbnailRenderer.cpp:171-175、EditorEngine.cpp:2092-2096 把 FMath::Tan(角度) 修为 FMath::Tan(DegreesToRadians(角度))。

步骤 1Runtime/Engine/Private/Streaming/AsyncTextureStreaming.cppUE5 AsyncTextureStreaming.cpp:24 与 ComputeViewInfoExtras :89-90

加 CVar r.Streaming.ConsiderFOV 并在 ViewInfoExtras 计算处选用 FOVScreenSize

#if XD_BUG_FIX_CONSIDERING_FOV_FOR_TEXTURE_STREAMING
static TAutoConsoleVariable<int32> CVarConsiderFOV(TEXT("r.Streaming.ConsiderFOV"), 0, TEXT("0 (Default): DO NOT consider FOV...\n1: Consider FOV"), ECVF_Scalability);
#endif
...
#if XD_BUG_FIX_CONSIDERING_FOV_FOR_TEXTURE_STREAMING
const float ScreenSize = CVarConsiderFOV.GetValueOnAnyThread() > 0 ? ViewInfo.FOVScreenSize : ViewInfo.ScreenSize;
const float EffectiveScreenSize = (Settings.MaxEffectiveScreenSize > 0.0f) ? FMath::Min(Settings.MaxEffectiveScreenSize, ScreenSize) : ScreenSize;
#else
// UE5 :24 之前加 CVar(同上，注意 UE5 无该项目宏时用 #if 0/#endif 包裹并保留 CVar)
static TAutoConsoleVariable<int32> CVarConsiderFOV(TEXT("r.Streaming.ConsiderFOV"), 0, TEXT("1: 用 FOVScreenSize 计算流送 ScreenSize"), ECVF_Scalability);
// ComputeViewInfoExtras(:89)改为:
#if XD_BUG_FIX_CONSIDERING_FOV_FOR_TEXTURE_STREAMING
const float ScreenSize = CVarConsiderFOV.GetValueOnAnyThread() > 0 ? ViewInfo.FOVScreenSize : ViewInfo.ScreenSize;
#else
const float ScreenSize = ViewInfo.ScreenSize;
#endif
const float EffectiveScreenSize = (Settings.MaxEffectiveScreenSize > 0.0f) ? FMath::Min(Settings.MaxEffectiveScreenSize, ScreenSize) : ScreenSize;

⚠ UE5 已确认 ComputeViewInfoExtras:90 仍只用 ViewInfo.ScreenSize（无 FOV 消费方，仅 SparseVolumeTexture.cpp:998 用 FOVScreenSize）

步骤 2Editor/UnrealEd/Private/ThumbnailHelpers.cppUE5 ThumbnailHelpers.cpp:170；WorldThumbnailRenderer.cpp:191

修正 Tan 参数单位（角度→弧度），EditorEngine.cpp 上游已修

float FOVScreenSize = static_cast<float>(SizeX) / FMath::Tan(FOVDegrees);
// WorldThumbnailRenderer.cpp:191
FOVScreenSize = SizeX / FMath::Tan(FOVDegrees);
float FOVScreenSize = static_cast<float>(SizeX) / FMath::Tan(FMath::DegreesToRadians(FOVDegrees));
// WorldThumbnailRenderer.cpp:191 同样:
FOVScreenSize = SizeX / FMath::Tan(FMath::DegreesToRadians(FOVDegrees));
// EditorEngine.cpp:2617 UE5 已是 XSize / FMath::Tan(FMath::DegreesToRadians(InViewportClient->ViewFOV * 0.5f))，无需改

⚠ FMath::DegreesToRadians 为模板函数，float 入参直接可用；与 Before 相比 FOVScreenSize 会变大(除 0.577)，流送更激进

风险评估

原代码风险：UE4 侧 FMath::Tan(角度) 直接喂度数值属量纲错误，FOVScreenSize 偏小→流送按小屏幕尺寸算 mip，远处贴图偏糊；CVar 默认 0 时行为不变。

移植风险：开启 ConsiderFOV 后预算按更大屏幕尺寸计算，显存/带宽上升可能触发 r.Streaming.PoolSize 不足与掉帧；缩略图与编辑器视口的流送请求量变化。

开发自检

  • r.Streaming.ConsiderFOV=1 时远处贴图分辨率与实测 FOV 一致（对比 0）
  • 编辑器缩略图/视口开关 FOV 时流送请求无异常
  • 显存不超 PoolSize，r.Streaming.MaxEffectiveScreenSize 上限仍生效

结论置信度：medium — UE5 未提供 r.Streaming.ConsiderFOV（grep 无匹配），CVar 需新增；编辑器侧是否也要消费 FOVScreenSize 取决于项目缩略图策略
