修改草案 · XD_FIX_BUG_ELECTRA_PLAYER_BLOCK_GT_WHEN_RELEASE

修复 Electra 播放器释放时阻塞游戏线程（PC 编辑器模式禁用）

待确认 常开补丁 引擎内实现 引擎内补丁 工作量 S风险 中开发者 Ran Qing Sen主要模块 Plugins/ElectraPlayer

一句话结论：UE5 Electra 已重写，先实测再定。

0. 根因溯源（这个宏为什么存在）

平台/工具链绕行

结论：UE4 的 ElectraPlayer_PC.cpp DestroyDirectXResources 在 UE_EDITOR 下手工 Release DxDeviceContext/DxDevice/RenderingDx11Device，并跳过 s_DXDeviceInfo.Reset()（即跳过 IMFDXGIDeviceManager->Release()），理由仅一句注释 “the blow code will block GT in editor model”，XD 自己也不确定原因（配置注释：“not sure the reason, so disable it in pc editor mode”）。这属于典型的平台/第三方组件绕行，而非明确的引擎逻辑缺陷：绕过 Reset 会泄漏引用、并让 COM 引用计数脱离 UE 管理（fork 风险：Release 后解码线程仍可能访问）。UE5 中该文件/类已不存在，等价能力落在 AVEncoder，且关闭被显式移到工作线程。

上游引入：上游代码来源：ElectraPlayer 于 9c14a2be1a50（2021-01-06，Achim Moller，“ElectraPlayer: RELEASE. Moved from NFL to public”，以删除+新增方式搬运）进入公开分支，DestroyDirectXResources/FDXDeviceInfo 即当时形态；XD 宏在 UE4 fork 中加入并仅作用于 UE_EDITOR（fork Plugins/Media/ElectraPlayer/Source/ElectraPlayerRuntime/Private/ElectraPlayer_PC.cpp:201 DestroyDirectXResources、:203 #if XD_FIX_BUG_ELECTRA_PLAYER_BLOCK_GT_WHEN_RELEASE && UE_EDITOR）。宏定义：XDBuildFixBugConfiguration.cs:144-145（注释 “GT will be blocked when Electra::FDXDeviceInfo::s_DXDeviceInfo->DxDeviceManager->Release() called, not sure the reason…”）。

上游历史（是否修过）：上游已彻底移除该代码路径：ebabab67194c，2023-04-03，Jens Petersam，“Electra: Copy-up from codec refactor task stream”（git tag --contains 显示首个发布版本 5.3.0-preview-1）把解码器/设备管理从 ElectraPlayer 复制到 AVEncoder 并删掉 ElectraPlayer_PC.cpp。UE5 5.8.2 现状：ElectraPlayer 目录内已无 FDXDeviceInfo/DestroyDirectXResources（rg 无命中），Runtime/Platforms/Windows/PlayerRuntime_PC.cpp 仅 23 行（GetPlatformID/CurrentMSec）。等价逻辑在 Source/Runtime/AVEncoder/Private/Decoders/Windows/VideoDecoderH264_Windows.cpp:727-760 FDXDeviceInfo（成员改为 TRefCountPtr，Reset 置空即释放）、:1084-1087 ReleaseD3DResources、:2269-2275 PerformAsyncShutdown、:2285-2296 Shutdown——Shutdown 注释明确说明把整个关闭放到独立线程以避免阻塞（CreateThread + AsyncShutdownProc）。

为什么可以断定不是「故意为之」4 条依据
  • XD 自己的注释写“not sure the reason”，说明是现象驱动的绕过，而非有意设计生命周期。
  • 绕过 Reset 会造成 IMFDXGIDeviceManager 引用未释放（泄漏）并让 COM 引用计数脱离 UE 管理，任何有意设计都不会以泄漏换不卡。
  • 上游后续（5.3）把同类关闭改成异步线程（VideoDecoderH264_Windows.cpp:2287-2291 注释“shutdown would be blocked forever which is why we move it to another thread”），正是把“阻塞”当作要解决的问题而非可接受行为。
  • 该宏只在 UE_EDITOR 生效，编辑器与打包行为分叉，不符合引擎平台一致性惯例。

调用方契约：调用方是 ElectraPlayer 的 PC 平台生命周期（fork ElectraPlayer_PC.cpp 内 DestroyDirectXResources 与 CreateDirectXResources 成对），其返回值 bHaveDirectXResources 决定解码器是否使用硬件设备管理；绕过 Reset 后该状态与实际 COM 引用不一致。UE5 中同一职责由 AVEncoder FVideoDecoderH264_WindowsImpl 的 SetupFirstUseResources/Shutdown（:2299/:2285）承担。

内层真实语义：UE4 修复分支（宏开启）：只 Release 三个设备对象，Reset 与 IMFDXGIDeviceManager->Release() 被注释掉 → 不阻塞但泄漏、且 s_DXDeviceInfo 仍指向已 Release 的对象（悬垂，后续使用即崩）。宏关闭路径（原逻辑）：s_DXDeviceInfo.Reset() 正常释放全部引用，可能阻塞 GT。UE5：Shutdown() 立即返回，ReleaseD3DResources 在专用线程执行，不存在“调用者被阻塞”的路径。

代码库惯例：引擎惯例是耗时的 D3D/MF 关闭放到工作线程或异步任务（AVEncoder 的做法即为此），而不是在 GT 上手工 Release 单个 COM 对象并跳过统一 Reset；COM 包装统一用 TRefCountPtr，不裸调 Release()。

为何长期未被发现：表现为编辑器偶发卡顿/假死（尤其反复开关 Media 播放器时），无崩溃、无日志、无 dump，且只在 UE_EDITOR 出现，很难进入自动化回归；XD 当年也无法复现根因。

XD 侧的做法与意图：fork：Plugins/Media/ElectraPlayer/Source/ElectraPlayerRuntime/Private/ElectraPlayer_PC.cpp:201-227（DestroyDirectXResources）在 UE_EDITOR 下把 s_DXDeviceInfo.Reset() 与 IMFDXGIDeviceManager->Release() 注释掉，仅逐个 Release DxDeviceContext/DxDevice/RenderingDx11Device；开关 XDBuildFixBugConfiguration.cs:145。意图：让 PC 编辑器在媒体播放器释放时不被卡住。

⚠ 在 UE5 里“照搬这段绕过”会制造 COM 悬垂：Reset 被跳过后 s_DXDeviceInfo 仍持有已 Release 的对象；⚠ 反过来把异步 Shutdown 改回同步 Release 以“更干净”会重新引入 GT 阻塞（AVEncoder 的注释正说明这点）；⚠ 用 delete/singleton 重置替代 Reset 同样会让解码线程访问已释放的设备管理器。

迁移方案（按根因定）

按“平台绕行 + 代码已消失”处理：1) 删除宏定义（XDBuildFixBugConfiguration.cs:145）与其 #if 分支，不向 UE5 迁移——UE5 ElectraPlayer 已无 Windows 直接 D3D 设备管理，绕过对象不存在。2) UE5 侧等价路径是 AVEncoder H264 硬解（VideoDecoderH264_Windows.cpp）：确认项目仍在使用 AVEncoder/ElectraCodecs 的 Windows 硬解，并保持其 Shutdown 异步实现（:2285-2296），不要改成同步。3) 若项目侧仍有 Windows Media 关闭卡顿，用 UE5 的 async/工作线程方案复现并向上游报，而不是恢复手工 Release。

根因级自检用例

  • 编辑器：反复打开/关闭使用 ElectraPlayer 的视频（含硬件解码），GT 无 >100ms 的阻塞尖峰。
  • 资源：无 IMFDXGIDeviceManager/D3D11Device 引用泄漏（任务管理器/GPU 内存句柄稳定）。
  • 生命周期：播放器关闭后原解码线程不再访问已释放设备（无 UAF/dump）。
  • 代码检查：UE5 树内无 XD_FIX_BUG_ELECTRA_PLAYER_BLOCK_GT_WHEN_RELEASE，且无手工 Release + 跳过 Reset 的写法。
  • 回归：ElectraPlayer/AVEncoder 在打包（非编辑器）构建下行为不变。

可反馈上游：UE4.26（ElectraPlayer 仍自带 Windows 设备管理）最小复现：PC 编辑器反复开关 Electra 视频播放器，观察 DestroyDirectXResources 调 s_DXDeviceInfo.Reset()/IMFDXGIDeviceManager->Release() 时 GT 长阻塞。上游在 5.3 的 AVEncoder 版本里已用异步 Shutdown（VideoDecoderH264_Windows.cpp:2285-2296）规避同类问题，可据此关闭。
