引擎初始化时预挂载指定 Pak 目录（提前读取热更资源）

未覆盖 接入点 需接入点 仅加接入点 工作量 L风险 高开发者 Huang Chen主要模块 Core

一句话结论：热更核心能力：把引擎改动压缩为“暴露时机委托”，策略与状态持久化进插件；预挂载时机需与 LaunchEngineLoop 初始化顺序重新对齐

1. UE5 现状与证据

结论依据：UE5 无预挂载阶段：grep bIsInInitPreMountPakProcedure / XDPreMountStatusReport / UpdatePremountConfigJson 无结果；CoreDelegates.h:118-155 仅标准 mount 委托，无赛季节日 json/热更预挂载概念

2. 修改步骤（接入点）

  1. 引擎侧只加接入点
    需要的接入点：FCoreDelegates::PakFileMountFailedDelegate / GetOnPakFileMounted2、FCoreDelegates::MountPak / MountPaksEx、AddShaderSourceDirectoryMapping / ShaderCodeLibrary 打开时机钩子（机制：Delegate）。引擎改动应最小、稳定、无业务语义。
  2. 插件侧实现完整逻辑
    引擎只暴露挂载/失败/ShaderLibrary 打开时机委托；pak 目录扫描、赛季 json、熔断状态机全部放热更插件
  3. 无插件时的行为
    未绑定接入点时应回退到官方默认行为（引擎侧不能假设插件存在）。
  4. Shader 侧配套
    删除 DerivedDataCache 重编 Shader；同步更新受影响的 shader permutation / ShaderVersion。

3. 代码级实现（开发用）

审核意见：方向正确（丢弃预挂载状态机、只暴露时机），但 steps[0] 会误删 5 个仍在用的委托且缺 CoreDelegates.cpp 定义；steps 也未覆盖 ShaderCodeLibrary/Paths/AsyncLoading 等核心调用点。

风险评估

原代码风险：预挂载目录/JSON 损坏或崩溃时 semaphore 会累积，启动早期即降级或阻塞资源加载。

移植风险：启动顺序变动牵连 shader library 打开时机与 pak 失败路径，可能启动崩溃或热更资源未挂载。

开发自检

  • 真机热更包能预挂载并读到赛季资源
  • 预挂载失败时 mount_*.json 的 semaphore 正确累加
  • 预挂载 shader library 打开无缺 shader

结论置信度：medium — XD_TORCHLIGHT_SEASON 与 PRE_MOUNT_PAK_MINIMAL_VERSION 的迁移细节需人工确认。
