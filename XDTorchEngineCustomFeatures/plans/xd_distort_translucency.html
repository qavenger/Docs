修改草案 · XD_DISTORT_TRANSLUCENCY

半透明扭曲（Distortion）支持：独立 Distortion Pass 与材质开关

部分覆盖 移植 需接入点 仅加接入点 工作量 M风险 中开发者 Peng TianCheng主要模块 Renderer

一句话结论：优先评估 UE5 原生折射是否满足；XD 独立 Distortion Pass 组合语义需确认保留

背景：新增 DistortionRendering 路径与材质/场景视图参数，热浪、水波、空间扭曲等效果可控且可排序。

0. 根因溯源（这个宏为什么存在）

XD 定制需求（非上游缺陷）

结论：XD 新增 EMeshPass::DistortTranslucencyPass(MeshPassProcessor.h:57-58)、ETranslucencyPass::TPT_DistortTranslucency(TranslucencyPass.h:24)、UMaterial::bDistortTranslucency(Material.h:543)、ShouldUseDistortTranslucency(DistortionRendering.cpp:254；DeferredShadingRenderer.cpp:2711 调用)，并配 shader CombineSeparateTransTexForDistort.usf。

上游引入：XD 需求：UE5 只有原生 EMeshPass::Distortion(MeshPassProcessor.h:70、DistortionRendering.cpp:1250)与 bUsesDistortion(Material.h:810)/RefractionMethod(:1188)，无该 pass 与 usf。

上游历史（是否修过）：上游从未有该通道，属能力缺失；UE5 只改命名/位置(枚举迁到 Renderer/Internal/TranslucentPassResource.h:16)。

为什么可以断定不是「故意为之」3 条依据
  • 上游已有 EMeshPass::Distortion 与折射开关，“缺通道”是 XD 额外需求
  • CVar r.DistortTranslucency 默认不开，属可选管线
  • MaterialInterface.cpp:244 把它定义为 bEnableSeparateTranslucency 的子集

调用方契约：DeferredShadingRenderer.cpp:2711 写入 PostProcessingInputs.bShouldUseDistortTranslucency；DistortionRendering.cpp:387-430 走组合 shader；BasePassRendering.cpp:1989-1992 绘制条件=IsTranslucencyAfterDOFEnabled()&&IsDistortTranslucency()。

内层真实语义：两判定皆真(MaterialShared.cpp:1335/:1345)→同一材质进 AfterDOF 与 DistortTranslucency 两个 pass(MaterialInterface.cpp:269-272 有意保留 bSeparateTranslucency=true)。空路径：CVar!=1 或无 draw 时返回 false(:258/:277)走原组合。

代码库惯例：上游惯例=双枚举+TranslucencyPassToMeshPass(:120-122)+复用 FBasePassMeshProcessor 传 ETranslucencyPass(:2508)。

为何长期未被发现：需材质勾选+CVar 双开。

XD 侧的做法与意图：Material.h:543 DisplayName="Distort Separate Translucency"。

⚠ 打开 MaterialInterface.cpp:269-272 被注释的 `bSeparateTranslucency=false` 会让材质从 AfterDOF 消失、DOF 顺序突变(XD 有意保留两通道后在 combine 去重)；⚠ 只加 EMeshPass 不加 ETranslucencyPass/映射会 check 失败(:126)；⚠ UE5 枚举改名 TPT_TranslucencyStandard。

迁移方案（按根因定）

①先评估能否用 UE5 原生 Distortion 表达，能则删宏；②保留时枚举加到 TranslucentPassResource.h(TPT_MAX 前)与 MeshPassProcessor.h:70 之后；③用 REGISTER_MESHPASSPROCESSOR_AND_PSOCOLLECTOR(:2485)+FBasePassMeshProcessor 范式。

根因级自检用例

  • CVar=0/无 draw 时合成与不开宏一致
  • 仅勾 bDistortTranslucency：两 pass 有 draw 但颜色无重复叠加
  • TranslucencyPassToMeshPass 全枚举无 check 失败

3. 代码级实现（开发用）

独立 Agent 审核并修正修正 2 处　提出问题 4 条　其中高风险 1 条

审核意见：脉络基本真实，但 ShouldUseDistortTranslucency 的文件/行号写错、after 缺 View 循环不可编译。

完全重构 改动方式：UE5 保留 Distortion 通道与 DistortionRendering，但无 XD 的独立 DistortTranslucency 组合语义，须在 UE5 Distortion 管线基础上重写。

代码脉络：宏新增独立 Distortion 半透明通道：MeshPassProcessor.h:58 加 EMeshPass::DistortTranslucencyPass，DistortionRendering.cpp:254 定义 ShouldUseDistortTranslucency()（DeferredShadingRenderer.cpp:2711 调用），DistortionRendering.cpp:387/402 用 FDistortionCombineSeparateTransPS 预合成 SeparateTrans，TranslucentRendering.cpp:121 / BasePassRendering.cpp:2456 / MaterialShared.h 联动材质标志。UE5 已有原生 Distortion：DistortionRendering.cpp:1250 REGISTER_MESHPASSPROCESSOR_AND_PSOCOLLECTOR(… EMeshPass::Distortion)、EMeshPass::Distortion(MeshPassProcessor.h:70) 存在，但无 XD 的 DistortTranslucencyPass 与 ShouldUseDistortTranslucency。

bool FDeferredShadingSceneRenderer::ShouldUseDistortTranslucency() const
{
#if XD_DISTORT_TRANSLUCENCY
    static auto* CVar = IConsoleManager::Get().FindTConsoleVariableDataInt(TEXT("r.DistortTranslucency"));
    if (!CVar || CVar->GetValueOnAnyThread() != 1) { return false; }
    for (int32 ViewIndex = 0; ViewIndex < Views.Num(); ++ViewIndex)
    {
        const FViewInfo& View = Views[ViewIndex];
        if (View.ShouldRenderView() && HasAnyDraw(View.ParallelMeshDrawCommandPasses[EMeshPass::DistortTranslucencyPass])) { return true; }
    }
#endif
    return false;
}

风险评估

原代码风险：新增独立 pass 与 SeparateTrans 预合成侵入 Translucent/BasePass/Material 全链路，排序与 stencil 语义复杂。

移植风险：改动涉及 EMeshPass 枚举与 Distortion 管线，顺序/屏蔽设置错误会造成半透明重复或漏绘。

开发自检

  • 热浪/水波/空间扭曲效果可排序且正确
  • 移动端 r.DisableDistortion 生效

结论置信度：medium — UE5 原生折射/扭曲是否已满足需求、是否仍需 XD 独立 DistortTranslucencyPass 须先评估。
