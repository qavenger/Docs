3. 代码级实现（开发用）

待独立 Agent 审核该草案尚未进入审核轮次：审核会打开 UE5 源码逐条核对行号、函数与 after 代码 引用的 API 是否存在。

简单移植 改动方式：UPrimitiveComponent::Serialize 与 IsPrecomputedLightingValid/HasValidSettingsForStaticLighting 在 UE5 仍在且签名一致，代码可照搬，仅 dump 调用点从 CookCommandlet.cpp 迁到 CookProfiling.cpp。

代码脉络：PrimitiveComponent.h:2073 声明 FInvalidPrecomputeLightingComponentInfo、static TSet PrimitiveCompsNeedToBuildLighting 与 DumpPrimitiveCompsWithInvalidPrecomputeLighting()；PrimitiveComponent.cpp:1002 在 Serialize 中判定 IsCooking && !IsPrecomputedLightingValid() && HasValidSettingsForStaticLighting(true) 且关卡路径命中 GEditorIni 的 PathsToCheckLightingBuild 且有静态光，才加入 TSet。CookCommandlet.cpp:413（DetailedCookStats::LogCookStats 末尾）调用 Dump 打印并 Empty()。

风险评估

原代码风险：static TSet 与 static 缓存变量(IsMapInTargetPath/bHasStaticLight)在 cook 多线程/多世界下非线程安全，且在 Serialize 热路径上执行会影响 cook 速度。

移植风险：改动落在 Runtime/Engine 序列化热路径，仅打印不影响逻辑；回归需覆盖带静态光关卡的 cook 与日志。

开发自检

  • 带静态光但未重建光照的关卡在 cook 日志出现 'XD DET Cooking: Component[...] of Actor[...]' 警告
  • 光照有效的关卡不产生该警告
  • 宏关闭时 Serialize 无额外开销与符号引用

结论置信度：high — UE5 无 XDBuildToolsConfiguration.cs，若不做插件化则在项目 UBT 配置补定义宏，需人工确认归属。
