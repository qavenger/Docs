2. 修改步骤（插件化）

  1. 确定插件/模块归属
    项目插件维护 ParticleSystem→分类标签映射（DataAsset），或经 GetAssetRegistryTags/AssetRegistry tag 走项目侧汇总，不改 UObject schema
  2. 实现主体逻辑
    把原引擎内实现迁到插件：Source/Editor/CascadeParticleOptimizationStrategiesEdExt/Private/AssetActionMenuExtentions.cpp、Source/Editor/CascadeParticleOptimizationStrategiesEdExt/Private/CascadeEditorToolbarExtentions.cpp、Source/Editor/ContentBrowser/Private/AssetViewWidgets.cpp、Source/Runtime/Engine/Classes/Particles/ParticleSystem.h、Source/Runtime/Engine/Private/Particles/XDParticleOptimizationCommon.cpp、Source/Runtime/Engine/Public/Particles/XDParticleOptimizationCommon.h。引擎侧只保留必要接口/事件。
  3. 模块与构建规则
    Editor 工具放 Editor 模块（Shipping 自动剔除）；运行时逻辑放 Runtime 模块；如需引擎接口，见「引擎改动」列。

3. 代码级实现（开发用）

独立 Agent 审核并修正修正 2 处　提出问题 2 条

审核意见：消费点/编辑器引用与 UE5 GetAssetRegistryTags 重载(ParticleSystem.h:431/433、ParticleSystem.cpp:728)全部核实无误；补全 after 的 UPROPERTY 代码即可。

简单移植 改动方式：UPROPERTY/CanEditChange/AssetRegistrySearchable 机制在 UE5 仍在，逻辑可照搬，仅实现文件位置与 GetAssetRegistryTags 重载签名变化。

代码脉络：宏开启后在 ParticleSystem.h:460-475 给 UParticleSystem 加 PrimaryCategoryTag（AssetRegistrySearchable）并 override CanEditChange 禁编辑；枚举在 XDParticleOptimizationCommon.h:11-23、映射表在 XDParticleOptimizationCommon.cpp:6-11。运行时由 ParticleSystemRender.cpp:9862、FastParticleSystemRender.cpp:5999、XDParticleOptimizationCommon.cpp:60/94 读取标签决定亮度/Alpha 缩放；编辑器侧在 AssetActionMenuExtentions.cpp:54、CascadeEditorToolbarExtentions.cpp:26 与 AssetViewWidgets.cpp:1311 展示。

风险评估

原代码风险：给核心资产 UParticleSystem 加 UPROPERTY 会改资产 schema 与序列化版本，跨版本加载存在兼容风险；AssetRegistrySearchable 会在扫描时全量读取标签。

移植风险：UPROPERTY 直接搬会让 UE5 资产与 XD 分支之外的工具链不兼容，需回归资产 cooker 与 AssetRegistry 扫描。

开发自检

  • UE5 打开含该字段的 ParticleSystem 资产不报 schema 错
  • ContentBrowser 能显示 PrimaryCategoryTag 列
  • 运行时按分类取亮度/Alpha 缩放正确（对照 UE4 行为）

结论置信度：medium — disposition=plugin 主张不扩 UObject schema、改用项目 DataAsset 映射，需与项目侧确认哪条路线；Uncertain 是否已存在同名 tag 资产数据。
