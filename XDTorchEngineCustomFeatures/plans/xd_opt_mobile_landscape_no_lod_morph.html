修改草案 · XD_OPT_MOBILE_LANDSCAPE_NO_LOD_MORPH

允许关闭 Landscape LOD Morph（移动端）

未覆盖 配置化 需接入点 结构性改动 工作量 M风险 中开发者 Liu Xing Kui主要模块 Engine

一句话结论：改 Shader 会触发 permutation 与 DDC 重编

0. 根因溯源（这个宏为什么存在）

上游缺失能力（UE5 可能已补）

结论：地形 LOD 之间的顶点变形（Morph）能消除 LOD 切换的跳变，但在移动端（ES3.1 及以下）开销明显。XD 为此加了项目级开关：项目设置 `bMobileDisableLandscapeLodMorph`（RendererSettings.h:176-179）绑定 CVar `r.Mobile.DisableLandscapeLODMorph`（LandscapeRender.cpp:67），并由 ShaderCompiler（ShaderCompiler.cpp:3981-3986）与 RenderCore/Shader.cpp:1470 转成着色器宏，最终在地形顶点工厂里跳过移动端 Morph 插值。已核实 UE5 **仍保留地形 Morph 逻辑**（LandscapeVertexFactory.ush:657 计算 MorphAlpha、:680/:684 分别对位置与法线做 lerp），但**没有**上述开关/CVar/项目设置——即该定制未上游化，需在 UE5 同一位置重新落点。

上游引入：XD 的移动端地形性能优化（RendererSettings.h:176-179 项目设置 + LandscapeRender.cpp:67 建 CVar + ShaderCompiler.cpp:3981-3986 / RenderCore/Shader.cpp:1470 转着色器宏 + LandscapeVertexFactory.ush:737 `#if XD_OPT_MOBILE_LANDSCAPE_NO_LOD_MORPH && (FEATURE_LEVEL <= FEATURE_LEVEL_ES3_1)` 包裹 Morph 插值）。

上游历史（是否修过）：已核实（rg 精确检索）：①UE5 Shaders/Private/LandscapeVertexFactory.ush:657 `float MorphAlpha = LODCalculated - LodValue;`、:680 `Intermediates.LocalPosition = lerp( float3(InputPositionLODAdjusted, Height), float3(InputPositionNextLOD, HeightNextLOD), MorphAlpha );`、:684 `float2 InterpNormal = lerp( Normal, NormalNextLOD, MorphAlpha ) * float2(2.0,2.0) - float2(1.0,1.0);` —— 地形 Morph 机制在 UE5 依然存在且无特性级别限制；②UE5 全仓（Source + Shaders）检索 `LODMorph` 只命中骨骼网格的 MorphTarget 相关代码，无地形 LOD 变形开关；③UE5 RendererSettings.h 中无 landscape/mobile 相关设置项，也无 `DisableLandscapeLODMorph` CVar。

为什么可以断定不是「故意为之」2 条依据
  • UE5 保留了地形 Morph 的完整实现（位置与法线插值），说明上游未把"移动端关闭 Morph"作为默认行为或可选项。
  • XD 的开关是项目侧性能取舍（移动端省插值开销），上游没有等价能力，属能力缺失而非上游缺陷。

调用方契约：关闭 Morph 后，地形在 LOD 切换时必须仍然正确（不能出现位置跳变导致的裂缝/穿插），且移动端与 PC 的画质差异可接受。

内层真实语义：UE4（XD）：在顶点工厂里用编译期宏（受 CVar/项目设置驱动）在移动端跳过 Morph 插值（位置与法线都跳过）。UE5（上游）：无条件执行 Morph（MorphAlpha 插值位置与法线），无移动端开关。

代码库惯例：上游用"项目设置 → CVar → 着色器宏"的链路控制渲染特性（XD 沿用了这套惯例，落点正确）。移植时应保持同一链路（设置项 + CVar + 着色器宏），不要只删着色器分支导致无法回退。

为何长期未被发现：属"移动端地形性能"取舍：不迁移不会崩，只在移动端大世界地形上体现为顶点着色开销与帧率差异；且 UE5 的着色器目录位置已从 Source 迁到 Engine 根（Shaders/），按旧路径查找会误判为"代码不存在"。

XD 侧的做法与意图：XD 的目标是降低移动端地形渲染的顶点开销（移动端不需要 Morph 平滑，画质损失可接受）。

⚠ 三点注意：①**UE5 着色器在 `Engine/Shaders/`（引擎根目录）而非 `Engine/Source/Shaders/`**——按 UE4 路径找不到文件时不要误判为"机制被删"，检索请用全仓 rg 定位；②UE5 的 Morph 代码把"位置插值"（:680）与"法线插值"（:684）分开，**必须两处一起条件化**，只关其中一处会导致法线错乱（光照异常）；③保持"项目设置 + CVar + 着色器宏"完整链路（便于按设备回退），并注意 UE5 移动端特性级别命名与 UE4 不同（FEATURE_LEVEL_ES3_1 等在 UE5 的变化），条件表达式需按 UE5 重写。

迁移方案（按根因定）

按 port-as-is 处理：在 UE5 的 RendererSettings.h 重加 `bMobileDisableLandscapeLodMorph` 设置项、LandscapeRender.cpp 重建 `r.Mobile.DisableLandscapeLODMorph` CVar、ShaderCompiler 与 RenderCore/Shader.cpp 把 CVar 转成着色器宏，并在 `Engine/Shaders/Private/LandscapeVertexFactory.ush` 的 Morph 位置/法线插值处（:657-684 区域）按移动端特性级别条件化跳过。

根因级自检用例

  • 移动端默认：地形无 Morph（顶点开销下降，帧率提升可量化）
  • 开关关闭时 Morph 恢复正常（画质对照可用，无 LOD 切换跳变）
  • 位置与法线均正确（无裂缝、无光照异常）
  • PC 端行为不受影响（默认仍执行 Morph）
  • 大世界地形快速移动时无可见裂缝/跳变

可反馈上游：可向上游提议：为地形 Morph 提供移动端开关（移动端 Morph 收益低、开销明显）。

风险评估

原代码风险：关闭 morph 会在地形 LOD 切换处产生接缝/跳变，仅移动端适用。

移植风险：改 shader 触发 permutation 与 DDC 重编；只影响移动端，回归地形 LOD 接缝与性能。

开发自检

  • ES3.1 下地形 LOD 无明显接缝
  • 桌面/SM5 渲染不变

结论置信度：high
