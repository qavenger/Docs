修改草案 · XD_OPT_FAST_PARTICLE_SYSTEM_COMPONENT

UFastParticleSystemComponent：把部分粒子重计算搬到渲染线程

部分覆盖 保留引擎 引擎内实现 深度侵入 工作量 L风险 高开发者 Lu Xun主要模块 Engine

一句话结论：26 处引用的核心优化，建议先评估 UE5 异步 tick 是否已满足绝大多数收益再决定移植范围

背景：RT 接管部分粒子计算，避免 GT→RT 的整帧数据拷贝与同步，是粒子性能的关键组件。

可主动舍弃性（UE5 架构更替）

直接舍弃 Cascade 粒子 → Niagara

判定依据：UE5 特效体系已全面转向 Niagara，Cascade 仅保留兼容维护；项目迁移到 UE5 后特效会重做，针对 Cascade 运行时的定制可在迁移时直接不带过去。

舍弃前提：前提：迁移后在 UE5 用 Niagara 重做特效（不再走 Cascade 运行时）

UE5 替代能力：Niagara（NiagaraSystem / NiagaraComponent / NiagaraDataInterface）

相关文件：Source/Runtime/Engine/Classes/Particles/FastParticleSystemComponent.h Source/Runtime/Engine/Classes/Particles/FastParticleSystemManager.h Source/Runtime/Engine/Classes/Particles/ParticleModule.h

1. UE5 现状与证据

结论依据：UE5.8 PSC 已具备异步 tick：ParticleSystemComponent.h:610-618 bAsyncDataCopyIsValid/bParallelRenderThreadUpdate/bAsyncWorkOutstanding，ParticleSystemComponent.cpp:1897 CVar FX.EarlyScheduleAsync、:2477 ComputeTickComponent_Concurrent、:2554 FinalizeTickComponent；ParticleSystemManager.h:161-162 QueueAsyncTick/FlushAsyncTicks

覆盖说明：UE5 异步 tick 部分覆盖，XD 的渲染线程重算/去 GT→RT 拷贝仍独有

证据路径（UE5.8.2）行号核对结果

覆盖度：部分覆盖  处置：保留引擎

2. 修改步骤（暂留引擎）

  1. 登记 Feature Card
    记录 owner、影响面、依赖、关闭条件、验证方式与回滚方式；这是当前最高风险的一类（引擎内深度改动）。
  2. 评估替代路径
    优先考虑改用 UE5 原生机制（如 Niagara / Substrate / PSOPrecache / WorldPartition）替代自研实现；替代前保留最小可用补丁。
  3. 设定复查条件
    每个版本复查一次：是否可以降级为插件/配置，或直接删除。

3. 代码级实现（开发用）

独立 Agent 审核并修正修正 3 处　提出问题 4 条

审核意见：亮点：UE4 静态化补丁(ParticleSystemRender.cpp:55/536/3872)与 UE5 异步 tick 锚点(ParticleSystemComponent.cpp:2477/2554/1897、.h:612)全部核实，refactor 分类正确。最大问题：类定义/构造与 UE5 ParticleHelper 行号错、before 基类写错。

风险评估

原代码风险：RT 接管粒子计算改变 GT/RT 数据所有权，去拷贝后失去同步屏障，易出现撕裂/悬垂。

移植风险：改动 PSC 生命周期、渲染代理与内存池；崩溃面覆盖所有特效，需大规模回归。

开发自检

  • 粒子表现与默认路径一致
  • 无 GT/RT 数据竞态与断言
  • 帧时间与内存符合预期

结论置信度：medium — UE5.8 异步 tick 是否已覆盖大部分收益、是否值得整包移植待评估
