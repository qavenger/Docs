可主动舍弃性（UE5 架构更替）

直接舍弃 PhysX / Apex → Chaos

判定依据：补丁全部落在 FPhysScene_PhysX 的 DeferredKinematicUpdateSkelMeshes 容器上（UE4 PhysScene_PhysX.cpp:968/1021/1038/1044 把 TArray<USkeletalMeshComponent*> 换成 TWeakObjectPtr），而 UE5 已移除 PhysX 场景实现：E:/TorchLight_UE5/.../Engine/Private/PhysicsEngine/PhysScene_PhysX.cpp 只剩余版权头（空壳），物理由 Chaos 承担。该代码在新引擎里不存在，无法也不需要移植。

舍弃前提：项目随引擎一起从 PhysX 切到 Chaos（UE5 无回退选项）

UE5 替代能力：Chaos 物理场景（Runtime/Engine/Private/PhysicsEngine/Experimental/PhysScene_Chaos.cpp）

0. 根因溯源（这个宏为什么存在）

上游缺陷（需上游修复或长期携带补丁）

结论：FPhysScene(PhysX) 的 DeferredKinematicUpdateSkelMeshes 用 TArray<TPair<USkeletalMeshComponent*, FDeferredKinematicUpdateInfo>> 保存延迟运动学更新的组件，但物理 Tick 遍历时组件可能已被 GC/销毁 → 悬垂指针 UAF（TORCHLIGHT-138970）。XD 把该数组改成 TWeakObjectPtr 并在 MarkForPreSimKinematicUpdate/ClearPreSimKinematicUpdate/UpdateKinematicsOnDeferredSkelMeshes 里用 Key.Get()/IsValid 判空跳过。上游在 Chaos 侧独立发现同类问题并修复（c04d48b07f4e，2023-02-13 jaco vandyk，AABBTree crash）。UE5 已删除 PhysX 场景实现，只剩 Chaos 版且已是弱指针，故无需移植。

上游引入：上游引入：git log -S "DeferredKinematicUpdateSkelMeshes"（限定 PhysScene_PhysX.h/PhysScene_Chaos.h）最早命中 ab108c215e0f，2019-01-08，Marc Audy，“Copying to Dev-Main @ CL# 4688301”；核验 git show ab108c215e0f~1:<PhysScene_PhysX.h> 该符号计数为 0、该提交为 1（:416），确认裸指针数组系此提交引入。4.26 上游两处副本均为此形态：PhysScene_PhysX.h:426 与 Experimental/PhysScene_Chaos.h:314（后者同样裸指针）。

上游历史（是否修过）：上游已修（仅 Chaos 副本）：c04d48b07f4e，2023-02-13，jaco vandyk，提交说明明确 “Change DeferredKinematicUpdateSkelMeshes to use TWeakObjectPtr to avoid garbage collected upointers getting into the tree update”，git tag --contains 显示首个发布版本 5.3.0-preview-1，diff 仅含 Experimental/PhysScene_Chaos.h/cpp。UE5 5.8.2 现状：Chaos 版 Source/Runtime/Engine/Public/Physics/Experimental/PhysScene_Chaos.h:501 已是 TWeakObjectPtr，遍历处 :2027/:2031/:2047-2049/:2124-2127 均 Key.Get() 并判空；而 PhysScene_PhysX.h 已退化为 24 行孤立 stub（无 FPhysScene_PhysX 类），PhysX 实现随 PhysX 移除。

为什么可以断定不是「故意为之」4 条依据
  • 延迟数组跨越 GC，元素生命周期不由物理场景控制，持裸 UObject 指针属明确缺陷而非设计。
  • 同一数组在 Chaos 副本里被上游自己改成 TWeakObjectPtr（c04d48b07f4e），等于官方确认原写法危险。
  • UE4 代码里其它持有组件引用处普遍使用 TWeakObjectPtr（如 PhysScene_PhysX.cpp:1330 BodyInstance->OwnerComponent.IsValid()），裸指针在本文件是例外。
  • 该数组清理点只有 UpdateKinematicsOnDeferredSkelMeshes 末尾的 Reset() 与 ClearPreSimKinematicUpdate，一旦组件在中途销毁就无法保证被移除，不是有意的生命周期约定。

调用方契约：契约方是 USkeletalMeshComponent：MarkForPreSimKinematicUpdate/ClearPreSimKinematicUpdate 由组件驱动（bDeferredKinematicUpdate 标志），物理 Tick 调 UpdateKinematicsOnDeferredSkelMeshes 消费；XD fork 中对应 PhysScene_PhysX.cpp:968/1021/1038/1044，声明在 PhysScene_PhysX.h:426-429。上游 Chaos 版对应 PhysScene_Chaos.cpp:1738/1759-1760/1774/2027/2047/2124。

内层真实语义：失败路径（修复前）：组件被 GC 后 Key 为悬垂，遍历里解引用 → UAF 崩溃。修复后：Key.Get() 返回 null 即 continue/跳过，不进入树更新。正常路径：组件有效则照常更新运动学；空数组为合法 no-op。

代码库惯例：物理场景里跨帧持有的 Actor/Component 引用一律 TWeakObjectPtr + IsValid/Get()（如 PhysScene_PhysX.cpp:1330、Chaos 版 DeferredKinematicUpdate.Key.Get() 的所有调用点）；UE5 全树现无该裸指针写法。

为何长期未被发现：需要“延迟更新登记后组件在物理 Tick 前被销毁/GC”这一时序，多见于关卡切换、蓝图销毁 SkeletalMesh，且偶发（依赖 GC 时机）；崩溃堆栈在 Chaos/PhysX 内部或 tree update，容易被归因于物理引擎。

XD 侧的做法与意图：fork：Source/Runtime/Engine/Public/Physics/PhysScene_PhysX.h:426-429 把数组元素改为 TPair<TWeakObjectPtr<USkeletalMeshComponent>, ...>；Source/Runtime/Engine/Private/PhysicsEngine/PhysScene_PhysX.cpp:968（FindByPredicate 用 Key.Get() 比较）、:1021（RemoveAll 用 Key.Get()）、:1038-1044（遍历时 IsValid 后 continue）配套修改。开关：XDBuildFixBugConfiguration.cs:189（注释 “DeferredKinematicUpdateSkelMeshes Contain invalid skel-mesh ptr，REF TORCHLIGHT-138970”）。注意：UE4 fork 的 Chaos 副本 Experimental/PhysScene_Chaos.h:314 仍是裸指针，XD 只修了 PhysX 路径。

⚠ 在 UE5 上重建 PhysScene_PhysX 或把宏套到 Chaos 代码上毫无意义（UE5 无此类，Chaos 已修）；⚠ 把 Key.Get() 判空改成 ensure()/check() 会把偶发时序问题变成必崩；⚠ 只改数组类型不改 FindByPredicate/RemoveAll 的比较表达式（仍写 InItem.Key == InSkelComp）会编译失败或语义错（拿弱指针与裸指针比较）。

迁移方案（按根因定）

变更类型 abandon：直接删除宏与 fork 的 PhysX 补丁，不向 UE5 迁移。理由：UE5 5.8.2 的 Chaos 版已用 TWeakObjectPtr（PhysScene_Chaos.h:501），PhysX 场景实现已删除（PhysScene_PhysX.h 仅剩 24 行 scratch buffer 定义）。迁移动作仅剩两项校验：①项目侧是否有代码直接使用 FPhysScene_PhysX API（rg 项目源码，若无则删除干净）；②若项目在 UE5 上启用 Chaos 且自研了 deferred kinematic 逻辑，确认沿用 Key.Get() + IsValid 的写法而非裸指针。

根因级自检用例

  • 回归：Chaos 物理下关卡切换/销毁带动画组件时无 UAF（压力测试含 GC）。
  • 编译：UE5 无 PhysScene_PhysX 相关引用（含项目侧），删除宏后全量编译通过。
  • 行为：延迟运动学更新仍生效（隐藏场景下骨骼物理跟随正确）。
  • 边界：数组为空时 UpdateKinematicsOnDeferredSkelMeshes 为 no-op。
  • 代码检查：全树无 TArray<TPair<USkeletalMeshComponent*, FDeferredKinematicUpdateInfo>> 残留写法的自研代码。

可反馈上游：UE4.26 + PhysX 最小复现：USkeletalMeshComponent 调用 MarkForPreSimKinematicUpdate 后，在该帧物理 Tick 前销毁/GC 该组件 → UpdateKinematicsOnDeferredSkelMeshes 遍历裸指针 UAF。上游修法也可见 c04d48b07f4e（Chaos 副本）——统一改 TWeakObjectPtr + Key.Get() 判空。

风险评估

原代码风险：裸指针在组件销毁后仍留在延迟更新数组，物理 Tick 遍历时 UAF 崩溃（TORCHLIGHT-138970）。

移植风险：不迁移即删除宏，风险在于万一仍有项目侧代码直接用 PhysScene_PhysX API（UE5 已无此类），需编译验证。

开发自检

  • 骨架网格在 PreSimKinematicUpdate 后立即销毁不崩溃
  • UpdateKinematicsOnDeferredSkelMeshes 无 ensure
  • 打包(Shipping/Dev)与编辑器一致

结论置信度：high
