地图检查时自动修正与静态网格材质不匹配的 Override 材质

未覆盖 插件化 需接入点 仅加接入点 工作量 M风险 中开发者 Han Shu Bin主要模块 Engine

背景：组件覆盖材质数量/顺序与网格不一致时按名称自动对齐，避免运行时材质错位。

// 实现内（照搬 UE4:445-525，替换 UE5 类型/访问器）
void UStaticMeshComponent::CheckAndSolveUnmatchedOverrideMats()
{
	const TArray<FStaticMaterial>& SMs = GetStaticMesh()->GetStaticMaterials();
	if (OverrideMaterials.Num() > SMs.Num())
	{
		TArray<TObjectPtr<UMaterialInterface>> TempOverrideMaterials = OverrideMaterials;
		switch (SolveUnmatchedOverrideMaterialsMethod)
		{
		case 0: break;                                   // Do nothing
		case 1: OverrideMaterials.Reset(); LogWarningForUnmatchedOverrideMats(GetStaticMesh()->GetName()); break;
		case 2: OverrideMaterials.Remove(nullptr); LogWarningForUnmatchedOverrideMats(GetStaticMesh()->GetName()); break;
		case 3: OverrideMaterials.RemoveAt(SMs.Num(), OverrideMaterials.Num() - SMs.Num(), true); LogWarningForUnmatchedOverrideMats(GetStaticMesh()->GetName()); break;
		case 4: /* 同 UE4：从末尾去 nullptr + IsOverrideMatsSubsetOfStaticMats，比较用 SMs[i].MaterialInterface */ break;
		case 5: /* 同 UE4：Remove(nullptr) + IsOverrideMatsSubsetOfStaticMats */ break;
		default: /* 同 UE4 的 MapCheck 报错 */ break;
		}
	}
}

⚠ UE5 的 OverrideMaterials 仍 public（MeshComponent.h:31，TArray<TObjectPtr<UMaterialInterface>>）；FStaticMaterial::MaterialInterface 为 TObjectPtr（StaticMesh.h:508）；CVar 与 UE4 完全一致。

风险评估

原代码风险：方案 1/2 直接 Reset/Remove(nullptr) 会静默丢弃美术手工覆盖材质，且不自动重烘场景（原日志已提示需 rebake）。

移植风险：改到所有 UStaticMeshComponent 的地图检查路径，误判会批量改写资产覆盖材质；建议默认 CVar=0，只在项目 commandlet 打开。

开发自检

  • CVar=0 时 CheckForErrors 行为与 UE5 原生一致
  • CVar=3/4 在测试地图只修正不匹配组件，重启可复现
  • 取一个 OverrideMaterials>StaticMaterials 的资产跑 MapCheck，warning 出现且材质被对齐

结论置信度：high
