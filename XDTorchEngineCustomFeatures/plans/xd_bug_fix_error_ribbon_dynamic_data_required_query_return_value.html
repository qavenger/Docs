修改草案 · XD_BUG_FIX_ERROR_RIBBON_DYNAMIC_DATA_REQUIRED_QUERY_RETURN_VALUE

修正 Ribbon 粒子 IsDynamicDataRequired 的返回值（原实现恒返回 true）

未覆盖 常开补丁 引擎内实现 结构性改动 工作量 S风险 中开发者 Lu Xun主要模块 Engine

一句话结论：Ribbon 可见性判断错误会导致无谓 DynamicData 生成，建议补丁

可主动舍弃性（UE5 架构更替）

直接舍弃 Cascade 粒子 → Niagara

判定依据：宏只出现在 Cascade Ribbon/Trail2 发射器实例的 IsDynamicDataRequired() 返回路径上（UE4 ParticleTrail2EmitterInstance.cpp:2713-2720），是 Cascade 运行时专属修补，Niagara 的 Ribbon 渲染器有独立的 dynamic-data 判定，没有对应物。

舍弃前提：迁移后特效在 Niagara 重做，不再加载/运行 Cascade 资产

UE5 替代能力：Niagara（NiagaraComponent + Ribbon Renderer 的 dynamic data 判定）

  1. 在 UE5 上复核问题
    UE5 证据：UE5 ParticleTrail2EmitterInstance.cpp:2615-2624 FParticleRibbonEmitterInstance::IsDynamicDataRequired 末尾仍无条件 return true。先在 UE5 复现原问题；若已不存在，则按「删除」处理。
  2. 在 UE5 fork 重新应用补丁
    原实现位置：Source/Runtime/Engine/Private/Particles/ParticleTrail2EmitterInstance.cpp。引擎侧改动点：FParticleRibbonEmitterInstance::IsDynamicDataRequired。补丁应保持最小范围，避免改公共接口。
  3. 登记为常开补丁
    在 Feature Registry 记录：问题、修法、验证方式、回滚方式；不再挂编译开关。

3. 代码级实现（开发用）

独立 Agent 审核并修正修正 1 处　提出问题 1 条　其中高风险 1 条

审核意见：宏定义行（XDBuildFixBugConfiguration.cs:528=1）、UE5 恒 true（ParticleTrail2EmitterInstance.cpp:2624）均属实，但 after 的返回逻辑写反，必须修。

简单移植 改动方式：函数名/签名与逻辑壳在 UE5 完全一致，仅返回逻辑需照抄。

代码脉络：宏定义 XDBuildFixBugConfiguration.cs:528（值1）。生效链：FParticleRibbonEmitterInstance::IsDynamicDataRequired 原实现末尾无条件 return true（UE5 ParticleTrail2EmitterInstance.cpp:2626）。宏改为：ActiveParticles<2 时 return false，其余 return true（UE4 ParticleTrail2EmitterInstance.cpp:2709-2721），避免无谓 DynamicData 生成。

bool FParticleRibbonEmitterInstance::IsDynamicDataRequired(UParticleLODLevel* InCurrentLODLevel)
{
 if (FParticleEmitterInstance::IsDynamicDataRequired(InCurrentLODLevel) == true)
 { if ((ActiveParticles < 2)) { return false; } }
 return true;
}
bool FParticleRibbonEmitterInstance::IsDynamicDataRequired(UParticleLODLevel* InCurrentLODLevel)
{
    if (FParticleEmitterInstance::IsDynamicDataRequired(InCurrentLODLevel) == true)
    {
        if (ActiveParticles < 2)
        {
            return false;
        }
        return true;
    }
    return false;
}

⚠ UE5 现状是恒 true，改为恒 false 需确认上层对 false 的处理；XD 补丁本意即“仅在基类要求且有≥2粒子时为 true”。

风险评估

原代码风险：Ribbon 恒真返回导致即使无有效 trail 也生成 DynamicData，浪费渲染线程开销。

移植风险：改动 Ribbon 可见性判断，可能影响 Ribbon 粒子渲染；需回归 Ribbon/AnimTrail 表现。

开发自检

  • ActiveParticles<2 的 Ribbon 不再生成 DynamicData
  • 正常 Ribbon/AnimTrail 仍正确渲染

结论置信度：high
