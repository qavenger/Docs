修改草案 · XD_RENDERING_TOON_LIT_SHADING_MODEL

新增 ToonLit 卡通光照着色模型（火炬之光卡通渲染核心）

部分覆盖 移植 需接入点 深度侵入 工作量 L风险 高开发者 Guo DengJi主要模块 Shaders

一句话结论：建议先做 Substrate Toon 与项目美术风格对比评估；保留 MSM_ToonLit 会带来枚举/序列化/shader permutation 深度侵入

背景：在着色模型列表中增加 ToonLit，提供分档光照、Ramp 贴图、描边等卡通渲染所需的 Shading Model 支持；编辑器材质、渲染器与 Shader 全部打通。

2. 修改步骤（移植）

  1. 定位 UE5 对应文件
    见下方「UE5 对应文件」；重点比对同文件在 UE4/UE5 的差异。
  2. 移植实现
    原实现位置：Shaders/Private/BasePassCommon.ush、Shaders/Private/BasePassPixelShader.usf、Shaders/Private/ClusteredDeferredShadingPixelShader.usf、Shaders/Private/DeferredLightPixelShaders.usf、Shaders/Private/DeferredLightingCommon.ush、Shaders/Private/DeferredShadingCommon.ush、Shaders/Private/ForwardLightingCommon.ush、Shaders/Private/LightShaderParameters.ush。如涉及 Shader，需同步改 shader define 或共享 include。
  3. 适配 UE5 接口与规范
    注意 C++20、UHT（反射）规则、bValidateCircularDependencies 默认开启等差异；必要时回归 DDC/Cook。
  4. Shader 侧配套
    删除 DerivedDataCache 重编 Shader；同步更新受影响的 shader permutation / ShaderVersion。

风险评估

原代码风险：深侵入 shading model 枚举/序列化/shader permutation，MP_MAX 与 MSM_NUM static_assert 关联，任一处漏改即编译失败或错位。

移植风险：改枚举与 GBuffer 语义，影响所有材质资产与 171 处引用；MSM_NUM 增到 15 逼近 16 上限。

开发自检

  • 含 ToonLit 材质在 PC Deferred/Mobile 编译并渲染
  • 旧资产 shading model 数值不错位
  • Substrate 与 legacy 路径均不崩

结论置信度：low — 强烈建议先评估改用 UE5 官方 Substrate Toon（UMaterialExpressionSubstrateToonBSDF/MaterialExpressionSubstrate.h:861、UToonProfile）替代 MSM_ToonLit；若保留则全管线改造工作量 L。
