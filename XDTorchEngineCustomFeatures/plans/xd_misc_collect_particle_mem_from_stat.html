修改草案 · XD_MISC_COLLECT_PARTICLE_MEM_FROM_STAT

从 STAT 中提取粒子相关内存数据（默认关闭）

部分覆盖 配置化 需接入点 仅加接入点 工作量 S风险 低开发者 Zhao Shuai Nan主要模块 Core

一句话结论：默认关闭的工具项，建议用项目统计插件+CVar 重做

⚠ 原宏备注：XD_MISC_MEMREPORT_TIMER=1 时要求该项为 1。

可主动舍弃性（UE5 架构更替）

直接舍弃 Cascade 粒子 → Niagara

判定依据：UE5 特效体系已全面转向 Niagara，Cascade 仅保留兼容维护；项目迁移到 UE5 后特效会重做，针对 Cascade 运行时的定制可在迁移时直接不带过去。

舍弃前提：前提：迁移后在 UE5 用 Niagara 重做特效（不再走 Cascade 运行时）

UE5 替代能力：Niagara（NiagaraSystem / NiagaraComponent / NiagaraDataInterface）

相关文件：Source/Runtime/Engine/Private/Particles/ParticleMemoryStatManager.cpp

风险评估

原代码风险：GetPermanentStats 会阻塞等待 StatsThread（FTaskGraph WaitUntilTaskCompletes），在 GT 频繁调用有卡顿风险；仅在编辑器 memreport 使用。

移植风险：改 Core Stats 影响面大（所有 stat 命令），且 memreport timer 依赖关系（:534）需一并保留校验。

开发自检

  • memreport / 粒子 mem 报表数值正确
  • 未开宏时 Core 无新增符号依赖、打包无未定义引用

结论置信度：medium — UE5 GStatsPipe 线程模型与 UE4 FSimpleDelegateGraphTask 不同，重载实现细节需按 2487-2489 的实际写法调整。
