修复 FOpenGLDynamicRHI::RHICreateUnorderedAccessView_RenderThread 崩溃

一句话结论：UE5 已移除 renderthread 版 UAV 创建接口

可主动舍弃性（UE5 架构更替）

需评估 旧 RHI / 平台图形路径

判定依据：UE5 的 RHI 层有增删（部分旧路径废弃、移动端默认管线变化），需按目标平台复核。

舍弃前提：需确认：新工具链/新插件/新 RHI 下该问题是否仍存在

UE5 替代能力：UE5 保留的 RHI（D3D12/Vulkan/Metal），部分旧路径已淘汰

0. 根因溯源（这个宏为什么存在）

上游已自行修复（该宏可直接删除）

结论：移动端 OpenGL(ES) 上用不支持 tex buffer 的设备创建 typed-buffer UAV 会导致崩溃。XD 的做法是新增 FOpenGLDynamicRHI::RHISupportUnorderedAccessView()（转发 FOpenGLBase::SupportTexBuffer）并在创建入口提前 return nullptr。UE5 把 UAV 创建收敛为 FRHIViewDesc 单入口，旧的能力探测函数与创建路径一并消失，XD 所防的崩溃场景不再成立。

上游引入：上游早期 OpenGL RHI 有多个 UAV 创建入口（含 renderthread 版）且未做能力过滤；XD 在 UE4.26 fork 的 OpenGLDrv.h:335 / OpenGLUAV.cpp:313/:322 增加能力检查与提前返回。

上游历史（是否修过）：已核实 UE5.8.2：Source/Runtime/OpenGLDrv/Private/OpenGLUAV.cpp 中 UAV 创建只剩 ViewDesc 形态 —— :375 `FUnorderedAccessViewRHIRef FOpenGLDynamicRHI::RHICreateUnorderedAccessView(class FRHICommandListBase& RHICmdList, FRHIViewableResource* Resource, FRHIViewDesc const& ViewDesc)`；该文件内 grep 不到 RHISupportUnorderedAccessView（XD 新增的能力探测函数）。即接口层面已重构，旧的崩溃路径不复存在。

为什么可以断定不是「故意为之」2 条依据
  • 上游把 UAV 创建统一到 FRHIViewDesc（RHI 层的整体重构方向），不是针对该崩溃的局部补丁——属于结构性消除。
  • XD 的防护依赖旧接口存在（渲染线程版创建 + 能力探测），UE5 没有这些入口，防护无处附着。

调用方契约：RHI 层创建 UAV 需要保证底层资源支持（typed buffer / tex buffer）；不支持时应返回空指针而非发起非法创建。

内层真实语义：UE4（XD 宏）：创建前用 SupportTexBuffer 判定，不支持则提前 return nullptr。UE5（上游）：统一走 ViewDesc 创建路径，能力校验在视图描述层处理。

代码库惯例：RHI 创建接口收敛为 ViewDesc 是上游近年重构方向（减少入口数量、统一校验点）。

为何长期未被发现：只在"移动端 OpenGL ES + 设备不支持 tex buffer + 使用 typed-buffer UAV"组合下崩溃；PC 与主流移动设备不触发。

XD 侧的做法与意图：XD 的目标是避免低端/不支持的 GLES 设备上创建 UAV 时崩溃，改为安全回退。

⚠ 迁移时不要按 UE4 的位置补"能力探测函数"：UE5 已无对应创建入口，硬补会形成游离于新架构之外的死代码；若确实需要能力判定，应在 ViewDesc/平台层处理。

迁移方案（按根因定）

删除 XD_BUG_FIX_MOBILE_OPENGLES_CREATE_UAV_ERROR 及 OpenGLUAV 中的相关改动；如需保留"不支持即安全返回"的语义，在 UE5 的 ViewDesc 路径上确认已由上游覆盖。

根因级自检用例

  • 在不支持 tex buffer 的 GLES 设备/模拟器上创建 typed-buffer UAV：不崩溃（安全失败）
  • 支持该能力的设备上 UAV 功能正常（无能力误判）
  • 移动端渲染回归（含 compute 相关特性链路）

可反馈上游：无需反馈（上游接口重构后该路径消失）。

风险评估

原代码风险：在无 texture buffer 能力的 GLES 驱动上创建 typed UAV，GL 调用返回错误并置空句柄，随后访问崩溃。

移植风险：靠新增能力开关规避，若探测函数未覆盖 ES3.1/EXT 两条路径会误判为不可用而静默丢 UAV，影响移动端 compute。

开发自检

  • Android GLES 低端机（无 GL_EXT_texture_buffer）跑依赖 vertex buffer UAV 的渲染用例
  • 确认返回 nullptr 时上层不 crash 且降级路径生效

结论置信度：medium — UE5 是否在别处已对 typed buffer UAV 做过能力过滤未逐一核实；SupportsTextureBuffer 需自建。
