关于本文档

本文档把心动定制 UE4.26 引擎里的全部特性宏整理成可查、可评估、可排期的工程资料，并针对迁移目标 UE5.8.2 给出逐宏的迁移结论与代码级修改草案。

一、范围与结论速览

项数量说明
特性宏总数566分布在 XDBuild*Configuration.cs 的 7 个类里
参与迁移分析549另有 17 个宏按原需求排除（CustomUnlit 家族、描边、SmoothNormal、HDR 输出、DepthStencil 修复）
代码级修改草案549每个宏一份，含代码脉络、改动方式、before/after 代码、风险评估
独立 Agent 审核403 个已过审去源码实证核对行号/函数/API 是否真实，给出修正
可主动舍弃候选92 个（含 15 项待确认）因 UE5 架构更替（Cascade→Niagara、PhysX→Chaos、旧工具链等）可不必迁移
跨维度分歧90 处早期处置结论与代码级分析不一致处，附取舍建议

二、怎么用这份文档

  1. 要排期 → 看 迁移实施清单：按落地动作分成 7 组，组内按工作量排序，带工作量/风险/改动方式。
  2. 要决策某项能不能不做 → 看 可主动舍弃：92 个候选 + 15 项待确认，附舍弃前提与 UE5 替代能力，还有与草案的交叉核对。
  3. 要具体改法 → 看任意 修改草案：代码脉络（文件:行）、改动方式、分步 before/after 代码、风险与自检。
  4. 要核对结论 → 看 草案审核报告：审核结论、问题明细（带证据）、修正示例、跨维度分歧。
  5. 要按人/按模块看 → 看 开发者 × 模块视图 与 全量评估矩阵。
  6. 要看宏本身 → 看 全量参考卡片（每个宏的作用、注释、引用位置、上下文）或 主题脉络。

三、四个分析维度

维度回答什么取值
覆盖度UE5 是否已经提供该能力已覆盖 / 部分覆盖 / 未覆盖 / 待确认
落地位置能力应该写在哪可工程化（配置） / 需接入点 / 引擎内实现

四、代码级草案是怎么产出的

  1. 源码定位：用 find + grep 扫描引擎目录（Source / Shaders / Plugins / Config / Build），排除中间产物后得到每个宏的全部引用位置（文件:行 + 代码原文），共 6035 处。
  2. 逐宏分析：每个批次 8 个宏交给一个分析 Agent，要求先 grep/read 真实源码，再产出「代码脉络 + 改动方式（简单移植 / 改接口改名 / 完全重构 / 建议舍弃）+ 分步 before/after 代码 + 原代码风险 + 移植风险 + 自检 + 置信度」。
  3. 独立审核：另一位 Agent 逐条实证核对——行号/函数名是否存在、before 是否真出自 UE4 源码、after 引用的类/函数/枚举在 UE5 是否真实存在，问题必须带证据，修正必须可直接替换。
  4. 交叉审计：把早期处置结论与代码级分析做交叉比对，标出分歧（多数是"早期以为要移植、实际可以不做"）。

五、口径与提醒

  • 本文档的迁移结论针对 UE5.8.2；工程 E:\TorchLight_UE5、迁移工程 F:\UE5_Projects\Torchlight_Migrate。
  • 「可舍弃」的判定都写在前提成立的条件下（例如"迁移后用 Niagara 重做特效"）；前提变化时对应宏要回到移植清单。
  • 草案是给技术同学评估用的工程草案，不是最终实现；改动前请以草案页的「代码脉络 + UE4 侧改动位置」自行复核。
  • 置信度标 low 或被审核标为「需重做」的条目，请优先人工确认其「不确定点」。
标签说明

颜色规则：覆盖度=红绿灯 · 工程化=蓝色系 · 侵入=紫色系 · 处置=中性灰。
分级方式：工程化/侵入用「实心 → 底色 → 描边 → 虚线」四级形态表示程度递进（实心最强）。

UE5 覆盖度

UE5 已覆盖UE5.8 原生等价，可直接删除
部分覆盖UE5 有同类能力，只迁差异部分
未覆盖UE5 没有该能力，需迁移或补丁
待确认证据不足，迁移前需人工确认

落地位置（工程化可行性）

可工程化放项目/插件/配置即可，不动引擎
需接入点引擎留少量 Hook，逻辑在工程侧
引擎内实现必须改引擎核心
—处置=删除的行不适用（已删除/不迁移）

引擎改动方式

L0 无需改引擎纯工程/插件/配置即可（对应「可工程化」）
L0 引擎内补丁需改引擎源码，但不必新增扩展点（对应「引擎内实现」）
L1 仅加接入点引擎只需暴露 Delegate / Interface / CVar 等扩展点
L2 结构性改动枚举 slot / 新 Pass / schema 字段
L3 深度侵入核心结构/生命周期/序列化，慎入

迁移处置

删除UE5 已覆盖，直接删
常开补丁确认的 bugfix，作为 fork 常开补丁
配置化改为 CVar / ini / DeviceProfile / 命令行
插件化迁到项目模块 / 编辑器插件
接入点引擎只留 Hook，逻辑在插件
移植代码保留，适配后移植
保留引擎深度绑定，暂留并登记 Feature Card
