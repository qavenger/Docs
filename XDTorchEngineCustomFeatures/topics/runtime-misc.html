🧭 运行时接口与诊断

日志、崩溃上报、退出行为与杂项接口

一句话概括：面向线上运维与项目接入的一组「小接口、大作用」改动：统一退出/重启、日志与崩溃可诊断、Http/媒体等运行时接口补齐、以及一批运行时委托供项目注入逻辑。

1. 退出、重启与异常

  • XD_MISC_EXT_APP_EXIT_METHOD：统一的正常/异常退出接口，项目可决定退出方式。
  • XD_MISC_ANDROID_EXIT_WITH_ABORT_METHOD / XD_MISC_IOS_EXIT_WITH_ABORT_METHOD：主动退出改用 abort，让 Backtrace 捕获信号并留下日志。
  • XD_REPORT_ALL_REQUEST_EXIT_EVENT_AS_ERROR：强制退出前 Flush 全部日志并上报为错误事件。
  • XD_MISC_WINDOWS_FORCE_EXIT_WITH_CRASH：Windows 以崩溃方式退出以产出崩溃报告。
  • XD_EXT_USE_SHARED_REBOOT_REQUEST：收集应用初始化期间的重启请求统一执行（Android 走 JNI，Generic 仅告警）。
  • XD_BUG_FIX_PARSE_PROJECTNAME_FROM_COMMANDLINE：从命令行正确解析 ProjectName（UE4Editor-Cmd.exe -project=... 场景）。
  • XD_BUG_FIX_ENGINE_INITIALIZED_FAIL：引擎初始化失败时主动触发崩溃，保证「静默退不出日志」变成可上报的崩溃。

2. 日志体系

  • XD_TOOL_ONLY_BACKUP_ONE_FILE_FOR_BACKTRACE：移动端只保留一个日志备份文件，专供 Backtrace 崩溃上报，避免日志刷爆磁盘。
  • XD_MISC_CHECK_EXPRESSION_ALSO_PRINT_UE_LOG：CHECK 失败时同时输出 UE_LOG，便于在完整日志里定位崩溃点。
  • XD_MISC_FATAL_ERROR_PRINT_FILE_NAME_IN_SHIPPING_MODE：Shipping 包的致命错误也带源码文件名。
  • XD_MISC_LOG_REDUCTION：减少 Shipping 构建的运行时日志量。
  • XD_BUG_FIX_LOG_LOST_TIMESTAMP、XD_BUGFIX_STAT_MESSAGES_CHUNK_SIZE_OVERFLOW、XD_BUG_FIX_UPGRADE_PREVIEWSCENE_LOG_LEVEL：日志时间戳丢失、Stat 线程消息块溢出、PreviewScene 日志级别。
  • XD_MISC_ADD_INTERFACE_TO_GET_LOG_VERBOSITY：查询日志级别接口。
  • XD_MSIC_GENERIC_STACK_TRACE：通用平台堆栈回溯，支持自定义深度。
  • XD_EXT_REPORT_ERROR_MSG_VIA_CRASH_TOOLS：把错误信息通过 Themis 等崩溃平台上报。
  • XD_EXT_SUPPORT_DUMP_FNAME：Dump FName 名称表（配合 DumpConsoleCommands_XD 使用）。
  • XD_USE_BIG_ERROR_MESSAGE_SIZE（默认 0）：放大错误信息缓冲区以便调试。

3. 运行时接口扩展

  • XD_MISC_CONSOLE_VARIABLES：登记所有 xd.* 控制台变量（XDConsoleVariables.inc），是 DumpConsoleCommands_XD 与线上热调的基础（UBT 强制为 1）。
  • XD_TOOL_ADD_RUNTIME_DELEGATES_EXTENSION：新增一批运行时多播委托（粒子生命周期、SkeletalMesh、WorldCulling 等），项目可在不改引擎的情况下挂接逻辑。
  • XD_MISC_SUPPORT_HTTP_REQUEST_COMPLETION_RESULT_GETTER：Http 请求提供完成结果 Getter，便于状态记录与检查。
  • XD_MISC_MEDIA_TEXTURE_ALLOW_KEEP_LAST_FRAME：媒体播放结束后可保留末帧。
  • XD_BUG_FIX_WMF_SESSION_CLOSE_HANG、XD_FIX_BUG_ELECTRA_PLAYER_BLOCK_GT_WHEN_RELEASE、XD_AVF_NO_PREROLL、XD_BUG_FIX_AVF_TASK_QUEUE：PC WMF 关闭卡死、Electra 释放阻塞 GT、iOS AVF 回调与线程安全问题。
  • XD_BUG_FIX_HTTP_THREAD_INVALID_SLEEP_TIME：修复 Http 线程睡眠时间负值。
  • XD_BUG_FIX_CODE_REFERENCED_ASSETS：避免引擎代码直接引用资源导致无用加载。
  • XD_BUG_FIX_GC_SYNCOBJ：GC 等待空指针修复。

4. 使用建议

  • 线上排障首选 DumpConsoleCommands_XD（列出所有定制 CVar 当前值）+ MemReport + Backtrace 日志；这三个能力分别由本页与内存专题的宏支撑。
  • XD_MISC_CONSOLE_VARIABLES 是强制为 1 的基础设施；新增自定义 CVar 时应加入 XDConsoleVariables.inc 以便统一管理。
  • 退出方式（abort / 崩溃退出）与崩溃平台策略强相关，改动前先与运维/QA 确认崩溃上报口径。

引擎改动方式

L0 无需改引擎纯工程/插件/配置即可（对应「可工程化」）
L0 引擎内补丁需改引擎源码，但不必新增扩展点（对应「引擎内实现」）
L1 仅加接入点引擎只需暴露 Delegate / Interface / CVar 等扩展点
L2 结构性改动枚举 slot / 新 Pass / schema 字段
L3 深度侵入核心结构/生命周期/序列化，慎入
