⚙️ 宏系统与构建机制

UBT 如何把 566 个特性宏注入到引擎

1. 这套机制是什么

XDBuildConfiguration 不是一个普通配置文件，而是构建期特性开关系统：UBT（UnrealBuildTool）在构建目标时用反射读取 7 个 C# 类里的 public static int 字段，把「字段名=值」注入编译环境的全局宏定义，最终写进每个模块的 Definitions.*.h。因此：

  • C++ 与 Shader（USF/USH）都可以直接 #if XD_XXX 使用，无需 include。
  • 宏是全局的——同一个宏在所有模块里取值一致，没有按模块区分的可能。
  • 修改宏的值会改变 Definitions.h 的内容，从而触发全量重新编译，所以不要把随平台/编辑器状态频繁变化的开关放在这里。

3. 构建流程（源码级）

  1. XDBuildConfiguration.ConfigurationClasses 列出 7 个类名。
  2. UEBuildTarget.SetupXDNewFeaturesGlobalMacros()（Configuration/UEBuildTarget.cs）在初始化全局编译环境时被调用。
  3. 先执行 XDBuildConfiguration.CheckDependencies()：串联调用 7 个类的 CheckDependencies()，失败即 throw new BuildException("Check XD Features Dependencies Error !!!")，构建直接中止。
  4. 遍历 7 个类，用 BindingFlags.Public | Static 反射所有字段，逐个 GlobalCompileEnvironment.Definitions.Add("字段名=值")；类名找不到时抛 BuildException。
  5. 构建系统把这些定义写进各模块的 Definitions.*.h（可在 Intermediate/Build/.../Definitions.XXX.h 中核对实际值）。

4. 依赖检查与自动改值

UBT 会在构建时校验宏之间的前提关系，不满足则报 XD Feature Dependency Error 并中止构建。下表是全部硬性规则：

规则含义 / 原因
XD_PC_RENDERING_NATIVESTENCIL_SUPPORT_MATERIAL → XD_RENDERING_NATIVESTENCIL_SUPPORT_MATERIALPC 模板扩展依赖材质模板功能
XD_RENDERING_AUTO_GENERATE_PER_MESHBATCH_... → XD_RENDERING_PER_MESHBATCH_TRANSLUCENTPASS_RENDERING_PRIORITY粒子自动排序依赖半透明优先级机制

5. 使用建议

  • 新增 Feature：在对应类的 public static int 区域加宏 + 注释（作者/原因），并在引擎源码里用 #if 使用；如果与其它宏有依赖，补进 CheckDependencies。
  • 关闭 Feature：直接把值改为 0。注意值只有 0/1 两种语义（XD_TORCHLIGHT_SEASON 等为参数值）。
  • 改宏后的必做动作：全量编译 + 清理 Engine/DerivedDataCache 与项目 DDC 重新编译 Shader；PSO/DDC 相关宏还需要清理打包缓存。
  • 平台差异尽量下沉到 C++：宏是构建期全局值，团队约定不要把 IsWithEditor 之类的差异写进 UBT 逻辑，否则 Editor/Runtime 引擎会因 Definitions.h 不同而整包重编。
  • 验证宏是否生效：在 Intermediate/Build/<Platform>/<Config>/... 的 Definitions.*.h 里搜索宏名；构建日志中也会打印 Start/End Setup XD Features Macros 与依赖检查结果。
