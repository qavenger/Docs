🧩 着色器与 PSO

PSO 预编译/缓存、Shader 库、DDC 与编译流水线

一句话概括：把 UE4.26 的 PSO（Pipeline State Object）/程序二进制缓存（PBC）/Shader 库三套体系，改造成「能热更、能熔断、能被项目接管、能在移动端平滑预热」的形态，并在 Cook 阶段保证产物确定性。

1. 为什么要做这些改造

UE4.26 的 PSO 体系在移动端和长线运营项目上有三个痛点：

  • 首次进入战斗/新场景时的编译卡顿——PSO 需要在运行时现场链接（GLES/Vulkan 尤其昂贵），表现为第一次施法、第一次开大招掉帧。
  • 热更困难——.upipelinecache 与 Shader 库绑定 Cook 产物，赛季更新包体时容易失效或与新 Shader 不匹配。
  • 异常不可控——驱动/IO 损坏时 UE 默认行为是 Fatal 崩溃，缺少熔断与回退。

心动引擎围绕 Runtime/RenderCore/ShaderPipelineCache.*、Runtime/RHI/PipelineFileCache.*、Runtime/OpenGLDrv、Runtime/VulkanRHI 与 ShaderCodeLibrary 做了一整条链路的改造。

2. 功能分组

2.1 PSO 预编译调度：平滑、限时、可中断

  • XD_OPT_PRECOMPILE_PSO_SMOOTHLY：把 FShaderPipelineCache 改成高频 Tickable，并用 GFrameNumberRenderThread 限制「每帧最多处理一次」，让 PSO 预编译分摊到多帧，避免一次性长时间卡死（RenderCore/Private/ShaderPipelineCache.cpp）。
  • XD_BUG_FIX_MAX_PSO_PRECOMPILE_TIME_NON_FIRST_RUN：新增 CVar r.ShaderPipelineCache.MaxPrecompileTimeNonFirstRun，非首次启动（缓存已有效）时收紧前台预编译墙钟上限，尽快把控制权还给玩家。
  • XD_BUG_FIX_PSO_PRECOMPILE_REMAINING_REAL_COUNT_WHEN_COMPLETE：修正剩余数量统计，不再用时间比例估算，进度条不会「永远差一点」。
  • XD_BUG_FIX_PSO_PRECOMPILIING_STUCK：Android 预编译批结束时强制 ImmediateFlush(FlushRHIThread)，修复 RHI 线程 LastPrecompilingFence 卡住导致游戏停在 Logo 的问题。
  • XD_BUG_FIX_DONT_WAIT_PSO_PRECOMPILE_COMPLETED_WHEN_BATCH_JOB_PAUSED：批处理已暂停时跳过 Android 启动阶段的 busy-wait。

2.2 PSO 缓存文件：多文件合并与赛季清理

  • XD_MISC_SUPPORT_MULTIPLE_PSO_CACHE_FILES：支持多份 .stable.upipelinecache（对应多次热更），新增 MergeStableGameCacheFiles() 按 CL 或文件大小排序合并，输出合并文件到 Saved；Windows 侧把 PSO 启用推迟到热更状态检查之后。
  • XD_MISC_CLEAN_OBSOLETE_PSO_CACHE_AND_PROGRAM_CACHE：ini 未配置游戏版本时用 XD_TORCHLIGHT_SEASON 作为 game version，赛季号一变旧缓存自动失效。
  • XD_BUG_FIX_PSO_INCREMENTAL_SAVE_TOC_GUID：增量保存时先拷贝 TOC 再序列化，避免 FileGuid 被清零。
  • XD_OPT_LOAD_PSO_CACHE_BY_QUALITY_LEVEL（默认 0）：按机型物理内存选择 Low/All 档 PSO 子集加载，低端机省内存；需要时再开启。
  • XD_BUG_FIX_BUILD_PSO_WITH_SHADER_HASH：Cook 时用 ShaderHash 构建 stable cache，防止 Shader 代码变化后缓存里出现非法 VS~PS 组合。
  • XD_BUG_FIX_WARNING_WHEN_PSO_MAPS_TO_MULTIPLE_SHADERS：一个 stable PSO 映射多个 Shader 时从 Error 降级为 Warning，不阻断出包。

2.3 驱动级 PBC（程序二进制缓存）

  • XD_OPT_INCREMENTALLY_STORE_PROGRAM_BINARY_CACHE：OpenGL 的 PBC 支持增量构建/存储（GLProgramBinaryCache），不再每次全量重写。
  • XD_EXT_ANDROID_FORCE_PBC_RELOCATION：PBC 强制放内部存储，修复部分机型 SD 卡上的 pbc 非法导致崩溃（UE4-2196）。
  • XD_BUG_FIX_DISABLE_PROGRAM_BINARY_IN_MUMU_EMULATOR：MuMu 模拟器（x86_64 Android）禁用 PBC。
  • XD_OPT_RESTART_APPLICATION_WHEN_VULKAN_PSO_FILE_CACHE_COMPLETED：Vulkan PSO 文件缓存生成后按 CVar r.Vulkan.RestartAndroidAfterPrecompile 重启应用使其生效。
  • XD_EXT_SHDADER_UNUSED_PBC_EVICT：换关卡时驱逐已加载的 PBC，释放内存。
  • XD_MISC_PSO_PRECOMPILE_LLM_TAG：新增 LLM 标签 PSOU，把预编译内存与运行时 PSO 内存分开统计。

2.4 熔断、LRU 与容错

  • XD_MISC_STOP_PSO_CACHING_IF_FAILES：新增异常捕获与熔断机制（FShaderPipelineCacheExceptionCatcher），OpenGL/Vulkan 在保存或创建失败时停止后续缓存，避免 IO/驱动异常被当成崩溃。
  • XD_MISC_PSO_LRU_FALLBACK_TO_COMPILE、XD_MISC_PSO_LRU_AVOID_REPEATED_EVICTION、XD_BUG_FIX_LRU_ASYNC_PRELOAD_OVERWRITE_EVICTED：LRU 驱逐/恢复链路的三个容错点，避免 LinkedProgram 被孤立导致 ensure。
  • XD_BUG_FIX_DUPLICATE_FOPENGLPROGRAMKEY、XD_BUG_FIX_CRASH_ON_CREATE_GL_PROGRAM_FROM_BINARY、XD_BUG_FIX_OPENGL_SHADERS_RELINK_FAILD、XD_BUG_FIX_PSO_FOUND_DUPLICATED_PROGRAM_KEY_WHEN_LOADING_PROGRAM_BINARY_CACHE：GL 程序缓存加载/链接失败时改为容错/回退，而不是 Fatal。
  • XD_BUG_FIX_SHADER_COMPILING_CRASH：跟踪被取消的 ShaderMap 作业，防止半成品 Shader 触发 check。

2.5 项目接管与重启统一

  • XD_EXT_USE_PSO_PROJECT_TAKEOVER_POINTS：在 CoreDelegates 暴露 3 个 PSO 接管委托（EngineLoop 前后重定义批行为、Android 启动预编译检查）以及 Android 强制重启接管点；宏开启但无人绑定时行为与原生一致。
  • XD_EXT_USE_SHARED_REBOOT_REQUEST：重启请求统一走 FPlatformMisc::RegisterRestartApplicationRequest()，Android 走 JNI，Generic 平台只告警。
  • XD_EXT_CHECK_ACTUAL_SHADER_PRECOMPILE_NUM：只声明宏、Engine 内无使用点，属项目层接口。

2.6 Shader 库：热更与增量 Cook

  • XD_OPT_SHADER_LIB_SRIP：按资源路径把 Shader 剥离到可热更的独立 ShaderLib，配合 XDLivePatch 插件实现部分 Shader 热更。
  • XD_BUG_FIX_PATCH_SHADER_LIB_ADDITIONAL_ERROR_BOOL_FLAG：CreatePatchLibrary() 增加错误出参（UE4.26 原实现恒返回 true，调用者无法判断失败）。
  • XD_BUG_FIX_SHADER_LIB_ASSET_INFO_NOT_COMPLETE：修复 assetinfo.json 为空/未随 Cook 拷贝/热更未生成三个问题。
  • XD_BUG_FIX_SUPPORT_ITERATIVE_SHADER_LIBRARY_COOKING_FOR_NATIVE_SHADER_LIBRARY_PLATFORM：Metal 等原生库平台支持增量 Shader 库 Cook（UE4-3692）。
  • XD_BUG_FIX_IOS_GENERATE_STABLE_SHADER_OUTPUTHASHES：iOS/Metal 生成稳定 output hash，避免重 Cook 后无谓热更（UE4-3470）。

2.7 字节码压缩与调试信息

  • XD_OPT_SHADER_BYTE_CODE_PREFER_OODLE_COMPRESSION_FORMAT：Shader 库默认压缩从 LZ4 换成 Oodle。
  • XD_OPT_OPENGL_USBC_COMPRESS / XD_OPT_VULKAN_USBC_COMPRESS / XD_OPT_METAL_METALLIB_COMPRESS：各平台生成原生/进一步压缩的 Shader 库格式，缩短加载时间、减小包体。
  • XD_MISC_SHADER_KEEPDEBUG_INFO：低于 Shipping 的构建保留 USBC/metallib 调试信息（CVar r.Shaders.XD_KeepDebugInfoBelowShipping），兼顾线上崩溃排查。

2.8 变体裁剪与编译诊断

  • XD_OPTIMIZATION_GLOBAL_SHADER_PERMUTATION_EDITOR_ONLY / _MOBILE_DEFERRED_RENDERING / _VIRTUAL_TEXTURING / _SKYATMOSPHERE / _TONEMAPPER：按项目实际用到的渲染特性裁剪全局 Shader 变体，直接减少 PSO 总量与编译时间。
  • XD_OPTIMIZATION_PPMATERIAL_USE_IN_BASEPASS、XD_OPTIMIZATION_MOVABLE_DIRECTIONAL_LIGHT_PERMUTATION：为移动端 BasePass / 可移动平行光增加「是否编译该排列」的开关。
  • XD_MISC_ADD_SHADER_COMPILE_LOG、XD_MISC_LOG_SHADER_DETAILED_DDC_KEY、XD_FIX_BUG_SOLVE_FAIL_TO_FIND_SHADER_MAP、XD_TOOL_STAT_GL_PROGRAM_MEM_SIZE：编译失败诊断与 GL Program 内存统计。

3. 调试与验证入口

  • 统计命令：stat Shaders（含 GL Program 内存）、r.ShaderPipelineCache.* 系列 CVar。
  • Cook 侧：ShaderPipelineCacheToolsCommandlet 生成/合并 .stable.upipelinecache；-LogMATSMDDCKey 打印 DDC Key。
  • 赛季清理：改 XD_TORCHLIGHT_SEASON 即可让旧 PSO/PBC 全部失效，是热更前最常用的开关。

4. 注意事项

  • 平台限定：Vulkan 重启仅 Android；MuMu 检测仅在 USE_ANDROID_OPENGL && UE_ANDROID_X86_64 下生效；metallib 压缩仅 Apple。
  • 依赖：XD_OPT_SHADER_LIB_SRIP/XD_OPT_COOK_ENABLE_CHERRY_PICK 需要 XDLivePatch 插件配合；XD_MISC_CLEAN_OBSOLETE_PSO_CACHE_AND_PROGRAM_CACHE 依赖 XD_TORCHLIGHT_SEASON。
  • 默认关闭：XD_OPT_LOAD_PSO_CACHE_BY_QUALITY_LEVEL=0、XD_OPTIMIZATION_GLOBAL_SHADER_PERMUTATION_TONEMAPPER=0，改动前先确认收益。
  • 命名注意：源码里存在历史拼写，如 XD_EXT_SHDADER_UNUSED_PBC_EVICT（SHDADER）、XD_FIX_BUG_SOLVE_FAIL_TO_FIND_SHADER_MAP，检索时以实际宏名为准。
