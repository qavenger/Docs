设计原则：艺术家主导，AI 扩展表达

艺术家主导

创意所有权不变

艺术家决定故事、情绪、表演和镜头是否成立。AI 提供候选、解释差异并吸收反馈，每一轮结果都服务于人的创作判断。

视频是中间媒介

先看见，再制作

AI 视频用于快速回答“这个创意看起来怎样”，承担预视觉、比较方案和锁定方向的功能；获批的导演意图随后进入结构化生产阶段。

Sequencer 是交付物

结果必须可编辑

最终输出使用项目真实角色、场景、动画、相机、灯光和声音，团队可以继续调整、优化、回滚并在目标平台运行。

期望的艺术家体验

艺术家说

“镜头不要这么英雄化。让角色更疲惫，停顿久一点；月光只勾出轮廓，暂时不要让观众看清神殿内部。”

系统理解并提案

降低机位和推镜速度，延长反应停顿；将正面主光改为弱冷轮廓光；生成两版 6 秒预视觉供比较，并解释变化。

方向批准后

检索项目角色、场景、动作和灯光模板，生成 ShotSpec；Agent 在 UE 中创建 Level Sequence，输出 Proxy Render 和差异清单。

相邻的成熟工作流：3D 白盒 → AI 视频
与本愿景方向相反的生产链路已经形成较多公开实践：创作者先在 UE 或 Blender 中搭建白盒场景、角色走位和相机运动，输出 Playblast，再交给视频生成模型补充角色外观、材质、环境和电影化光影。由于三维空间和运镜在输入端已经确定，这条路线具有较强的运动控制力，并验证了“3D 结构 + AI 视觉生成”的价值。

本愿景在此基础上进一步向创意上游延伸：以艺术家的文字描述和 AI 预视觉为起点，在方向获批后，将导演意图反向编译为项目内可编辑的 Sequencer。后续章节评估这条新增链路中各环节的成熟度、可自动化范围和研发缺口。

SECTION 01

执行摘要：愿景的当前可行性

围绕“艺术家文字创意 → AI 预视觉与审核 → AI + MCP 生成 Sequencer”这一总体目标，当前各环节的成熟度并不相同。文字理解、创意扩写、预视觉和编辑器自动组装已经可以承担实际工作；生成视频到三维表演、相机和灯光的转换仍是决定端到端质量的主要研发区。

高可行

创意与自动组装

AI 关键帧 / 视频非常适合探索构图、情绪、节奏和导演意图。锁定镜头清单后，UE 的 Sequencer Scripting 能确定性地创建相机、绑定、轨道、区段和动画引用。

中可行

视频转表演动画

单人、全身可见、遮挡较少的身体动作已可实用；面部在 MetaHuman 体系内较成熟。手指、道具、双人接触、地面接触、快速翻滚仍需要专门捕捉或较多清理。

研发项

视频反推镜头与布光

镜头切分、主体追踪、粗略相机运动和光照语义可自动分析；从单段生成视频唯一还原三维镜头、焦距、场景尺度和光源参数不可保证，只能“匹配画面”，不能宣称“恢复真值”。

一句话建议
将项目定义为“AI 辅助的实时过场编译管线”：AI 负责提出意图与候选，ShotSpec 负责把意图结构化，专业求解器负责产生动画 / 相机数据，MCP 与 UE Python 负责安全组装，人负责锁定、修正和签收。

SECTION 02

六条设想逐项评估

1. 一次性角色动画外包成本高

判断成立 一次性过场通常存在大量不可复用的表演：停顿、视线、手势、道具接触、双人距离、镜头内节奏。它们的成本不仅是“做骨骼动画”，还包括导演沟通、参考拍摄、重定向、修脚、面部、布料、碰撞和返修。

AI 真正能省的

减少错误方向的动画制作；把导演意图在进入昂贵动画阶段前可视化；为动画师提供带时间的参考；自动处理一部分基础身体运动、口型和初始 Sequencer 组装。

AI 不会自动消失的

角色 rig 质量、道具约束、接触、风格化运动、动画层、镜头遮挡、可玩状态切换、审美签收和资产治理。

建议：不要以“替代动画外包”为唯一 ROI。更稳的收益是更早暴露问题、减少方向性返工、将重复组装自动化。

2. AI 生关键帧 / 视频做前期创意迭代

可立即采用 这是整条流程中最成熟、回报最快的一环，适合探索景别、构图、光色、节奏、表演强弱和镜头衔接。

  • 先建立角色、服装、场景、道具和色彩脚本，使用批准的资产参考，而非每镜自由生成。
  • 以镜头为单位生成 3–8 秒候选，再在剪辑软件中拼接；不要一开始追求 30–60 秒连续生成。
  • 在画面上叠加镜头编号、时长、角色、动作、台词和“不可改项”，让评审针对导演意图而不是像素瑕疵。
  • 给每个镜头保留 prompt、seed / 参考图、模型版本、裁切和剪辑记录，以便复现。
边界
生成视频会产生结构漂移、角色身份变化、肢体幻觉和不可能的相机运动。它是设计提案，不能默认为动作捕捉或相机求解的无噪声输入。

3. 对满意视频进行角色表演拆解

可落地，但必须结构化 “拆解”应输出数据，而不是另一段自然语言。最低限度需要 Shot Manifest 和每角色的 Performance Sheet。

层级应记录内容原因
镜头入出点、画幅、景别、镜头运动、焦点、剪辑动机决定 Sequencer 时间轴和相机切换
角色可见区间、根运动、动作阶段、朝向、视线、情绪、接触物决定身体 / 面部 / 眼神 / 道具的独立任务
环境地面、座椅、门、武器等约束对象与接触帧纯视觉 mocap 不知道 UE 中真实碰撞位置
声音台词、呼吸、动作点、音乐 hit point、环境声支持口型、节奏和音频事件轨
不确定性遮挡、出画、AI 幻觉、无法确定的手或脚直接标为人工处理，不把错误自动传下游

建议：用视觉模型辅助切镜、追踪、姿态和事件识别，但由导演 / 动画负责人锁定镜头时长与动作意图。被锁定的视频应冻结版本，后续改剪辑要触发依赖失效。

4. 由视频生成一次性表演动画资产

条件性可用 商业单目方案已能从普通视频生成 3D 骨骼运动并导出 FBX / BVH / GLB 等，再通过 UE IK Rig / IK Retargeter 转到目标骨架。MetaHuman Animator 可以用单目视频、深度或音频产生 MetaHuman 表演。

适配较好

单人、全身可见、固定相机、光线均匀、3–10 秒、行走转身和普通手势。

需要清理

脚滑、根运动漂移、髋部高度、关节穿插、动作抖动、落地冲击、视线和节奏。

建议改用捕捉

双人搏斗、拥抱、坐椅 / 开门、武器交锋、手指特写、地面翻滚、强遮挡和长镜头。

更正：“根据视频中角色动画生成资产”并不意味着必须使用 AI 生成视频作为求解源。若创意锁定，最好让真人按同样节奏重新表演一条干净参考，用单目 / 多目 mocap 求解；生成视频保留为导演参考。这样通常比强行从有幻觉、遮挡和运动模糊的视频反求更稳定。

5. 大模型分析角色、运镜、布光，并通过 MCP 在 UE 还原

部分可用，核心是工程研发 应拆成四个独立问题：

  1. 语义理解：识别角色、动作阶段、主光方向、色温、景别和“推 / 拉 / 摇 / 移 / 跟”等意图，当前模型可以给出有用初稿。
  2. 测量与求解：人物分割、2D 跟踪、姿态、深度、光流、特征点、相机标定。这应交给专业 CV / DCC 求解器，而不是只靠 LLM 看图描述。
  3. 三维匹配：把求解结果映射到已有 UE 场景、角色尺度、镜头内参与灯具。生成视频往往没有一致三维几何，只能优化到视觉相似。
  4. 编辑器执行：通过受约束 MCP 调用 UE Python / Remote Control / Editor Utility，创建序列和轨道。这部分高度可自动化。
不能跳过的事实
单张或单目视频中的光照、材质和几何存在不可辨识性：多组灯光与材质可以产生相近像素。相机焦距和相机距离也可互相补偿。最终目标应叫参考匹配（reference matching），而不是“恢复原始参数”。

6. 最后生成配乐、台词、音效

可落地 文本转语音、语音转换、文本转音效、音乐生成已适合快速样片和部分正式资产。声音不应放到“最后才考虑”：台词时长影响口型与剪辑，音乐重拍影响动作和切镜，脚步 / 武器 / 门等音效需要事件点。

建议：前期先用临时对白和 temp music 锁节奏，画面锁定后再生成或录制最终对白；动作音效通过 Sequencer / Animation Notify 绑定；最终在 DAW 中做响度、空间、动态和版权审查。

SECTION 03

关键修正：从“一条模型链”改成“分支汇合”

原设想中容易踩坑的线性逻辑

创意视频 → 直接提取所有角色动画 → 直接反推相机和灯光 → MCP 完整还原。

任何一个上游幻觉都会变成下游资产错误；一旦剪辑改变，全部重做。

建议的生产逻辑

创意视频只负责锁意图；身体、脸、手、道具、相机、灯光、声音分别选择最合适的数据源和求解器，最后以 ShotSpec 和时间码汇合。

每个分支都可替换、可降级、可人工接管。

每个关口应锁定什么

Gate A · 创意锁定

锁定镜头顺序、每镜时长、角色动作意图、台词和音乐节拍。不锁像素瑕疵，也不承诺 3D 参数。

Gate B · 动画锁定

在灰盒场景和目标角色比例上检查轮廓、接触、脚滑、根运动、面部时序和进出状态。

Gate C · 镜头锁定

锁定 camera cut、transform、filmback、focal length、focus、关键灯光意图和可见性。之后才进入高成本灯光 / 布料 / 声音精修。

SECTION 05

动画生成：不是一个模型，而是五条轨道

Body

身体与根运动

单目视频 mocap 可提供初始骨架运动。优先选清晰、短、无遮挡、全身在画面的表演。导入后通过 IK Retargeter 转到目标骨架。

Hands

手指与抓握

多数单目全身方案的弱项。特写镜头建议手部专门捕捉、手势库、Control Rig 或关键帧。抓握要绑定真实道具 socket / constraint。

Face

脸与口型

MetaHuman 可走视频、深度或音频工作流。自定义角色需要解决 blendshape / joint 映射和风格化比例，不应默认零成本。

Contact

物体与双人接触

用接触事件、IK Goal、约束、Motion Warping 和手工 pose 修复。仅从独立人物视频求解无法保证双方表面相遇。

Secondary

布料、毛发、附件

在身体动画锁定后由 UE 物理 / 缓存或 DCC 模拟处理。AI 视频中的飘动只作为风格和时序参考。

Layering

动画分层

基础 locomotion、上身表演、头眼、呼吸、手部和面部独立成层，避免每次修改都重算整段。

推荐的输入拍摄规范

  • 一镜一动作，优先 3–10 秒；录制开始和结束留静止姿态。
  • 人物全身持续入画，避免宽松衣物遮住关节；背景与服装有反差。
  • 相机固定、少运动模糊、均匀照明；高帧率优先于电影感。
  • 地面可见，并记录演员身高、相机高度、距离和焦距，提供尺度锚点。
  • 双人 / 道具镜头另录手、接触和相对位置参考；不要只上传最终合成视频。

SECTION 06

相机与灯光：从“恢复真值”改成“约束匹配”

相机匹配的可靠性梯度

较可靠

真实静态场景视频

有稳定特征点、已知 filmback / 焦距、少运动模糊、无变焦，可用 SfM / matchmove 求相机轨迹，再导入 UE。

可粗配

实拍人物 + 简单背景

人物是动态遮挡，应先 mask，再用背景特征求解；焦距和尺度仍需锚点。

只做视觉优化

AI 生成视频

跨帧几何可能变化，光流和特征点不服从真实相机。建议用 UE 场景渲染与参考画面做轮廓 / 构图损失迭代，而非相信唯一轨迹。

相机参数应拆开处理

参数可从视频得到什么还需要什么
Camera Cut / 时长镜头边界、入出点通常可自动检测并人工修正剪辑锁定版本
Transform真实静态场景可求轨迹；生成视频多为粗略趋势3D 特征、尺度锚点、场景对齐
Focal Length / Filmback可按透视和主体占比拟合，不一定唯一传感器、镜头先验或镜头库约束
Focus / Aperture可估计清晰主体和景深观感UE 内目标距离、Cine Camera 的物理参数
Lens Distortion实拍标定板可求；生成视频无真实镜头模型镜头标定数据或风格化后期
Shake / 手持感可从 2D 运动频谱提取风格与主体运动分离、幅度限制

灯光建议采用“两层方案”

第一层：语义 LightingSpec

视觉模型输出“暖色硬主光从画面左上、冷色弱填充、背后窄轮廓、背景雾中有体积光”等描述，并给出置信度。它负责初始化，而非直接生成几十盏灯。

第二层：UE 画面匹配

在既定材质、曝光和 OCIO 下，仅优化少量参数：主光方位 / 尺寸 / 色温 / 强度、fill ratio、轮廓光、天空与雾。用参考 / UE 并排和差值图评审。

Lumen 相关限制
Lumen 提供动态间接光和反射，但结果取决于几何、材质、追踪模式、缓存和性能设置；大范围光照变化可能有更新延迟，小而强的 emissive 也可能产生噪声。参考匹配必须在目标平台配置下验收，而不是只看编辑器最高画质。
SECTION 07

市场与公开验证：方向存在，但尚未看到同等完整的端到端产品

调研结论（资料快照：2026-08-20）
公开市场已经分别验证了3D 灰盒控制生成视频、视频求相机、单图 / 视频估光、Agent 操作 DCC / UE四个组件；但本次检索没有找到一个具有可复现实验、公开工程细节或独立评测的成熟方案，能把 AI 生成视频 → 恢复相机与显式灯光参数 → Agent 在 UE 中自动搭建 → 渲染闭环验证完整跑通。最接近的公开实践多数是相反方向：先在 UE / Blender 设计相机和灰盒，再让视频生成模型沿用运动并完成视觉渲染。Seedance 只是这类模型中公开案例较多的一个例子，结论同样适用于其他支持图像、视频或运动参考的生成模型。

AI 视频 × 3D 的公开工作流，主要是“正向约束”

公开案例覆盖多种支持视频或运动参考的生成模型，其中 Seedance 因当前运动跟随效果和社区案例较多而经常出现。例如 Seedance Camera Reference using Unreal Engine、Can AI Render Unreal Engine 5 Blockouts?、Turning Unreal Engine 5 Blockouts into Cinematic AI Renders，以及 ComfyUI 的 Playblast to Final Render。这些案例在本报告中只作为通用“3D 参考 → AI 视频”范式的样本，不把工作流绑定到某个模型。共同模式是：

01UE / Blender 灰盒人物、场景和相机轨迹已在 3D 中确定
02Playblast输出稳定运动、遮挡和透视参考
03AI 视频生成使用适合当前项目的模型增强角色、材质和灯光观感
04筛选 / 后期接受视频输出，不要求返回可编辑三维参数
结果运动受控的 AI 视频不是由 AI 视频恢复出来的 Sequencer

这条正向路线之所以先成熟，是因为相机和空间约束在输入端就已知。它也提示了一个更稳的混合策略：AI 创意视频用于设计；正式生产时，在项目现有镜头模板中找近邻或先搭粗略 3D 相机，再让视频模型做第二轮创意渲染，而不是要求一次反求全部未知量。

相机反求：已有强组件，但 AI 生成视频是特殊输入域

开源研究工具

ParticleSfM 用光流、运动分割和全局 SfM 从动态视频重建相机轨迹；VGGT 可由图像 / 视频帧预测相机内外参、深度、点图和轨迹；DUSt3R 可输出焦距、图像 pose 和对齐点云；DROID-SLAM 通过稠密 BA 估计相机与深度。

它们证明“视频 → 初始 3D camera”技术上成立，但共同依赖跨帧对应和相干三维结构。

直接面向 UE 的商业工具

Boundless Genesis 宣称在 UE 5.7 / 5.8 内自动完成真实素材的相机跟踪、环境 mesh / point cloud、镜头畸变和 background plate，并输出 tracked UE camera。

这是市场上离“视频进、UE 相机出”最近的成品证据；但厂商明确依赖环境细节和视差，页面没有通用 AI 生成视频测试，也没有独立准确率评测。

对 AIGC 视频的含义
可以把这些求解器直接用于 PoC，但必须把“解算失败”视为正常分支。不同视频生成模型都可能出现局部尺寸变化、背景漂移、伪变焦、物体生成 / 消失或非物理镜头；求解器会把这些误认为相机或动态物体运动。建议测试时覆盖至少两种视频模型，并同时跑 VGGT / ParticleSfM / Genesis 中至少两种求解方案，用重投影误差、轨迹平滑度和 UE proxy 对比选择，而不是只相信单一输出。

灯光反求：研究较活跃，但显式 UE 灯具仍是空白

方法 / 产品输入 → 输出可以怎样接 UE不能证明什么

因此，“Agent 布光”当前最现实的实现不是由一个模型恢复全部物理灯，而是：

  1. DiffusionLight / lighting-estimation 模型给出 HDR 环境光、主光方向、色温和置信度。
  2. 检索项目已有 Lighting Template，选择最相近的一套批准 rig。
  3. Agent 只调整有限参数：模板、主光方位 / 高度、强度倍率、fill ratio、色温、曝光。
  4. 通过 Unreal MCP / Python 应用参数，输出 viewport / MRQ proxy。
  5. 视觉模型比较参考与 proxy 的主体明暗分区、阴影方向、轮廓光、色温和曝光，迭代 3–5 次后交灯光师签收。

Agent 布光和 Sequencer 执行层已经出现

Epic 已为 UE 5.8 文档化实验性的 Unreal MCP，可调用 All Toolsets / Toolset Registry 中的编辑器工具，官方示例包含 Actor 与灯光修改。社区的 Flux Point Unreal MCP 则明确列出 manage_lighting、manage_sequence、camera / viewport / screenshot 等能力；BlenderMCP 也演示了从参考图创建场景、添加 studio lights / HDRI、调整相机并让 Claude 查看 viewport screenshot。

这些案例验证了闭环的后半段：

结构化 LightingSpec / CameraSpec → Agent 调 MCP 创建或修改灯光与相机 → 获取 viewport screenshot / proxy render → 多模态模型评价 → Agent 调整少量参数 → 人工批准

公开资料尚未证明前半段——“对任意 AI 生成视频稳定生成正确 LightingSpec / CameraSpec”——已经成为成熟产品。

安全边界
UE Remote Control HTTP / WebSocket 文档没有提供完整的认证、授权和传输安全方案，并且相关能力被标为 Beta。不要把编辑器端口直接暴露到公网。MCP Server 应部署在本机或受控网络，做鉴权、白名单、速率限制、超时、事务、审计和输出目录隔离。

Editor 与 Runtime 的区别

UE Python 是编辑器内容生产工具：可批量处理资产、创建序列、调用编辑器 API，但不能作为 PIE、Standalone 或 cooked build 中的游戏逻辑。这里的“实时过场”应理解为：在编辑阶段生成 / 烘焙 Level Sequence 与 AnimSequence，游戏运行时由原生 Sequencer 系统播放。若要在玩家运行时实时生成新过场，则需要另行设计 C++ / Blueprint 运行时系统、网络与性能边界，其风险和范围显著更高。

隐私与未发布资产外泄高把剧本、角色、镜头上传云服务企业条款、数据保留设置、脱敏 / 本地模型、资产分级
审美趋同中完全依赖模型默认镜头和表演导演规则、镜头语法库、批准参考、人工 hero pass
目标平台性能失败中高质量 Lumen、groom、cloth 只在工作站可播早期平台预算、自动 profile、LOD、预烘焙和降级路径

推荐的数据治理字段

每个生成或转换资产至少记录：source_asset、source_license、consent、vendor、model/version、prompt、seed/reference、created_at、operator、reviewer、approved_use、derived_assets。这些字段应进入资产管理系统，而不是只留在聊天记录。

SECTION 11

4–6 周最小试点

建议样本
选择一段 20–30 秒、2 个角色、3–5 个镜头的对白型过场：包含一次走位、一次坐 / 站或拿取道具、一个面部特写，但避免复杂打斗、群演、载具和长镜到底。使用项目现有角色、场景与 rig，才能测到真实集成成本。

第 1 周 · 基线与约束

选定镜头；用现有传统流程估时；建立角色 / 场景资产白名单、ShotSpec v0、镜头编号和验收 rubric。输出传统方案的基线工时与 proxy。

第 2 周 · AI Animatic

制作关键帧与 3–5 版短视频候选，锁定剪辑、台词与动作意图。记录生成次数、人工筛选时间和不可实现设计。

第 3 周 · 表演求解

同时测试两条路径：A 从锁定视频直接求解；B 真人按锁定节奏重演后求解。导入 UE、重定向，并记录清理工时与误差。

第 4 周 · Camera / Light / Sequencer 编译

实现最小 MCP 工具：plan、create sequence、bind、add animation、configure camera、proxy render。相机和灯光只做有限参数匹配。

第 5 周 · 声音、QC 与目标平台

加入对白、面部、音效和 temp music；输出 MRQ 对照和运行时 build；检查穿插、失焦、渲染差异、帧率与内存。

第 6 周 · 复盘与第二轮

只针对瓶颈重跑一轮，验证工具是否降低第二次迭代成本。形成保留、替换、放弃的能力清单。

KPI：不要只看“生成用了几分钟”

指标测量方式意义
首版可评审时间需求确认 → 有声音 proxy 可观看验证创意迭代收益
锁剪辑后返工时间一次明确导演修改 → 新 proxy验证结构化与自动组装是否有价值
动画清理比清理人工小时 / 最终镜头秒数识别视频 mocap 是否真的省工
自动组装成功率无需手动修复即可生成有效序列的 ShotSpec 比例验证 MCP 与 schema 稳定性
接触 / 穿插缺陷每镜严重缺陷数，按脚、手、道具、双人分类避免主观“看起来不错”掩盖生产问题
参考匹配切点、主体框、视线、构图、色温与关键动作点的 rubric比像素相似度更贴近导演意图
目标平台成本帧时间、显存、序列加载和峰值内存确保它是实时过场而非仅离线 CG
单分钟总成本服务费 + 人工 + 重跑 + 清理 + 集成与传统基线公平比较

试点角色配置

最小团队建议包含：过场导演 / 叙事设计、动画师、技术动画 / TA、UE 工程师、灯光、声音设计。一个人可兼多职，但签收责任要明确。不要只由 AI 工程师判断动作和镜头是否达到制作标准。

SECTION 12

Go / No-Go 决策标准

GO · 扩大试点
  • AI Animatic 明显减少方向性返工，团队愿意用其签审。
  • Standard 镜头的视频 mocap 清理工时低于传统基线。
  • ShotSpec → Sequencer 可重复、幂等，第二轮修改更快。
  • Hero 镜头有明确人工升级路径，不被全自动目标拖累。
  • 授权、数据安全和供应商条款得到法务 / 安全认可。
NO-GO · 暂停端到端
  • 大部分镜头因遮挡 / 接触需重做，清理超过手工制作。
  • 生成视频反复设计出现有资产无法实现的表演与场景。
  • 镜头 / 灯光求解无法稳定复现，仍靠逐镜手工猜测。
  • MCP 缺少 schema、diff、事务和审计，修改不可控。
  • 目标平台性能、数据合规或声音 / 参考授权无法关闭。

推荐的阶段路线

  1. 先投产：AI storyboard / animatic、临时声音、Shot Manifest、Sequencer 批量组装与 proxy 渲染。
  2. 再规模化：针对 Standard 镜头建立规范化真人重演 + 视频 mocap + Retarget + Control Rig 清理模板。
  3. 后研发：生成视频的相机 / 灯光参考匹配、视觉差值优化、多 Agent 自动 QC。
  4. 最后评估：真正运行时动态生成新过场。它涉及 shipping API、安全、确定性、联网、延迟和性能，不应与编辑器内自动制片混为一谈。
最终建议
项目值得做，且最有价值的近期目标不是“无人化”，而是把过场制作从松散手工步骤变成有结构化契约、可替换求解器、可自动组装、可追踪回滚的生产系统。先用 20–30 秒试点证明“第二次迭代更便宜”，再决定是否投入视频反求相机 / 灯光等研发项。

  6. Epic Games — MetaHuman Animator：视频、深度和音频的实时 / 离线 MetaHuman 表演工作流。

  10. Epic Games — Color Management with OpenColorIO：媒体、视口、Composure 与 MRQ 的色彩变换。

  20. ElevenLabs — Music：音乐 / 歌曲生成、提示控制、参考和时长；商业许可与输出能力以当前条款 / 套餐为准。

  22. JSFILMZ — AI Render Unreal Engine 5 Blockouts：UE blockout 到 AI 视频渲染的创作者测试；证明运动参考价值，不证明输出可反解。
  23. 社区案例 — Unreal Engine Camera Reference：以 Seedance 为例的 UE camera reference 演示；在本报告中仅作为“3D 约束 → 视频生成”范式样本。
  24. Epic Games — Unreal MCP in Unreal Editor（UE 5.8）：实验性官方 MCP、Toolset Registry 与 Agent 编辑器操作；执行工具，不包含参考视频反求。
  25. Flux Point Studios — Unreal MCP：社区 MIT 项目，包含 lighting、sequence、camera、viewport、screenshot 等 Agent 工具；未包含视频逆向重建。
  26. BlenderMCP：参考图建场景、studio lights / HDRI、相机与 viewport screenshot 的 Agent 演示；未声明视频相机 / 灯光精确恢复。
  27. Boundless Entertainment — Genesis：商业 UE 5.7 / 5.8 matchmove 插件，厂商宣称自动 tracked camera、environment mesh、point cloud、lens distortion 与 plate setup；面向真实素材，未公开通用 AIGC 视频验证。
  28. ByteDance — ParticleSfM：动态视频中的光流、运动分割与全局 SfM，输出相机轨迹和 COLMAP 结构；GPL-3.0。
  29. Meta — VGGT：从图像 / 视频帧预测相机内外参、深度、点图和轨迹；需做 OpenCV → UE 坐标与曲线清理，商用 checkpoint 条款需单独核实。
  30. Naver — DUSt3R：从重叠图像恢复焦距、pose 和对齐点云；代码 / 权重为非商业许可，且要求跨帧几何一致。
  31. Princeton — DROID-SLAM：从单目 / 双目 / RGB-D 图像序列估计 camera motion 与 depth；BSD-3-Clause，需已知或合理相机标定。
  32. DiffusionLight：单图 chrome-ball 多曝光估计 HDR environment map；可作为 UE HDRI 初值，但不是局部灯具恢复。
  33. NVIDIA Research — UniRelight：联合 albedo 分解和视频 relighting；输出 relit video / albedo，不输出显式 UE 灯具参数。
  34. DiffusionRenderer（CVPR 2025）：视频到 G-buffer 的神经逆向渲染与 G-buffer 到图像；公开摘要未声明显式相机 / 光源恢复。
  35. IllumiCraft：以视频、prompt 和可选背景控制几何 / 照明观感；Apache-2.0，属于视频生成 / relighting，不是灯具反解。
  36. Light-X（ICLR 2026）：由源视频、用户给定相机轨迹和文本 / HDR / 图像照明联合生成 4D 视频；证明联合控制，但 trajectory 与 lighting 是输入条件而非恢复结果。
  37. Video Camera Trajectory Editing with Generative Rendering（AAAI 2026）：由单目视频和用户定义 camera path 重合成新视角；不提供 UE camera track 导出，也不反求灯光。

PoC 前必须补做的实测

  • 用团队真实角色骨架对 10 类动作测试 2–3 个视频 mocap 供应商，而非引用 demo。
  • 对相同镜头比较“生成视频直接求解”和“真人干净重演求解”的清理小时。
  • 确认 MetaHuman Animator 与目标 UE 版本、目标角色类型、部署平台和许可相容。
  • 在内网环境做 MCP / Remote Control 威胁建模，验证未授权对象和路径无法访问。
  • 让法务审阅使用的图像、视频、声音和音乐服务条款，并保存当日条款快照。
  • 在真实目标机测 Level Sequence、Lumen、groom、cloth、音频和加载峰值。
